# 주문팡팡 + 소싱라이프 서비스 기획

## 1. 서비스 정의

주문팡팡은 여러 판매처의 주문을 한 화면에서 수집, 조회, 처리하는 통합 주문관리 프로그램이다.
주문 처리 과정에서 소싱라이프를 연결해 상품 소싱, 구매 처리, 국내송장 확보를 진행한다.

## 2. 핵심 목표

1. 모든 판매처의 주문을 한 화면에서 통합 조회한다.
2. 마켓별 주문 상태를 주문팡팡 내부 상태로 통일한다.
3. 운영자는 주문팡팡에서 주문확인, 소싱 진행상태 확인, 국내송장 확인, 배송중 처리를 진행한다.
4. 소싱라이프는 외부 소싱/구매 서비스로 연결하며, 주문팡팡은 소싱라이프 연동 상태만 관리한다.
5. 스마트스토어, 쿠팡을 먼저 연동하고 11번가, 지마켓, 옥션으로 확장한다.

## 3. 연동 우선순위

최종 연동 대상은 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션이다.
초기에는 스마트스토어와 쿠팡만 계정 등록 및 주문수집을 활성화한다.
11번가, 지마켓, 옥션은 확장 예정 마켓으로 관리하며, 초기 화면에서는 비활성 상태로 노출하거나 추후 활성화한다.

| 우선순위 | 판매처 | 연동 기준 |
|---|---|---|
| 1 | 스마트스토어 | 커머스API |
| 2 | 쿠팡 | 쿠팡 Open API |
| 3 | 11번가 | 11번가 Open API |
| 4 | 지마켓 | ESM PLUS API |
| 5 | 옥션 | ESM PLUS API |

## 3-1. 판매처 계정 등록 정책

- 주문팡팡은 마켓별 다중 계정 등록을 지원한다. 최종적으로 사용자는 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션에서 운영 중인 판매자 계정 또는 스토어를 개수 제한 없이 등록할 수 있다.
- 주문수집은 활성화된 모든 연동 계정을 대상으로 실행하며, 특정 판매처만 수집하거나 특정 계정만 수집하는 기능은 초기 범위에 포함하지 않는다.
- 주문 목록에는 판매처뿐 아니라 어떤 판매자 계정/스토어에서 수집된 주문인지 함께 표시한다.
- 여러 개의 스토어/판매자 계정이 등록된 경우 주문수집 화면에서 마켓별, 계정별, 기간별, 검색어 기준으로 주문 목록을 조회할 수 있어야 한다.
- 주문 목록에는 주문이 수집된 마켓과 연동 계정을 별도 정보로 표시한다.
- 주문 테이블과 주문상세 모달은 주문 처리에 필요한 정보와 현재 상태에서 가능한 다음 단계 액션을 제공한다.
- 마켓별/계정별 필터는 주문 조회용 필터이며, 주문수집 실행 범위를 제한하는 기능은 아니다.
- 계정별 인증 상태, 수집 성공/실패 상태, 마지막 수집 시각은 계정 단위로 관리한다.

## 4. 전체 주문 처리 흐름

```text
마켓 결제완료 주문
→ 주문팡팡 주문수집
→ 신규주문
→ 주문확인
→ 상품준비
→ 소싱하기(상품 매칭/구매/결제)
→ 발송대기
→ 소싱라이프 국내송장 확보 또는 운영자 수동 입력
→ 국내송장 자동저장
→ 배송중 처리(마켓 송장전송)
→ 배송중
→ 배송완료
```

## 5. 소싱라이프 관계 정의

- 소싱라이프는 주문팡팡 내부 기능이 아니다.
- 주문팡팡은 소싱라이프 주문 생성 여부, 소싱라이프 결제 여부, 국내송장 확보 여부를 주문 단위로 관리한다.
- 소싱라이프 주문번호는 소싱라이프 주문 생성 성공 시점에 저장하며, 소싱라이프 결제 완료 여부와 별도로 관리한다.
- 소싱라이프 내부의 구매, 검수, 입고, 물류 상세 처리는 주문팡팡 범위가 아니다.
- 주문팡팡의 책임은 소싱라이프 처리 결과를 주문 상태에 반영하고, 국내송장을 마켓에 전송할 수 있도록 관리하는 것이다.
- 소싱 후보가 적합하지 않은 경우 운영자는 소싱라이프 화면으로 이동해 직접 검색 또는 이미지 검색으로 상품을 찾을 수 있다.

## 6. 주요 메뉴

| 메뉴 | 역할 |
|---|---|
| 대시보드 | 주문 처리 현황, 수집 실패, 배송중 처리 실패 요약 |
| 주문수집 > 전체 | 일반 주문 전체 통합 조회 |
| 주문수집 > 신규주문 | 수집된 마켓 결제완료 주문 확인 및 주문확인 |
| 주문수집 > 상품준비 | 소싱라이프 상품 매칭, 구매, 결제 진행 |
| 주문수집 > 발송대기 | 소싱라이프 결제 완료 후 국내송장 대기, 입력, 송장 수집, 배송중 처리 |
| 주문수집 > 배송중 | 마켓 송장전송 완료 주문 추적 |
| 주문수집 > 배송완료 | 배송완료, 구매확정 주문 조회 |
| 내정보 > 마켓연동 | 판매처별 API 인증 정보와 마켓수수료율 관리 |

## 7. 주요 화면 흐름

| 화면 | 핵심 기준 |
|---|---|
| 사이드바 | 주문수집(일반 주문: 전체, 신규주문, 상품준비, 발송대기, 배송중, 배송완료 / 클레임: 취소/반품/교환), 문의관리, 장부다운로드, 내정보 |
| 주문수집 화면 | 좌측 메뉴에서 선택한 주문 그룹과 상태 기준으로 상태별 집계 + 검색/필터 + 주문 테이블을 구성 |
| 신규주문 | 선택된 주문에만 `주문확인` 전역 액션 제공, 행별 `주문확인`, `소싱하기`, `주문취소` 노출 |
| 상품준비 | `소싱하기` 액션으로 소싱라이프 상품 매칭, 구매, 결제 진행, 소싱라이프 송장 수신 시 자동 배송중 처리 토글 제공 |
| 발송대기 | `전체`, `송장 있음`, `송장 없음` 필터와 `송장 수집`, `배송중 처리` 제공 |
| 배송중/배송완료 | 상태 확인 목적 조회 화면, 개별 액션은 기본적으로 비활성 |
| 취소/반품/교환 | 일반 주문과 별도 클레임 그룹으로 노출하고 주문별 `클레임확인` 액션 제공 |
| 소싱라이프 페이지 | 매칭 후보 확인, 결제 신청, 소싱라이프 결제 완료 반영 경로로 연동 |

## 8. 초기버전 주문 테이블 기준

- 초기버전에서는 주문 행을 펼쳐 상세정보를 보는 구조를 사용하지 않는다.
- 운영자가 주문 처리에 필요한 정보를 주문 테이블에서 바로 확인할 수 있도록 한다.
- 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 서로 다른 업무 목적의 상품정보, 구매자정보, 수령인정보, 소싱정보, 송장정보, 처리버튼을 한 컬럼에 섞어 표시하지 않는다.
- 마켓수수료율은 판매처 또는 스토어별로 설정할 수 있어야 하며, 장부 기능과 마진 계산에 사용한다.
- 마켓수수료율 설정 위치는 `내정보 > 마켓연동`이며, 마켓 또는 연동 계정 단위로 관리한다.
- 주문수집 화면에서는 주문 처리에 필요한 핵심 정보와 액션을 우선 표시하고, 수수료 상세값은 장부/정산 기능에서 중심적으로 다룬다.
- 처리이력은 초기버전 주문관리 화면 범위에서 제외한다.

## 8-1. 국내송장 처리 기준

- 상품준비에서 `소싱하기`로 소싱라이프 결제가 완료되면 소싱라이프 주문번호, 결제정보, 국내송장 정보를 함께 반영한다.
- 국내송장이 없으면 주문은 발송대기 상태로 이동한다.
- 국내송장이 있더라도 `소싱라이프 송장 수신 시 자동 배송중 처리`가 OFF이면 송장번호가 입력된 상태로 발송대기에 남긴다.
- 국내송장이 있고 해당 토글이 ON이면 배송중 처리를 자동 시도하고 성공 시 배송중으로 이동한다.
- 발송대기 상태는 배송중 처리 전 국내송장 수집 또는 확인이 필요한 상태다.
- 국내송장은 소싱라이프에서 발급된 송장을 가져오거나 운영자가 직접 입력한다.
- 국내송장은 자동수집, 송장 수집, 운영자 수동 입력 중 어떤 방식으로 입력되어도 즉시 자동저장된다.
- 자동수집 ON은 발송대기 상태에서 소싱라이프에 발급된 국내송장을 자동으로 가져오는 기능이다.
- 송장 수집은 운영자가 버튼을 눌러 소싱라이프 주문번호 기준으로 발급된 국내송장을 조회하는 기능이다.
- 송장 수집 대상은 소싱라이프 주문번호가 있고 국내송장이 없는 발송대기 주문이다.
- 수동 입력은 운영자가 국내 택배사와 국내송장번호를 직접 입력하는 기능이다.
- 자동 배송중 처리 ON은 국내송장이 입력되는 즉시 마켓 송장전송을 시도하고 배송중으로 넘기는 기능이다.
- 자동 배송중 처리 OFF일 때는 국내송장이 입력되어도 운영자가 `배송중 처리` 버튼을 눌러야 마켓으로 전송한다.
- 배송중 처리는 국내송장이 있는 발송대기 주문만 대상으로 한다.
- 배송중 처리가 성공하면 주문 상태는 배송중으로 변경된다.

## 9. 단계별 처리 건수 표시

- 사이드바의 주문수집 하위 메뉴에는 단계별 처리해야 할 주문 건수를 표시한다.
- 주문수집 하위 메뉴는 일반 주문 그룹과 클레임 그룹으로 분리한다.
- 건수 표시는 운영자가 오늘 우선 처리해야 할 단계를 빠르게 파악하기 위한 목적이다.
- 일반 주문 그룹 표시 대상은 전체, 신규주문, 상품준비, 발송대기, 배송중, 배송완료다.
- 클레임 그룹 표시 대상은 취소/반품/교환이다.
- 전체 메뉴는 처리 대기 건수 합계를 표시한다.
- 일반 주문 전체의 처리 대기 건수 합계는 신규주문, 상품준비, 발송대기 건수를 합산한다.
- 클레임 처리 대기 건수는 취소/반품/교환 그룹에서 별도로 표시한다.
- 배송완료 상태는 마켓 배송완료와 구매확정 주문을 포함하는 조회 상태이며, 구매확정 여부는 별도 속성으로 저장할 수 있다.
