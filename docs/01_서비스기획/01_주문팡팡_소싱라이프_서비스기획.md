# 커머스라이프 주문관리 서비스 기획

## 1. 서비스 정의

커머스라이프는 마켓 주문 수집, 조회, 처리를 제공하는 독립 주문관리 서비스다.
소싱라이프의 상위 메뉴 구조와 계정 영역을 공유하지 않으며, 주문 처리 과정에서만 소싱라이프 상품 후보 검색, 구매대행 신청/결제, 국내송장 확보 결과를 주문 단위로 연결한다.

현재 저장소는 PostgreSQL·로그인·스마트스토어 주문/클레임 수집·명령 코어와 실원장 화면을 함께 갖춘 전환 단계다. 실제 판매자 계정 UAT와 소싱라이프 구매 연동 전이므로 실서비스 완료로 보지 않는다.
mock data와 브라우저 상태는 API 자격증명 없이 UI 정상·예외 경로를 확인하는 명시적 데모 모드에만 사용한다.

## 2. 핵심 목표

1. 모든 판매처의 주문을 한 화면에서 통합 조회한다.
2. 마켓별 주문 상태를 주문관리 내부 상태로 통일한다.
3. 운영자는 커머스라이프에서 주문확인, 소싱 진행상태 확인, 국내송장 확인, 배송중 처리를 진행한다.
4. 커머스라이프는 독립 서비스이며, 주문 처리 중 소싱라이프 결제와 국내송장 결과만 외부 연동으로 연결한다.
5. 스마트스토어, 쿠팡을 먼저 연동하고 11번가, G마켓, 옥션으로 확장한다.
6. 화면 기준의 MVP에서는 실제 API 호출보다 운영 흐름, 상태 전환, 화면 구성, 사용자 판단 기준을 먼저 확정한다.

## 3. 연동 우선순위

최종 연동 대상은 스마트스토어, 쿠팡, 11번가, G마켓, 옥션이다.
화면 프로토타입에서는 5개 마켓 모두 등록 대상으로 제공한다.
실제 API 안정화와 운영 우선순위는 스마트스토어, 쿠팡을 먼저 검증하고 11번가, G마켓, 옥션 순서로 확장한다.

| 우선순위 | 판매처 | 연동 기준 |
|---|---|---|
| 1 | 스마트스토어 | 커머스API |
| 2 | 쿠팡 | 쿠팡 Open API |
| 3 | 11번가 | 11번가 Open API |
| 4 | G마켓 | ESM PLUS API |
| 5 | 옥션 | ESM PLUS API |

## 3-1. 판매처 계정 등록 정책

- 주문관리는 마켓별 다중 계정 등록을 지원한다. 최종적으로 사용자는 스마트스토어, 쿠팡, 11번가, G마켓, 옥션에서 운영 중인 판매자 계정 또는 스토어를 개수 제한 없이 등록할 수 있다.
- 주문수집은 활성화된 모든 마켓 계정과 스토어를 대상으로 실행하며, 특정 판매처만 수집하거나 특정 스토어만 수집하는 기능은 초기 범위에 포함하지 않는다.
- 주문 목록의 주문일시 아래에는 마켓 약자 아이콘과 해당 주문이 수집된 스토어명을 함께 표시한다.
- 여러 개의 스토어가 등록된 경우 주문수집 화면에서 마켓별, 스토어별, 기간별, 검색어 기준으로 주문 목록을 조회할 수 있어야 한다.
- 주문 목록에는 주문이 수집된 마켓과 스토어명을 주문일시 안의 보조 정보로 표시한다.
- 주문 테이블과 행 확장 자세히 보기는 주문 처리에 필요한 정보와 현재 상태에서 가능한 다음 단계 액션을 제공한다.
- 마켓별/스토어별 필터는 주문 조회용 필터이며, 주문수집 실행 범위를 제한하는 기능은 아니다.
- 현재 마켓연동 화면은 마켓, 스토어명, 연동상태, 활성, 관리 중심으로 제공한다. 수집 성공/실패 상태와 마지막 수집 시각은 추후 API 연동 또는 운영 진단 정보로 분리한다.

## 4. 전체 주문 처리 흐름

```text
마켓 결제완료 주문
→ 커머스라이프 주문수집
→ 신규주문
→ 주문확인 또는 매칭하기(소싱라이프 후보/옵션 매칭 + 주문확인)
→ 상품준비
→ 소싱하기(리펀디형 소싱라이프 구매) 또는 외부구매 배송처리(샵마인형 직접구매·송장 전달)
→ 결제완료 후 선택 배송대행지 사이트 열기와 주문서 자동입력
→ 접수대기/접수신청(동일 단계) 실행
→ 국내송장 즉시 발급과 택배사·송장번호 저장
→ 자동 배송중 처리 ON이면 마켓 발송 후 배송중
→ OFF이거나 자동 발송 실패이면 발송대기
→ 운영자 배송중 처리
→ 배송중
→ 배송완료
```

마켓 직접전달 예외 흐름:

```text
상품준비
→ 배송중 처리에서 직접전달 선택
→ 스마트스토어·11번가 직접전달 API 성공
→ 마켓 상태만 배송중으로 변경
→ 내부 작업 단계는 상품준비 유지
→ 소싱라이프 또는 외부 구매 완료 + 국내송장 저장
→ 내부 발송대기로 이동
→ 배송중 처리 재실행
→ 내부 배송중으로 이동
```

주문은 다음 두 상태를 분리해 관리한다.

| 구분 | 역할 | 예시 |
|---|---|---|
| 내부 작업 단계 | 운영자가 다음으로 처리할 업무를 정함 | 신규주문, 상품준비, 발송대기, 배송중, 배송완료 |
| 마켓 상태 | 마켓 API에 반영된 구매자 노출 상태 | 결제완료, 배송중, 배송완료 |

마켓 직접전달 API가 성공해도 소싱라이프 결제가 남아 있으면 내부 작업 단계는 `상품준비`에 유지한다.
직접전달 이후에도 구매 방식은 반드시 소싱라이프 구매 또는 외부 구매 중 하나여야 한다. `구매 안 함` 상태는 제공하지 않으며, 구매 완료 전 직접전달 주문은 국내송장 없이 상품준비에 유지한다.
소싱라이프 결제가 끝나면 마켓 발송 여부와 관계없이 내부 작업 단계는 `배송중`으로 이동한다. 운영자는 같은 배송중 작업함에서 중국 판매자 대화, 결제상품 조회, 배송추적, 반품·환불, 운송장 수정과 마켓 `배송중 처리`를 수행한다. 외부 구매는 기존 발송대기 흐름을 유지한다.
소싱라이프 실제 국내송장이 배송완료되면 내부 주문은 `배송완료`로 이동한다. 직접전달 주문의 마켓 상태가 배송중으로 남아 있어도 내부 배송완료를 지연하지 않는다.

## 5. 소싱라이프 연동 관계 정의

- 커머스라이프는 소싱라이프와 분리된 독립 주문관리 서비스다.
- 주문관리는 마켓에서 수집된 주문을 기준으로 소싱라이프 주문 생성 여부, 소싱라이프 결제 여부, 국내송장 확보 여부를 주문 단위로 관리한다.
- 소싱라이프에서 직접 생성하거나 주문한 내역은 주문관리의 주문수집 목록에 넣지 않는다.
- 소싱라이프 주문번호는 마켓 주문을 소싱라이프 결제 흐름으로 넘긴 뒤 생성된 주문서 식별값으로 저장하며, 소싱라이프 결제 완료 여부와 별도로 관리한다.
- 소싱라이프 연동으로 수신한 구매, 검수, 입고, 물류 상태와 결과는 커머스라이프 내부에서 조회한다. 소싱라이프 주문내역 화면으로 이동하는 기능은 제공하지 않는다.
- 주문관리의 책임은 소싱라이프 결제/송장 처리 결과를 마켓 주문 상태에 반영하고, 국내송장을 기준으로 배송중 처리를 할 수 있도록 관리하는 것이다.
- 소싱 후보가 적합하지 않은 경우 운영자는 모달 안에서 키워드 또는 타오바오/소싱라이프 상품 URL로 후보를 추가로 찾는다.
- 개인통관부호가 일치하지 않는 주문은 상품준비에서 소싱라이프 결제를 진행할 수 없다. 통관부호를 수정해 일치 상태가 된 뒤 소싱한다.
- 키워드 찾기는 검색 후보 20개를 기존 이미지 매칭 후보 목록 상단에 추가하고, URL 찾기는 해당 상품 1개를 기존 후보 목록 상단에 추가한다.
- 현재 MVP는 타오바오 직접 결제와 내부 배대지/창고 관리 기능을 제공하지 않는다. 외부 연동 상태와 결과는 커머스라이프 주문 단위로 표시한다.

## 6. 주요 메뉴

| 메뉴 | 역할 |
|---|---|
| 주문관리 > 주문수집 | 일반 주문의 신규주문, 상품준비, 발송대기, 배송중, 배송완료 상태별 통합 조회 |
| 주문관리 > 취소/반품/교환 | 마켓에서 수집된 구매자 클레임과 판매자 직접취소 완료 이력 조회 |
| 주문관리 > 문의관리 | 마켓 문의 확인 및 응대 |
| 주문관리 > 마켓연동 | 판매처별 API 인증 정보와 스토어명 관리 |

## 7. 주요 화면 흐름

| 화면 | 핵심 기준 |
|---|---|
| 사이드바 | `커머스라이프` 브랜드 아래 `주문관리`와 하위 메뉴 주문수집, 취소/반품/교환, 문의관리, 마켓연동만 제공. 아이템 검색, 찜 리스트, 장바구니, 주문 내역, 배송 조회, 통관고유부호와 타오바오/1688 전환은 제공하지 않음 |
| 주문수집 화면 | 본문 상단 탭에서 신규주문, 상품준비, 발송대기, 배송중, 배송완료를 선택하고 검색/필터 + 주문 테이블을 구성 |
| 신규주문 | 선택된 주문에만 `주문확인`, `주문취소` 전역 액션 제공. 행과 상세 처리하기에는 `주문확인`, `매칭하기`, `주문취소`를 제공하고, `배송정보 수정`은 상세의 구매자·배송정보 영역에서만 제공 |
| 상품준비 | 목록 `처리하기`에는 `소싱하기`, `주문취소`만 표시한다. 결제대기 주문도 목록에서는 `소싱하기`로 통일하고, 결제·채팅과 외부구매 배송처리·직접전달 같은 추가 기능은 자세히 보기에서 제공한다. |
| 상품준비 외부구매 | 소싱라이프를 사용하지 않고 직접 구매한 주문은 자세히 보기의 `처리하기` 섹션에서 `외부구매 배송처리`를 실행해 배송대행지에서 받은 택배사와 국내송장번호를 필수 입력한다. 자동 배송중 처리 OFF는 발송대기, ON은 마켓 발송 성공 후 배송중으로 이동 |
| 발송대기 | 목록 `처리하기`에는 `배송중 처리`만 표시한다. 자세히 보기에서는 저장된 송장과 기본 발송 방식 등 추가 정보를 확인·수정할 수 있다. |
| 배송중 | 소싱라이프 결제완료 직후부터 이 작업함에서 관리한다. 목록 `처리하기`는 비워 두고, 자세히 보기에서 `소싱상품관리`, `배송추적`, 조건부 `배송중 처리`, 처리 시작 전 `운송장 수정`을 제공한다. 배송중 처리를 시작하면 운송장 수정은 즉시 잠근다. 반품·환불은 `소싱상품관리` 안에서 신청·진행한다. |
| 배송완료 | 목록 `처리하기`는 비워 둔다. 자세히 보기의 `소싱상품관리`와 `배송추적`에서 결제정보·중국 판매자 대화·누적 배송 이력·기존 환불 요청을 조회한다. |
| 취소/반품/교환 | 구매자 신청과 판매자 직접취소를 접수 주체로 구분해 노출. 구매자 신청은 `취소처리`, `반품처리`, `교환처리`, 판매자 직접취소 완료는 `상세보기` 제공 |
| 매칭하기/소싱하기 모달 | 신규주문의 `매칭하기`에서는 `주문확인` 아래 `주문취소`를 제공하고, 상품준비의 `소싱하기`에서는 매칭 후보·옵션·수량 확인, 저장된 배대지 수령 프로필 선택, 구매대행 신청, 결제대기·중국 판매자 채팅, 별도 결제 흐름을 제공 |

구매대행 신청은 결제 완료와 분리한다. 신청 직후 주문은 `결제대기`에서 멈추며, 운영자는 원주문 상품과 소싱상품의 상품명·옵션·수량을 나란히 비교하고 상품원가·소싱처 이용료·환전 수수료·예상 배송비·예상 순이익·마진율을 확인한다. 이후 상품 가격·재고·중국 내 배송 조건을 중국 판매자 채팅으로 확인한 뒤 `상품 결제하기`로 결제 단계를 다시 시작한다. 결제대기 하단에는 `주문 취소하기`도 제공하며 기존 주문취소 확인 절차를 연다. 결제대기 채팅에는 가격 인하 요청을 보내는 `깎아줘`와 진행 중 요청을 철회하는 `깎아줘 취소`를 제공한다. `깎아줘` 요청 중에는 `상품 결제하기`를 비활성화하고, 요청을 취소해 대기 상태로 돌아오면 다시 활성화한다. 이 요청은 채팅 메시지만 전송하며 가격 변경이나 결제를 자동 실행하지 않는다. 채팅 상대는 소싱라이프 운영자가 아니다. 여기서 배대지 선택은 소싱라이프에 저장된 수령 프로필을 고르는 기능이며 커머스라이프가 배대지·창고 운영을 직접 관리한다는 의미가 아니다.
결제완료 시 선택한 배송대행지 사이트를 열고 주문서를 자동입력한다. 연결 대상은 접수 시 국내송장을 즉시 발급하는 배송대행지로 제한하며 `접수대기`와 `접수신청`은 같은 접수 단계다. 접수 응답의 택배사·국내송장번호를 주문에 저장한 뒤 결제완료 조회 화면으로 전환한다. 현재 프로토타입은 외부 사이트 열기·자동입력·접수 화면을 생략하고 결제완료 클릭 시 더미 송장을 즉시 생성해 결과만 시연한다.
배송중은 소싱라이프 결제완료 또는 외부구매 후 마켓 발송 완료가 선행된 주문만 진입할 수 있다. 소싱라이프 결제완료 주문은 중국배송 전이라도 배송중으로 관리하며, 미결제 상태가 발견되면 `결제하기`를 노출하지 않고 `결제상태 불일치`로 표시한다.
| 마켓연동 | 우측 상단 `마켓 추가`, 마켓별 인증정보 입력, 테스트, 설정/삭제, 활성 스위치 제공 |

## 7-1. 검색/필터 기준

- 기간 필터는 `오늘`, `3일`, `7일`, `30일`, `직접 입력`을 제공한다.
- `직접 입력`은 시작날짜와 끝나는날짜를 선택하는 작은 팝오버로 처리한다.
- 검색어는 상품명, 주문번호, 주문자, 수령인 기준으로 주문 목록을 좁힌다.
- 마켓/스토어 필터는 중복 선택을 지원한다.
- 마켓을 선택하면 해당 마켓에 속하지 않은 스토어는 숨기지 않고 비활성화한다.
- 모든 일반 주문 단계에 `판매처`, `상태` 드롭다운을 제공한다.
- 상태 드롭다운은 현재 주문 존재 여부와 관계없이 단계별 고정 상태값을 제공하며, 배송완료 단계는 `전체`, `배송완료`, `구매확정`을 제공한다.
- 배송완료 주문은 모두 목록 상태 `배송완료`를 가지며, `marketOrderStatus`가 `PURCHASE_DECIDED`이면 목록 상태 `구매확정`을 추가로 가진다.
- 필터는 조회 조건이며 주문수집 실행 대상 마켓 계정과 스토어를 제한하지 않는다.

## 8. 초기버전 주문 테이블 기준

- 주문 목록은 처리에 필요한 핵심 컬럼만 우선 노출한다.
- 주문 행을 클릭하면 행 아래에 자세히 보기를 펼쳐 목록에 없는 주문 관련 정보를 확인한다.
- 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 서로 다른 업무 목적의 상품정보, 구매자정보, 수령인정보, 소싱정보, 송장정보, 처리버튼을 한 컬럼에 섞어 표시하지 않는다.
- 마켓별 수수료율을 사용자가 직접 설정하는 화면은 현 주문수집 MVP 범위에서 제외한다. 마진 분석은 주문 결제 금액을 기준으로 수집된 판매 수수료와 소싱 상품 금액·소싱처 이용료·환전 수수료·예상 배대지 운임을 각각 직접 차감한다.
- 주문수집 화면에서는 주문 처리에 필요한 핵심 정보와 액션을 우선 표시하고, 수수료 상세값은 장부/정산 기능에서 중심적으로 다룬다.
- 처리이력은 초기버전 주문관리 화면 범위에서 제외한다.

초기 주문 테이블 컬럼 순서는 다음 기준을 따른다.

1. 선택
2. 처리하기
3. 주문일시
4. 진행상태
5. 상품정보
6. 택배정보
7. 배송정보

판매처 전용 컬럼은 두지 않는다. 주문일시 아래에 마켓 약자 아이콘 `N`, `C`, `G`, `11`, `A`와 스토어명을 표시한다.

진행상태 컬럼은 주문마다 대표 상태 배지 하나만 표시한다. 소싱 환불·반품이 있으면 이를 우선하고, 그 외에는 구매확정 또는 기본 소싱 진행상태를 표시한다. 기본 상태는 `소싱필요`, `소싱완료`, `결제대기`, `결제완료`, `중국배송중`, `통관 중`, `국내 배송중`, `배송완료`이며 수동 검증 전 단계도 `소싱필요`로 통합한다. 소싱 환불은 `소싱환불 승인대기`, `소싱반품 송장필요`, `소싱반품 배송중`, `소싱환불 처리중`, `소싱환불 완료`, `소싱환불 거절`, `소싱환불 확인필요`로 표시한다. `마켓 취소요청`, `처리보류`, 내부 환불 `REQUESTED`는 진행상태 종류로 노출하지 않고 원본 상태와 구매경로는 자세히 보기에서 확인한다.
`구매확정`은 내부 주문 단계가 아니라 배송완료 주문의 마켓 동기화 결과에서 파생되는 추가 목록 상태값이다.
소싱 결제완료부터 배송완료까지 행 자세히 보기의 `소싱상품관리`로 결제정보와 중국 판매자 채팅을 계속 관리한다. 같은 상세 `처리하기`의 `배송추적`에서 결제완료 → 중국배송 → 통관 → 국내배송 → 배송완료의 현재 단계와 누적 이력을 확인한다. 이 관리 화면에는 배대지·창고 운영 기능을 포함하지 않고 기존 소싱 과정의 저장된 배대지 수령 프로필 선택만 유지한다.
소싱 진행 단계는 마켓 주문상태와 독립된 판매자/소싱라이프 관점의 실제 진행 상태다.
국내 택배번호를 마켓에 등록해 마켓에는 배송중으로 보이더라도, 실제 소싱 단계는 중국 내 배송 전/중일 수 있다.
마켓 또는 내부 주문이 배송완료로 확정된 경우 소싱 단계도 `배송완료`로 맞춘다.

행 확장 자세히 보기는 넓은 화면에서 세 영역으로 나눈다. 왼쪽에는 구매자·배송정보와 택배정보를 위에서 아래로 표시하고, 가운데에는 상품 비교와 마진계산을 위에서 아래로 표시하며, 오른쪽에는 현재 주문에서 사용할 수 있는 처리 기능을 세로로 표시한다. 상품 비교 안에서는 주문상품 아래에 소싱상품을 배치하고, 마진계산 안에서는 매출·정산 아래에 예상 소싱비용과 예상 순이익·마진율을 차례로 배치한다. 화면이 좁으면 상품 비교·마진계산, 구매자·배송정보·택배정보, 처리하기 순서로 한 줄씩 배치한다. 상품 비교와 마진계산은 매칭된 소싱상품이 있을 때만 표시한다.
배송정보는 목록과 자세히 보기에서 모두 수정할 수 있다.
택배정보는 목록과 자세히 보기에서 `국내 송장번호`, 직접전달 표시, `중국 송장번호` 순으로 구성한다. 직접전달을 선택한 주문에만 `직접전달`을 표시하고 일반 주문에는 해당 표시를 하지 않는다. 아직 받지 못한 송장번호는 `-`로 표시한다.

## 8-1. 국내송장 처리 기준

- 상품준비에서 소싱라이프 결제가 완료되면 선택 배송대행지 주문서 접수를 실행하고, 접수 응답으로 발급된 소싱라이프 주문번호·소싱금액·국내송장을 함께 반영한다.
- 연결된 배송대행지는 접수와 동시에 실제 국내송장을 발급한다. 송장이 없으면 결제 성공은 보존하되 접수 결과 오류로 처리하고 발송 단계로 이동하지 않는다.
- 마켓 직접전달을 먼저 처리한 주문에도 같은 규칙을 적용한다. 직접전달 + 소싱라이프 구매 완료 + 국내송장 없음 조합은 생성하지 않으며, 구매 완료와 내부 상태 변경을 모두 차단한다.
- 국내송장이 있더라도 `자동 배송중 처리`가 OFF이면 송장번호가 입력된 상태로 발송대기에 남긴다.
- 국내송장이 있고 해당 토글이 ON이면 마켓 발송 API를 자동 호출한다. 성공 시 마켓 주문을 배송중으로 변경하고 내부 주문도 배송중으로 함께 이동한다.
- 자동 발송 API가 실패하면 마켓과 내부 상태를 배송중으로 변경하지 않고, 송장이 있는 발송대기에 남겨 재처리할 수 있어야 한다.
- 발송대기 상태는 구매와 국내송장 확보가 끝났으며 단일 `배송중 처리`가 남은 상태다.
- 국내송장은 소싱라이프 구매 완료 결과로 반영되거나 외부 구매 완료 시 운영자가 필수 입력한다.
- 직접전달 주문도 택배정보에 실제 국내 택배사·송장번호를 표시하고 그 아래에 `직접전달`을 표시한다. 일반 주문에는 직접전달 관련 문구를 표시하지 않는다.
- 상품준비에서 마켓 직접전달을 먼저 완료한 주문이 구매와 실제 국내송장 확보를 마치면 내부 주문은 `발송대기`로 이동한다. 마켓 상태는 배송중으로 유지하고 `배송중 처리` 재실행 전까지 내부 단계만 발송대기로 남긴다.
- 직접전달 주문은 실제 국내송장 배송완료 시 내부 주문을 배송완료로 이동한다. 직접전달 여부는 택배정보의 `직접전달` 표시로 확인하며, 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않는다.
- 발송대기 상태에서는 소싱라이프 송장 자동 수집 토글을 제공하지 않는다.
- 발송대기 상태에서는 별도 `소싱라이프 송장 수집` 버튼을 제공하지 않는다.
- 수동 입력은 운영자가 국내 택배사와 국내송장번호를 직접 입력하는 기능이다.
- 자동 배송중 처리 ON은 구매 완료와 국내송장 확보 직후 마켓 발송을 시도하고 성공 시 배송중으로 넘기는 기능이다.
- 자동 배송중 처리 OFF일 때는 국내송장이 입력되어도 운영자가 발송대기의 `배송중 처리`를 실행해야 배송중으로 이동한다.
- 마켓 발송 전 주문은 `배송중 처리` 모달에서 송장 또는 직접전달을 선택한다. 직접전달은 지원 마켓에만 제공하며 실제 국내송장은 내부 추적에만 사용한다.
- 백엔드는 모든 `배송중 처리` 요청에서 마켓 상태를 먼저 조회한다. 이미 송장 또는 직접전달로 발송됐다면 같은 정보를 다시 보내지 않고 실제 마켓 방식과 내부 배송중 상태만 반영한다.
- 발송대기 처리는 구매 완료와 국내송장을 갖춘 주문만 대상으로 하며, 상품준비의 직접전달 선처리는 동일 버튼에서 예외적으로 허용한다.
- 상품준비에서 직접 구매한 주문은 `외부구매 배송처리`를 사용하며 배송대행지에서 받은 택배사와 국내송장번호를 필수 입력해야 한다. 송장번호가 없으면 처리와 상태 이동을 허용하지 않는다.
- 마켓 직접전달을 먼저 처리한 외부 구매 주문도 예외가 아니다. 직접전달 + 외부 구매 완료 + 국내송장 없음 조합은 생성하지 않으며, 완료와 내부 배송중 전환을 모두 차단한다.
- 외부구매 배송처리 후 주문은 진행상태를 `결제완료`로 표시하되 구매경로 `외부구매`는 내부 데이터로 유지한다. 매칭된 소싱상품이 없으므로 자세히 보기에는 소싱상품 영역을 표시하지 않고 소싱라이프 주문번호도 연결하지 않는다.
- 외부구매 배송처리도 소싱라이프 구매 완료와 동일하게 `자동 배송중 처리` 설정을 적용한다. OFF이면 송장만 저장하고 발송대기에 남으며, ON이면 마켓 발송 API 성공 후 마켓과 내부 주문을 배송중으로 변경한다.
- 상품준비와 발송대기의 `자동 배송중 처리` 토글은 동일한 설정값을 공유하며 한 화면에서 변경하면 다른 화면에도 그대로 적용한다.
- 마켓 직접전달 주문에는 판매자 `주문취소` 액션을 노출하지 않는다.
- 배송중 상태에서는 마켓 API로 송장 변경을 자동 전송하지 않으며, 변경된 송장번호 항목도 목록/상세에 표시하지 않는다.

## 9. 단계별 처리 건수 표시

- 주문수집 본문 상단 탭에는 단계별 주문 건수를 표시한다.
- 일반 주문 표시 대상은 신규주문, 상품준비, 발송대기, 배송중, 배송완료다.
- `전체` 탭은 처리보류를 포함한 일반 주문을 조회하고 `처리보류` 상태 필터를 제공한다.
- 클레임 처리 건수는 취소/반품/교환 화면에서 별도로 표시한다.
- 배송완료 상태는 마켓 배송완료와 구매확정 주문을 포함하는 조회 상태이며, 구매확정 여부는 별도 속성으로 저장할 수 있다.
- 배송완료 필터는 구매확정 주문을 포함한 전체 배송완료 주문을 조회하고, 구매확정 필터는 그중 구매확정 배지가 있는 주문만 조회한다.

## 10. 현재 데이터/기술 전제

- PostgreSQL tenant/account/order/item/recipient/sync/command/claim/audit 원장과 RLS, 브라우저 세션, 스마트스토어 수집 worker가 현재 실서비스 코드 경로다.
- `/orders` 기본 진입 화면은 신규주문 탭이다.
- 주문 목록은 `/api/orders` 실원장을 우선 표시하고, 연결 실패·0건 시 별도 원장 안내 문구 없이 데모 주문을 표시한다. 클레임 작업함도 데이터 원천을 설명하는 상단 안내 문구를 표시하지 않는다.
- 소싱라이프 후보는 `lib/mock-data/sourcing-life.ts`의 더미 데이터를 기준으로 표시한다.
- 실주문 매핑·국내송장은 서버 원장/API를 사용한다. 소싱 결제와 demo 주문 처리 결과만 브라우저 저장소로 화면 동작을 검증한다.
- 브라우저 저장소 초기화는 demo 상태만 삭제하며 PostgreSQL 실원장을 변경하지 않는다.
- 사용 중인 저장소 키는 `jumunpangpang.syncedInvoices`, `jumunpangpang.sourcingMatches`, `jumunpangpang.sourcingPayments`다.
- React Query는 실주문·마켓계정·클레임 cursor API 조회와 오류/재시도에 사용한다.
- Zustand는 현재 대시보드 등 클라이언트 상태 관리 기반으로 사용한다.

## 11. 소싱환불의 커머스라이프 적용 위치

리펀디의 환불 메뉴 구조를 복제하지 않고 커머스라이프의 기존 주문 업무에 다음처럼 배치한다.

| 현재 영역 | 적용 기능 | 적용하지 않는 것 |
|---|---|---|
| `주문수집 > 소싱상품관리 > 구매대행 신청 상품` | 결제완료부터 국내 배송중까지 소싱상품의 신규 환불 요청과 기존 환불 진행·내역 조회. 목록과 상세 `처리하기`에는 별도 환불 버튼을 표시하지 않음 | 별도 `소싱환불` 사이드바 메뉴 |
| 자세히 보기의 `소싱상품` | 요청 수량·금액과 현재 환불 상태 요약 | 창고 입고·검수·반송 실행 |
| `취소/반품/교환 > 클레임 상세` | 마켓 처리와 분리된 `소싱 구매 후속조치` 상태·연결 참조 | 소싱환불로 마켓 클레임 자동 완료 |
| `주문현황 > 소싱 환불` | 실제 환불 원장의 8개 상태 집계와 예외 이슈 | 취소 주문을 환불 진행으로 임의 추정 |

소싱환불 요청은 환불 유형, 사유, 수량, 요청 금액, 선택적 마켓 클레임 ID를 저장한다. 소싱라이프 결제금액을 초과할 수 없고 구매 수량 범위를 벗어날 수 없다. 외부 직접구매는 커머스라이프가 소싱라이프 환불을 실행하지 않는다.

환불 완료 후 다른 판매처 구매가 필요한 경우에는 국내배송 시작 전 주문에만 `다시 소싱하기`를 제공한다. 기존 환불 원장은 이력으로 남기고 현재 소싱 연결을 초기화하여 후보 상품·옵션·판매처 선택, 배대지 선택, 결제대기, 상품 결제를 기존 소싱 흐름으로 다시 수행한다. 재소싱을 시작하기 전 환불 완료 주문은 과거 국내송장으로 발송 처리할 수 없다.

마켓 취소 성공과 소싱환불 성공은 서로 다른 완료 증거다. 한쪽만 끝나면 전체 완료로 표시하지 않고 미완료 쪽을 후속 작업으로 남긴다.
