# 커머스라이프 기능요구서 목록

## 문서를 보는 순서

기능요구서는 아래 순서로 확인한다.

| 순서 | 확인 문서 | 확인 내용 |
|---:|---|---|
| 1 | `00_기능요구서_목록.md` | 문서 작성 원칙, 중요도 기준과 전체 화면 목록을 확인한다. |
| 2 | 화면별 상위 기능요구서 | 선택한 화면의 목적, 전체 흐름, 화면 항목과 기능 간 연결 관계를 확인한다. |
| 3 | 화면별 `하위문서/00_기능목록.md` | 해당 화면의 전체 기능과 `필수·중요·낮음` 중요도를 비교한다. |
| 4 | 기능별 상세 기능요구서 | 구현하거나 검토할 기능의 노출 조건, 실행 흐름, 상태 변화, 결과와 예외를 확인한다. |

처음부터 모든 상세 문서를 순서대로 읽지 않는다. 먼저 화면별 상위 문서로 전체 흐름을 이해한 다음, 화면별 기능 목록에서 `필수` 기능을 우선 선택해 해당 상세 문서만 확인한다. 필수 기능이 끝나면 같은 방식으로 `중요`, `낮음` 기능을 확인한다.

### 확인 예시: 배송추적

```text
00_기능요구서_목록.md
→ 03_주문수집_기능요구서.md
→ 하위문서/03_주문수집/00_기능목록.md
→ 24_배송추적_기능요구서.md
```

이 순서로 보면 주문수집 화면의 전체 흐름 안에서 배송추적이 어디에 표시되고, 왜 `필수`인지 확인한 뒤 상세 동작과 예외를 검토할 수 있다.

## 문서 원칙

- 기획팀 문서는 화면별 `기능요구서` 한 종류로 시작한다.
- 요청 배경, 요청 대상, 요청 ID, API, DB, 컴포넌트 구조는 작성하지 않는다.
- 화면 안의 모든 기능은 기능별 소제목으로 나누어 작성한다.
- 각 기능에는 최소한 `노출 위치`, `노출 조건`, `실행 흐름`, `상태 변화`, `처리 결과`, `예외·제한`을 작성한다.
- 기능 실행으로 다른 기능의 노출 조건이나 주문 상태가 바뀌면 그 연결 관계까지 작성한다.
- 아직 정하지 않은 조건은 임의로 확정하지 않고 `정책 결정 필요`로 표시한다.
- 현재 프로토타입에서 직접 확인되는 동작과 아직 실행되지 않는 데모·제한 기능을 구분한다.
- 내용이 많거나 개발팀에서 상세 정의를 요청한 기능만 별도 상세 기능요구서로 분리한다.
- 분리한 상세 문서의 상위 화면 문서에는 표시 위치, 표시 조건, 시작 조건과 최종 결과만 남긴다.

## 중요도 기준

기능 중요도는 셀러픽·리펀디 등 주문관리 프로그램의 공통 기능과 커머스라이프의 주문 처리 흐름을 기준으로 판단한다. 경쟁서비스에 존재한다는 이유만으로 필수로 정하지 않고, 해당 기능이 없을 때 주문 업무를 끝까지 처리할 수 있는지를 우선 판단한다.

| 중요도 | 판단 기준 | 적용 순서 |
|---|---|---|
| **필수** | 주문수집, 주문확인, 소싱·결제, 송장·배송, 배송추적, 취소·환불·클레임처럼 빠지면 주문 처리가 중단되거나 잘못 처리되는 기능 | 가장 먼저 구현·검수 |
| **중요** | 수작업 대안은 있지만 반복 업무, 처리 속도, 누락 방지와 운영 품질에 큰 영향을 주는 기능 | 필수 기능 안정화 후 구현 |
| **낮음** | 핵심 주문 처리 없이도 운영할 수 있는 편의, 분석, 미리보기와 고도화 기능 | 필수·중요 기능 이후 검토 |

현재 121개 상세 기능은 `필수 60개`, `중요 41개`, `낮음 20개`로 분류한다. 중요도는 구현 난이도가 아니라 업무 필요성을 뜻하며, 정책이나 서비스 범위가 바뀌면 기능요구서에서 함께 조정한다.

### 기능별 작성 형식

```text
### 기능명

- 중요도: 필수 / 중요 / 낮음
- 노출 위치: 기능이 표시되는 화면·영역
- 노출 조건: 버튼·입력·정보가 표시되거나 활성화되는 조건
- 실행 흐름: 사용자가 기능을 시작해 완료하는 순서
- 상태 변화: 실행 전후 화면·주문·설정 상태의 변화
- 처리 결과: 사용자가 확인하는 최종 결과
- 예외·제한: 실행 차단, 빈 결과, 실패, 더미데이터 범위
- 정책 결정 필요: 아직 확정되지 않은 운영 기준
```

## 기능별 하위문서

- 전체 기능별 문서는 [하위문서/00_기능별_문서목록.md](./하위문서/00_기능별_문서목록.md)에서 확인한다.
- 상위 화면 문서는 화면 구성·공통 흐름·기능 목록을 관리한다.
- 하위 기능 문서는 해당 기능의 노출 위치·조건, 실행 흐름, 상태 변화, 처리 결과와 예외를 관리한다.
- 상세 요구사항을 변경할 때는 하위 기능 문서를 우선 수정하고 상위 화면 문서의 요약과 링크가 일치하는지 확인한다.

## 로직 확인

- 프로토타입과 요구사항이 충돌하거나 운영 기준이 정해지지 않은 경우 해당 기능의 상세 요구사항에 `정책 결정 필요`로 표시한다.
- 문서를 작성하거나 검토하는 과정에서 새로운 불일치를 발견하면 임의로 결정하지 않고 사용자에게 먼저 알린다.
- 불일치가 해결되면 해당 화면 기능요구서와 기능별 상세 요구사항을 함께 수정한다.

## 상세 문서 분리 기준

다음 중 하나에 해당할 때만 별도 상세 기능요구서를 추가한다.

- 독립 화면 또는 복잡한 모달 안에서 여러 단계가 진행된다.
- 입력 항목, 상태 조건, 정상·실패 흐름이 많아 상위 문서의 가독성을 해친다.
- 여러 화면에서 공통으로 사용하는 기능이다.
- 개발팀이 별도 상세 정의를 요청한다.

현재 프로토타입에서 정의한 모든 상세 기능은 기능별 하위문서로 분리되어 있다. 기능이 새로 추가되면 같은 화면의 하위문서 폴더에 기능 문서를 추가한다.
