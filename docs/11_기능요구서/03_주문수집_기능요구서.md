# 주문수집 기능요구서

> 기능별 중요도와 상세 문서: [주문수집 기능목록](./하위문서/03_주문수집/00_기능목록.md)

## 전체 흐름

```text
마켓 주문수집
→ 신규주문
→ 주문확인 또는 매칭하기
→ 상품준비
→ 소싱라이프 구매대행 신청·결제 또는 직접구매 배송처리
→ 필요 시 마켓 배송중 처리
→ 배송중
→ 배송완료
```

마켓 상태, 구매 완료 여부, 실제 물류 단계는 별도로 관리한다. 마켓 배송중 처리는 소싱라이프 결제 또는 직접구매 완료 뒤에만 실행한다. 구매가 끝난 뒤에는 국내송장이 이미 발급되어 있어도 실제 국내배송 시작 전에 직접전달·해외기타배송으로 마켓을 먼저 배송중 처리할 수 있으므로, 마켓 배송중과 실제 국내 배송중을 같은 의미로 간주하지 않는다.

## 주문 단계 탭

| 탭 | 포함 주문 |
|---|---|
| 전체 | 신규주문, 상품준비, 발송대기, 배송중, 배송완료, 판매자취소, 처리보류 |
| 신규주문 | 수집 후 주문확인 전 주문 |
| 상품준비 | 주문확인 후 구매·결제 전 주문 |
| 발송대기 | 소싱라이프 결제 또는 직접구매 완료 후 마켓 발송 대기 주문 |
| 배송중 | 구매 완료와 마켓 발송 처리가 모두 끝난 주문. 실제 물류 단계는 진행상태·배송추적으로 별도 확인 |
| 배송완료 | 배송이 완료된 주문 |

각 탭에는 현재 전체 주문 데이터 기준 건수를 표시한다. 기본 진입 탭은 신규주문이다.

## 검색·필터

| 항목 | 요청 내용 |
|---|---|
| 기간 | 오늘, 3일, 7일, 30일, 직접 입력 |
| 직접 입력 | 시작날짜와 끝나는날짜 |
| 검색어 | 상품명, 주문번호, 주문자, 수령인 검색 |
| 마켓·스토어 | 상단에 전체 마켓, 하단에 연동한 전체 스토어를 표시하고 각각 복수 선택 |
| 상태 | 마켓·스토어 필터 바로 오른쪽에 배치하고, 현재 주문 존재 여부와 관계없이 탭별로 가능한 전체 소싱·구매·배송 상태 표시 |

스토어 목록은 현재 탭의 주문이나 검색 결과에서 만들지 않고 연동한 전체 스토어 목록을 사용한다. 선택한 마켓에 속하지 않은 스토어는 비활성화한다. 현재 탭에 주문이 없는 스토어도 계속 표시하며, 선택 결과가 없으면 주문 0건을 표시한다. 검색 조건이 바뀌면 목록과 선택 상태를 갱신한다.

### 마켓·스토어 필터 구성

마켓과 스토어는 하나의 필터 안에서 다음 순서로 표시한다.

```text
전체
마켓
├─ 스마트스토어
├─ 쿠팡
├─ 11번가
├─ G마켓
└─ 옥션
스토어
├─ 스마트스토어 연동 스토어
├─ 쿠팡 연동 스토어
├─ 11번가 연동 스토어
├─ G마켓 연동 스토어
└─ 옥션 연동 스토어
```

| 영역 | 요청 내용 |
|---|---|
| 전체 | 선택한 마켓과 스토어를 모두 해제 |
| 마켓 | 5개 마켓을 항상 전체 표시하고 복수 선택 허용 |
| 스토어 | 사용자가 연동한 모든 스토어를 항상 표시하고 복수 선택 허용 |
| 마켓 선택 전 | 모든 연동 스토어 선택 가능 |
| 마켓 선택 후 | 선택한 마켓의 스토어만 활성화하고 나머지는 비활성화 |
| 주문이 없는 스토어 | 목록에서는 유지하고 선택 결과를 주문 0건으로 표시 |

현재 프로토타입의 연동 스토어 목록은 다음과 같다.

| 마켓 | 스토어 |
|---|---|
| 스마트스토어 | 리빙온마켓, 홈데코랩 |
| 쿠팡 | 쿠팡라이프샵, 스마트홈셀러 |
| 11번가 | 글로벌픽스토어, 홈앤키친11 |
| G마켓 | 지마켓리빙박스, 데일리홈마켓 |
| 옥션 | 옥션리빙셀렉트, 하우스웨어옥션 |

별도의 `판매처 전체` 드롭다운은 제공하지 않는다. 마켓과 스토어 선택은 위 필터 한 곳에서만 관리한다.

### 탭별 상태 드롭다운

상태 드롭다운은 상단 검색 영역의 마켓·스토어 필터 바로 오른쪽에 같은 줄로 배치한다.

상태 선택지는 현재 주문에 실제로 사용된 상태만 추출하지 않는다. 각 탭에서 발생할 수 있는 전체 상태를 고정으로 표시한다.

| 탭 | 상태 드롭다운 전체 선택지 |
|---|---|
| 전체 | 전체, 소싱필요, 매칭완료, 결제대기, 결제완료, 중국배송중, 통관 중, 국내 배송중, 배송완료, 구매확정 |
| 신규주문 | 전체, 소싱필요 |
| 상품준비 | 전체, 소싱필요, 매칭완료, 결제대기 |
| 발송대기 | 전체, 결제완료, 중국배송중, 통관 중, 국내 배송중 |
| 배송중 | 전체, 결제완료, 중국배송중, 통관 중, 국내 배송중 |
| 배송완료 | 전체, 배송완료, 구매확정 |

- 해당 상태의 주문이 0건이어도 선택지는 숨기지 않는다.
- 탭을 변경하면 이전 탭에서만 가능한 상태 선택은 `전체`로 초기화한다.
- 상태 선택 결과가 없으면 주문 0건을 표시한다.

## 공통 화면 항목

| 항목 | 표시 내용 |
|---|---|
| 선택 | 일괄 처리할 주문 선택 |
| 처리하기 | 주문 상태와 상황에 맞는 기능 |
| 주문일시 | 마켓 주문일시와 그 아래 마켓 약자 아이콘·스토어명 |
| 진행상태 | 현재 대표 소싱·구매·배송 상태 |
| 상품정보 | 상품명, 옵션, 수량, 주문번호 |
| 결제가격/마진 | 결제금액, 마진율, 마진금. 상품정보 바로 다음에 표시 |
| 택배정보 | 조회 전용. 국내 택배사와 송장번호를 한 행에 표시하고, 마켓 처리 방식은 `직접전달` 또는 `해외기타배송`만 구분해 표시하며 중국 송장번호를 별도로 표시. 해외기타배송에 사용한 임의 해외 운송장번호는 표시하지 않음 |
| 배송정보 | 수령인명, 연락처, 개인통관부호 일치·불일치 배지. 주소와 개인통관부호 원문은 목록에서 제외 |

목록의 마진은 상품 매입 기준의 간이 마진으로 표시한다. `마진금 = 결제금액 - 매칭·결제 상품금액`, `마진율 = 마진금 ÷ 결제금액 × 100`으로 계산한다. 매칭·결제 상품금액은 실제 소싱 결제금액, 매칭 상품 단가×수량, 직접구매 기록 금액 순으로 사용하며 원가를 확인할 수 없는 주문은 마진율과 마진금을 `-`로 표시한다. 플랫폼 판매수수료·소싱 이용료·환전수수료·배송비를 반영한 상세 예상 마진은 펼친 상세의 마진계산에서 별도로 표시한다.

행을 선택하면 넓은 화면에서 왼쪽에는 `구매자·배송정보 → 택배정보`, 가운데에는 `상품 비교 또는 주문상품 → 마진계산`, 오른쪽에는 세로형 `처리하기`를 표시한다. 상품 비교는 `주문상품 → 소싱상품`, 마진계산은 `매출·정산 → 예상 소싱비용 → 예상 순이익·마진율` 순으로 세로 배치한다. 작은 화면에서는 가운데 정보, 왼쪽 정보, 처리하기 순서로 한 줄씩 배치한다. 매칭 상품이 없으면 상품 비교와 마진계산을 표시하지 않는다. 국내송장은 목록에서 조회만 하고, 국내배송 시작 뒤 가능한 주문에 한해 상세 `처리하기`에서 `운송장 수정`을 수행한다. 모든 주문 상세의 `처리하기`에는 장부 빈 항목을 입력하는 `비용 추가`와 현재까지 실제로 확인된 단계만 조회하는 `주문 히스토리`를 표시한다.

## 진행상태 표시

- 소싱필요
- 매칭완료
- 결제대기
- 결제완료
- 중국배송중
- 통관 중
- 국내 배송중
- 배송완료
- 구매확정
- 소싱환불 관련 진행상태
- 처리보류, 주문취소, 결제상태 불일치

`매칭완료`는 소싱상품 연결만 끝나고 결제는 완료되지 않은 상태다. 이 단계에서는 세 가지 마켓 배송중 처리 방식을 모두 제공하지 않는다. 실제 소싱 결제 또는 직접구매가 끝난 주문만 마켓 배송중 처리를 실행하고 `결제완료` 이후 단계로 표시한다.

## 주문수집 시연

| 상황 | 처리 결과 |
|---|---|
| 연동 스토어 있음 | 더미 주문수집 진행 상태 표시 |
| 수집 완료 | 더미 신규·갱신 건수를 표시하고 주문목록 갱신 |
| 수집 결과 없음 | 새로 수집된 더미 주문이 없음을 안내 |
| 시연 실패 상태 | 실패한 스토어와 다시 시도 안내를 더미 상태로 표시 |

주문수집은 실제 마켓에 연결하지 않고 더미데이터의 정상·결과없음·일부실패 상태를 시연한다.

## 단계·상황별 기능

| 단계·상황 | 목록 기능 | 상세 추가 기능 |
|---|---|---|
| 신규주문 | 주문확인, 매칭하기, 주문취소 | 왼쪽 구매자·배송정보 영역에서 배송정보 수정 |
| 상품준비·통관부호 정상 | 소싱하기, 주문취소 | 소싱상품관리, 직접구매 배송처리, 왼쪽 구매자·배송정보 영역에서 수정 |
| 상품준비·결제대기 | 소싱하기, 주문취소 | 소싱상품관리, 왼쪽 구매자·배송정보 영역에서 수정 |
| 상품준비·통관부호 오류 | 소싱하기 미제공 | 왼쪽 구매자·배송정보 영역에서 통관부호 교정 |
| 발송대기·직접구매 완료 | 배송중 처리 | 송장 유무와 관계없이 운송장 수정, 주문취소, 왼쪽 구매자·배송정보 영역에서 수정 |
| 배송중·구매 완료 | 없음 | 소싱상품관리, 배송추적, 소싱상품관리 안의 조건부 반품·환불, 국내배송이 시작된 직접전달·해외기타배송 선처리 주문의 운송장 수정 |
| 배송완료 | 없음 | 소싱상품관리, 배송추적, 소싱상품관리 안의 기존 환불 내역 조회 |
| 처리보류 | 없음 | 보류 사유와 처리이력 확인, 일반 처리 기능 차단 |
| 결제상태 불일치 | 없음 | 불일치 사유 확인, 일반 처리 기능 차단 |

버튼은 주문의 실제 조건에 따라 일부만 표시된다. 지원 마켓, 마켓 발송 완료 여부, 국내송장, 구매완료, 소싱환불 진행 여부에 따라 달라진다. `비용 추가`와 `주문 히스토리`는 모든 주문의 상세 `처리하기`에 공통으로 표시한다.

## 신규주문 처리

### 주문확인

```text
신규주문 선택
→ 주문확인
→ 데모 주문은 상품준비로 즉시 이동
→ 더미 주문 상태와 화면 건수 변경
```

- 목록 선택 주문을 일괄 주문확인할 수 있다.
- 목록과 주문 상세에서 행별 주문확인도 제공한다.
- 상품 매칭 여부와 관계없이 주문확인을 실행하면 상품준비로 이동한다.
- 매칭된 상품이 있으면 매칭 상태를 유지하고, 매칭되지 않은 주문은 상품준비에서 소싱필요 상태로 유지한다.

### 매칭하기

- 신규주문 목록 또는 상세의 `매칭하기`에서 후보 상품, 옵션, 수량을 선택한다.
- 키워드 또는 타오바오·소싱라이프 상품 URL로 후보를 추가할 수 있다.
- 저장하면 상품 매칭과 주문확인을 함께 처리해 상품준비로 이동한다.
- 매칭이 완료되는 즉시 주문 상세의 `처리하기`에 `소싱상품관리`를 표시한다.

### 주문취소

- 공식 취소 사유, 상세 사유, 취소 수량을 입력한다.
- 일괄 취소는 선택 주문의 전체 수량을 각각 처리한다.
- 직접전달 방식으로 지정된 주문은 마켓 처리 완료 여부와 관계없이 판매자 주문취소를 제공하지 않는다.
- 데모 주문은 즉시 판매자취소 상태로 변경하고 취소·반품·교환의 완료 목록에 `판매자 직접취소`로 추가한다.

## 상품준비 처리

### 소싱하기

```text
상품 후보·옵션·수량 확인
→ 저장된 배대지 수령 프로필 선택
→ 구매대행 신청
→ 결제대기
→ 원주문·소싱상품과 예상 비용·수익 비교
→ 중국 판매자 채팅 및 가격 인하 요청
→ 상품 결제하기
→ 결제수단·약관 확인
→ 결제 완료
→ 국내송장 생성
→ 배송중에서 관리
```

- 통관부호가 `P`와 숫자 12자리 형식이 아니면 구매대행 신청·결제를 진행할 수 없다.
- 구매대행 신청과 상품 결제는 분리한다.
- 결제대기에서 주문취소, 중국 판매자 채팅, `깎아줘`, `깎아줘 취소`를 제공한다.
- 가격 인하 요청 중에는 결제를 차단한다.
- 결제완료 후에도 결제상품과 기존 채팅을 계속 조회한다.
- 데모 결제완료 시 더미 소싱라이프 주문번호와 국내송장을 생성한다. 국내송장은 배송대행지 주문서 생성 시점부터 프로그램의 목록·상세에 표시하지만 국내배송 시작 전에는 마켓에 전달하지 않는다.
- 자동 배송중 처리 ON이면 결제 성공을 먼저 기록한 다음 주문에서 선택한 직접전달·해외기타배송 방식으로 마켓 발송을 시연한다. 송장입력 방식은 국내배송 시작이 확인된 뒤에만 자동·수동 전송한다. 결제가 실패하거나 확정되지 않으면 마켓 발송을 실행하지 않는다.

### 직접구매 배송처리

- 데모 상품준비 주문의 상세에서만 제공한다.
- 배송중 처리 방식은 주문이 연결된 스토어의 마켓연동 기본값을 사용하며 직접구매 배송처리 모달에서는 선택하지 않는다.
- 직접구매 배송처리 모달에는 국내 택배사·국내송장번호와 해외 운송장번호 입력란을 표시하지 않는다.
- 직접구매 완료와 스토어 기본 처리 방식만 저장하고 실제 마켓 발송 전 상태인 발송대기로 이동한다.
- 스토어 기본값이 송장입력인 주문은 발송대기 상세의 `운송장 수정`에서 국내 택배사와 송장번호를 입력하거나 수정한다. 이 작업은 송장정보만 저장하고 발송대기를 유지한다. 이후 별도의 `배송중 처리`에서 마켓 송장입력과 내부 배송중 전환을 완료한다.
- 스토어 기본값이 직접전달·해외기타배송인 주문은 발송대기의 `배송중 처리`에서 저장된 기본 방식을 사용한다. 해외기타배송에 필요한 해외 운송장번호는 이 단계에서 입력한다.
- 직접전달·해외기타배송으로 선처리한 주문은 국내송장을 이미 프로그램에 보유하더라도 국내배송 시작 전에는 마켓에 전달하지 않는다. 국내배송 시작이 확인되면 상세의 `운송장 수정`에서 기존 송장을 확인하고 마켓 발송방식을 송장입력으로 갱신한다.

### 배송정보 수정

- 데모의 신규주문, 상품준비, 발송대기에서 제공한다.
- 수령인명, 연락처, 우편번호, 주소, 상세주소, 배송메시지, 개인통관부호를 수정한다.
- 수령인명, 연락처, 주소, 정상 형식의 개인통관부호가 있어야 저장할 수 있다.

## 배송중 처리

- 마켓연동에서 저장한 스토어별 기본 배송중 처리 방식은 해당 스토어 주문의 개별·일괄·자동 처리 최초값으로 사용한다. 일괄 처리도 주문마다 연결된 스토어의 기본값을 적용하며, 주문에서 사용자가 다른 지원 방식을 고르면 주문 선택값을 우선한다.
- 직접전달·해외기타배송·송장입력 중 하나를 선택한다. 송장입력은 저장된 택배사와 송장번호를 사용하고 해외기타배송은 별도 해외 운송장번호를 사용한다.
- 마켓별 허용 범위는 네이버 3종, 11번가 직접전달·송장입력, 쿠팡·G마켓·옥션 송장입력으로 제한한다.
- 직접전달은 스마트스토어와 11번가에서만 제공한다.
- 세 방식 모두 소싱라이프 결제 또는 직접구매 완료를 공통 선행조건으로 한다. 상품준비의 매칭완료·결제대기 주문에는 별도 `배송중 처리`를 표시하지 않는다. `직접구매 배송처리` 안에서는 직접구매 완료를 먼저 저장하는 하나의 작업으로 세 방식 중 지원 방식을 선택할 수 있다.
- 발송대기에서는 목록·상세와 화면 상단에서 배송중 처리를 제공한다.
- 구매만 완료되고 마켓 발송 전인 주문은 발송대기에서 관리한다. 구매와 마켓 발송이 모두 완료된 주문만 배송중에서 관리한다.
- 이미 더미 마켓 배송중인 주문은 전송 시연을 반복하지 않고 내부 상태만 반영한다.
- 직접전달·해외기타배송은 구매를 완료했지만 실제 국내배송이 아직 시작되지 않은 구매대행 주문의 우선 발송 처리 방식이다. 배대지 주문서 생성과 함께 국내송장이 먼저 발급되어도 프로그램에만 표시하고 마켓에는 전달하지 않는다. 실제 국내배송이 시작되면 `운송장 수정`으로 마켓 발송방식을 `송장입력`에 갱신한다. 처음부터 국내배송이 시작된 주문만 바로 `송장입력`을 선택한다.
- 발송대기 화면에서 주문을 선택하면 선택 주문 중 처리 가능한 주문만 일괄 처리한다. 선택 주문이 없으면 검색어·기간·마켓·스토어 필터 적용 전의 현재 탭·상태 조건 주문 중 처리 가능한 주문 전체를 대상으로 한다. 따라서 화면에 보이는 검색 결과와 실제 처리 대상이 다를 수 있다.

## 배송·결제 조회

### 소싱상품관리

- 소싱상품이 매칭되는 즉시 주문 상세의 `처리하기`에 표시한다.
- 매칭 직후에는 매칭 상품·옵션·수량을 표시하고, 결제정보·소싱라이프 주문번호·국내송장은 각 정보가 생성된 이후 표시한다.
- 결제대기에서는 결제 기능과 중국 판매자 채팅을 제공하고 결제완료 이후에는 재결제를 제공하지 않는다.
- 소싱상품 환불 신청·진행·내역 조회는 목록이나 주문 상세보기의 `처리하기`에 별도 버튼으로 표시하지 않고, `소싱상품관리`의 구매대행 신청 상품 영역에서 제공한다.
- 환불 처리 후에도 `소싱상품관리`를 유지하고, 신청 여부와 진행상태에 따라 버튼명을 `반품·환불 신청` → `환불 진행` → `환불 내역`으로 변경한다.

### 배송추적

- 결제완료, 중국배송, 통관, 국내배송, 배송완료의 현재 상태와 누적 이력을 표시한다.
- 반품·교환 이력이 있으면 배송 이력과 구분해 표시한다.

### 운송장 수정

- 배송대행지 주문서 생성 시 발급된 국내송장은 즉시 내부 원장에 저장하고 목록·상세에 표시한다. 송장 존재 자체를 국내배송 시작으로 간주하지 않는다.
- 직접구매 완료 후 발송대기에 있는 주문은 송장 유무와 관계없이 상세 `처리하기`에 `운송장 수정`을 표시한다. 저장된 택배정보가 있으면 기존 값을 불러오며 사용자가 수정할 수 있다. 저장 시 택배정보만 변경하고 주문은 발송대기를 유지한다. 마켓 발송과 내부 배송중 전환은 별도의 `배송중 처리`에서 실행한다.
- 직접전달·해외기타배송으로 우선 처리한 주문이 `국내 배송중` 단계가 되면 상세에 `운송장 수정`을 표시한다.
- 발송대기 주문의 운송장 수정은 마켓의 일반 송장입력 발송 처리로 실행한다. 이미 직접전달·해외기타배송으로 발송한 배송중 주문의 변경은 마켓 API를 사용하지 않고, 마켓 2차 로그인 인증을 완료한 판매자센터 세션에서 크롤링으로 기존 발송방식을 국내 택배사·송장번호로 바꾼다.
- 실제 송장으로 마켓 갱신이 끝난 뒤에는 중복 수정을 막는다. 목록의 택배정보는 항상 조회 전용으로 유지한다.

## 소싱 반품·환불

- 행 자세히 보기의 `처리하기 > 소싱상품관리`로 진입한 뒤, 구매대행 신청 상품 영역에서 `반품·환불 신청`을 선택한다.
- 목록과 주문 상세보기의 `처리하기`에는 `환불하기`, `환불 진행`, `환불 내역`을 별도 버튼으로 표시하지 않는다.
- 소싱 결제가 완료되고 TaoWorld 구매 주문라인이 연결된 `결제완료·중국배송중·통관 중·국내 배송중` 주문에 신규 신청 기능을 표시한다. 배송완료부터는 신규 신청을 표시하지 않는다.
- 환불 유형, 상품 상태, 사유, CNY 요청금액, 설명, 이미지 URL을 입력한다.
- 마켓 클레임과 소싱 구매 환불은 별도로 처리한다.
- 중국 반품이 필요하면 반품 택배사, 송장번호, 전화번호와 설명을 추가로 입력한다.
- 신청 후에는 같은 구매대행 신청 상품 영역에서 `환불 진행` 또는 `환불 내역`으로 표시하고 누적 결과를 확인한다.
- 환불 완료 후 마켓 배송이 시작되지 않은 주문에는 상세 `처리하기`에서 `다시 소싱하기`를 제공한다.
- 환불 요청과 진행 결과는 더미 주문 상태에 반영한다.

## 빈 상태와 실패

| 상황 | 화면 결과 |
|---|---|
| 조회 결과 없음 | `주문이 없습니다` 표시 |
| 필수 입력 누락 | 모달을 유지하고 필요한 입력 안내 |
| 시연 처리 실패 | 기존 더미 상태 유지 및 오류 안내 |
| 소싱환불 진행 중 | 출고 관련 기능 차단 |

## 현재 프로토타입 제한

- 모든 주문, 결제, 송장, 배송, 취소와 환불 결과는 더미데이터로만 처리한다.
- 새로고침 후에도 시연 상태를 유지할지 초기화할지는 기능별로 일관된 기준이 필요하다.

## 완료 확인 기준

- 주문 단계, 검색·필터, 목록과 상세 항목을 확인할 수 있다.
- 주문 상태와 조건에 맞는 처리 버튼만 표시된다.
- 처리 성공 후 주문 단계, 진행상태, 택배정보와 다음 버튼이 함께 변경된다.
- 실패 또는 미지원 기능은 기존 상태를 유지하고 이유를 안내한다.
- 모든 기능은 실제 외부 전송 없이 화면 안에서 정상·예외 흐름을 확인할 수 있어야 한다.
