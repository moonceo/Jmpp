# 운송장 수정

> 중요도: **필수**

## 기능 요구사항

- 노출 위치: 발송대기·배송중 주문을 펼친 상세의 오른쪽 `처리하기`. 목록 택배정보는 조회 전용이며 입력 컨트롤을 표시하지 않는다.
- 내부 송장 생성: 배송대행지 주문서를 생성하면 국내 택배사와 송장번호를 즉시 내부 원장에 저장한다. 실제 배송 시작 여부와 관계없이 목록·상세의 조회 전용 택배정보에 바로 표시한다.
- 노출 조건: 국내송장 유무와 관계없이 직접구매 완료·발송대기 주문에 표시한다. 직접전달·해외기타배송 선처리 주문은 국내배송이 시작되고 내부 국내송장이 존재하는 배송중 단계에 표시한다.
- 발송대기 송장 흐름: 발송대기 주문의 `운송장 수정` → 저장된 택배정보가 있으면 기존 값 표시 → 국내 택배사·송장번호 입력 또는 수정 → 송장정보 저장 → 발송대기 유지
- 기존 송장 변경 흐름: 배송중 주문의 `운송장 수정` → 내부에 수집된 국내 택배사·송장번호 확인 → 마켓 2차 로그인 인증 → 인증 완료 세션으로 판매자센터 접속 → 크롤링으로 기존 발송방식을 송장입력으로 수정 → 결과 확인
- 입력 원칙: 직접구매 완료·발송대기 주문에서는 택배사와 송장번호를 입력하거나 기존 값을 수정할 수 있다. 배송중인 선처리 주문에서는 수집된 택배사·송장번호를 조회 전용으로 표시한다.
- 연동 방식: 발송대기 주문의 운송장 수정은 내부 송장정보만 저장하며 마켓에 전송하지 않는다. 실제 마켓 송장입력은 별도의 `배송중 처리`에서 실행한다. 이미 직접전달·해외기타배송으로 마켓 발송을 마친 배송중 주문의 변경은 마켓 주문 API를 사용하지 않고 2차 로그인 인증 기반 판매자센터 크롤링으로 처리한다. 인증정보와 인증 세션은 로그·더미데이터·일반 주문 속성에 평문 저장하지 않는다.
- 상태 변화: 발송대기 주문의 송장을 입력하거나 수정해도 발송대기를 유지한다. 별도의 배송중 처리가 성공하면 배송중으로 변경한다. 기존 송장 변경은 주문의 배송중 상태를 유지하고 마켓 발송방식만 직접전달·해외기타배송에서 송장입력으로 바꾸며 `crawler` 방식으로 기록한다.
- 처리 결과: 수정된 택배정보를 목록과 상세에 표시한다. 목록의 국내 택배사와 송장번호는 줄바꿈 없이 한 행에 표시한다. 국내배송 시작 전 잠금, 크롤링 수정 가능, 수정 완료 사례를 더미데이터로 각각 제공한다.
- 더미 식별: `0040`은 기존 송장이 표시되는 직접구매 완료·발송대기 수정 가능 사례, `0045`·`0056`은 국내배송 시작 전 잠금, `0039`·`0054`·`0057`은 크롤링 수정 가능, `0055`·`0058`은 크롤링 수정 완료 사례로 유지한다.
- 예외·제한: 신규 송장 입력은 택배사와 송장번호가 모두 있어야 완료한다. 기존 송장 변경은 국내배송 시작 전에는 버튼을 표시하지 않으며, 국내송장이 없거나 2차 로그인 인증이 실패·만료되거나 판매자센터 화면 구조가 달라지면 크롤링을 실행하지 않는다. 이미 실제 송장으로 갱신한 주문은 중복 수정을 막으며 목록에서는 수정할 수 없다.
