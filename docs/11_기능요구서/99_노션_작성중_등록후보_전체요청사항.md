# 전체 요청사항

이 문서는 기능요구서의 전체 요청사항을 한 곳에서 확인하고, 개발서버 적용 여부를 확인한 뒤 노션에 `작성중`으로 옮길 항목을 선별하기 위한 검토본이다.

- 개발서버 적용 여부는 이 문서에서 미리 판단하지 않는다.
- 개발서버에서 이미 적용된 기능은 노션에 새로 등록하지 않는다.
- 일부만 적용된 기능은 빠진 요청만 노션에 작성한다.
- 현재 노션에 같은 기능이 있으면 새 항목을 만들지 않고 기존 항목을 보완한다.
- 실제 API, DB, 인증 방식과 개발 구현 방법은 노션 요청사항에 포함하지 않는다.

## 확인 표시 방법

각 기능을 개발서버에서 확인한 뒤 해당 항목의 상태를 표시한다.

- 개발서버: `적용` / `부분 적용` / `미적용`
- 노션 처리: `등록 안 함` / `신규 작성중` / `기존 항목 보완`

## 대시보드

### [대시보드] 조회 월 변경

- 중요도: **낮음**
- 개발서버: ☐ 적용 ☐ 부분 적용 ☐ 미적용
- 노션 처리: ☐ 등록 안 함 ☐ 신규 `작성중` ☐ 기존 항목 보완

#### 요청사항

- 노출 위치: 월별 통계 영역 상단의 이전 월·다음 월 버튼과 기준 월 표시 영역
- 노출 조건: 대시보드 진입 시 항상 표시한다.
- 실행 흐름: 이전 월 또는 다음 월 선택 → 기준 월 변경 → 월별 통계와 일별 매출 다시 계산
- 상태 변화: 선택 월을 변경하고 변경된 월을 화면에 표시한다.
- 처리 결과: 통계 요약과 달력은 동일한 선택 월을 기준으로 표시한다.
- 예외·제한: 조회 데이터가 없는 월은 0원·0건과 빈 달력을 표시해야 하며 다른 월의 값을 재사용하지 않는다.

### [대시보드] 마진 확정 주문만 보기

- 중요도: **낮음**

#### 요청사항

- 노출 위치: 월별 통계 조건 영역
- 노출 조건: 대시보드 진입 시 항상 표시한다.
- 실행 흐름: 조건 ON/OFF → 포함 주문 재선정 → 통계 요약과 일별 매출 갱신
- 상태 변화: ON이면 마진이 확정된 주문만 집계하고 OFF이면 확정 여부와 관계없이 집계한다.
- 처리 결과: 총 매출, 정산예정금, 비용, 예상마진과 주문건수가 같은 대상 주문을 기준으로 변경된다.
- 예외·제한: 필터 조건을 변경하면 선택 조건에 맞춰 통계값도 즉시 다시 집계한다.

### 배송중 처리 관련 요청 구분

| 요청 항목 | 담당 범위 |
|---|---|
| 마켓연동의 스토어별 기본 배송중 처리 방식 | 주문 처리 전에 스토어별 최초 선택값 저장 |
| 직접구매 배송처리 | 직접구매 완료와 스토어 기본 처리 방식 저장, 운송장 입력 없이 발송대기로 이동 |

직접구매 완료, 운송장 입력, 마켓 배송중 처리는 서로 다른 단계로 관리한다. 직접구매 배송처리에서는 연결된 스토어의 기본 방식을 저장하고 운송장을 입력하지 않으며, 실제 마켓 발송은 발송대기의 후속 처리에서 실행한다.

- 처리 결과: 환불 신청 모달을 닫아도 `소싱상품관리`를 유지하고 버튼을 `환불 진행`으로 변경한다. 판매자 승인 이후 중국 반품이 없으면 환불완료로 진행하고, 중국 반품이 필요하면 반품 택배정보 입력 후 환불완료로 진행한다.
- 예외·제한: 배송완료부터는 신규 신청을 표시하지 않는다. 이미 환불을 신청한 주문은 후속 단계에서도 `환불 진행` 또는 `환불 내역`을 유지한다. 마켓 취소·반품·교환과 소싱상품 환불은 별도 이력으로 관리하고 환불 처리 결과와 금액을 기록한다.

### [주문수집] 주문 히스토리

- 중요도: **중요**
- 개발서버: ☐ 적용 ☐ 부분 적용 ☐ 미적용
- 노션 처리: ☐ 등록 안 함 ☐ 신규 `작성중` ☐ 기존 항목 보완

#### 요청사항

- 노출 위치: 모든 주문 상세의 오른쪽 `처리하기` 영역
- 노출 조건: 주문 단계나 처리 가능 기능과 관계없이 모든 주문 상세에 표시한다.
- 실행 흐름: 주문 히스토리 → 마켓 주문번호·상품·수량 확인 → 현재까지 확인된 주문 접수·주문 확인·상품 매칭·소싱 결제 준비·소싱 결제 완료·중국 배송·통관·국내 배송·배송완료 또는 주문취소 이력 확인 → 닫기
- 상태 변화: 조회만 수행하며 주문이나 배송 상태를 변경하지 않는다.
- 처리 결과: 각 단계의 발생시각과 주문금액·수령정보·매칭상품·결제금액·소싱 주문번호·송장번호 등 해당 단계에서 확인된 데이터를 표시한다. 마지막 미완료 단계는 현재 단계로 구분한다.
- 예외·제한: 아직 발생하지 않은 예정 단계는 표시하지 않는다. 발생시각을 받지 못한 단계는 `시간 미수신`으로 표시하고, 취소·처리보류 주문은 사유를 상단에 함께 표시한다.

#### 서비스 데이터 확인 범위

| 사례 | 서비스에 포함할 이력·데이터 |
|---|---|
| 신규주문 | 주문 접수시각, 마켓 주문번호, 판매처, 주문금액 |
| 상품 매칭 | 주문 확인시각, 매칭시각, 매칭상품, 옵션, 매칭률, 예상 소싱금액 |
| 결제대기 | 구매대행 신청시각, 배송대행지, 예상 결제금액 |
| 결제완료 | 실제 결제시각·금액, 소싱 주문번호, 해외 결제금액·결제번호 |
| 중국배송 | 중국 출고시각, 현지 택배사·송장번호·위치 |
| 통관 | 통관 시작 또는 완료시각, 세관 위치, 개인통관부호 |
| 국내배송 | 국내 인계시각, 국내 택배사·송장번호·허브 위치 |
| 배송완료 | 배송 완료시각, 택배사·송장번호·배송 위치 |
| 판매자취소 | 취소시각, 취소 사유, 중단된 이전 단계 |
| 처리보류 | 보류된 현재 단계와 보류 사유 |
| 취소·반품·교환 | 클레임 접수시각·사유·상태와 완료된 경우 처리 완료시각·최종상태 |

- 각 정상 단계는 주문수집의 해당 탭과 상태 필터에서 최소 한 건 이상 확인할 수 있어야 한다.
- 판매자취소와 처리보류 전용 주문은 `전체` 탭에서 확인할 수 있어야 한다.
- 배송 단계가 진행된 주문은 현재 단계 이전의 중국배송·통관·국내배송 이벤트를 누적 보존한다.
- 생성 기준시각이 바뀌면 주문 접수, 처리, 결제, 배송, 클레임 시각을 같은 간격으로 함께 이동한다.
