# 기획문서 작성 스킬

## 적용 범위

- 이 스킬은 주문팡팡 + 소싱라이프 기획문서를 작성하거나 수정할 때 적용한다.
- `01_서비스기획`, `02_UI_UX_명세서`, `03_기능명세서`는 현재 기준 문서이며 최종 확정본이 아니다.
- `01`, `02`, `03`은 사용자의 기능 추가, 제외, 용어 변경, 상태 변경 요청에 따라 언제든 다시 수정할 수 있다.
- `04_시스템_아키텍처_및_API`, `05_프론트엔드_개발가이드`, `06_운영_및_매뉴얼`, `07_주문팡팡개별`은 사용자가 명시적으로 요청할 때만 개별 수정한다.

## 작업 전 확인

- 수정 전 관련 문서에서 같은 개념이 이미 작성되어 있는지 먼저 확인한다.
- 이미 작성되어 있으면 사용자에게 어디에 있는지 알려주고 중복 작성하지 않는다.
- 일부만 작성되어 있으면 누락된 부분만 보강한다.
- 새 기능이면 영향을 받는 문서 전체에 반영한다.
- 사용자가 "추가"라고 말해도 기존 문서에 같은 기능이 있으면 새 항목을 중복 생성하지 않는다.

## 문서별 역할

- `01_서비스기획`: 서비스 목적, 범위, 정책, 운영 원칙, 비즈니스 규칙을 작성한다.
- `02_UI_UX_명세서`: 화면, 메뉴, 탭, 필터, 컬럼, 라벨, 버튼, 모달, 사용자 흐름을 작성한다.
- `03_기능명세서`: 기능 동작, 조건, 상태 변경, 성공 처리, 실패 처리, 예외 처리를 작성한다.
- `04_시스템_아키텍처_및_API`: 공통 데이터 모델, 상태 모델, API 처리 기준, 마켓 API 매핑, 소싱라이프 연동 기준을 작성한다.
- `05_프론트엔드_개발가이드`: 프론트엔드 구현 기준, 화면 구성, 컴포넌트 동작, 상태별 UI 표시 기준을 작성한다.
- `06_운영_및_매뉴얼`: 운영자가 실제 업무에서 따라야 하는 처리 절차와 주의사항을 작성한다.
- `07_주문팡팡개별`: 주문팡팡 내부 정책, 유지해야 할 판단 기준, 확장 원칙을 작성한다.

## 동시 반영 기준

- 기능을 추가하거나 변경할 때는 영향을 받는 문서를 같은 작업 안에서 함께 수정한다.
- 정책, 화면, 동작이 모두 바뀌면 `01`, `02`, `03`을 함께 수정한다.
- 용어만 바뀌어도 해당 용어가 등장하는 모든 현재 기준 문서를 수정한다.
- 기능을 제외하거나 삭제할 때도 관련 문서 전체에서 같은 기준으로 제거하거나 제외 기준을 명시한다.
- 한 문서에는 있고 다른 문서에는 없는 상태, 버튼, 컬럼, 정책이 생기지 않도록 확인한다.

## 용어 규칙

- 사용자 화면 액션명은 `주문확인`을 사용하고 `발주확인`은 사용하지 않는다.
- 마켓명은 `네이버 스마트스토어`, `쿠팡`, `11번가`, `지마켓`, `옥션`을 기준으로 작성한다.
- 판매처 또는 스토어 연결 단위는 `연동 계정`으로 작성한다.
- `마켓`과 `연동 계정`은 서로 다른 정보로 분리한다.
- `주문확인` 이후 단계는 `상품준비`로 작성한다.
- 소싱라이프 결제 완료 후 마켓 송장전송 전 단계는 `발송대기`로 작성한다.
- 상품준비 단계에서 소싱라이프 결제 화면으로 이동하는 동작은 `소싱하기` 흐름 안에 포함한다.
- 별도 사용자-facing 액션으로 `결제하기`를 만들지 않는다.

## 주문수집 범위와 필터

- 주문수집 대상은 활성화된 모든 연동 계정이다.
- 마켓 필터와 계정 필터는 주문 목록 조회용 필터다.
- 마켓 필터와 계정 필터를 주문수집 실행 범위 제어 기능으로 작성하지 않는다.
- 특정 판매처만 주문수집하는 기능과 특정 계정만 주문수집하는 기능은 초기 범위에서 제외한다.
- 동일 마켓 안에서도 여러 스토어 또는 판매자 계정을 개수 제한 없이 등록할 수 있다는 기준을 유지한다.

## 테이블 컬럼 규칙

- 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 서로 다른 업무 목적의 정보를 한 컬럼에 섞지 않는다.
- 상품명, 옵션명, 수량, 주문번호는 각각 필요한 목적에 맞춰 분리한다.
- 수령인명, 수령인 연락처, 배송지 주소는 각각 분리한다.
- `국내송장` 컬럼에는 같은 업무 목적의 국내 택배사와 국내 송장번호를 함께 표시할 수 있다.
- `개인통관부호` 컬럼에는 부호 값과 일치/불일치/확인필요 상태를 함께 표시할 수 있다.
- 송장 입력 경로, 마켓 전송 결과, 처리이력은 초기 주문 테이블의 별도 컬럼으로 두지 않는다.
- 컬럼을 추가, 삭제, 이름 변경할 때는 전체 컬럼 리스트를 다시 작성하고 번호를 재정렬한다.

## 상태와 액션 규칙

- `NEW`는 마켓 결제완료 주문이 수집되었고 주문확인 전인 상태다.
- `PREPARING`은 주문확인 완료 후 소싱라이프 결제 완료 전 상태다.
- `READY_TO_SHIP`은 소싱라이프 결제 완료 후 국내송장 수집, 입력, 마켓 송장전송 전 상태다.
- `SHIPPING`은 마켓 송장전송 성공 후 상태다.
- `DELIVERED`는 마켓 배송완료 또는 구매확정 상태다.
- `CLAIM`은 취소, 반품, 교환 처리 대상 상태다.
- 새 버튼을 추가할 때는 표시 위치, 활성 조건, 성공 결과, 실패 결과를 함께 정의한다.
- 자동화 기능을 추가할 때는 ON/OFF 동작, 대상 주문, 성공 결과, 실패 결과를 함께 정의한다.
- 주문상세 모달 하단 버튼은 현재 주문 상태에서 가능한 다음 단계 버튼만 표시한다.

## 국내송장 규칙

- 국내송장은 `READY_TO_SHIP` 상태에서만 입력 또는 수집할 수 있다.
- 국내송장은 자동수집, 송장 수동수집, 운영자 수동 입력 중 어떤 경로로 입력되어도 즉시 자동저장한다.
- 별도의 국내송장 저장 버튼이나 중간 저장 단계를 만들지 않는다.
- 자동수집은 소싱라이프에서 발급된 국내송장을 가져오는 기능이다.
- 송장 수동수집은 운영자가 버튼을 눌러 소싱라이프 국내송장을 조회하는 기능이다.
- 자동 송장전송은 국내송장이 입력된 뒤 마켓에 자동으로 전송하는 기능이다.
- 자동 송장전송은 국내송장이 입력된 경로와 관계없이 동작한다.
- 송장전송 성공 시 주문상태는 `SHIPPING`으로 변경한다.
- 송장전송 실패 시 주문상태는 `READY_TO_SHIP`으로 유지하고 실패 사유를 표시한다.

## 소싱라이프 규칙

- 소싱라이프는 주문팡팡 내부 기능이 아니라 외부 소싱/구매 서비스다.
- 주문팡팡은 소싱라이프 주문번호, 결제 완료 여부, 실제결제금액, 국내송장 확보 여부를 주문 단위로 관리한다.
- `NEW` 상태의 `소싱하기`는 매칭 저장과 주문확인을 함께 처리한다.
- `PREPARING` 상태의 `소싱하기`는 후보 확인, 옵션 선택, 매칭 저장, 소싱라이프 결제 화면 이동을 포함한다.
- 소싱 후보가 없거나 적합하지 않은 경우 `후보 없음, 소싱라이프에서 찾기` 버튼을 제공한다.
- 해당 버튼은 운영자가 소싱라이프로 이동해 직접 검색 또는 이미지 검색으로 상품을 찾는 흐름이다.

## 작성 톤

- 개발자에게 전달할 실제 기획문서처럼 작성한다.
- 문서에는 대화 히스토리, 수정 요청 히스토리, 작업 경위를 작성하지 않는다.
- `사용자가 요청했다`, `이번에 수정`, `현재 논의 중` 같은 표현을 쓰지 않는다.
- 구현 과정에 대한 해설이나 작업자 메모를 기획문서 본문에 쓰지 않는다.
- 기존 내용과 충돌되는 내용은 뒤에 덧붙이지 말고 기존 문장을 교체한다.
- 문장은 간결하고 판단 기준이 분명한 제품 기획 문체로 작성한다.

## 검증 규칙

- 수정 후 현재 기준 문서 전체에서 충돌 표현이 남아있는지 검색한다.
- 기본 충돌 검색어는 `발주확인`, `송장저장`, `송장 저장`, `송장 출처`, `마켓 전송상태`, `직접발주`, `배송대행`, `배대지`, `타오월드`다.
- 상태 코드, 버튼명, 컬럼명, 모달 버튼이 문서 간 서로 충돌하지 않는지 확인한다.
- `주문확인`, `소싱하기`, `국내송장 자동저장`, `송장전송`, `자동 송장전송`, `활성화된 모든 연동 계정` 기준이 필요한 문서에 반영되어 있는지 확인한다.
- 문서가 UTF-8 기준으로 정상 읽히는지 확인한다.

## 완료 보고

- 수정이 끝나면 실제로 수정한 문서만 보고한다.
- 요청 내용이 이미 문서에 있으면 수정하지 않고 어느 문서에 있는지 알려준다.
- 검증한 항목이 있으면 충돌 표현 검색 결과와 주요 정합성 확인 내용을 함께 요약한다.
