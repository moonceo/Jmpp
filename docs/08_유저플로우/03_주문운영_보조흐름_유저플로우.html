일괄 주문취소

flowchart TD
    A["신규주문"] --> B{"체크된 주문 있음?"}
    B -->|"없음"| C["주문취소 버튼 비활성"]
    B -->|"있음"| D["주문취소"]
    D --> E["공식 사유·상세 사유 확인 모달"]
    E --> F{"주문별 명령 접수"}
    F -->|"전부 접수"| G["처리보류 / 마켓 취소요청"]
    F -->|"일부 실패"| H["모달 유지 + 실패 주문번호·사유"]
    G --> I["최종 CANCELED 확인 후 판매자취소"]
    G --> J["UNKNOWN 수동 대사 · 자동 재호출 금지"]

개별·일괄 주문취소 모두 확인 모달을 거치며, 일부 실패 시 창을 유지한다. 접수 성공은 처리보류이고 최종 취소 확인 전에는 완료로 표시하지 않는다.

선택 상태 초기화

    B -->|"상단 탭 변경"| C["체크 해제"]
    B -->|"검색/필터 변경"| C
    B -->|"주문 데이터 갱신"| C
    C --> D["현재 화면 기준으로 다시 선택"]

클레임 보조 흐름

flowchart TD
    A["취소/반품/교환"] --> B["유형 필터"]
    B --> C{"클레임 유형"}
    C -->|"취소"| D["취소처리"]
    C -->|"반품"| E["반품처리"]
    C -->|"교환"| F["교환처리"]

취소 클레임은 승인 또는 거부를 선택할 수 있고, 반품/교환은 현재 MVP에서 조회 중심이다.
