# 주문운영 보조흐름 유저플로우

## 1. 일괄 주문확인

```mermaid
flowchart TD
    A["신규주문"] --> B{"체크된 주문 있음?"}
    B -->|"없음"| C["주문확인 버튼 비활성"]
    B -->|"있음"| D["주문확인"]
    D --> E["체크된 NEW 주문만 처리"]
    E --> F["상품준비로 이동"]
```

상단 `주문확인`은 체크된 항목만 대상으로 한다.
체크된 주문이 없으면 누를 수 없다.

## 2. 일괄 주문취소

```mermaid
flowchart TD
    A["신규주문"] --> B{"체크된 주문 있음?"}
    B -->|"없음"| C["주문취소 버튼 비활성"]
    B -->|"있음"| D["주문취소"]
    D --> E["공식 사유·상세 사유 확인 모달"]
    E --> F{"주문별 명령 접수"}
    F -->|"전부 접수"| G["처리보류 / 마켓 취소요청"]
    F -->|"일부 실패"| H["모달 유지 + 실패 주문번호·사유"]
    G --> I["provider 최종 CANCELED 확인 후 판매자취소"]
    G --> J["UNKNOWN이면 수동 대사 · 자동 재호출 금지"]
```

개별 주문취소와 일괄 주문취소 모두 확인 모달을 거친다. 일괄 일부 실패는 성공으로 닫지 않으며 같은 멱등키로 실패 주문을 다시 처리한다.

## 3. 선택 상태 초기화 흐름

```mermaid
flowchart TD
    A["주문 체크 선택"] --> B{"화면 조건 변경"}
    B -->|"상단 탭 변경"| C["체크 해제"]
    B -->|"검색/필터 변경"| C
    B -->|"주문 데이터 갱신"| C
    C --> D["현재 화면 기준으로 다시 선택"]
```

체크박스 선택은 탭과 필터마다 독립적으로 다뤄지며, 다른 단계로 이동하거나 필터가 바뀌면 이전 선택을 유지하지 않는다.

## 4. 클레임 보조 흐름

```mermaid
flowchart TD
    A["취소/반품/교환"] --> B["유형 필터"]
    B --> C{"클레임 유형"}
    C -->|"취소"| D["취소처리"]
    C -->|"반품"| E["반품처리"]
    C -->|"교환"| F["교환처리"]
```

현재 MVP의 취소/반품/교환 화면에는 현재단계 필터를 제공하지 않는다.
취소 클레임은 `취소처리`에서 승인 또는 거부를 선택할 수 있다.
반품/교환은 현재 MVP에서 사유와 진행 상태를 확인하는 조회 중심 화면으로 제공한다.

## 5. 자세히 보기 흐름

```mermaid
flowchart TD
    A["주문 행 클릭"] --> B["자세히 보기 펼침"]
    B --> C["주문상품"]
    B --> D["구매자"]
    B --> E["배송정보"]
    B --> F["택배정보"]
    B --> G["소싱상품"]
    E --> H["배송정보 수정"]
```

목록 컬럼은 처리에 필요한 최소 정보만 표시하고, 상세 정보는 행 확장으로 확인한다.

## 6. 배송정보 수정 흐름

```mermaid
flowchart TD
    A["목록 또는 자세히 보기"] --> B["수정"]
    B --> C["수취인 이름/연락처/주소/개인통관부호 수정"]
    C --> D{"필수 배송정보와 통관부호 형식 확인"}
    D -->|"문제 있음"| E["통관부호 불일치 상태 유지"]
    D -->|"문제 없음"| F["통관부호 일치 상태"]
    E --> G["저장"]
    F --> G
    G --> H["주문 데이터 반영"]
```

배송정보는 목록의 `수정` 버튼과 행 확장 상세에서 수정할 수 있다.
개인통관부호는 일치/불일치 여부와 관계없이 운영자가 다시 수정할 수 있다.

## 7. 데모 데이터 초기화 흐름

```mermaid
flowchart TD
    A["주문관리 화면 진입"] --> B["mock 주문 데이터 로드"]
    B --> C["소싱 매칭/결제/송장 localStorage 초기화"]
    D["좌측 데이터 초기화"] --> C
    C --> E["데모 기준 주문 목록 재표시"]
```

현재 MVP는 백엔드 없이 mock 데이터와 브라우저 저장소를 사용하는 데모 구현이다.
주문관리 화면 진입 또는 임시 데이터 초기화 버튼으로 데모 상태를 다시 맞춘다.
