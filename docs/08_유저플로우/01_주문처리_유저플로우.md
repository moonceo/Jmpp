# 주문처리 유저플로우

## 1. 문서 목적

이 문서는 주문팡팡 + 소싱라이프 주문처리 흐름을 시각화하기 위한 기준 문서다.
현재 기준 문서는 `01_서비스기획`, `02_UI_UX_명세서`, `03_기능명세서`, `04_시스템_아키텍처_및_API`, `05_프론트엔드_개발가이드`, `06_운영_및_매뉴얼`, `07_주문팡팡개별`의 내용을 바탕으로 한다.

MD 파일은 유저플로우의 원본 기준 문서이며, HTML 파일은 브라우저 확인용 시각화 산출물이다.

## 2. 유저플로우 작성 범위

이번 문서에서는 주문관리의 핵심 흐름을 우선 시각화한다.

- 전체 주문 처리 흐름
- 주문상세 모달 진입과 상태별 다음 단계 버튼
- 소싱하기 상세 흐름
- 국내송장 수집, 입력, 자동저장, 송장전송 흐름
- 실패와 보류 흐름

## 3. 전체 주문 처리 흐름

```mermaid
flowchart TD
    A["마켓 결제완료 주문"] --> B["주문팡팡 주문수집"]
    B --> C["신규주문<br/>NEW"]
    C --> D{"운영자 처리"}
    D -->|"주문확인"| E["상품준비<br/>PREPARING"]
    D -->|"소싱하기<br/>매칭 저장 + 주문확인"| E
    D -->|"주문취소"| X["판매자취소<br/>CANCELED"]

    E --> F["소싱하기"]
    F --> G{"소싱 후보 적합?"}
    G -->|"예"| H["후보/옵션 선택"]
    G -->|"아니오"| I["후보 없음, 소싱라이프에서 찾기"]
    I --> H
    H --> J["소싱라이프 결제 화면 이동"]
    J --> K{"소싱라이프 결제 완료?"}
    K -->|"예"| L["발송대기<br/>READY_TO_SHIP"]
    K -->|"아니오"| E

    L --> M{"국내송장 있음?"}
    M -->|"없음"| N["송장 수집대기"]
    M -->|"있음"| O["송장전송 대기"]

    N --> P["자동수집 / 송장 수동수집 / 수동 입력"]
    P --> Q["국내송장 자동저장"]
    Q --> R{"자동 송장전송 ON?"}
    R -->|"ON"| S["마켓 송장전송"]
    R -->|"OFF"| O
    O -->|"운영자 송장전송"| S

    S --> T{"송장전송 성공?"}
    T -->|"예"| U["배송중<br/>SHIPPING"]
    T -->|"아니오"| V["발송대기 유지<br/>실패 사유 표시"]
    U --> W["배송완료 또는 구매확정<br/>DELIVERED"]
```

## 4. 상태별 운영자 액션

| 주문상태 | 화면 의미 | 주요 액션 | 성공 시 상태 |
|---|---|---|---|
| `NEW` | 신규주문 | `주문확인` | `PREPARING` |
| `NEW` | 신규주문 | `소싱하기` | 매칭 저장 + 주문확인 후 `PREPARING` |
| `NEW` | 신규주문 | `주문취소` | `CANCELED` |
| `PREPARING` | 상품준비 | `소싱하기` | 소싱라이프 결제 완료 후 `READY_TO_SHIP` |
| `READY_TO_SHIP` | 발송대기 | 국내송장 자동수집, 송장 수동수집, 수동 입력 | 국내송장 자동저장 후 `READY_TO_SHIP` 유지 |
| `READY_TO_SHIP` | 발송대기 | `송장전송` | 성공 시 `SHIPPING` |
| `SHIPPING` | 배송중 | 조회 | 배송완료 또는 구매확정 수집 시 `DELIVERED` |
| `DELIVERED` | 배송완료 | 조회 | 상태 유지 |
| `CANCELED` | 판매자취소 | 조회 | 상태 유지 |
| `CLAIM` | 취소/반품/교환 | `취소처리` / `반품처리` / `교환처리` | 유형별 클레임 처리 |

## 5. 주문상세 모달 흐름

마켓 주문번호를 클릭하면 주문상세 모달을 연다.
모달은 공통 주문 정보를 보여주고, 하단에는 현재 주문상태에서 가능한 다음 단계 버튼만 표시한다.

```mermaid
flowchart TD
    A["주문 테이블"] --> B["마켓 주문번호 클릭"]
    B --> C["주문상세 모달 열기"]
    C --> D["공통 주문 정보 표시"]
    D --> E{"현재 주문상태"}

    E -->|"NEW"| F["하단 버튼<br/>주문확인 / 소싱하기"]
    E -->|"PREPARING"| G["하단 버튼<br/>소싱하기"]
    E -->|"READY_TO_SHIP"| H["하단 버튼<br/>송장전송"]
    E -->|"SHIPPING"| I["조회 전용"]
    E -->|"DELIVERED"| J["조회 전용"]
    E -->|"CANCELED"| M["조회 전용"]
    E -->|"CLAIM"| K["하단 버튼<br/>취소처리 / 반품처리 / 교환처리"]

    F --> L["상태별 액션 실행"]
    G --> L
    H --> L
    K --> L
```

주문취소는 신규주문 테이블 행 액션으로 제공하며, 주문상세 모달 하단 버튼에는 표시하지 않는다.

## 6. 소싱하기 상세 흐름

`소싱하기`는 `NEW`와 `PREPARING`에서 동작 범위가 다르다.

```mermaid
flowchart TD
    A["소싱하기 클릭"] --> B{"주문상태"}

    B -->|"NEW"| C["match-only 모드"]
    C --> D["소싱 후보 확인"]
    D --> E{"후보 적합?"}
    E -->|"예"| F["상품/옵션 선택"]
    E -->|"아니오"| G["후보 없음, 소싱라이프에서 찾기"]
    G --> H["소싱라이프 직접 검색 / 이미지 검색"]
    H --> F
    F --> I["매칭 저장"]
    I --> J["주문확인 동시 처리"]
    J --> K["상품준비<br/>PREPARING"]

    B -->|"PREPARING"| L["payment 모드"]
    L --> M["소싱 후보 확인"]
    M --> N{"후보 적합?"}
    N -->|"예"| O["상품/옵션 선택"]
    N -->|"아니오"| P["후보 없음, 소싱라이프에서 찾기"]
    P --> Q["소싱라이프 직접 검색 / 이미지 검색"]
    Q --> O
    O --> R["매칭 저장"]
    R --> S["소싱라이프 결제 화면 이동"]
    S --> T{"결제 완료 반영?"}
    T -->|"예"| U["발송대기<br/>READY_TO_SHIP"]
    T -->|"아니오"| V["상품준비 유지<br/>실패 사유 또는 처리 보류"]
```

## 7. 국내송장과 송장전송 흐름

국내송장은 `READY_TO_SHIP` 상태에서만 입력 또는 수집할 수 있다.
자동수집과 자동 송장전송은 서로 다른 기능이다.

```mermaid
flowchart TD
    A["발송대기<br/>READY_TO_SHIP"] --> B{"국내송장 있음?"}
    B -->|"없음"| C["송장 수집대기"]
    B -->|"있음"| D["송장전송 대기"]

    C --> E{"국내송장 입력 경로"}
    E -->|"자동수집 ON"| F["소싱라이프 국내송장 자동 조회"]
    E -->|"송장 수동수집"| G["운영자가 수동 조회"]
    E -->|"수동 입력"| H["운영자가 택배사/송장번호 입력"]

    F --> I["국내송장 자동저장"]
    G --> I
    H --> I

    I --> J{"자동 송장전송 ON?"}
    J -->|"ON"| K["마켓 송장전송 자동 실행"]
    J -->|"OFF"| D

    D -->|"운영자 송장전송"| K
    K --> L{"마켓 송장전송 성공?"}
    L -->|"예"| M["배송중<br/>SHIPPING"]
    L -->|"아니오"| N["발송대기 유지<br/>실패 사유 표시<br/>소싱상태 HOLD 가능"]
```

## 8. 실패와 보류 흐름

```mermaid
flowchart TD
    A["처리 시도"] --> B{"실패 유형"}
    B -->|"주문수집 실패"| C["계정 단위 실패 표시<br/>다른 계정 수집 계속"]
    B -->|"주문확인 실패"| D["NEW 유지<br/>실패 사유 표시"]
    B -->|"소싱라이프 연동 실패"| E["현재 주문상태 유지<br/>소싱상태 HOLD"]
    B -->|"결제 실패"| F["PREPARING 유지<br/>소싱상태 HOLD"]
    B -->|"송장전송 실패"| G["READY_TO_SHIP 유지<br/>실패 사유 표시<br/>소싱상태 HOLD 가능"]
    B -->|"클레임 처리 실패"| H["CLAIM 유지<br/>실패 사유 표시"]
    B -->|"판매자 주문취소"| I["CANCELED 처리<br/>판매자 취소일시 저장"]
```

## 9. 화면 전환 기준

| 출발 화면 | 사용자 행동 | 도착 화면 또는 결과 |
|---|---|---|
| 주문수집 > 전체 | 좌측 상태 메뉴 선택 | 선택한 상태 목록 |
| 주문수집 > 신규주문 | `주문확인` | 상품준비 |
| 주문수집 > 신규주문 | `소싱하기` | 소싱하기 모달 |
| 주문수집 > 상품준비 | `소싱하기` | 소싱하기 모달, 소싱라이프 결제 화면 |
| 주문수집 > 발송대기 | `송장 수동수집` | 소싱라이프 국내송장 조회 후 자동저장 |
| 주문수집 > 발송대기 | 국내송장 수동 입력 | 자동저장 |
| 주문수집 > 발송대기 | `송장전송` | 성공 시 배송중 |
| 주문 테이블 | 마켓 주문번호 클릭 | 주문상세 모달 |
| 주문 테이블 | 상품이미지 클릭 | 이미지 크게 보기 |
| 주문 테이블 | 상품명 클릭 | 오픈마켓 상품 상세 |
