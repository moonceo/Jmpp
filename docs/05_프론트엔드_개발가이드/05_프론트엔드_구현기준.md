# 프론트엔드 구현 기준

## 1. 문서 목적

이 문서는 주문관리 화면을 구현할 때 적용해야 하는 화면 구조, 좌측 메뉴, 필터, 테이블 컬럼, 버튼, 모달, 상태별 액션 기준을 정의한다.

주문관리 화면은 마켓별 원문 상태가 아니라 주문팡팡 내부 상태를 기준으로 구성한다.

## 2. 주문수집 화면 라우팅 기준

주문수집 화면은 상태별 뷰를 제공한다.

| 뷰 | 상태 코드 | 화면 의미 |
|---|---|---|
| `all` | 전체 | CLAIM을 제외한 일반 주문 전체 조회 |
| `new` | `NEW` | 신규주문 |
| `preparing` | `PREPARING` | 상품준비 |
| `waiting` | `READY_TO_SHIP` | 발송대기 |
| `shipping` | `SHIPPING` | 배송중 |
| `delivered` | `DELIVERED` | 배송완료 |
| `claims` | `CLAIM` | 클레임 그룹의 취소/반품/교환 |

`all`, `new`, `preparing`, `waiting`, `shipping`, `delivered`는 일반 주문 그룹이다.
`claims`는 일반 주문과 다른 컬럼/액션 확장이 가능한 클레임 그룹이다.
개별 상태 메뉴에서는 해당 상태의 주문만 표시한다.
전체 메뉴에서는 상태 필터를 통해 여러 일반 주문 상태를 함께 조회할 수 있다.
좌측 메뉴가 상태 이동을 담당하므로 본문에는 동일한 상태 목록을 중복 탭으로 제공하지 않는다.

## 3. 화면 레이아웃

주문수집 화면은 다음 순서로 구성한다.

1. 페이지 헤더
2. 핵심 지표 카드
3. 검색/필터 영역
4. 주문 테이블
5. 상태별 모달 또는 처리 팝업

페이지 헤더에는 현재 화면 제목과 해당 상태에서 가능한 전역 액션을 표시한다.
검색/필터 영역은 주문 목록 조회 조건이며, 주문수집 실행 범위를 제한하지 않는다.

## 4. 사이드바 메뉴와 건수 배지

사이드바 주문수집 하위 메뉴에는 상태별 건수를 표시한다.

| 메뉴 | 표시 건수 |
|---|---|
| 전체 | 일반 주문 처리 대기 합계 |
| 신규주문 | `NEW` 주문 수 |
| 상품준비 | `PREPARING` 주문 수 |
| 발송대기 | `READY_TO_SHIP` 주문 수 |
| 배송중 | `SHIPPING` 주문 수 |
| 배송완료 | `DELIVERED` 주문 수 |
| 취소/반품/교환 | 클레임 그룹의 `CLAIM` 주문 수 |

전체 처리 대기 합계는 일반 주문 그룹의 `NEW + PREPARING + READY_TO_SHIP`이다.
클레임 처리 대기 건수는 `CLAIM` 주문 수로 별도 표시한다.
송장 수집대기는 `READY_TO_SHIP` 중 국내송장이 없는 주문 수다.
송장전송 대기는 `READY_TO_SHIP` 중 국내송장이 있고 마켓 송장전송 전인 주문 수다.

## 5. 마켓연동 화면 기준

위치: `내정보 > 마켓연동`

| 항목 | 구현 기준 |
|---|---|
| 초기 활성 마켓 | 스마트스토어, 쿠팡 |
| 확장 예정 마켓 | 11번가, 지마켓, 옥션 |
| 계정 등록 | 마켓별 판매자 계정 또는 스토어를 개수 제한 없이 등록 |
| 계정 목록 | 마켓, 스토어명, 판매자 계정명, 인증상태, 활성 여부, 마지막 수집시각, 수집 실패 여부, 마켓수수료율 표시 |
| 계정 액션 | 활성/비활성, 재인증, 삭제 |
| 수수료 설정 | 마켓 또는 연동 계정 단위 마켓수수료율 입력/수정 |

마켓연동 화면에는 특정 판매처만 주문수집하거나 특정 계정만 주문수집하는 버튼을 제공하지 않는다.

## 6. 검색/필터 기준

| 필터 | 항목 |
|---|---|
| 주문 검색 | 마켓 주문번호, 상품주문번호, 상품명, 구매자명, 수령인명, 구매자 연락처, 수령인 연락처, 개인통관부호 |
| 기간 필터 | 시작일, 종료일, 오늘, 7일, 15일, 1개월 |
| 마켓 필터 | 전체, 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션 |
| 계정 필터 | 전체 계정, 등록된 스토어/판매자 계정 |
| 상태 필터 | 전체 메뉴에서는 일반 주문 상태 다중 선택, 개별 메뉴에서는 해당 상태로 제한 |

여러 필터를 함께 선택하면 AND 조건으로 동작한다.
연락처 검색은 하이픈 포함/미포함 입력을 모두 처리할 수 있어야 한다.

## 8. 컬럼 표시 원칙

- 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 주문수집 목록은 반복 처리 속도를 우선하므로 관련 정보는 업무 단위로 병합할 수 있다.
- `상품정보`에는 상품이미지, 상품명, 옵션명, 마켓 주문번호를 함께 표시한다.
- `판매처`에는 마켓과 연동 계정을 함께 표시한다.
- `처리하기`에는 주문확인, 소싱하기, 주문취소를 함께 표시한다.
- `결제`에는 결제금액, 수량, 상품단가를 함께 표시한다.
- `구매자`에는 구매자명, 구매자 아이디, 구매자 연락처를 함께 표시한다.
- `배송정보`에는 수령인, 연락처, 주소, 배송메시지, 개인통관부호를 함께 표시한다.
- `송장`에는 국내 택배사, 국내 송장번호, 송장전송을 함께 표시한다.
- 마켓 송장전송 완료 여부는 별도 컬럼이 아니라 주문상태가 `배송중`으로 바뀌는 것으로 표현한다.
- 후보 일치율은 소싱 후보 리스트에서만 표시하고 주문 테이블에는 표시하지 않는다.
- 국내송장 수신 시각과 처리이력은 초기버전 주문 테이블에 표시하지 않는다.
- 마켓수수료 상세값은 주문 테이블 기본 컬럼이 아니라 장부/정산 기능에서 중심적으로 표시한다.

## 9. 주문수집 목록 표시/숨김 기준

주문수집 목록은 아래 컬럼만 노출한다.

| 목록 컬럼 | 포함 정보 |
|---|---|
| 선택 | 주문 선택 체크박스 |
| 처리하기 | 주문확인, 소싱하기, 주문취소 |
| 주문상태 | 내부 주문 상태 |
| 판매처 | 마켓, 연동 계정 |
| 주문일시 | 마켓 주문 발생 일시 |
| 상품정보 | 상품이미지, 상품명, 옵션명, 마켓 주문번호 |
| 결제 | 결제금액, 수량, 상품단가 |
| 구매자 | 구매자명, 구매자 아이디, 구매자 연락처 |
| 배송정보 | 수령인명, 수령인 연락처, 우편번호, 배송지 주소, 배송메시지, 개인통관부호 |
| 송장 | 국내송장, 송장전송 |

아래 항목은 주문수집 목록에서만 숨긴다. 타입, mock data, 주문 상세 모달, 검색/계산/상태 처리에는 유지하며 필요 시 목록 컬럼으로 다시 노출할 수 있다.

| 구분 | 숨김 또는 병합 항목 |
|---|---|
| 목록 숨김 | 마켓 결제완료일시, 상품주문번호, 정산예정금액, 예상마진, 클레임 사유, 실패 사유, 클레임확인 |
| 목록 숨김 | 소싱상품명, 소싱옵션명, 예상원가, 실제결제금액, 실제마진 |
| 목록 표시 | 소싱라이프 주문정보(소싱라이프 주문번호만 표시) |
| 목록 병합 | 상품이미지, 상품명, 옵션명, 마켓 주문번호는 `상품정보`로 병합 |
| 목록 병합 | 마켓, 연동 계정은 `판매처`로 병합 |
| 목록 병합 | 주문확인, 소싱하기, 주문취소는 `처리하기`로 병합 |

삭제 요청으로 목록에서 제외한 컬럼도 원천 데이터에서는 삭제하지 않는다. 목록 화면의 표시 여부만 조정하며, 운영 또는 개발 판단에 따라 다시 꺼내 쓸 수 있어야 한다.

전체 페이지에는 좌우 스크롤이 생기지 않게 하고, 필요한 경우 주문 테이블 내부에서만 가로 스크롤을 허용한다.

## 10. 버튼 표시 규칙

- 메인 화면의 버튼은 아이콘 전용 버튼 또는 텍스트 전용 버튼으로만 표시한다.
- 텍스트 버튼 안에는 아이콘을 함께 넣지 않는다.
- 아이콘 전용 버튼은 `aria-label` 또는 `sr-only` 텍스트로 기능을 알 수 있게 한다.
- 좌측 사이드바 메뉴는 이 규칙의 예외로 둔다.
- 버튼이 아닌 상태 배지, 입력창 장식 아이콘, 링크 보조 아이콘은 별도 정책에 따른다.

## 11. 상품 이미지와 상품명 인터랙션

- 상품이미지 클릭 시 이미지 크게 보기 모달을 연다.
- 이미지 크게 보기 모달에는 이미지 복사 버튼을 제공한다.
- 상품명 클릭 시 새 창 또는 새 탭으로 오픈마켓 상품 상세 페이지를 연다.
- 상품 상세 URL이 없는 경우 상품명은 일반 텍스트로 표시한다.

## 12. 주문상세 모달

마켓 주문번호를 클릭하면 주문상세 모달을 연다.

모달 상단에는 주문번호, 주문상태, 마켓, 연동 계정을 표시한다.
모달 본문에는 공통 주문 정보를 표시한다.
모달 하단에는 현재 주문 상태에서 가능한 다음 단계 버튼만 표시한다.

| 주문상태 | 하단 버튼 |
|---|---|
| 신규주문 | `주문확인`, `소싱하기` |
| 상품준비 | `소싱하기` |
| 발송대기 | `배송중 처리` |
| 배송중 | 조회 전용 |
| 배송완료 | 조회 전용 |
| 취소/반품/교환 | `클레임확인` |

`주문취소`는 신규주문 테이블 행 액션으로만 제공하고, 주문상세 모달 하단 버튼에는 표시하지 않는다.

## 13. 상태별 행 액션

| 상태 | 행 액션 |
|---|---|
| `NEW` | `주문확인`, `소싱하기`, `주문취소` |
| `PREPARING` | `소싱하기` |
| `READY_TO_SHIP` | 국내송장이 있으면 `배송중 처리`, 없으면 송장대기 표시 |
| `SHIPPING` | 조회 전용 |
| `DELIVERED` | 조회 전용 |
| `CLAIM` | `클레임확인` |

버튼은 현재 상태에서 실행 가능한 작업만 활성화한다.
실행 조건이 충족되지 않은 버튼은 비활성화하거나 상태 배지로 표시한다.

## 14. 메뉴별 전역 액션

| 메뉴 | 전역 액션 |
|---|---|
| 전체 | `주문수집` |
| 신규주문 | `전체 주문확인`, `선택 주문확인 n건` |
| 상품준비 | `소싱라이프 송장 수신 시 자동 배송중 처리 ON/OFF` |
| 발송대기 | `자동수집 ON/OFF`, `자동 배송중 처리 ON/OFF`, `송장 수집`, `배송중 처리` |
| 배송중 | 조회 전용 |
| 배송완료 | 조회 전용 |
| 취소/반품/교환 | 주문별 `클레임확인` |

일괄 주문확인은 `NEW` 상태 주문만 대상으로 한다.
일괄 배송중 처리는 `READY_TO_SHIP` 상태이며 국내송장이 있는 주문만 대상으로 한다.
발송대기 메뉴는 `전체`, `송장 있음`, `송장 없음` 필터를 제공하며, 검색과 일괄 액션은 현재 선택된 송장 상태 필터 결과를 기준으로 동작한다.

## 15. 소싱하기 모달

`소싱하기` 모달은 주문상태에 따라 모드가 다르다.

| 모드 | 대상 | 동작 |
|---|---|---|
| `match-only` | `NEW` | 소싱 후보 확인, 매칭 저장, 주문확인 동시 처리 |
| `payment` | `PREPARING` | 소싱 후보 확인, 옵션 선택, 매칭 저장, 소싱라이프 결제 화면 이동 |

`payment` 완료 시 소싱라이프에서 국내송장을 함께 수신할 수 있다.
상품준비의 자동 배송중 처리 토글이 OFF이면 국내송장을 저장한 뒤 `READY_TO_SHIP`으로 이동한다.
상품준비의 자동 배송중 처리 토글이 ON이면 국내송장을 마켓에 전송하고 성공 시 `SHIPPING`으로 이동한다.
국내송장이 없으면 토글 상태와 관계없이 `READY_TO_SHIP`으로 이동한다.

모달에는 현재 주문 정보, 이미지 매칭 후보 리스트, 선택 상품/옵션, 예상원가, 수량, 예상마진을 표시한다.

후보가 없거나 적합하지 않은 경우 `후보 없음, 소싱라이프에서 찾기` 버튼을 제공한다.
이 버튼은 운영자가 소싱라이프로 이동해 직접 검색 또는 이미지 검색으로 상품을 찾는 흐름이다.

상품준비 단계에서 소싱라이프 결제 화면 이동은 `소싱하기` 흐름 안에서 처리한다.
별도 독립 버튼으로 분리하지 않는다.

## 16. 국내송장 입력과 전송

국내송장 컬럼은 상태별로 다르게 동작한다.

| 상태 | 국내송장 컬럼 동작 |
|---|---|
| `NEW` | 표시값 고정, 편집 불가 |
| `PREPARING` | 표시값 고정, 편집 불가 |
| `READY_TO_SHIP` | 택배사 선택과 송장번호 입력 가능 |
| `SHIPPING` | 표시값 고정, 편집 불가 |
| `DELIVERED` | 표시값 고정, 편집 불가 |

국내송장은 자동수집, 송장 수집, 수동 입력 중 어떤 경로로 입력되어도 즉시 자동저장한다.
`송장 수집`은 소싱라이프 주문번호가 있고 국내송장이 없는 주문만 대상으로 한다.
`배송중 처리`는 국내송장이 있는 주문만 대상으로 하며, 체크박스에 다른 주문이 함께 선택되어도 대상에서 제외한다.
별도 저장 버튼은 제공하지 않는다.

자동 송장전송 ON이면 국내송장 자동저장 직후 마켓 송장전송을 실행한다.
자동 송장전송 OFF이면 운영자가 `송장전송` 버튼을 눌러 마켓으로 전송한다.
송장전송 성공 시 주문상태는 `SHIPPING`으로 변경한다.
송장전송 실패 시 주문은 `READY_TO_SHIP`에 남고 실패 사유를 표시한다.

## 17. 사용자 메시지

주요 작업 결과는 사용자에게 명확히 안내한다.

| 상황 | 메시지 기준 |
|---|---|
| 주문확인 성공 | 주문확인이 완료되고 상품준비로 이동 |
| 주문확인 실패 | 실패 건은 신규주문에 남기고 실패 사유 표시 |
| 필수정보 누락 | 소싱 진행에 필요한 정보가 부족함을 표시 |
| 소싱라이프 결제 반영 | 발송대기로 이동 |
| 국내송장 자동저장 | 국내송장 입력 또는 수집 완료 표시 |
| 송장전송 성공 | 배송중으로 이동 |
| 송장전송 실패 | 발송대기에 남기고 실패 사유 표시 |
