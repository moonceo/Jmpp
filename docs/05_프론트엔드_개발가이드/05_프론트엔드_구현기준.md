# 프론트엔드 구현 기준

## 1. 현재 구현 전제

현재 MVP는 백엔드 없이 Next.js App Router, React, TypeScript, Tailwind CSS, shadcn/ui 조합으로 구현한다.
주문 데이터는 mock data와 클라이언트 상태를 기준으로 동작하며, 일부 소싱/송장 결과는 localStorage에 저장한다.

실제 패키지 기준:

- Next.js 16.1.4
- React 19.2.3
- TypeScript 5 strict mode
- Tailwind CSS 4
- shadcn/ui 스타일의 Radix 기반 UI primitive

경로 별칭은 `@/*`를 사용한다.
공유 타입은 `types/`, 도메인 상수는 `lib/constants/`, mock fixture는 `lib/mock-data/`, 공유 client state는 `lib/stores/` 기준으로 둔다.

현재 주문 MVP의 주요 데이터 흐름은 React state, mock data, localStorage 중심이다.
React Query는 의존성에 포함되어 있으나 주문관리 핵심 데이터 로딩에는 아직 사용하지 않는다.
Zustand는 현재 대시보드 store 중심으로 사용한다.

## 2. 실제 라우트

| 라우트 | 화면 |
|---|---|
| `/orders` | 주문관리 > 주문수집, 기본 신규주문 |
| `/orders?view=new` | 신규주문 |
| `/orders?view=preparing` | 상품준비 |
| `/orders?view=waiting` | 발송대기 |
| `/orders?view=shipping` | 배송중 |
| `/orders?view=delivered` | 배송완료 |
| `/orders?view=claims` | 취소/반품/교환 |
| `/me/markets` | 주문관리 > 마켓연동 |

`all` view 타입과 `ORDER_STATUSES.ALL` 상수는 내부 호환 목적으로 코드에 남아 있다.
다만 `app/orders/page.tsx` 라우트와 현재 화면 탭에는 별도 전체 주문수집 탭을 제공하지 않는다.

## 3. 주문관리 메뉴 구조

좌측 메뉴의 주문관리 하위 메뉴:

- 주문수집
- 취소/반품/교환
- 문의관리
- 마켓연동

주문수집 내부 상태는 본문 상단 탭으로 제공한다.

- 신규주문
- 상품준비
- 발송대기
- 배송중
- 배송완료

## 4. 검색/필터 구현

- 기간 버튼: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 검색 placeholder: `상품명, 주문번호, 주문자, 수령인 검색`.
- 마켓/스토어 필터는 하나의 아이콘 버튼으로 제공한다.
- 마켓과 스토어는 중복 선택 가능하다.
- 선택한 마켓과 관계없는 스토어는 비활성화한다.
- 마켓/스토어를 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하고, 이때 스토어가 속한 마켓은 자동 포함된 것으로 본다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 필터는 주문 목록 조회 조건이며 주문수집 실행 범위 제한이 아니다.
- `주문수집` 버튼은 상단 우측 공통 액션으로 유지한다.

## 5. 주문 테이블 컬럼

주문수집 테이블 컬럼 순서:

1. 선택
2. 처리하기
3. 주문일시
4. 상품정보
5. 택배정보
6. 배송정보
7. 판매처
8. 소싱라이프

전체 페이지에는 좌우 스크롤이 생기지 않게 한다.
필요 시 테이블 내부에서만 가로 스크롤을 허용한다.
컬럼 폭은 메뉴별로 최대한 동일하게 유지한다.

## 6. 행 확장 상세

주문 행을 클릭하면 자세히 보기 영역을 펼친다.
상세 섹션 순서:

1. 주문상품
2. 구매자
3. 배송정보
4. 택배정보
5. 소싱상품

상세의 구매자는 이름과 연락처만 표시한다.
상세의 배송정보는 수정 가능하다.
상세의 소싱상품은 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호만 표시한다.

행 상세와 체크 선택은 탭, 검색어, 필터, 데이터 변경 시 현재 화면 기준으로 초기화한다.
다른 탭에서 선택한 체크 상태가 현재 탭으로 이어져 보이면 안 된다.

## 7. 상태별 버튼

| 상태 | 처리하기 버튼 |
|---|---|
| `NEW` | `주문확인`, `매칭하기`, `주문취소` |
| `PREPARING` | `소싱하기`, `수동구매 완료`, `주문취소` |
| `READY_TO_SHIP` | `배송중 처리`, `주문취소` |
| `SHIPPING` | 조회 전용 |
| `DELIVERED` | 조회 전용 |
| `CLAIM` | `취소처리`, `반품처리`, `교환처리` |

메인 화면 버튼 규칙:

- 아이콘 버튼은 아이콘만 표시한다.
- 텍스트 버튼은 텍스트만 표시한다.
- 메인 화면에서 아이콘과 텍스트를 한 버튼 안에 섞지 않는다.
- 사이드바 메뉴는 예외로 둔다.

## 8. 소싱하기 모달

신규주문의 `매칭하기`:

- match-only 모드로 동작한다.
- 후보/옵션 매칭 저장과 주문확인을 함께 처리한다.
- 처리 후 상품준비로 이동한다.

상품준비의 `소싱하기`:

- 추천 소싱 상품 목록을 표시한다.
- 후보는 썸네일, 한국어 상품명, 중국어 상품명, 판매처, 원화/위안 상품원가를 표시한다.
- 구매횟수, AI 매칭률, 별점, 배송일수는 표시하지 않는다.
- 옵션 드롭다운은 한국어 옵션명 아래 중국어 옵션명을 표시한다.
- 옵션이 품절이면 결제 버튼을 비활성화한다.
- 수량 변경을 제공한다.
- `소싱라이프에서 직접 찾기` 버튼은 `추천 소싱 상품` 제목 오른쪽에 배치한다.
- `소싱라이프 결제 하기`를 누르면 모달 내부에서 구매대행 신청 화면과 결제 화면을 표시한다.

## 9. 택배정보/배송중 처리

발송대기:

- 송장 필터 드롭다운: `전체`, `송장 있음`, `송장 없음`.
- `소싱라이프 송장 수집` 버튼을 제공한다.
- `소싱라이프 송장 자동 수집` 토글을 제공한다.
- `자동 배송중 처리` 토글을 제공한다.
- `배송중 처리` 버튼은 송장번호가 있는 주문만 대상으로 한다.
- 발송대기 전역 액션은 체크된 주문이 있으면 체크된 주문을 우선 대상으로 하고, 체크가 없으면 현재 필터에 보이는 주문을 대상으로 한다.
- `소싱라이프 송장 수집`은 소싱라이프 주문번호가 있고 송장번호가 없는 주문만 실제 수집 대상으로 처리한다.
- `배송중 처리`는 송장번호가 있는 주문만 실제 처리 대상으로 처리한다.

행:

- 택배사와 송장번호 입력은 발송대기에서 가능하다.
- 송장번호 입력값은 자동 저장된다.
- 송장번호가 없으면 배송중 처리 버튼은 비활성화한다.
- 송장번호가 있으면 배송중 처리 버튼은 활성화한다.

배송중:

- 송장 수정 버튼은 제공하지 않는다.
- 변경된 송장번호가 있으면 번호만 표시한다.

## 10. 마켓연동 화면

`/me/markets` 화면 구성:

- 우측 상단 `마켓 추가` 버튼.
- 목록 컬럼: 마켓, 스토어명, 연동상태, 활성, 관리.
- 관리 버튼은 마켓 추가와 동일한 계정 수정 모달을 연다.
- 삭제 버튼은 삭제 확인 모달 후 삭제한다.

마켓 추가/수정 모달:

- 마켓 선택 드롭다운: 스마트스토어, 쿠팡, 11번가, G마켓, 옥션.
- 공통 필수: 스토어명, 사업자번호.
- 스마트스토어: 연동용 판매자 ID, 클라이언트 아이디, 클라이언트 시크릿.
- 쿠팡: 쿠팡 업체코드, Access Key, Secret Key, 쿠팡 윙 로그인 ID.
- 11번가: API Key.
- G마켓/옥션: Master ID, Seller ID.

현재 MVP에서 제공하지 않는 항목:

- 플랫폼 수수료율
- 마지막 수집
- 결과
- 결제카드
- 별도 계정설정 페이지

## 11. localStorage 키

| 키 | 용도 |
|---|---|
| `jumunpangpang.syncedInvoices` | 소싱라이프 송장 수집 결과 |
| `jumunpangpang.sourcingMatches` | 소싱 매칭 저장 |
| `jumunpangpang.sourcingPayments` | 소싱 결제 완료 가정 결과 |

현재 구현은 주문 화면 진입 시 demo data를 초기화한다.
좌측 하단 `데이터 초기화` 버튼은 위 localStorage 키를 삭제하고 데모 데이터를 되돌리는 임시 기능이다.

## 12. 와이어프레임 문서 기준

현재는 별도 정적 와이어프레임을 먼저 만든 것이 아니라 실제 프론트 프로토타입을 먼저 구현했다.
따라서 `docs/09_와이어프레임`의 HTML은 현재 화면을 페이지별/모달별로 확인하기 위한 정적 참조 파일로 유지한다.

- 페이지 HTML: 주문수집 5개 상태, 취소/반품/교환, 마켓연동
- 모달/팝오버 HTML: 주문상세, 소싱하기, 수동구매 완료, 배송정보 수정, 주문취소 확인, 마켓 추가/수정, 마켓 삭제 확인, 클레임 처리, 이미지 크게보기, 직접 기간 선택, 마켓/스토어 필터

## 13. 검증 기준

현재 저장소에는 테스트 러너가 없다.
의미 있는 프론트 또는 문서 기준 변경 후 검증은 다음 기준으로 한다.

- `npm run lint`
- `npm run build`

`npm test`는 현재 `package.json`에 정의되어 있지 않으므로 사용하지 않는다.

## 14. 제외 범위

현재 프론트 MVP에는 다음을 구현하지 않는다.

- 타오바오 직접 결제
- 내부 배대지/창고 관리
- 배송중 송장 변경 API 전송
- 플랫폼 수수료율 설정 화면
- 처리이력 전용 화면
