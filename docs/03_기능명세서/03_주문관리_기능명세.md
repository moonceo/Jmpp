# 주문관리 기능명세

## 1. 기능 범위

주문수집과 소싱라이프 연동의 핵심 흐름을 운영 기능 중심으로 구성한다.

- 일반 주문 상태 분리 조회(NEW, PREPARING, READY_TO_SHIP, SHIPPING, DELIVERED)
- 클레임 그룹 조회(CLAIM)
- 초기 활성 마켓인 스마트스토어와 쿠팡 주문수집
- 확장 예정 마켓인 11번가, 지마켓, 옥션 주문수집 구조
- 판매처별 다중 판매자 계정 등록 및 활성화된 모든 연동 계정 수집
- 상태별 액션 제어
- 소싱 매칭/결제/국내송장 수집 흐름
- 마켓 송장전송(송장 입력 + 마켓 전송)
- 마켓수수료율 설정값을 장부 기능과 마진 계산에 활용
- 주문 테이블 기반 운영 정보
- 사이드바 단계별 처리 건수 표시
- 클레임 노출

## 2. 주문 상태 표준

| 코드 | 라벨 |
|---|---|
| NEW | 신규주문 |
| PREPARING | 상품준비 |
| READY_TO_SHIP | 발송대기 |
| SHIPPING | 배송중 |
| DELIVERED | 배송완료 |
| CANCELED | 판매자취소 |
| CLAIM | 취소/반품/교환 |

## 3. 주문수집 화면(상태 조회)

- 뷰 파라미터로 조회 분기
  - `all`, `new`, `preparing`, `waiting`, `shipping`, `delivered`, `claims`
- `all`, `new`, `preparing`, `waiting`, `shipping`, `delivered`는 일반 주문 그룹이다.
- `claims`는 취소/반품/교환 클레임 그룹이다.
- 일반 주문 그룹의 `all` 목록은 CLAIM을 제외한 주문을 표시한다.
- `CANCELED`는 판매자가 직접 취소 처리한 종료 상태이며 취소/반품/교환 클레임 그룹에 포함하지 않는다.
- 목록은 선택된 뷰 상태 코드와 주문 그룹 기준으로 표시한다.
- 주문 검색은 마켓 주문번호, 상품주문번호, 상품명, 구매자명, 수령인명, 연락처, 개인통관부호 기준 텍스트 검색을 지원한다.
- 주문 검색어, 기간 필터, 마켓 필터, 계정 필터는 교차 적용한다.
- 기간 필터는 마켓 주문일시 또는 마켓 결제완료일시 기준으로 주문 목록을 제한한다.
- 마켓 필터는 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션 기준으로 주문 목록을 제한하며 중복 선택할 수 있다.
- 계정 필터는 사용자가 연동한 스토어/판매자 계정 기준으로 주문 목록을 제한하며 중복 선택할 수 있다.
- 계정 필터는 주문 조회용 필터이며, 주문수집 실행 범위를 특정 계정으로 제한하지 않는다.
- 주문 테이블에는 마켓과 연동 계정을 `판매처` 컬럼에 함께 표시한다.
- 사이드바 하위 메뉴에는 일반 주문 그룹과 클레임 그룹을 분리해 상태별 건수를 표시한다.

### 3-1. 필터 동작 기준

- 기본값은 기간 필터 `최근 7일`, 마켓 필터 `전체`, 계정 필터 `전체 계정`이다.
- 주문 검색어, 기간 필터, 마켓 필터, 계정 필터를 동시에 적용하면 AND 조건으로 동작한다.
- 마켓 필터 또는 계정 필터에서 여러 항목을 선택하면 해당 필터 내부에서는 OR 조건으로 동작한다.
- 마켓 필터 또는 계정 필터의 `전체`는 해당 필터 선택을 모두 해제한 상태다.
- 주문 검색어는 부분 일치 검색을 지원한다.
- 연락처 검색은 하이픈 포함/미포함 입력을 모두 검색할 수 있어야 한다.
- 주문 검색어를 비우면 검색 조건은 적용하지 않는다.
- 기간 필터는 오늘, 3일, 7일, 한달, 직접선택을 제공한다.
- 직접선택은 시작일과 종료일을 작은 모달에서 지정한다.
- 계정 필터 목록은 내정보 > 마켓연동에 등록된 활성/비활성 계정 목록을 기준으로 표시한다.
- 비활성 또는 인증 만료 계정도 과거 주문 조회를 위해 필터 목록에 표시할 수 있다.
- 필터를 변경해도 주문수집 대상 계정은 바뀌지 않는다.

## 3-2. 사이드바 단계별 건수(F0)

- 전체: 일반 주문 처리 대기 주문 수 합계
- 신규주문: `NEW` 상태 주문 수
- 상품준비: `PREPARING` 상태 주문 수
- 발송대기: `READY_TO_SHIP` 상태 주문 수
- 배송중: `SHIPPING` 상태 주문 수
- 배송완료: `DELIVERED` 상태 주문 수
- 취소/반품/교환: 클레임 그룹의 `CLAIM` 상태 주문 수
- 건수는 주문 목록 데이터가 갱신될 때 함께 갱신한다.
- 주문확인, 소싱 결제 반영, 배송중 처리 등 상태가 바뀌는 액션 이후 건수를 즉시 다시 계산한다.
- 일반 주문 전체 처리 대기 주문 수는 NEW, PREPARING, READY_TO_SHIP 상태 주문 수를 합산한다.
- 클레임 처리 대기 주문 수는 CLAIM 상태 주문 수로 별도 표시한다.
- 송장 수집대기 수는 READY_TO_SHIP 중 국내송장이 없는 주문 수다.
- 배송중 처리 대기 수는 READY_TO_SHIP 중 국내송장이 있고 마켓 송장전송 전인 주문 수다.

## 4. 주문 조회 동작(F1)

- 주문수집은 활성화된 모든 연동 계정을 대상으로 실행한다.
- 특정 판매처만 수집하거나 특정 계정만 수집하는 기능은 초기 범위에서 제외한다.
- 수집 주기, 중복 처리, 실패 재시도 정책은 판매처 API 정책에 맞춰 적용한다.

## 4-1. 판매처 계정 등록(F1-1)

- 최종적으로 사용자는 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션에서 운영 중인 판매자 계정 또는 스토어를 개수 제한 없이 등록할 수 있다.
- 초기 활성 연동은 스마트스토어와 쿠팡이며, 11번가, 지마켓, 옥션은 연동 준비 상태로 관리한 뒤 순차적으로 활성화한다.
- 계정 등록 시 최소 관리 정보는 다음과 같다.
  - 판매처 코드
  - 스토어명
  - 판매자 계정 식별값
  - 인증 방식/API 키 또는 토큰 상태
  - 활성 여부
  - 마지막 수집 시각
  - 마지막 수집 성공/실패 상태
  - 마켓수수료율
- 마켓수수료율은 마켓 또는 연동 계정 단위로 관리하며, 정산예정금액, 예상마진, 실제마진, 장부 기능 계산에 사용한다.
- 주문수집은 활성화된 모든 연동 계정을 대상으로 수행한다.
- 특정 판매처 또는 특정 계정만 선택해 주문수집하는 기능은 제공하지 않는다.
- 특정 계정 인증이 실패해도 다른 계정 수집은 계속 진행한다.
- 계정 단위 실패는 전체 주문수집 실패가 아니라 해당 계정 실패로 표시한다.

## 4-2. 계정별 주문수집 기준(F1-2)

- 수집 단위는 `마켓 + 연동 계정 + 마켓 주문번호/상품주문번호`다.
- 동일 마켓 주문번호라도 연동 계정이 다르면 별도 주문으로 관리한다.
- 중복 방지 기준은 다음과 같다.
  - 주문 단위: `마켓 + 연동 계정 + 마켓 주문번호`
  - 주문상품 단위: `마켓 + 연동 계정 + 상품주문번호`
- 주문 목록에는 마켓과 연동 계정명이 함께 저장되어야 한다.
- 수집 실패 로그는 마켓 전체가 아니라 연동 계정 단위로 기록한다.

## 5. 주문 액션(F2)

### 5-1. 신규주문 메뉴

- `주문확인`
  - 대상: NEW 상태
  - 효과: 상태를 PREPARING으로 변경
  - 텍스트: 주문번호와 함께 주문확인 완료 토스트
- `소싱하기`
  - 대상: NEW 상태
  - 동작: 매칭 후보 및 옵션 선택 창 오픈
  - `match-only` 모드: 매칭 저장 후 주문확인 동시 처리
- `주문취소`
  - 대상: NEW 상태
  - 효과: CANCELED 상태로 이동하고 판매자 취소 사유와 취소일시 반영

### 5-2. 상품준비 탭

- `소싱하기`
  - 대상: PREPARING 상태
  - 동작: 후보 확인, 옵션 선택, 매칭 저장, 소싱라이프 결제 화면 이동
  - 소싱라이프 결제 완료 반영 시 소싱라이프 주문번호, 결제금액, 국내송장 정보를 함께 조회한다.
  - 국내송장이 없으면 주문 상태를 READY_TO_SHIP으로 변경한다.
  - 국내송장이 있더라도 `소싱라이프 송장 수신 시 자동 배송중 처리`가 OFF이면 국내송장을 입력한 상태로 READY_TO_SHIP에 남긴다.
  - 국내송장이 있고 `소싱라이프 송장 수신 시 자동 배송중 처리`가 ON이면 마켓 송장전송을 시도하고 성공 시 SHIPPING으로 변경한다.
  - 소싱라이프 주문번호는 소싱라이프 주문 생성 성공 시점에 저장한다.
  - 소싱라이프 결제 완료 전에도 주문번호가 발급될 수 있으며, 결제 완료 여부는 소싱상태로 별도 관리한다.
- `수동구매 완료`
  - 대상: PREPARING 상태
  - 동작: 소싱라이프를 통하지 않고 운영자가 직접 구매한 주문을 다음 단계로 이동한다.
  - 송장번호 없이 완료하면 주문 상태를 READY_TO_SHIP으로 변경한다.
  - 국내송장을 입력하고 `송장 저장 후 발송대기`를 선택하면 국내송장을 manual 출처로 저장하고 주문 상태를 READY_TO_SHIP으로 변경한다.
  - 국내송장을 입력하고 `배송중 처리`를 선택하면 국내송장을 manual 출처로 저장하고 마켓 송장전송 완료로 보고 주문 상태를 SHIPPING으로 변경한다.
  - 수동구매 완료는 소싱라이프 주문번호를 생성하지 않는다.

### 5-3. 발송대기 메뉴

- `배송중 처리`
  - 대상: READY_TO_SHIP 상태 + 국내송장 존재 + 미전송
  - 동작: 마켓에 국내송장을 전송하고 성공 시 다음 단계로 이동
  - 성공: SHIPPING 상태
  - 실패/예외: 발송대기 상태를 유지하고 실패 사유 표시
- 발송대기 상태는 국내송장 수집 대상과 배송중 처리 대기 주문을 모두 포괄
- 발송대기 목록은 `전체`, `송장 있음`, `송장 없음`으로 구분해 조회할 수 있다.
- `송장 있음`은 국내송장 값이 있고 아직 배송중 처리 전인 주문이다.
- `송장 없음`은 국내송장 값이 없어 자동수집 또는 수동입력이 필요한 주문이다.

### 5-4. 배송중, 배송완료, 클레임

- SHIPPING, DELIVERED: 기본적으로 처리작업은 배지로 완료 상태 표시
- CLAIM: 일반 주문 그룹이 아닌 클레임 그룹에서 클레임 유형별 처리 액션 제공
- CANCELED: 판매자가 직접 주문취소한 완료 상태이며 조회 전용으로 표시한다.
- 구매자 취소 요청 클레임은 `취소처리` 액션을 제공하고, 현재 진행단계를 확인한 뒤 `취소승인` 또는 `취소거부`를 마켓에 전송한다.
- 반품 클레임은 `반품처리`, 교환 클레임은 `교환처리` 액션을 제공한다.
- 반품, 교환의 승인/회수/재발송 처리는 별도 클레임 처리 기능에서 확장한다.

## 6. 전역 액션(F3)

### 6-1. 주문확인 일괄

- 탭: 신규주문
- 체크박스로 선택한 주문만 처리
- 상단 버튼명은 `주문확인`으로 고정한다.
- 선택 주문이 없으면 `주문확인` 버튼은 비활성화한다.
- 처리 대상은 NEW 상태 주문만 포함한다.
- 처리 대상 NEW 주문이 없으면 `주문확인할 신규주문이 없습니다.` 안내를 표시한다.
- 일괄 처리 성공 건은 PREPARING 상태로 이동한다.
- 일부 실패가 발생할 수 있으며, 실패 건은 NEW 상태에 남기고 실패 사유를 표시한다.

### 6-2. 송장 수집

- 메뉴: 발송대기
- 전역 동작
  - 자동수집 ON/OFF 토글
  - 자동 배송중 처리 ON/OFF 토글
  - 송장 수집
  - 배송중 처리
- 자동수집
  - 발송대기 메뉴에서 실행한다.
  - 소싱라이프와 연동해 발급된 국내송장을 가져온다.
  - 수집 대상은 국내송장 없는 READY_TO_SHIP 주문이다.
- 송장 수집
  - 운영자가 버튼을 눌러 소싱라이프 주문번호 기준으로 발급된 국내송장을 조회한다.
  - 수집 대상은 READY_TO_SHIP 중 소싱라이프 주문번호가 있고 국내송장이 없는 주문이다.
  - 체크박스로 국내송장이 이미 있는 주문을 함께 선택해도 송장 수집 대상에서는 제외한다.
- 수동 입력
  - 운영자가 국내 택배사와 국내송장번호를 직접 입력한다.
  - 입력 대상은 READY_TO_SHIP 주문이다.
- 자동수집, 송장 수집, 수동 입력 모두 국내송장 값이 입력된 것으로 보고 즉시 자동저장한다.

### 6-2-0. 상품준비 자동 배송중 처리

- 메뉴: 상품준비
- 전역 동작
  - `소싱라이프 송장 수신 시 자동 배송중 처리` ON/OFF 토글
- 기본값은 OFF다.
- OFF 상태에서는 소싱라이프 결제 완료 시 국내송장이 함께 수신되어도 주문은 READY_TO_SHIP으로 이동하고, 국내송장 값만 저장한다.
- ON 상태에서는 소싱라이프 결제 완료 시 국내송장이 함께 수신되면 마켓 송장전송을 자동 시도하고, 성공 시 SHIPPING으로 이동한다.
- 국내송장이 수신되지 않은 주문은 ON/OFF와 관계없이 READY_TO_SHIP으로 이동한다.

### 6-2-1. 자동 배송중 처리

- 메뉴: 발송대기
- 자동 배송중 처리가 ON이면 국내송장이 입력되는 즉시 시스템이 자동으로 마켓에 송장전송하고 배송중 전환을 시도한다.
- 자동 배송중 처리가 OFF이면 국내송장이 입력되어도 운영자가 `배송중 처리`로 직접 전송한다.
- 자동 배송중 처리는 국내송장이 자동수집, 송장 수집, 운영자 수동 입력 중 어떤 방식으로 입력됐는지와 관계없이 동작한다.
- 자동 전송 대상은 `READY_TO_SHIP` 상태이며 국내송장 값이 있는 주문이다.
- 자동 배송중 처리 성공 시 상태는 SHIPPING으로 변경한다.
- 자동 배송중 처리 실패 시 주문은 발송대기에 남기고 실패 사유를 표시한다.

### 6-3. 소싱라이프 주문 결제 이동

- PREPARING 상태에서는 소싱라이프 결제 화면 이동을 위한 별도 독립 버튼을 제공하지 않는다.
- PREPARING 상태의 결제 화면 이동은 `소싱하기` 기능 흐름 안에서 처리한다.
- `소싱하기`는 소싱 후보 확인, 옵션 선택, 결제 화면 이동까지 포함한다.

## 7. 소싱라이프 연동(F4)

- 후보 수집
  - 화면에서 20개 후보 노출
  - 후보당 썸네일, 일치율, 위안/원화/배송일수 표시
- 옵션 선택
  - 후보별 옵션 카드 선택
  - 예상마진 계산(주문단가 * 수량 기준)
- 매칭 저장
  - 매칭 대상 저장 시 `sourcingLifeMatch` 값 반영
- 미매칭 대응
  - `후보 없음, 소싱라이프에서 찾기` 버튼 제공
  - 버튼 클릭 시 운영자는 소싱라이프 화면으로 이동한다.
  - 소싱라이프에서 직접 검색 또는 이미지 검색으로 상품을 찾는다.
  - 검색 후 선택한 상품/옵션을 주문팡팡 주문에 다시 매칭할 수 있어야 한다.
- 결제 전/결제 후 구분
  - 결제 전: 소싱 결제 대기 상태
  - 소싱라이프 결제 완료 후: 실제 결제금액 반영, 소싱 결제 완료 상태 전환

### 7-1. 소싱상태 값

- 소싱상태는 주문상태를 대체하지 않고, 소싱라이프 연동 진행도를 주문 단위로 표시한다.

| 코드 | 라벨 | 전환 기준 |
|---|---|---|
| NOT_LINKED | 소싱 전 | 주문 수집 후 소싱라이프 매칭 전 |
| MATCHING | 이미지 매칭 중 | `소싱하기` 실행 후 후보 조회 중 |
| MATCH_SAVED | 매칭 저장 | 후보와 옵션을 선택해 매칭 정보를 저장한 상태 |
| PAYMENT_READY | 결제 가능 | 매칭 완료 후 소싱라이프 결제 화면으로 이동 가능한 상태 |
| PAID | 소싱라이프 결제완료 | 소싱라이프 결제 완료가 주문팡팡에 반영된 상태 |
| INVOICE_RECEIVED | 국내송장 수신 | 소싱라이프 국내송장이 수집되었거나 운영자가 국내송장을 입력한 상태 |
| HOLD | 처리 보류 | 필수정보 누락, 매칭 실패, 결제 실패, 배송중 처리 실패로 처리를 보류한 상태 |

- `PAID` 반영 시 주문상태는 READY_TO_SHIP으로 변경한다.
- `INVOICE_RECEIVED`는 READY_TO_SHIP 주문에 국내송장이 수집되거나 입력된 경우 표시한다.
- 필수정보 누락 또는 매칭 실패는 주문상태를 변경하지 않고 소싱상태를 HOLD로 표시한다.
- 결제 실패는 주문상태를 PREPARING으로 유지하고 소싱상태를 HOLD로 표시한다.
- 배송중 처리 실패는 주문상태를 READY_TO_SHIP으로 유지하고 소싱상태를 HOLD로 표시한다.

## 8. 송장 처리(F5)

- 입력/표시 규칙
  - `READY_TO_SHIP`은 편집 가능
  - `SHIPPING`은 쿠팡 주문만 편집 가능
  - `NEW`, `PREPARING`은 입력필드 비활성
  - `DELIVERED`는 입력필드 비활성(완료표시)
  - 국내송장 컬럼에서 택배사와 송장번호를 함께 입력/표시한다.
- 국내송장 입력 경로와 마켓 전송 결과는 초기버전 주문 테이블의 별도 컬럼으로 두지 않는다.
- 배송중 처리 성공 여부는 별도 상태 컬럼이 아니라 주문상태가 SHIPPING으로 변경되는 것으로 표시한다.
- 발송대기 주문에는 `배송중 처리` 버튼을 항상 표시한다.
- 국내송장번호가 없으면 `배송중 처리` 버튼은 비활성화한다.
- 국내송장번호 입력을 시작하면 현재 입력값 기준으로 `배송중 처리` 버튼을 활성화한다.
- 국내송장번호만 입력하고 `배송중 처리`를 누르지 않으면 국내송장 저장만 수행하고 주문상태는 READY_TO_SHIP으로 유지한다.
- `배송중 처리`를 누르면 현재 입력된 국내송장을 저장하면서 마켓 송장전송을 수행하고, 성공 시 주문상태를 SHIPPING으로 변경한다.
- 국내송장 자동저장
  - 대상: READY_TO_SHIP 상태 주문
  - 조건: 국내 택배사와 국내송장번호 입력 또는 수집
  - 성공: 주문 상태는 READY_TO_SHIP으로 유지하고 국내송장 값을 자동저장한다.
  - 자동 배송중 처리 ON: 자동저장 직후 마켓 송장전송을 자동 실행한다.
- 자동 배송중 처리 ON + 전송 성공: 주문상태를 SHIPPING으로 변경한다.
- 자동 배송중 처리 OFF: 자동저장만 수행하고 운영자가 `배송중 처리`를 눌러야 마켓으로 전송한다.
  - 저장 실패/예외: 주문 상태는 READY_TO_SHIP으로 유지하고 실패 사유를 표시한다.
- 배송중 송장 수정
  - 대상: SHIPPING 상태의 쿠팡 주문
  - 조건: 국내 택배사 또는 국내송장번호 수정 후 `송장수정` 버튼 클릭
  - 성공: 주문 상태는 SHIPPING으로 유지하고 수정된 국내송장을 쿠팡에 전송한다.
  - 네이버 등 쿠팡 외 배송중 주문은 주문수집 화면에서 송장수정 버튼을 제공하지 않는다.

## 9. 주문 테이블 정보 노출(F6)

- 초기버전에서는 행 확장 상세 기능을 제공하지 않는다.
- 주문 처리에 자주 필요한 정보는 주문 테이블 목록 컬럼으로 노출한다.
- 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 주문수집 목록은 선택, 처리하기, 주문상태, 주문일시, 상품정보, 송장, 배송정보, 판매처, 소싱라이프 컬럼을 기본으로 한다.
- 일반 주문수집 메뉴 간 같은 컬럼은 동일한 폭을 유지한다.
- 전체 페이지에는 좌우 스크롤이 생기지 않게 하고, 주문 테이블 내부에서만 가로 스크롤을 허용한다.
- 취소/반품/교환 클레임 목록에는 주문상태 컬럼 안에 실제 주문 진행상태 배지와 클레임 상태 배지를 함께 표시한다.
- 상품정보, 판매처, 처리하기, 배송정보, 송장은 각각 관련 값을 업무 단위로 병합해 표시할 수 있다.
- 목록에서 숨긴 컬럼도 원천 데이터, 검색/계산/상태 처리에는 유지한다.
- 마켓 주문번호는 상품정보 컬럼 안에서 `마켓 주문번호 : 주문번호` 형식의 일반 텍스트로 표시하며 클릭 링크나 주문상세 모달은 제공하지 않는다.
- 소싱 후보 리스트에서는 일치율을 표시하고, 주문 테이블에는 후보 일치율 또는 매칭률 컬럼을 표시하지 않는다.
- 송장 수신일시는 초기버전 주문 테이블에 표시하지 않는다.
- 마켓수수료 상세값은 주문수집 테이블의 기본 컬럼에서 제외하고 장부/정산 기능에서 중심적으로 사용한다.
- 처리이력은 초기버전 주문관리 기능 범위에서 제외한다.

### 9-0. 주문수집 목록 숨김 컬럼

아래 항목은 주문수집 목록에서만 숨긴다. 데이터 모델, mock data, 검색/계산/상태 처리에는 유지하며 필요 시 목록 컬럼으로 다시 노출할 수 있다.

| 구분 | 숨김 또는 병합 항목 |
|---|---|
| 목록 숨김 | 마켓 결제완료일시, 상품주문번호, 구매가/결제금액, 구매자명, 구매자 연락처, 구매자 아이디, 정산예정금액, 예상마진, 클레임 사유, 실패 사유 |
| 목록 숨김 | 소싱상품명, 소싱옵션명, 예상원가, 실제결제금액, 실제마진 |
| 목록 표시 | 소싱라이프 주문정보(소싱라이프 주문번호 표시 및 주문내역 링크) |
| 목록 병합 | 상품이미지, 상품명, 옵션명, 마켓 주문번호는 `상품정보`로 병합 |
| 목록 병합 | 마켓, 연동 계정은 `판매처`로 병합 |
| 목록 병합 | 주문확인, 소싱하기, 주문취소는 `처리하기`로 병합 |

삭제 요청으로 목록에서 제외한 컬럼도 원천 데이터에서는 삭제하지 않는다. 목록 화면의 표시 여부만 조정하며, 운영 또는 개발 판단에 따라 다시 꺼내 쓸 수 있어야 한다.

### 9-1. 상품 이미지/상품명 동작

- 상품명 클릭 시 오픈마켓 상품 상세 페이지를 새 창 또는 새 탭으로 연다.
- 상품 상세 URL이 없는 경우 상품명은 클릭 불가 텍스트로 표시한다.
- 상품 썸네일 클릭 시 이미지 크게 보기 모달을 연다.
- 이미지 크게 보기 상태에서 이미지 복사 버튼을 제공한다.
- 이미지 복사 성공/실패 결과는 사용자에게 메시지로 표시한다.

### 9-2. 주문번호 표시와 원천 데이터 유지

- 마켓 주문번호는 `상품정보` 컬럼 안에서 `마켓 주문번호 : 주문번호` 형식의 일반 텍스트로 표시한다.
- 마켓 주문번호 클릭 링크와 주문상세 모달은 제공하지 않는다.
- 목록에서 숨긴 원천 데이터는 데이터 모델에 유지하며, 필요 시 별도 화면 또는 컬럼으로 다시 노출할 수 있다.

원천 데이터 유지 항목:

- 마켓, 연동 계정, 주문상태
- 마켓 주문번호, 상품주문번호
- 주문일시, 마켓 결제완료일시
- 상품이미지, 상품명, 옵션명, 수량, 상품단가, 결제금액
- 구매자명, 구매자 아이디, 구매자 연락처
- 수령인명, 수령인 연락처, 우편번호, 배송지 주소, 배송메시지
- 개인통관부호와 확인완료/확인필요 상태
- 소싱상태, 소싱상품명, 소싱옵션명, 예상원가, 실제결제금액, 실제마진, 소싱라이프 주문번호
- 국내송장
- 클레임 사유, 실패 사유

- `주문취소`는 신규주문 테이블 행 액션으로만 제공한다.

### 9-3. 구매자/수령인/통관 필수 컬럼

- 주문 테이블 목록에는 구매자명, 구매자 연락처를 `구매자` 컬럼에 함께 표시한다.
- 주문 테이블 목록에는 수령인명, 수령인 연락처, 주소, 개인통관부호를 `배송정보` 컬럼에 함께 표시한다.
- 개인통관부호는 배송정보 안에서 부호 값과 확인완료/확인필요 상태를 함께 표시한다.
- 개인통관부호가 비어 있거나 형식이 맞지 않으면 모두 확인필요로 표시하고, 형식이 맞으면 확인완료로 표시한다.
- 주문수집 목록의 배송정보 컬럼은 확인완료/확인필요와 관계없이 `배송정보 수정` 버튼을 제공하고, 수령인 배송정보와 개인통관부호를 함께 수정할 수 있다.
- 배송정보 수정 모달은 입력 중인 개인통관부호의 확인완료/확인필요 상태를 같은 기준으로 표시한다.
- 마켓 결제완료일시는 목록에서 숨기고 원천 데이터에 유지한다.

## 10. 클레임(F7)

- CLAIM 상태 주문은 일반 주문 목록이 아니라 클레임 그룹의 취소/반품/교환 목록에 노출한다.
- 취소/반품/교환 목록은 구매자가 요청했거나 마켓에서 수집한 클레임만 노출한다.
- 취소/반품/교환 목록은 `claimType` 기준으로 전체, 취소, 반품, 교환 필터를 제공한다.
- 취소/반품/교환 목록은 `previousStatus` 기준으로 현재단계 전체, 신규주문, 상품준비, 발송대기, 배송중, 배송완료 필터를 제공한다.
- 취소/반품/교환 목록의 주문상태 컬럼은 `previousStatus` 기준 실제 주문 진행상태를 먼저 표시하고, `claimStatus` 기준 취소 요청, 출고중지 요청, 반품 요청, 교환 요청 등을 함께 표시한다.
- 송장번호가 없는 발송 전 클레임 더미는 반품이 아니라 취소 요청 또는 출고중지 요청으로 구성한다.
- 신규주문의 `주문취소`는 CANCELED 상태로 이동하며 CLAIM 상태로 보내지 않는다.
- 취소 클레임은 `취소처리` 액션을 제공한다.
- 취소처리 화면에는 클레임 사유, 현재 진행단계, 소싱라이프 주문번호, 소싱상태, 국내송장을 표시한다.
- 취소처리 화면에서 `취소승인` 또는 `취소거부`를 선택하면 마켓에 전송하고 클레임 상태를 `취소승인 전송완료` 또는 `취소거부 전송완료`로 변경한다.
- 반품 클레임은 `반품처리`, 교환 클레임은 `교환처리` 액션을 제공한다.
- 현재단계가 배송중 또는 배송완료인 클레임은 소싱라이프 주문번호와 국내송장번호가 반드시 있어야 한다.
- 반품/교환 요청 사유, 회수, 재발송, 환불 추적은 클레임 관리 기능에서 확장한다.

## 11. 운영 메시지/예외(F8)

- 전송/변경 시 사용자 메시지
  - `주문확인이 완료되고 상품준비로 이동했습니다.`
  - `배송중 처리 완료: n건을 마켓에 전송하고 배송중으로 이동했습니다.`
  - 송장 미입력 또는 필수정보 미입력 시 진행 제한 메시지
