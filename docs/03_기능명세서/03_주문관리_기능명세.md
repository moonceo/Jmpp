# 주문관리 기능명세

## 1. 적용 기준

현재 구현은 PostgreSQL 실원장/API와 명시적 demo mode를 분리한다. 주문·클레임 실데이터는 서버 API를 기준으로 하고 localStorage는 demo 주문의 소싱/결제/송장 UI 검증에만 사용한다.
문서와 구현이 다를 경우 `docs/00_문서맵/02_실서비스_완성목표_및_로드맵.md`와 실제 서버 계약을 우선한다.
주문관리는 소싱라이프 내부 메뉴로 제공한다.
주문수집 대상은 마켓에서 수집된 주문이며, 소싱라이프에서 직접 생성하거나 주문한 내역은 주문수집 목록에 포함하지 않는다.
소싱라이프의 구매, 검수, 입고, 물류 상세 처리는 소싱라이프 기존 기능에서 진행하고 주문관리 기능 범위에 포함하지 않는다.

이 문서는 다음 화면을 기준으로 한다.

| 화면 | 경로 | 역할 |
|---|---|---|
| 주문수집 | `/orders`, `/orders?view=new` | 신규주문 기본 진입 |
| 전체주문 | `/orders?view=all` | 처리보류를 포함한 일반 주문 전체 조회 |
| 상품준비 | `/orders?view=preparing` | 소싱라이프 소싱/결제 또는 직접구매 국내송장 등록 |
| 발송대기 | `/orders?view=waiting` | 국내송장 확인, 마켓 배송중 처리 |
| 배송중 | `/orders?view=shipping` | 배송중 주문 조회 |
| 배송완료 | `/orders?view=delivered` | 배송완료 주문 조회 |
| 취소/반품/교환 | `/orders?view=claims` | 클레임 주문 별도 조회 |
| 마켓연동 | `/me/markets` | 마켓 계정 추가, 수정, 삭제 |

`CANCELED`는 판매자가 직접 취소 처리한 종료 상태이며, 구매자 요청 클레임인 `CLAIM`과 분리한다.

## 2. 주문 상태

| 코드 | 화면 라벨 | 정의 |
|---|---|---|
| `NEW` | 신규주문 | 마켓 결제완료 주문이 수집되었고 판매자가 주문확인 전인 상태 |
| `PREPARING` | 상품준비 | 주문확인 후 소싱라이프 소싱/결제 또는 외부 구매가 필요한 상태 |
| `READY_TO_SHIP` | 발송대기 | 구매와 국내송장 저장 완료 후 마켓 배송중 처리를 기다리는 상태 |
| `SHIPPING` | 배송중 | 국내송장을 기준으로 배송중 처리된 상태 |
| `DELIVERED` | 배송완료 | 배송완료 또는 구매확정 상태 |
| `ON_HOLD` | 처리보류 | 판매자 취소 요청 접수 후 provider 최종 결과 대기. 마켓 상태 `CANCEL_REQUESTED`와 함께 표시 |
| `CANCELED` | 판매자취소 | 판매자가 직접 주문취소 처리한 종료 상태 |
| `CLAIM` | 취소/반품/교환 | 구매자 요청 또는 마켓에서 수집된 취소, 반품, 교환 클레임 |

## 3. 상단 검색/필터

- 기간 필터: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 기본 기간은 `7일`이다.
- 직접 입력은 시작일과 종료일을 선택하는 작은 팝오버로 처리한다.
- 검색어는 상품명, 마켓 주문번호, 상품주문번호, 내부 주문 ID, 구매자명, 수령인명, 연락처, 배송메시지, 개인통관부호를 대상으로 부분 일치 검색한다.
- 연락처는 하이픈 포함/미포함 입력을 모두 검색한다.
- 마켓/스토어 필터는 하나의 팝오버에서 제공한다.
- 마켓과 스토어는 중복 선택할 수 있다.
- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하며, 스토어가 속한 마켓은 자동 포함된 것처럼 본다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.
- `주문수집` 버튼은 우측에 고정하며, 활성·연결 상태이고 주문수집 어댑터가 활성화된 전체 계정과 스토어를 대상으로 한다. 현재 실서비스 어댑터 범위는 스마트스토어이며 쿠팡·11번가·ESM은 worker/UAT 완료 전 대상에서 제외한다.
- 수동 수집은 계정별 `sync_run`을 접수하고 기존 실행 중 작업은 재사용한다. 화면은 실행 완료까지 상태를 조회해 신규·갱신·오류 건수를 표시하고, 완료 후 주문 목록을 자동으로 다시 조회한다.
- 실행이 60초 안에 끝나지 않으면 화면 대기를 종료하되 작업은 백그라운드에서 계속 진행한다. `SUCCEEDED`, `PARTIAL`, `FAILED/CANCELED/DEAD`를 구분해 안내하며 접수 성공을 수집 성공으로 표시하지 않는다.
- 모든 일반 주문 단계와 전체주문에 `판매처`, `상태` 필터를 제공한다. 판매처는 현재 단계의 옵션을 마켓 네모 약자 아이콘(`N`, `C`, `11`, `G`, `A`)과 스토어명 형식으로 표시하고, 상태는 현재 데이터 건수와 무관하게 단계별 조회 가능 상태를 모두 표시해 주문을 좁힌다.
- 상태 필터의 고정 범위는 신규주문 `소싱필요`, 상품준비 `소싱필요·소싱 검증대기·소싱완료·결제대기`, 발송대기/배송중 `결제완료·중국배송중·통관 중·국내 배송중`, 배송완료 `배송완료·구매확정`이다. `결제완료`는 소싱라이프 결제와 외부 구매 완료를 함께 조회한다.
- 배송완료의 `구매확정` 배지는 추가 상태값이다. 배송완료 주문은 모두 `배송완료` 필터에 포함하고, `marketOrderStatus`가 `PURCHASE_DECIDED`인 주문은 `구매확정` 필터에도 포함한다.
- 전체주문은 `처리보류` 필터를 제공하고, 해당 행에 `처리보류`와 `마켓 취소요청` 배지를 표시한다. `ON_HOLD` 행에는 실행 액션을 제공하지 않는다.
- 단계별 도구 영역에서 처리 액션 버튼은 왼쪽에, 판매처·상태·송장·클레임 유형 필터는 오른쪽에 정렬한다.
- 자동 배송중 처리 토글은 오른쪽 필터/설정 그룹에 배치한다.

## 4. 주문 목록 컬럼

주문수집 목록의 기본 컬럼은 다음 순서로 고정한다.

1. 선택
2. 진행상태
3. 처리하기
4. 주문일시
5. 상품정보
6. 택배정보
7. 배송정보
8. 판매처

목록에서 숨긴 데이터도 mock data와 타입에는 유지한다.
필요 시 검색, 계산, 상세 펼침, 추후 컬럼 재노출에 사용할 수 있다.

### 4-1. 상품정보

- 썸네일, 상품명, 옵션명, 수량, 마켓 주문번호를 함께 표시한다.
- 마켓 주문번호는 `마켓 주문번호 : 주문번호` 형식의 텍스트로 표시한다.
- 마켓 주문번호 링크와 주문상세 모달은 제공하지 않는다.

### 4-2. 택배정보

- 발송대기에서는 구매 완료 시 저장된 택배사와 송장번호를 확인한다.
- 송장번호만 입력하고 `배송중 처리`를 누르지 않으면 상태는 발송대기로 유지된다.
- 배송중/배송완료에서는 택배사와 송장번호를 조회 전용으로 표시한다.
- 배송중에서는 변경된 송장번호 항목을 표시하지 않는다.
- 배송중 송장 변경 전송 버튼은 현재 MVP에서 제공하지 않는다.

### 4-3. 배송정보

- 수령인 이름, 연락처, 주소, 개인통관부호를 표시한다.
- 개인통관부호는 `통관부호 일치` 또는 `통관부호 불일치`로 표시한다.
- 개인통관부호가 없거나 형식이 맞지 않으면 불일치로 본다.
- `수정` 버튼으로 배송정보와 개인통관부호를 수정할 수 있다.

### 4-4. 상태

- 소싱 전이면 `소싱필요` 배지를 표시한다.
- 신규주문에서 소싱하기를 통해 상품준비로 이동한 주문은 `소싱완료` 배지를 표시한다.
- 소싱라이프 결제를 완료하면 `결제완료`, 이후 진행 단계에 따라 `중국배송중`, `통관 중`, `국내 배송중`, `배송완료` 배지를 표시한다.
- 배송완료 주문에서 네이버 API의 마켓 상태가 `PURCHASE_DECIDED`이면 진행상태 컬럼에 날짜 없이 `구매확정` 배지만 표시한다. 판매자가 구매확정을 실행하는 버튼은 제공하지 않는다.
- 진행상태가 `결제완료`일 때는 행 상세의 `처리하기` 섹션에서 `결제완료 보기`로 주문관리 모달을 열며 새 탭으로 이동하지 않는다. 발송대기 목록에는 `배송중 처리`만 표시하고 중국배송·통관·국내배송에는 조회 모달을 제공하지 않는다.
- 처리 버튼은 이 컬럼에 넣지 않고 상태/결과 표시만 한다.
- 진행상태 컬럼은 판매자/소싱라이프 관점의 실제 소싱 진행 단계를 기본 배지로 표시하고, 마켓 보조 상태는 `마켓 취소요청`, `구매확정`만 표시한다. `마켓 배송중`, `마켓 배송완료`는 배지로 표시하지 않는다.
- `처리하기` 컬럼에는 각 단계에서 자주 사용하는 실행 버튼만 표시한다. 저빈도 액션과 보조 조회는 행 상세의 `처리하기` 섹션에 모으며 배송 진행 배지와 중국배송·통관·국내배송 보기 버튼은 표시하지 않는다.
- 발송대기 목록 처리하기에는 `배송중 처리`만 표시하고, 행 상세 처리하기에는 `배송중 처리 → 결제완료 보기 → 주문취소` 순으로 표시한다.
- 마켓에는 국내 택배번호를 등록해 `배송중`으로 보냈더라도, 실제 소싱 단계는 `소싱완료`, `결제완료`, `중국배송중`일 수 있다.

## 5. 행 확장 상세

주문 행을 클릭하면 상세 영역이 아래로 펼쳐진다.
상세는 목록에 없는 주문 관련 정보를 확인하기 위한 보조 영역이다.

상세 섹션 순서는 다음과 같다.

1. 주문상품
2. 구매자
3. 배송정보
4. 택배정보
5. 처리하기
6. 소싱상품

상세의 구매자는 이름과 연락처만 표시한다.
상세의 배송정보는 수취인 배송정보를 표시하며 수정할 수 있다.
상세의 택배정보는 `CJ대한통운 512606170031`처럼 한 줄로 표시한다.
상세 하단은 `처리하기`와 `소싱상품`을 1:2 비율로 배치한다. 처리하기는 현재 단계에서 허용된 실행·조회 버튼을 모아 표시하고, 소싱상품에는 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호만 표시한다.
소싱금액은 소싱라이프 결제금액을 의미한다.

## 6. 상태별 액션

### 6-1. 신규주문

행 액션:

- `주문확인`: 해당 주문을 상품준비로 이동한다.
- `소싱하기`: 신규주문에서는 소싱 후보와 옵션을 저장하고 주문확인까지 함께 처리해 상품준비로 이동한다.
- `주문취소`: 확인 모달 후 판매자 직접 취소로 처리한다.

상단 액션:

- `주문확인`: 체크된 신규주문만 일괄 주문확인한다.
- `주문취소`: 체크된 신규주문을 확인 모달 후 일괄 취소한다.
- 체크된 주문이 없으면 일괄 버튼은 비활성화한다.
- 주문 탭, 검색어, 기간, 마켓/스토어 필터, 주문 데이터가 변경되면 기존 체크 선택은 초기화한다.

### 6-2. 상품준비

행 액션:

- `소싱하기`: 추천 소싱 상품, 옵션, 수량과 저장된 배대지 수령 프로필을 선택하고 구매대행 신청 후 `결제대기`로 전환한다.
- 개인통관부호가 불일치하면 `소싱하기` 클릭 시 통관부호 확인 안내 모달을 표시한다. 불일치 상태는 배송정보 컬럼에서 확인하며, 통관부호 형식이 `P` + 숫자 12자리로 일치한 주문만 소싱라이프 결제를 진행할 수 있다.
- 더미 주문도 같은 최종 결과 규칙을 적용한다. 결제대기 주문은 유효한 통관부호·소싱상품·배대지·신청시각을 필수로 가지며 결제정보·주문번호·국내송장은 가지지 않는다. 결제완료 클릭 시 외부 배대지 사이트 열기·주문서 자동입력·접수를 생략하고, 접수 성공 결과를 대신하는 더미 국내송장을 생성한다.
- 통관부호 불일치 더미는 신규주문 또는 결제 전 상품준비에만 두고 결제대기·발송대기·배송중·배송완료에는 배치하지 않는다.
- `국내송장 등록`: 소싱라이프에서 결제하지 않고 직접 구매한 주문의 택배사와 국내송장번호를 필수 저장한다. 구매경로는 `외부구매`로 저장하고 자동 배송중 처리 설정에 따라 발송대기 또는 배송중으로 이동한다.
- `주문취소`: 확인 모달 후 판매자 직접 취소로 처리한다.

직접구매 국내송장 등록 모달:

- 상단에 상품명, 옵션, 수량, 마켓주문번호를 표시한다.
- 택배사와 국내송장번호 입력은 한 줄로 제공하며 모두 필수값이다.
- `국내송장 등록`: 국내송장번호가 입력된 경우에만 활성화한다.
- 송장번호가 없으면 외부 구매 완료와 상태 변경을 실행하지 않고 입력 오류를 안내한다.
- 직접전달 처리 완료 주문도 동일하게 검증한다. `marketDeliveryMethod: DIRECT_DELIVERY`여도 국내송장 없이 `EXTERNAL_PURCHASE` 완료 또는 내부 `SHIPPING` 전환을 허용하지 않는다.

상품준비 상단 옵션:

- `자동 배송중 처리` 토글을 제공한다.
- OFF이면 소싱라이프 또는 외부 구매 완료 후 국내송장이 있어도 발송대기로 이동한다.
- ON이면 소싱라이프 또는 외부 구매가 완료된 일반 택배 주문의 마켓 발송 API를 자동 호출한다. API 성공 후 `marketOrderStatus: DELIVERING`, `marketDeliveryMethod: DELIVERY`, 내부 `status: SHIPPING`을 함께 저장한다.
- 마켓 발송 API 실패 시 내부 상태를 `SHIPPING`으로 변경하지 않고 송장이 있는 `READY_TO_SHIP`에 유지한다.
- 실서비스 결제완료 후 선택 배송대행지 사이트를 열고 주문서를 자동입력해 접수한다. `접수대기`와 `접수신청`은 동일 단계이며 연결 대상은 접수 응답에서 실제 국내송장을 즉시 발급하는 배송대행지로 제한한다.
- 접수 응답에 송장이 없으면 결제 성공은 보존하되 상태를 발송대기·배송중으로 변경하지 않고 연동 오류로 처리한다.
- 직접전달을 먼저 처리한 주문도 송장 없는 소싱라이프 구매 완료를 허용하지 않는다. 구매 완료 저장과 내부 `READY_TO_SHIP`·`SHIPPING` 전환을 모두 실행하지 않는다.

### 6-3. 발송대기

상단 액션:

- 구매 완료 주문은 국내송장을 필수로 보유하므로 송장 유무 필터는 제공하지 않는다.
- `배송중 처리`: 별도 방식 선택 모달 없이 저장된 국내송장을 즉시 마켓 API에 전송한다. 송장번호가 있는 주문만 배송중으로 이동한다.
- `자동 배송중 처리`: 구매 완료와 송장 확보 직후 자동으로 마켓 배송중 처리를 시도하는 토글이다.
- `마켓 직접전달`: 상품준비 상세의 별도 액션으로만 제공한다. 소싱라이프의 실제 국내송장은 유지한 채 마켓에는 직접전달 방식으로 발송처리한다.

행 액션:

- 목록에는 `배송중 처리`만 표시한다. 자세히 보기의 처리하기에는 `배송중 처리`, `결제완료 보기`, `주문취소`를 모두 표시한다.
- `배송중 처리`: 클릭 즉시 해당 주문의 저장된 국내송장을 마켓에 전송한다. 방식 선택 모달은 제공하지 않는다.
- 국내송장이 없거나 결제가 완료되지 않은 주문은 실행을 차단하고 오류를 안내한다.
- 상품준비에서는 네이버·쿠팡 주문에 한해 예외 액션 `마켓 직접전달`을 제공한다. 사전 발송방법 선택은 제공하지 않는다.
- `주문취소`: 자세히 보기의 처리하기에서 아래에 배치하되 마켓 직접전달 주문에는 표시하지 않는다.

처리 대상 기준:

- 발송대기에서 주문이 체크되어 있으면 체크된 주문을 우선 대상으로 한다.
- 체크된 주문이 없으면 현재 필터로 보이는 발송대기 주문을 대상으로 한다.
- 일괄 `배송중 처리`는 대상 중 송장번호가 있고 직접전달로 이미 처리되지 않은 주문만 처리한다.
- 조건에 맞지 않는 주문이 선택되어 있어도 해당 액션 대상에서 제외한다.

마켓 직접전달 기준:

| 마켓 | API 처리 | 입력 기준 | 내부 표시 |
|---|---|---|---|
| 네이버 | 발송 처리 API에 `deliveryMethod: DIRECT_DELIVERY` 전송 | 소싱라이프의 실제 국내송장은 내부 택배정보로 유지하며 마켓에는 전송하지 않음 | 마켓 상태 `배송중`, 내부 작업 단계 유지 |
| 쿠팡 | 송장업로드 API에 `deliveryCompanyCode: DIRECT` 전송 | 실제 국내송장은 내부 택배정보로 유지하고, 쿠팡 API에는 시스템이 생성한 임의의 숫자 식별값을 전송 | 마켓 상태 `배송중`, 내부 작업 단계 유지 |

- 마켓 발송방법은 실제 국내 물류 방식이 아니라 API 전송 시점의 마켓 발송처리 방식이다. 소싱라이프에서 수집한 실제 국내송장은 택배정보에 계속 저장·표시한다.
- 쿠팡 `DIRECT`는 마켓 배송추적과 자동 배송완료 처리를 지원하지 않는다. 실제 국내 배송 진행은 소싱라이프 송장으로 내부 확인한다.
- 상품준비에서 마켓 직접전달 성공 시 주문은 상품준비에 남는다. 이후 소싱라이프 구매가 완료되면 필수 국내송장을 함께 저장하고 내부 배송중으로 이동한다.
- 구매 방식은 `소싱라이프 구매` 또는 `외부 구매`만 허용한다. `구매 안 함` 상태·액션·배지는 생성하지 않는다.
- 직접전달만 완료되고 구매가 완료되지 않은 주문은 `PREPARING`, 국내송장 없음으로 유지한다. 구매 완료 없이 국내송장만 저장하는 조합은 허용하지 않는다.
- 소싱라이프 또는 외부 구매와 마켓 직접전달이 모두 완료되면 필수 국내송장을 보유하므로 내부 `SHIPPING`으로 이동한다.
- 직접전달 주문의 소싱라이프 국내송장이 배송완료되면 내부 `status`는 `DELIVERED`로 변경한다. `marketOrderStatus: DELIVERING` 값은 유지하되 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않는다.

### 6-4. 배송중, 배송완료

- 기본 조회 전용이다.
- 배송중 송장 변경 전송 버튼은 제공하지 않는다.
- 변경된 송장번호 항목은 사용자 확인용으로도 표시하지 않는다.
- 직접전달 주문도 실제 국내 택배사와 송장번호를 택배정보에 조회 전용으로 표시한다.
- 직접전달 주문의 택배정보에는 실제 국내송장 아래에 `직접전달` 배지를 표시한다.

### 6-5. 취소/반품/교환

- `/orders?view=claims`에서 별도 화면으로 관리한다.
- 구매자가 네이버 또는 쿠팡에서 신청한 취소·반품·교환만 MVP 대상으로 한다. 판매자 직접 취소와 판매자 생성 클레임은 이 화면에서 실행하지 않는다.
- 기본 `MVP 데모`는 네이버·쿠팡의 정상·예외 8건을 표시하며, 모든 액션은 로컬 상태만 변경하고 마켓에 전송하지 않는다.
- `실데이터 조회`는 `/api/claims`에서 `requesterType=CUSTOMER` 조건으로 조회한다. provider 실행 어댑터와 계정별 UAT를 통과한 API 액션만 활성화한다.
- 검색, 유형, 공통 상태, 처리기한 필터를 제공한다.
- 상세에는 현재 단계, 다음 작업, 주의사항, 신청 사유, 대상 수량, 주문·배송 상태, 회수 배송, 교환 재배송, 이벤트 이력을 표시한다.
- 네이버 취소는 공식 API가 있는 `취소 승인`만 제공하고 `취소 거부` 버튼은 만들지 않는다.
- 네이버 반품은 승인·보류·보류해제·거부, 교환은 수거완료·재배송·보류·보류해제·거부 API 범위만 제공한다.
- 쿠팡 취소는 출고중지 완료·이미출고, 반품은 입고확인·승인, 교환은 입고확인·거부·재배송 송장 API 범위만 제공한다.
- 쿠팡 반품은 `RETURNS_UNCHECKED`에서 `반품 입고 확인`만, `VENDOR_WAREHOUSE_CONFIRM`에서 `반품 승인`만 노출한다. 빠른환불 또는 쿠팡 자동 승인으로 이미 완료된 건에는 두 버튼을 노출하지 않는다.
- 단순 회수 상태 확인, 분쟁, 배송비 예외 등 조회 또는 판매자센터 수동 처리만 가능한 항목은 실행 버튼으로 만들지 않는다.
- 교환 재배송 작업은 택배사와 새 송장번호가 모두 입력되어야 활성화한다.
- 목록 행에는 유형별 단일 진입 버튼 `취소처리`, `반품처리`, `교환처리`만 제공한다. 실제 승인·보류·입고·재배송 버튼은 목록에 표시하지 않고 처리 모달 내부에서 계산한다.
- 처리 모달은 구매자 요청 사유, 요청수량, 주문 당시 상태, 현재 소싱·배송 진행상황, 회수·재배송 정보와 상태 이력을 보여준 후 `marketCode + claimType + marketStatusRaw` 기준으로 공식 API 액션을 노출한다.
- 실데이터 상세도 마켓·유형·상태에 맞는 공식 API 대상 버튼만 표시한다. 실행 어댑터 미연결 상태에서는 API 미연결 오류를 표시하고 판매자센터 이동으로 대체하지 않는다.
- provider 응답과 후속 재수집으로 결과가 확인되기 전에는 앱 내부 상태를 성공으로 선반영하지 않는다.

## 7. 소싱라이프 소싱/결제

### 7-1. 신규주문 소싱하기

- 신규주문에서 `소싱하기`를 누르면 소싱 후보와 옵션을 선택한다.
- 저장 시 소싱 매칭 정보를 localStorage에 저장하고 주문확인을 함께 처리한다.
- 처리 후 주문은 상품준비로 이동한다.
- 모달 오른쪽 하단에는 `주문확인` 바로 아래 `주문취소`를 제공한다. 주문취소를 누르면 매칭을 저장하지 않고 소싱 모달을 닫은 뒤 기존 판매자 주문취소 확인 모달로 전환한다.
- 취소 사유, 상세 사유, 취소 수량 검증과 실주문·데모 주문 처리 결과는 기존 개별 주문취소 규칙을 그대로 사용한다.

### 7-2. 상품준비 소싱하기

- 상품준비에서 `소싱하기`를 누르면 소싱 후보 선택 모달을 연다.
- 실주문 `매핑 관리`의 운영자 입력은 항상 `MANUAL_UNVERIFIED` revision으로 저장하고 `소싱 검증대기`로 표시한다. 이 상태에서는 구매신청·결제·결제 성공 추정을 모두 차단한다.
- 활성 매핑 조회와 revision 충돌 검사를 사용하므로 동일 주문상품을 두 운영자가 수정할 때 마지막 화면 값으로 조용히 덮어쓰지 않는다.
- 후보 카드는 한국어 상품명 값, 중국어 상품명 값, 판매처, 상품원가를 표시한다.
- 후보 카드에는 `한국어 상품명`, `중국어 상품명` 타이틀 라벨을 표시하지 않는다.
- 상품원가는 원화와 위안화를 함께 표시한다.
- AI 매칭률, 별점, 구매횟수, 배송비, 예상마진은 현재 MVP 후보 카드에서 사용하지 않는다.
- 옵션 드롭다운은 한국어 옵션명 아래 중국어 옵션명을 표시한다.
- 옵션 품절이면 결제 버튼을 비활성화한다.
- 수량은 모달 안에서 변경할 수 있다.
- 추천 소싱 상품 영역에는 키워드 또는 타오바오/소싱라이프 상품 URL 입력을 제공한다.
- 추천 상품 카드 상단의 기본 가격과 선택 옵션 요약의 위안화 개당 가격은 표시하지 않는다. 선택 옵션은 `옵션가격(재고)` 라벨 아래 원화 금액과 재고 수량으로 요약하고 모든 추천 상품 카드의 높이를 동일하게 유지한다.
- 추천 후보는 2열 카드로 표시하고 각 카드에 옵션 드롭다운, 수량 증감, 선택 옵션 합계 금액과 재고를 노출한다. 옵션 또는 수량 변경 시 해당 상품을 동시에 선택하고 카드별 선택값을 유지하며, 오른쪽 선택 상품 영역과 비용·마진 계산을 즉시 갱신한다. 재고는 오른쪽 영역에 중복 표시하지 않는다.
- 오른쪽 옵션 선택 요약에는 선택 후보의 썸네일을 표시한다.
- 소싱 비용 구성은 `상품 금액`, `소싱처 이용료`, `통화 환전 수수료`, `소싱 총비용`으로 나누어 표시한다. MVP 더미 계산은 소싱처 이용료 3%, 환전 수수료 2.5%를 원 단위 절사하고 예상 배대지 운임 4,750원을 적용한다.
- 마진 분석은 결제 금액을 시작값으로 표시하고 판매 수수료를 독립 차감 항목으로 노출한다. 예상 순이익은 `paymentPrice - platformFee - 상품 금액 - 소싱처 이용료 - 환전 수수료 - 예상 배대지 운임`으로 계산하며, 마진율은 `예상 순이익 ÷ paymentPrice × 100`으로 계산한다.
- `platformFee`가 없고 정산예정금액이 있으면 `paymentPrice - expectedSettlement`을 주문 판매수수료로 사용한다.
- 수수료율은 주문 결제금액과 수집된 판매수수료 금액으로 역산해 표시하며, 마켓별 고정 수수료율을 임의로 적용하지 않는다.
- 기본 이미지 매칭 후보는 20개를 캐싱해 표시한다.
- 키워드를 입력해 찾기 실행 시 새 검색 후보 20개를 기존 후보 목록 상단에 추가한다.
- 타오바오/소싱라이프 URL을 입력해 찾기 실행 시 해당 URL 상품 1개를 기존 후보 목록 상단에 추가한다.
- 상품·옵션 선택 후 `배대지 선택`을 누르면 소싱라이프에 저장된 수령 프로필 목록을 표시한다.
- 배대지 선택 화면의 마진 분석은 왼쪽 상품정보 아래에 표시하고 오른쪽 결제 요약에는 소싱 총비용만 표시한다. 최종 결제 화면에서는 비용 구성과 마진 분석을 기존처럼 함께 표시한다.
- `구매대행 신청`은 매칭, 수량, 수령 프로필과 신청시각을 저장하고 `PAYMENT_WAITING`으로 전환하지만 결제·주문번호·송장을 생성하지 않는다.
- 결제대기 화면에는 신청 요약과 채팅을 표시한다. 목록에서는 `소싱하기` 대신 `결제하기`를 표시한다.
- `결제하기`를 다시 누른 뒤에만 약관 동의와 결제 정보 입력 화면으로 이동하며, 결제 완료 시 기존 구매완료 흐름을 실행한다.
- 결제 완료 시 선택 배송대행지를 자동입력 완료로 기록하고 모달을 닫지 않은 채 결제완료 조회 화면으로 전환한다. 결제완료 화면은 실제 결제금액·결제일시·소싱라이프 주문번호·배송대행지 자동입력 결과와 채팅을 표시하고 재결제 기능을 제공하지 않는다.
- `결제하기`는 `PREPARING + PAYMENT_WAITING`에서만 허용한다. `READY_TO_SHIP`, `SHIPPING`, `DELIVERED`는 소싱라이프 결제완료 또는 외부구매 완료가 선행조건이며 미결제 조합에서는 `결제상태 불일치`만 표시한다.

### 7-3. 소싱상태

| 코드 | 의미 |
|---|---|
| `NOT_LINKED` | 소싱라이프와 연결 전 |
| `MATCHING` | 소싱 진행 중 |
| `MATCH_SAVED` | 소싱완료 |
| `PAYMENT_READY` | 결제 가능 |
| `PAID` | 소싱라이프 결제 완료 |
| `INVOICE_RECEIVED` | 국내송장 수신 |
| `HOLD` | 소싱 처리보류 |

현재 주문 목록의 진행상태 컬럼은 `소싱필요`, `소싱 검증대기`, `소싱완료`, `결제대기`, `결제완료`, `중국배송중`, `통관 중`, `국내 배송중`, `배송완료`, `구매확정` 상태값을 표시한다.
결제대기에서는 목록에 `결제하기`, 결제완료에서는 자세히 보기의 처리하기에 `결제완료 보기`를 제공한다. 결제완료 모달에서는 결제정보와 채팅을 조회할 수 있지만 다시 결제할 수 없다. `중국배송 보기`, `통관 보기`, `국내배송 보기`는 제공하지 않는다.

소싱 단계는 마켓 주문상태(`NEW`, `PREPARING`, `READY_TO_SHIP`, `SHIPPING`, `DELIVERED`)에서 역산하지 않는다.
마켓 `SHIPPING`은 국내 택배번호를 마켓에 전송한 고객-facing 상태일 수 있으며, 판매자 입장의 실제 물류는 중국 내 배송 전/중일 수 있다.
`결제완료`는 구매대행 결제/주문 생성 완료를 의미하고, 중국 내 트래킹번호 또는 중국 판매자 발송 이벤트가 확인되면 `중국배송중`으로 본다.
`PAYMENT_READY`는 목록에서 `결제대기`, `PAID`와 `INVOICE_RECEIVED`는 `결제완료`로 투영한다. 국내송장 수신만으로 중국 판매자 발송을 추정하지 않는다.
`EXTERNAL_PURCHASE`는 내부 구매경로로 유지하고 소싱라이프 결제상태를 `PAID`로 만들지 않는다. 목록 진행상태와 필터에서는 `결제완료`로 투영하며, 자세히 보기의 소싱상품 영역에서 `외부구매` 배지와 외부 구매처 결제완료 안내를 표시한다.
판매자 취소·구매자 클레임의 보류는 주문/클레임 상태로 관리하며 기존 소싱 상태를 보존한다. 소싱 상태 `HOLD`는 소싱라이프 연동 자체가 중단된 경우에만 사용한다.
수입 통관 접수 이후 국내 택배사 인계 전까지는 `통관 중`으로 본다.
국내 택배사 실제 인계 이후에만 `국내 배송중`으로 본다.
마켓 또는 내부 주문이 배송완료로 확정된 주문은 소싱 단계도 `배송완료`여야 하며, `중국배송중`, `통관 중`, `국내 배송중`으로 표시하지 않는다.

## 8. 실원장과 demo localStorage 데이터 흐름

`/api/orders`, `/api/claims`, `/api/market-accounts`와 PostgreSQL 원장이 실데이터 경로다. 아래 localStorage 키는 demo 주문의 임시 화면 상태이며 실마켓 처리 증거가 아니다.

사용 중인 localStorage 키:

| 키 | 용도 |
|---|---|
| `jumunpangpang.syncedInvoices` | 국내송장 저장 및 배송중 처리 결과 |
| `jumunpangpang.sourcingMatches` | 소싱 후보/옵션 매칭 저장 |
| `jumunpangpang.sourcingPayments` | 소싱라이프 결제 완료 가정 결과 |

좌측 하단 `데이터 초기화` 버튼은 같은 키만 삭제해 데모 데이터를 초기 상태로 되돌린다. PostgreSQL 실주문·클레임·명령·감사 원장은 삭제하지 않는다.
주문 화면에서 탭, 필터, 검색어 또는 데이터가 바뀌면 체크 선택과 행 확장 상태는 현재 화면 기준으로 다시 초기화된다.

React Query는 주문·클레임·마켓계정 실API cursor/query와 재시도 상태를 관리한다.
Zustand는 현재 대시보드 store 중심으로 사용된다.
