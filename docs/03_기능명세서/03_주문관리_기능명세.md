# 주문관리 기능명세

## 1. 적용 기준

현재 구현은 PostgreSQL 실원장/API와 명시적 demo mode를 분리한다. 주문·클레임 실데이터는 서버 API를 기준으로 하고 localStorage는 demo 주문의 소싱/결제/송장 UI 검증에만 사용한다.
문서와 구현이 다를 경우 `docs/00_문서맵/02_실서비스_완성목표_및_로드맵.md`와 실제 서버 계약을 우선한다.
커머스라이프는 소싱라이프와 분리된 독립 주문관리 서비스로 제공한다.
주문수집 대상은 마켓에서 수집된 주문이며, 소싱라이프에서 직접 생성하거나 주문한 내역은 주문수집 목록에 포함하지 않는다.
소싱라이프 연동으로 수신한 구매, 검수, 입고, 물류 상태와 결과는 커머스라이프 내부에서 조회한다. 소싱라이프 주문내역으로 이동하는 링크나 버튼은 제공하지 않는다.

이 문서는 다음 화면을 기준으로 한다.

| 화면 | 경로 | 역할 |
|---|---|---|
| 주문수집 | `/orders`, `/orders?view=new` | 신규주문 기본 진입 |
| 전체주문 | `/orders?view=all` | 처리보류를 포함한 일반 주문 전체 조회 |
| 상품준비 | `/orders?view=preparing` | 소싱라이프 소싱/결제 또는 외부구매 배송처리 |
| 발송대기 | `/orders?view=waiting` | 국내송장 확인, 마켓 배송중 처리 |
| 배송중 | `/orders?view=shipping` | 배송중 주문 조회 |
| 배송완료 | `/orders?view=delivered` | 배송완료 주문 조회 |
| 취소/반품/교환 | `/orders?view=claims` | 클레임 주문 별도 조회 |
| 마켓연동 | `/me/markets` | 마켓 계정 추가, 수정, 삭제 |

`CANCELED`는 판매자가 직접 취소 처리한 종료 상태이며, 구매자 요청 클레임인 `CLAIM`과 분리한다.

## 2. 주문 상태

| 코드 | 화면 라벨 | 정의 |
|---|---|---|
| `NEW` | 신규주문 | 마켓 결제완료 주문이 수집되었고 판매자가 주문확인 전인 상태 |
| `PREPARING` | 상품준비 | 주문확인 후 소싱라이프 소싱/결제 또는 외부 구매가 필요한 상태 |
| `READY_TO_SHIP` | 발송대기 | 구매와 국내송장 저장 완료 후 마켓 배송중 처리를 기다리는 상태 |
| `SHIPPING` | 배송중 | 국내송장을 기준으로 배송중 처리된 상태 |
| `DELIVERED` | 배송완료 | 배송완료 또는 구매확정 상태 |
| `ON_HOLD` | 처리보류 | 판매자 취소 요청 접수 후 provider 최종 결과 대기. 마켓 상태 `CANCEL_REQUESTED`와 함께 표시 |
| `CANCELED` | 판매자취소 | 판매자가 직접 주문취소 처리한 종료 상태 |
| `CLAIM` | 취소/반품/교환 | 구매자 요청 또는 마켓에서 수집된 취소, 반품, 교환 클레임 |

## 3. 상단 검색/필터

- 기간 필터: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 기본 기간은 `7일`이다.
- 직접 입력은 시작일과 종료일을 선택하는 작은 팝오버로 처리한다.
- 검색어는 상품명, 마켓 주문번호, 상품주문번호, 내부 주문 ID, 구매자명, 수령인명, 연락처, 배송메시지, 개인통관부호를 대상으로 부분 일치 검색한다.
- 연락처는 하이픈 포함/미포함 입력을 모두 검색한다.
- 마켓/스토어 필터는 하나의 팝오버에서 제공한다.
- 마켓과 스토어는 중복 선택할 수 있다.
- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하며, 스토어가 속한 마켓은 자동 포함된 것처럼 본다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.
- `주문수집` 버튼은 우측에 고정하며, 활성·연결 상태이고 주문수집 어댑터가 활성화된 전체 계정과 스토어를 대상으로 한다. 현재 실서비스 어댑터 범위는 스마트스토어이며 쿠팡·11번가·ESM은 worker/UAT 완료 전 대상에서 제외한다.
- 수동 수집은 계정별 `sync_run`을 접수하고 기존 실행 중 작업은 재사용한다. 화면은 실행 완료까지 상태를 조회해 신규·갱신·오류 건수를 표시하고, 완료 후 주문 목록을 자동으로 다시 조회한다.
- 실행이 60초 안에 끝나지 않으면 화면 대기를 종료하되 작업은 백그라운드에서 계속 진행한다. `SUCCEEDED`, `PARTIAL`, `FAILED/CANCELED/DEAD`를 구분해 안내하며 접수 성공을 수집 성공으로 표시하지 않는다.
- 모든 일반 주문 단계와 전체주문에 `판매처`, `상태` 필터를 제공한다. 판매처는 현재 단계의 옵션을 마켓 네모 약자 아이콘(`N`, `C`, `11`, `G`, `A`)과 스토어명 형식으로 표시하고, 상태는 현재 데이터 건수와 무관하게 단계별 조회 가능 상태를 모두 표시해 주문을 좁힌다.
- 상태 필터의 고정 범위는 신규주문 `소싱필요`, 상품준비 `소싱필요·소싱완료·결제대기`, 발송대기/배송중 `결제완료·중국배송중·통관 중·국내 배송중`, 배송완료 `배송완료·구매확정`이다. 수동 검증 전은 `소싱필요`, 외부 구매 완료는 `결제완료`로 조회한다.
- 배송완료의 `구매확정` 배지는 추가 상태값이다. 배송완료 주문은 모두 `배송완료` 필터에 포함하고, `marketOrderStatus`가 `PURCHASE_DECIDED`인 주문은 `구매확정` 필터에도 포함한다.
- 전체주문은 `ON_HOLD` 주문을 포함하지만 진행상태 필터에 `처리보류`를 제공하지 않고 `마켓 취소요청` 배지도 표시하지 않는다. 차단 상태는 처리 결과와 상세 화면에서 확인하며 `ON_HOLD` 행에는 실행 액션을 제공하지 않는다.
- 단계별 도구 영역에서 처리 액션 버튼은 왼쪽에, 판매처·상태·송장·클레임 유형 필터는 오른쪽에 정렬한다.
- 자동 배송중 처리 토글은 오른쪽 필터/설정 그룹에 배치한다.

## 4. 주문 목록 컬럼

주문수집 목록의 기본 컬럼은 다음 순서로 고정한다.

1. 선택
2. 처리하기
3. 주문일시
4. 진행상태
5. 상품정보
6. 택배정보
7. 배송정보

목록에서 숨긴 데이터도 mock data와 타입에는 유지한다.
필요 시 검색, 계산, 상세 펼침, 추후 컬럼 재노출에 사용할 수 있다.
주문일시 아래에는 마켓 약자 아이콘 `N`, `C`, `G`, `11`, `A`와 스토어명을 표시하며 별도 판매처 컬럼은 두지 않는다.

### 4-1. 상품정보

- 썸네일, 상품명, 옵션명, 수량, 마켓 주문번호를 함께 표시한다.
- 마켓 주문번호는 `마켓 주문번호 : 주문번호` 형식의 텍스트로 표시한다.
- 마켓 주문번호 링크와 주문상세 모달은 제공하지 않는다.

### 4-2. 택배정보

- 목록과 상세에서 `국내 송장번호`, 직접전달 표시, `중국 송장번호` 순으로 표시한다.
- 국내·중국 송장번호가 있으면 택배사와 함께 확인하며, 아직 수신되지 않은 번호는 `-`로 표시한다.
- 직접전달을 선택한 주문에만 `직접전달`을 표시하고 일반 주문에는 해당 표시를 하지 않는다.
- 발송대기에서는 구매 완료 시 저장된 국내 택배사와 송장번호를 확인한다.
- 송장번호만 입력하고 `배송중 처리`를 실행하지 않으면 상태는 발송대기로 유지된다.
- 배송중 상세에서는 `배송중 처리` 시작 전 택배사와 운송장번호를 등록·수정할 수 있다. 처리 명령이 시작되면 마켓 제출 완료 전이라도 수정할 수 없으며 목록과 처리 시작 후에는 조회 전용으로 표시한다.
- 마켓 제출 후 운송장 정정 전송은 현재 MVP에서 제공하지 않는다.

### 4-3. 배송정보

- 수령인 이름, 연락처, 주소, 개인통관부호를 표시한다.
- 개인통관부호는 `통관부호 일치` 또는 `통관부호 불일치`로 표시한다.
- 개인통관부호가 없거나 형식이 맞지 않으면 불일치로 본다.
- `수정` 버튼으로 배송정보와 개인통관부호를 수정할 수 있다.

### 4-4. 상태

- 소싱 전이면 `소싱필요` 배지를 표시한다.
- 신규주문에서 매칭하기를 통해 상품준비로 이동한 주문은 `소싱완료` 배지를 표시한다.
- 소싱라이프 결제를 완료하면 `결제완료`, 이후 진행 단계에 따라 `중국배송중`, `통관 중`, `국내 배송중`, `배송완료` 배지를 표시한다.
- 배송완료 주문에서 네이버 API의 마켓 상태가 `PURCHASE_DECIDED`이면 진행상태 컬럼에 날짜 없이 `구매확정` 배지만 표시한다. 판매자가 구매확정을 실행하는 버튼은 제공하지 않는다.
- 소싱 결제완료부터 배송완료까지 행 자세히 보기의 `소싱상품관리`로 주문관리 모달을 열며 새 탭으로 이동하지 않는다. 같은 상세 `처리하기`의 `배송추적`에서 결제완료부터 중국배송·통관·국내배송·배송완료와 후속 물류 이력을 누적 조회한다.
- 처리 버튼은 이 컬럼에 넣지 않고 상태/결과 표시만 한다.
- 진행상태 컬럼은 대표 배지 하나만 표시한다. 소싱 환불·반품이 있으면 이를 우선하고, 그 외에는 구매확정 또는 기본 소싱 진행상태를 선택한다. `마켓 취소요청`, `처리보류`, `마켓 배송중`, `마켓 배송완료`는 진행상태로 사용하지 않는다.
- `처리하기` 컬럼에는 현재 단계에서 가능한 실행·조회 버튼을 표시하고 상세에는 운송장 수정 같은 저빈도 편집 기능을 추가한다. 배송 진행 배지는 진행상태 컬럼에만 표시한다.
- 소싱라이프 결제완료부터 배송완료까지 `소싱상품관리`, `배송추적`은 행 자세히 보기의 `처리하기`에만 표시한다.
- 마켓에는 국내 택배번호를 등록해 `배송중`으로 보냈더라도, 실제 소싱 단계는 `소싱완료`, `결제완료`, `중국배송중`일 수 있다.

## 5. 행 확장 상세

주문 행을 클릭하면 상세 영역이 아래로 펼쳐진다.
상세는 목록에 없는 주문 관련 정보를 확인하기 위한 보조 영역이다.

넓은 화면의 상세는 다음 세 영역으로 구성한다.

1. 왼쪽: 구매자 · 배송정보 → 택배정보
2. 가운데: 상품 비교 → 마진계산
3. 오른쪽: 처리하기

오른쪽 `처리하기`에는 현재 단계에서 허용된 실행·조회 버튼을 세로로 표시한다. 작은 화면에서는 상품 비교·마진계산, 구매자·배송정보·택배정보, 처리하기 순서로 한 줄씩 배치한다.

상세의 구매자는 이름과 연락처만 표시한다.
상세의 배송정보는 수취인 배송정보를 표시하며 수정할 수 있다.
상세의 택배정보는 국내 송장번호와 중국 송장번호를 각각 한 줄로 표시하고, 직접전달 주문에만 두 번호 사이에 `직접전달`을 표시한다.
상품 비교는 매칭된 소싱상품이 있을 때 주문상품 아래에 소싱상품을 세로로 배치한다. 매칭된 소싱상품이 없으면 소싱상품 섹션과 빈 상태 안내를 렌더링하지 않고 주문상품만 표시한다. 소싱상품에는 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호를 표시한다.
마진계산은 매칭된 소싱상품이 있을 때만 표시한다. 상품원가는 소싱라이프 실제 결제금액, 매칭 예상원가, 주문 예상원가 순으로 사용하며 금액이 없으면 계산 대기 안내를 표시한다. 계산 가능한 경우 `매출·정산 → 예상 소싱비용 → 예상 순이익·마진율` 순으로 세로 배치한다.
구매자와 수령 정보는 같은 카드 안에서 위에서 아래로 표시하고 택배정보는 그 아래 카드에 표시한다.
`처리하기`는 넓은 화면에서 오른쪽에 배치하고 현재 단계에서 허용된 실행·조회 버튼을 위에서 아래로 표시한다. 작은 화면에서는 모든 정보 다음에 배치하되 버튼의 세로 순서는 유지한다.
소싱금액은 소싱라이프 결제금액을 의미한다.

## 6. 상태별 액션

### 6-1. 신규주문

행 액션:

- `주문확인`: 해당 주문을 상품준비로 이동한다.
- `매칭하기`: 신규주문에서는 소싱 후보와 옵션을 저장하고 주문확인까지 함께 처리해 상품준비로 이동한다.
- `주문취소`: 확인 모달 후 판매자 직접 취소로 처리한다.

상단 액션:

- `주문확인`: 체크된 신규주문만 일괄 주문확인한다.
- `주문취소`: 체크된 신규주문을 확인 모달 후 일괄 취소한다.
- 체크된 주문이 없으면 일괄 버튼은 비활성화한다.
- 주문 탭, 검색어, 기간, 마켓/스토어 필터, 주문 데이터가 변경되면 기존 체크 선택은 초기화한다.

### 6-2. 상품준비

행 액션:

- `소싱하기`: 추천 소싱 상품, 옵션, 수량과 저장된 배대지 수령 프로필을 선택하고 구매대행 신청 후 `결제대기`로 전환한다.
- 개인통관부호가 불일치하면 `소싱하기`와 `결제하기`를 숨긴다. 왼쪽 구매자·배송정보 영역의 수정 기능은 유지하며, 통관부호 형식이 `P` + 숫자 12자리로 일치하면 소싱·결제 버튼을 다시 표시한다. `처리하기`에는 배송정보 수정 버튼을 중복 표시하지 않는다.
- 더미 주문도 같은 최종 결과 규칙을 적용한다. 결제대기 주문은 유효한 통관부호·소싱상품·배대지·신청시각을 필수로 가지며 결제정보·주문번호·국내송장은 가지지 않는다. 결제완료 클릭 시 외부 배대지 사이트 열기·주문서 자동입력·접수를 생략하고, 접수 성공 결과를 대신하는 더미 국내송장을 생성한다.
- 통관부호 불일치 더미는 신규주문 또는 결제 전 상품준비에만 두고 결제대기·발송대기·배송중·배송완료에는 배치하지 않는다.
- `외부구매 배송처리`: 소싱라이프를 사용하지 않고 직접 구매한 주문의 배송대행지 택배사와 국내송장번호를 필수 저장한다. 구매경로는 `외부구매`로 저장하고 자동 배송중 처리 설정에 따라 발송대기 또는 배송중으로 이동한다.
- `주문취소`: 확인 모달 후 판매자 직접 취소로 처리한다.

외부구매 배송처리 화면:

- 상단에 상품명, 옵션, 수량, 마켓주문번호를 표시한다.
- 택배사와 국내송장번호 입력은 한 줄로 제공하며 모두 필수값이다.
- `외부구매 배송처리`: 국내송장번호가 입력된 경우에만 활성화한다.
- 송장번호가 없으면 외부 구매 완료와 상태 변경을 실행하지 않고 입력 오류를 안내한다.
- 직접전달 처리 완료 주문도 동일하게 검증한다. `marketDeliveryMethod: DIRECT_DELIVERY`여도 국내송장 없이 `EXTERNAL_PURCHASE` 완료 또는 내부 `READY_TO_SHIP`·`SHIPPING` 전환을 허용하지 않는다.

상품준비 상단 옵션:

- `자동 배송중 처리` 토글을 제공한다.
- OFF이면 소싱라이프 결제완료 주문은 내부 `SHIPPING`에서 마켓 발송 대기로 관리하고, 외부 구매 주문은 `READY_TO_SHIP`으로 이동한다.
- ON이면 소싱라이프 또는 외부 구매가 완료된 일반 택배 주문의 마켓 발송 API를 자동 호출한다. API 성공 후 `marketOrderStatus: DELIVERING`, `marketDeliveryMethod: DELIVERY`를 저장한다. 소싱라이프 주문의 내부 상태는 결제완료 시점부터 이미 `SHIPPING`이다.
- 마켓 발송 API 실패 시 소싱라이프 주문은 내부 `SHIPPING`, 외부 구매 주문은 `READY_TO_SHIP`을 유지하고 송장과 실패 사유를 보존한다.
- 실서비스 결제완료 후 선택 배송대행지 사이트를 열고 주문서를 자동입력해 접수한다. `접수대기`와 `접수신청`은 동일 단계이며 연결 대상은 접수 응답에서 실제 국내송장을 즉시 발급하는 배송대행지로 제한한다.
- 접수 응답에 송장이 없으면 결제 성공은 보존하되 상태를 발송대기·배송중으로 변경하지 않고 연동 오류로 처리한다.
- 직접전달을 먼저 처리한 주문도 소싱라이프 결제 성공은 즉시 보존하고 내부 `SHIPPING`으로 전환한다. 송장이 없으면 마켓 송장 발송과 배송완료 판정만 차단하고 송장 수신 오류를 별도로 표시한다.

### 6-3. 발송대기

상단 액션:

- 구매 완료 주문은 국내송장을 필수로 보유하므로 송장 유무 필터는 제공하지 않는다.
- `배송중 처리`: 단일/일괄 공통 액션이다. 마켓 미발송 주문은 모달에서 송장 또는 지원 마켓의 직접전달을 선택한다.
- `자동 배송중 처리`: 구매 완료와 송장 확보 직후 자동으로 마켓 배송중 처리를 시도하는 토글이다.
- 백엔드는 `배송중 처리` 실행 시 마켓 상태를 먼저 조회한다. 이미 송장 또는 직접전달로 발송됐으면 실제 방식을 반영하고 마켓 재전송 없이 내부 상태만 변경한다.

행 액션:

- 소싱라이프 결제완료 주문은 배송중 목록과 상세에서 관리한다. 목록 `처리하기`는 비워 두며, 행 자세히 보기에서 조건부 `배송중 처리`, `소싱상품관리`, `배송추적`, 처리 시작 전 `운송장 수정`을 제공한다. 배송중 처리 명령을 접수하면 운송장 수정 버튼과 저장 요청을 즉시 차단한다. 배송완료 전 조건부 `반품·환불 신청`은 `소싱상품관리` 안에 표시한다.
- 마켓 발송 전 `배송중 처리`는 모달을 열어 송장 또는 지원 마켓의 직접전달을 선택한다. 실제 국내송장은 직접전달을 선택해도 내부 배송 추적용으로 보관한다.
- 스마트스토어·11번가는 마켓연동 추가·수정에서 배송중 처리 기본값을 `송장전송` 또는 `직접전달`로 설정한다. 쿠팡·G마켓·옥션은 `송장전송`으로 고정한다. 주문 확인창은 계정 기본값을 읽기 전용으로 표시하고 일괄 처리는 계정별 방식으로 자동 분리한다.
- 마켓 발송이 이미 완료된 주문은 모달을 생략하고 백엔드가 실제 발송 방식을 조회해 재전송 없이 내부 상태를 배송중으로 변경한다.
- 국내송장이 없거나 결제가 완료되지 않은 발송대기 주문은 `배송중 처리`를 숨긴다. 결제완료인데 송장만 없으면 상세 `택배정보 등록`, 미결제 비정상 조합이면 `결제상태 불일치`를 표시한다.
- 상품준비에서는 기본값이 `직접전달`인 스마트스토어·11번가 주문에 한해 동일한 `배송중 처리`를 제공한다. 기본값이 `송장전송`이면 구매 완료와 국내송장 확보 전에는 버튼을 노출하지 않는다.
- `주문취소`: 자세히 보기의 처리하기에서 아래에 배치하되 마켓 직접전달 주문에는 표시하지 않는다.

처리 대상 기준:

- 발송대기에서 주문이 체크되어 있으면 체크된 주문을 우선 대상으로 한다.
- 체크된 주문이 없으면 현재 필터로 보이는 발송대기 주문을 대상으로 한다.
- 일괄 `배송중 처리`는 단일 주문과 같은 백엔드 선조회 규칙을 사용한다. 미발송 대상에는 모달에서 고른 방식을 적용하고 이미 발송된 대상은 내부 상태만 반영한다.
- 조건에 맞지 않는 주문이 선택되어 있어도 해당 액션 대상에서 제외한다.

| 마켓 | API 처리 | 입력 기준 | 내부 표시 |
|---|---|---|---|
| 네이버 | 발송 처리 API에 `deliveryMethod: DIRECT_DELIVERY` 전송 | 소싱라이프의 실제 국내송장은 내부 택배정보로 유지하며 마켓에는 전송하지 않음 | 상품준비 선처리는 내부 단계 유지, 발송대기 처리는 내부 배송중 이동 |
| 쿠팡 | 송장업로드 API에 `deliveryCompanyCode: DIRECT` 전송 | 실제 국내송장은 내부 택배정보로 유지하고, 쿠팡 API에는 시스템이 생성한 임의의 숫자 식별값을 전송 | 상품준비 선처리는 내부 단계 유지, 발송대기 처리는 내부 배송중 이동 |

- 마켓 발송방법은 실제 국내 물류 방식이 아니라 API 전송 시점의 마켓 발송처리 방식이다. 소싱라이프에서 수집한 실제 국내송장은 택배정보에 계속 저장·표시한다.
- 프로토타입 데모 주문은 모든 마켓에서 송장/직접전달 두 방식을 시연할 수 있다. 실주문은 마켓별 직접전달 API와 UAT가 확인된 계정에만 직접전달을 활성화하며, 미검증 마켓은 송장 처리만 제공한다.
- 쿠팡 `DIRECT`는 마켓 배송추적과 자동 배송완료 처리를 지원하지 않는다. 실제 국내 배송 진행은 소싱라이프 송장으로 내부 확인한다.
- 상품준비에서 마켓 직접전달 성공 시 주문은 상품준비에 남는다. 이후 소싱라이프 구매가 완료되면 필수 국내송장을 함께 저장하고 내부 발송대기로 이동한다.
- 구매 방식은 `소싱라이프 구매` 또는 `외부 구매`만 허용한다. `구매 안 함` 상태·액션·배지는 생성하지 않는다.
- 직접전달만 완료되고 구매가 완료되지 않은 주문은 `PREPARING`, 국내송장 없음으로 유지한다. 구매 완료 없이 국내송장만 저장하는 조합은 허용하지 않는다.
- 상품준비에서 먼저 직접전달한 주문은 소싱라이프 결제완료 시 내부 `SHIPPING`으로 이동하고, 외부 구매 완료 시에는 `READY_TO_SHIP`에 둔다. `배송중 처리`는 백엔드가 이미 마켓 발송된 사실을 대사해 같은 정보를 재전송하지 않는다.
- 직접전달 주문의 소싱라이프 국내송장이 배송완료되면 내부 `status`는 `DELIVERED`로 변경한다. `marketOrderStatus: DELIVERING` 값은 유지하되 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않는다.

### 6-4. 배송중, 배송완료

- 기본 조회 전용이다.
- 배송중 송장 변경 전송 버튼은 제공하지 않는다.
- 변경된 송장번호 항목은 사용자 확인용으로도 표시하지 않는다.
- 직접전달 주문도 실제 국내 택배사와 송장번호를 택배정보에 조회 전용으로 표시한다.
- 직접전달 주문의 택배정보에는 실제 국내송장 아래에 `직접전달` 배지를 표시한다.

### 6-5. 취소/반품/교환

- `/orders?view=claims`에서 별도 화면으로 관리한다.
- 구매자가 네이버 또는 쿠팡에서 신청한 취소·반품·교환과 판매자가 주문수집에서 직접 취소한 주문을 MVP 대상으로 한다.
- 기본 `MVP 데모`는 네이버·쿠팡의 구매자 정상·예외 8건과 판매자 직접취소 예시를 표시하며, 모든 액션은 로컬 상태만 변경하고 마켓에 전송하지 않는다.
- 판매자 직접취소는 `취소·완료`로 표시하고 구매자 취소 승인 작업은 제공하지 않는다.
- 검색, 접수 주체, 유형, 공통 상태, 처리기한 필터를 제공한다.
- 상세에는 현재 단계, 다음 작업, 주의사항, 신청 사유, 대상 수량, 주문·배송 상태, 회수 배송, 교환 재배송, 이벤트 이력을 표시한다.
- 네이버 취소는 공식 API가 있는 `취소 승인`만 제공하고 `취소 거부` 버튼은 만들지 않는다.
- 네이버 반품은 승인·보류·보류해제·거부, 교환은 수거완료·재배송·보류·보류해제·거부 API 범위만 제공한다.
- 쿠팡 취소는 출고중지 완료·이미출고, 반품은 입고확인·승인, 교환은 입고확인·거부·재배송 송장 API 범위만 제공한다.
- 쿠팡 반품은 `RETURNS_UNCHECKED`에서 `반품 입고 확인`만, `VENDOR_WAREHOUSE_CONFIRM`에서 `반품 승인`만 노출한다. 빠른환불 또는 쿠팡 자동 승인으로 이미 완료된 건에는 두 버튼을 노출하지 않는다.
- 단순 회수 상태 확인, 분쟁, 배송비 예외 등 조회 또는 판매자센터 수동 처리만 가능한 항목은 실행 버튼으로 만들지 않는다.
- 교환 재배송 작업은 택배사와 새 송장번호가 모두 입력되어야 활성화한다.
- 목록 행에는 구매자 신청 건의 `취소처리`, `반품처리`, `교환처리`와 판매자 직접취소 건의 `상세보기`를 제공한다. 실제 승인·보류·입고·재배송 버튼은 목록에 표시하지 않고 처리 모달 내부에서 계산한다.
- 처리 모달은 구매자 요청 사유, 요청수량, 주문 당시 상태, 현재 소싱·배송 진행상황, 회수·재배송 정보와 상태 이력을 보여준 후 `marketCode + claimType + marketStatusRaw` 기준으로 공식 API 액션을 노출한다.
- 실데이터 상세도 마켓·유형·상태에 맞는 공식 API 대상 버튼만 표시한다. 실행 어댑터 미연결 상태에서는 API 미연결 오류를 표시하고 판매자센터 이동으로 대체하지 않는다.
- provider 응답과 후속 재수집으로 결과가 확인되기 전에는 앱 내부 상태를 성공으로 선반영하지 않는다.

## 7. 소싱라이프 소싱/결제

### 7-1. 신규주문 매칭하기

- 신규주문에서 `매칭하기`를 누르면 소싱 후보와 옵션을 선택한다.
- 저장 시 소싱 매칭 정보를 localStorage에 저장하고 주문확인을 함께 처리한다.
- 처리 후 주문은 상품준비로 이동한다.
- 모달 오른쪽 하단에는 `주문확인` 바로 아래 `주문취소`를 제공한다. 주문취소를 누르면 매칭을 저장하지 않고 소싱 모달을 닫은 뒤 기존 판매자 주문취소 확인 모달로 전환한다.
- 취소 사유, 상세 사유, 취소 수량 검증과 실주문·데모 주문 처리 결과는 기존 개별 주문취소 규칙을 그대로 사용한다.

### 7-2. 상품준비 소싱하기

- 상품준비에서 `소싱하기`를 누르면 소싱 후보 선택 모달을 연다.
- 실주문 `매핑 관리`의 운영자 입력은 항상 `MANUAL_UNVERIFIED` revision으로 저장하되 진행상태는 `소싱필요`로 표시한다. 검증 완료 전에는 구매신청·결제·결제 성공 추정을 모두 차단한다.
- 활성 매핑 조회와 revision 충돌 검사를 사용하므로 동일 주문상품을 두 운영자가 수정할 때 마지막 화면 값으로 조용히 덮어쓰지 않는다.
- 후보 카드는 한국어 상품명 값, 중국어 상품명 값, 판매처, 상품원가를 표시한다.
- 후보 카드에는 `한국어 상품명`, `중국어 상품명` 타이틀 라벨을 표시하지 않는다.
- 상품원가는 원화와 위안화를 함께 표시한다.
- AI 매칭률, 별점, 구매횟수, 배송비, 예상마진은 현재 MVP 후보 카드에서 사용하지 않는다.
- 옵션 드롭다운은 한국어 옵션명 아래 중국어 옵션명을 표시한다.
- 옵션 품절이면 결제 버튼을 비활성화한다.
- 수량은 모달 안에서 변경할 수 있다.
- 추천 소싱 상품 영역에는 키워드 또는 타오바오/소싱라이프 상품 URL 입력을 제공한다.
- 추천 상품 카드 상단의 기본 가격과 선택 옵션 요약의 위안화 개당 가격은 표시하지 않는다. 선택 옵션은 `옵션가격(재고)` 라벨 아래 원화 금액과 재고 수량으로 요약하고 모든 추천 상품 카드의 높이를 동일하게 유지한다.
- 추천 후보는 2열 카드로 표시하고 각 카드에 옵션 드롭다운, 수량 증감, 선택 옵션 합계 금액과 재고를 노출한다. 옵션 또는 수량 변경 시 해당 상품을 동시에 선택하고 카드별 선택값을 유지하며, 오른쪽 선택 상품 영역과 비용·마진 계산을 즉시 갱신한다. 재고는 오른쪽 영역에 중복 표시하지 않는다.
- 오른쪽 옵션 선택 요약에는 선택 후보의 썸네일을 표시한다.
- 소싱 비용 구성은 `상품 금액`, `소싱처 이용료`, `통화 환전 수수료`, `소싱 총비용`으로 나누어 표시한다. MVP 더미 계산은 소싱처 이용료 3%, 환전 수수료 2.5%를 원 단위 절사하고 예상 배대지 운임 4,750원을 적용한다.
- 마진 분석은 결제 금액을 시작값으로 표시하고 판매 수수료를 독립 차감 항목으로 노출한다. 예상 순이익은 `paymentPrice - platformFee - 상품 금액 - 소싱처 이용료 - 환전 수수료 - 예상 배대지 운임`으로 계산하며, 마진율은 `예상 순이익 ÷ paymentPrice × 100`으로 계산한다.
- `platformFee`가 없고 정산예정금액이 있으면 `paymentPrice - expectedSettlement`을 주문 판매수수료로 사용한다.
- 수수료율은 주문 결제금액과 수집된 판매수수료 금액으로 역산해 표시하며, 마켓별 고정 수수료율을 임의로 적용하지 않는다.
- 기본 이미지 매칭 후보는 20개를 캐싱해 표시한다.
- 키워드를 입력해 찾기 실행 시 새 검색 후보 20개를 기존 후보 목록 상단에 추가한다.
- 타오바오/소싱라이프 URL을 입력해 찾기 실행 시 해당 URL 상품 1개를 기존 후보 목록 상단에 추가한다.
- 상품·옵션 선택 후 `배대지 선택`을 누르면 소싱라이프에 저장된 수령 프로필 목록을 표시한다.
- 배대지 선택 화면의 왼쪽 본문은 `주문상품 → 소싱상품 → 마진분석 → 배송대행지 선택` 순서로 표시해 판매 주문과 구매 대상 상품을 구분한다. 오른쪽 결제 요약에는 소싱 총비용만 표시한다. 최종 결제 화면에서는 비용 구성과 마진 분석을 기존처럼 함께 표시한다.
- `구매대행 신청`은 매칭, 수량, 수령 프로필과 신청시각을 저장하고 `PAYMENT_WAITING`으로 전환하지만 결제·주문번호·송장을 생성하지 않는다.
- 결제대기 화면에는 원주문 상품과 소싱상품의 상품명·옵션·수량·금액 비교, 상품원가·소싱처 이용료·환전 수수료·예상 배송비·예상 총비용, 정산예상금액·판매 수수료·예상 순이익·마진율과 중국 판매자 채팅을 표시한다. 예상 순이익은 `마켓 결제금액 - 판매 수수료 - 상품원가 - 소싱처 이용료 - 환전 수수료 - 예상 배송비`로 계산한다. 협상 요청 중에는 `상품 결제하기`를 비활성화하고 취소 후 다시 활성화한다. 상품준비 목록 버튼은 `소싱하기`로 유지하고, 행 자세히 보기에서 `결제하기`를 제공한다.
- `결제하기`를 다시 누른 뒤에만 약관 동의와 결제 정보 입력 화면으로 이동하며, 결제 완료 시 기존 구매완료 흐름을 실행한다.
- 결제 완료 시 선택 배송대행지를 자동입력 완료로 기록하고 모달을 닫지 않은 채 결제완료 조회 화면으로 전환한다. 결제완료 화면은 실제 결제금액·결제일시·소싱라이프 주문번호·배송대행지 자동입력 결과와 중국 판매자 채팅을 표시하고 재결제 기능을 제공하지 않는다.
- `결제하기`는 `PREPARING + PAYMENT_WAITING`에서만 허용한다. `READY_TO_SHIP`, `SHIPPING`, `DELIVERED`는 소싱라이프 결제완료 또는 외부구매 완료가 선행조건이며 미결제 조합에서는 `결제상태 불일치`만 표시한다.

### 7-3. 소싱상태

| 코드 | 의미 |
|---|---|
| `NOT_LINKED` | 소싱라이프와 연결 전 |
| `MATCHING` | 소싱 진행 중 |
| `MATCH_SAVED` | 소싱완료 |
| `PAYMENT_READY` | 결제 가능 |
| `PAID` | 소싱라이프 결제 완료 |
| `INVOICE_RECEIVED` | 국내송장 수신 |
| `HOLD` | 소싱 처리보류 |

현재 주문 목록의 진행상태 컬럼은 주문별 대표 상태 하나를 표시한다. 기본 상태는 `소싱필요`, `소싱완료`, `결제대기`, `결제완료`, `중국배송중`, `통관 중`, `국내 배송중`, `배송완료`이며 `구매확정`과 7개 소싱환불·반품 표시 상태를 추가로 사용한다. `소싱 검증대기`, `마켓 취소요청`, `처리보류`, `소싱환불 접수`는 별도 표시 상태로 사용하지 않는다.
결제대기 목록에는 `소싱하기`를 표시하고 행 자세히 보기에서 `결제하기`를 제공한다. 소싱 결제완료부터 배송완료까지 같은 결제·채팅 모달을 여는 `소싱상품관리`와 `배송추적`은 상세 처리하기에만 표시한다. 조회 모달에는 배대지·창고 관리 기능을 제공하지 않는다.

소싱 단계는 마켓 주문상태(`NEW`, `PREPARING`, `READY_TO_SHIP`, `SHIPPING`, `DELIVERED`)에서 역산하지 않는다.
마켓 `SHIPPING`은 국내 택배번호를 마켓에 전송한 고객-facing 상태일 수 있으며, 판매자 입장의 실제 물류는 중국 내 배송 전/중일 수 있다.
`결제완료`는 구매대행 결제/주문 생성 완료를 의미하고, 중국 내 트래킹번호 또는 중국 판매자 발송 이벤트가 확인되면 `중국배송중`으로 본다.
`PAYMENT_READY`는 목록에서 `결제대기`, `PAID`와 `INVOICE_RECEIVED`는 `결제완료`로 투영한다. 국내송장 수신만으로 중국 판매자 발송을 추정하지 않는다.
`EXTERNAL_PURCHASE`는 내부 구매경로로 유지하고 소싱라이프 결제상태를 `PAID`로 만들지 않는다. 목록 진행상태와 필터에서는 `결제완료`로 투영하되, 매칭된 소싱상품이 없으므로 자세히 보기에는 소싱상품 영역을 표시하지 않는다.
판매자 취소·구매자 클레임의 보류는 주문/클레임 상태로 관리하며 기존 소싱 상태를 보존한다. 소싱 상태 `HOLD`는 소싱라이프 연동 자체가 중단된 경우에만 사용한다.
수입 통관 접수 이후 국내 택배사 인계 전까지는 `통관 중`으로 본다.
국내 택배사 실제 인계 이후에만 `국내 배송중`으로 본다.
마켓 또는 내부 주문이 배송완료로 확정된 주문은 소싱 단계도 `배송완료`여야 하며, `중국배송중`, `통관 중`, `국내 배송중`으로 표시하지 않는다.

`/api/orders`, `/api/claims`, `/api/market-accounts`와 PostgreSQL 원장이 실데이터 경로다. 아래 localStorage 키는 demo 주문의 임시 화면 상태이며 실마켓 처리 증거가 아니다.

주문 화면에서 탭, 필터, 검색어 또는 데이터가 바뀌면 체크 선택과 행 확장 상태는 현재 화면 기준으로 다시 초기화된다.

React Query는 주문·클레임·마켓계정 실API cursor/query와 재시도 상태를 관리한다.
Zustand는 현재 대시보드 store 중심으로 사용된다.

## 11. 주문현황 기능

### 11-1. 상태 투영

- `projectOrderJourneyStatus(order)`는 기존 주문·소싱·배송·클레임 상태를 32개 주문현황 상태 중 하나로 투영한다.
- 실제 `sourcingRefund`가 있으면 8개 내부 상태를 7개 화면 상태로 투영한다. `REQUESTED/PROVIDER_REVIEW`는 모두 `소싱환불 승인대기`로 표시하며 결제완료 후 취소됐다는 사실만으로 환불 진행 상태를 만들지 않는다.
- 마켓 취소는 마켓 상태로 유지하며, 결제완료 취소 주문에 소싱환불 원장이 없으면 `소싱환불 요청 필요` 이슈를 별도로 만든다.
- 외부 배대지 입고·검수·재포장 세부 상태는 현재 주문 모델에 없으므로 임의 생성하지 않는다. 연동 이벤트가 추가되기 전까지 해당 타일은 0건일 수 있다.

### 11-2. 이슈 판정

- 개인통관고유부호가 없거나 형식이 유효하지 않으면 통관 이슈로 표시한다.
- 동기화·발송 실패 사유가 있으면 실패 이슈, 진행 중 클레임이면 클레임 이슈로 표시한다.
- 소싱환불이 미접수이거나 반품 접수·거절·결과 대사가 필요하면 소싱환불 이슈로 표시한다.
- 설정한 경과일을 넘은 신규·준비·배송 주문은 지연 이슈로 표시한다.
- `이슈 아님`과 `2시간 미루기`는 현재 프로토타입의 컴포넌트 상태에만 저장된다. 서버 저장·감사로그 기능으로 오해시키지 않는다.

## 12. 알림·AI 문의·장부 기능

- 알림 정책은 고객용 5종과 셀러용 3종의 활성 여부, 고객 발송 가능 시간, 통관 메시지 옵션을 관리한다. 저장은 데모 토스트만 표시한다.
- 문의 AI 초안은 확인되지 않은 배송일·환불 완료·보상 여부를 단정하지 않고, 답변을 만들 수 없는 정보는 운영자 확인 문구로 남긴다.
- AI 초안은 자동전송하지 않으며 사용자가 검토·수정한 뒤 답변 버튼을 눌러야 한다.
- 장부 실제마진은 `최종마진 - (직접 지출 - 직접 수입)`으로 계산하고, 직접비 반영 토글이 꺼지면 기존 최종마진을 유지한다.

## 13. 소싱상품 환불

### 13-1. 진입 조건

| 조건 | 결과 |
|---|---|
| TaoWorld 구매 주문라인 있음 + `결제완료`부터 `국내 배송중` | `소싱상품관리 > 구매대행 신청 상품`에서 신규 `반품·환불 신청` 가능 |
| `배송완료` + 신규 요청 | `반품·환불 신청` 미노출 |
| 기존 환불 원장 있음 | 이후 물류 단계에도 `환불 진행` 또는 `환불 내역` 조회 유지 |
| 기존 환불 원장 있음 | 현재 환불 상태와 요청 내역 조회 |
| `REFUNDED` + 국내배송 미시작 | `소싱상품관리` 안에 `환불 내역`, 상세 `처리하기`에 `다시 소싱하기` 표시. 기존 소싱 연결 초기화 후 신규 후보 선택·결제 가능 |
| `REFUNDED` + 마켓 배송 시작 | `다시 소싱하기` 미노출, 기존 배송 상태 우선 |
| 외부 직접구매 | 소싱환불 미노출, 외부 구매처 처리 안내 |
| 결제 전·매칭·결제대기 | 소싱환불 미노출 |
| 실주문 + 환불 API 미연결 | 정보 확인만 가능, 실행 버튼 `연동 준비 중` |

### 13-2. 요청 입력과 검증

- 환불 대상: TaoWorld `purchaseOrderLineId`가 저장된 구매 주문라인
- 요청 유형: `REFUND_ONLY=1`, `RETURN_AND_REFUND=2`
- 상품 상태: `NOT_SHIPPED=1`, `SHIPPED=2`, `NOT_RECEIVED=3`, `RECEIVED=4`, `SENT_BACK=5`, `SELLER_RECEIVED=6`
- 사유: `/order/refund/render` 응답의 `reasonId`와 표시문구를 그대로 사용하며 내부 고정 사유코드로 치환하지 않는다.
- 요청 금액: CNY 기준 0보다 크고 render 응답의 `maxRefundFee` 이하
- 수량: TaoWorld submit 계약에 별도 수량 파라미터가 없으므로 화면 입력과 전송 계약에서 제외한다.
- 설명·증빙: 선택적 `refundDesc`, `refundImages`
- 마켓 클레임 ID: 선택값이며 마켓 클레임과 소싱환불을 연결하는 참조
- 기타 상세 사유: `OTHER`일 때 필수
- 확인 체크: 마켓 주문 취소와 구매자 환불이 자동 처리되지 않음을 명시적으로 확인

### 13-3. 상태와 액션 잠금

| 상태 | 화면 의미 | 출고 액션 |
|---|---|---|
| `REQUESTED` | TaoWorld submit 데모 응답 저장 | 차단 |
| `PROVIDER_REVIEW` | 중국 판매자 환불·반품 동의 대기 | 차단 |
| `RETURN_REQUIRED` | `/render/logistics` 기준 중국 반품 송장 등록 필요 | 차단 |
| `RETURN_IN_TRANSIT` | 중국 반품 배송 중 | 차단 |
| `REFUND_PENDING` | 환불 금액 정산 중 | 차단 |
| `REFUNDED` | 소싱 구매금액 회수 완료 | 환불 잠금 해제 후 별도 주문 정책 적용 |
| `REJECTED` | 거절 사유 확인 필요 | 운영자 판단 전 자동 출고하지 않음 |
| `RECONCILIATION_REQUIRED` | 요청·응답 불일치 | 차단 |

현재 프로토타입은 demo 주문에서 TaoWorld `/render`, `/submit`, `message_type=9` 후 `/query`, `/render/logistics`, `/submit/logistics` 계약의 입력값과 상태 전이를 재현한다. 실주문 외부 쓰기와 최종 성공은 TaoWorld 어댑터 및 message/query 대사가 완료된 뒤에만 활성화한다.
