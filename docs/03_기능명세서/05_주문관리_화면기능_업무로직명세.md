# 주문관리 기능·업무로직 설명서

주문관리는 마켓에서 결제가 완료된 주문을 수집한 뒤 `주문확인 → 상품 매칭·구매 → 국내송장 확보 → 마켓 발송처리 → 실제 국내배송 완료`까지 관리한다.

구매자가 취소·반품·교환을 신청하면 일반 주문 처리에서 분리해 클레임 작업으로 관리한다. 판매자가 직접 주문을 취소한 내역도 같은 취소·반품·교환 작업함에 표시하되 접수 주체로 구분한다.

판매자 취소 요청은 즉시 완료하지 않고 처리보류 상태로 관리하며, 최종 취소 결과를 확인한 뒤 전체주문의 판매자취소와 취소 작업함의 완료 이력으로 함께 조회한다.

## 1. 주문관리 업무 범위

### 1-1. 관리 대상

- 마켓에서 수집된 주문의 조회와 검색
- 신규주문 확인과 상품 매칭
- 소싱라이프 구매와 외부구매 배송처리
- 국내송장 확인과 배송중 처리
- 배송중·배송완료 조회
- 판매자 직접 주문취소
- 구매자가 신청한 취소·반품·교환 조회와 처리
- 주문과 클레임의 상태, 항목, 예외, 처리이력
- 네이버와 쿠팡에서 실제로 실행 가능한 클레임 작업의 노출 규칙
- 데모 및 개발 검수용 더미데이터

### 1-2. 관리하지 않는 업무

- 소싱라이프에서 직접 생성한 주문
- 타오바오 직접 결제
- 내부 배대지·창고·검수 작업 관리
- 정산, 마진, 세금계산서, 수수료 관리
- 배송중 송장 변경 전송
- 판매자가 마켓에 새 반품·교환을 대신 신청하는 기능
- 마켓에서 지원하지 않거나 실사용 검증이 끝나지 않은 실행 작업
- 전용 처리이력·실패작업 메뉴

## 2. 업무 권한과 처리 단위

### 2-1. 사용자

| 사용자 | 할 수 있는 일 |
|---|---|
| 운영자 | 주문 조회, 주문확인, 소싱, 구매 처리, 배송중 처리, 클레임 조회와 허용 작업 실행 |
| 관리자 | 운영자 기능과 마켓계정 관리, 예외 확인, 재처리 판단 |
| 조회 사용자 | 주문과 클레임 조회만 가능하며 상태를 변경하는 기능은 사용할 수 없음 |

### 2-2. 처리 단위

| 단위 | 정의 | 주요 사용처 |
|---|---|---|
| 주문 | 구매자가 한 번에 결제한 주문 묶음 | 주문번호, 구매자, 배송지 조회 |
| 주문상품 | 주문 안의 개별 상품·옵션 | 주문확인, 취소, 수량, 송장, 매칭의 실제 처리 단위 |
| 클레임 | 취소·반품·교환 요청 한 건 | 요청 사유, 기한, 처리 단계 관리 |
| 클레임 상품 | 클레임에 포함된 주문상품과 신청 수량 | 부분 취소·부분 반품·부분 교환 |

한 주문에 여러 주문상품이 있으면 상품별 상태와 처리 결과가 다를 수 있다. 일괄처리 결과도 주문 전체 성공으로 뭉개지 않고 주문상품별 성공·실패를 보존한다.

## 3. 메뉴와 페이지 구성

### 3-1. 주문관리 메뉴 구조

```text
주문관리
├─ 주문수집(신규주문)
├─ 전체주문
├─ 상품준비
├─ 발송대기
├─ 배송중
├─ 배송완료 
└─ 마켓연동
```

### 3-2. 페이지별 역할

| 페이지 | 경로 | 포함 대상 | 주요 목적 |
|---|---|---|---|
| 주문수집 | `/orders`, `/orders?view=new` | 주문확인 전 주문 | 수집, 주문확인, 매칭, 판매자 취소 |
| 전체주문 | `/orders?view=all` | 일반 주문과 처리보류 주문 | 전체 진행상태 조회와 처리보류 확인 |
| 상품준비 | `/orders?view=preparing` | 주문확인 완료, 구매 미완료 | 소싱라이프 구매 또는 외부 구매 |
| 발송대기 | `/orders?view=waiting` | 구매·국내송장 완료, 발송처리 전 | 택배 발송 또는 직접전달 처리 |
| 배송중 | `/orders?view=shipping` | 발송처리 완료 | 실제 국내배송 진행 조회 |
| 배송완료 | `/orders?view=delivered` | 실제 국내배송 완료 | 배송완료·구매확정 조회 |
| 취소/반품/교환 | `/orders?view=claims` | 구매자 클레임과 판매자 직접취소 이력 | 취소·반품·교환 처리와 완료 이력 조회 |
| 마켓연동 | `/me/markets` | 연결된 마켓계정 | 계정 추가, 설정, 활성, 삭제 |

`판매자취소`는 판매자가 직접 취소한 종료 결과다. 판매자 취소 요청 후 최종 결과를 기다리는 주문은 `전체주문`의 `처리보류`에서 조회하고, 최종 완료 후에는 전체주문과 취소·반품·교환의 완료 목록에서 모두 조회한다.

## 4. 일반 주문 페이지의 논리 구성

일반 주문 페이지는 다음 영역으로 구성한다. 아래 순서는 정보 구조이며 시각 배치 규격이 아니다.

```text
일반 주문 페이지
├─ 현재 페이지 제목과 주문 건수
├─ 조회기간
├─ 통합검색
├─ 마켓·스토어 선택
├─ 주문수집 실행과 결과
├─ 주문 단계별 처리 기능
├─ 판매처·상태 필터
├─ 주문 목록
├─ 행 확장 상세
└─ 다음 목록 불러오기 또는 빈 상태·오류 상태
```

### 4-1. 조회기간

| 항목 | 값 | 기본값 | 규칙 |
|---|---|---|---|
| 빠른 기간 | 오늘, 3일, 7일, 30일 | 7일 | 주문일시를 기준으로 조회한다. |
| 직접 입력 | 시작일, 종료일 | 없음 | 시작일은 종료일보다 늦을 수 없다. |

### 4-2. 통합검색

검색어는 앞뒤 공백을 제거하고 부분 일치로 조회한다.

검색 대상:

- 상품명
- 마켓 주문번호
- 상품주문번호
- 내부 주문 ID
- 구매자명
- 수령인명
- 구매자·수령인 연락처
- 배송메시지
- 개인통관부호

연락처는 하이픈 포함 여부와 관계없이 같은 번호로 검색한다.

### 4-3. 마켓·스토어 선택

- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓에 속한 모든 스토어의 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하고 소속 마켓은 선택된 것으로 간주한다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 선택한 마켓에 속하지 않는 스토어는 선택할 수 없게 한다.
- 목록 조회 필터는 주문수집 실행 범위를 제한하지 않는다.

### 4-4. 판매처 필터

- 현재 페이지에 속한 주문의 마켓과 스토어를 선택한다.
- 값은 `마켓명 · 스토어명`으로 구분한다.
- 선택하지 않으면 현재 페이지의 모든 판매처를 표시한다.

### 4-5. 상태 필터

현재 데이터에 해당 상태의 주문이 없어도 페이지에서 사용할 수 있는 상태값은 항상 제공한다.

| 페이지 | 상태 필터 값 |
|---|---|
| 신규주문 | 소싱필요 |
| 상품준비 | 소싱필요, 소싱완료, 결제대기 |
| 발송대기 | 결제완료, 중국배송중, 통관 중, 국내 배송중 |
| 배송중 | 결제완료, 중국배송중, 통관 중, 국내 배송중 |
| 배송완료 | 배송완료, 구매확정 |
| 전체주문 | 위 상태 전체와 처리보류 |

구매확정 주문은 `배송완료` 필터와 `구매확정` 필터 모두에 포함한다.

### 4-6. 선택 초기화

다음 조건이 바뀌면 체크 선택과 펼쳐진 상세를 초기화한다.

- 페이지 또는 주문 단계
- 조회기간
- 검색어
- 마켓·스토어
- 판매처·상태 필터
- 클레임 유형
- 주문 데이터 갱신

## 5. 일반 주문 목록 컬럼

기본 컬럼 순서는 다음과 같다.

1. 선택
2. 처리하기
3. 주문일시
4. 진행상태
5. 상품정보
6. 택배정보
7. 배송정보

### 5-1. 컬럼 정의

| 컬럼 | 표시 항목 | 표시·처리 규칙 |
|---|---|---|
| 선택 | 주문상품 체크 | 현재 페이지의 일괄처리 대상 선택에 사용한다. |
| 진행상태 | 소싱 진행상태와 필요한 보조상태 | 처리 버튼은 포함하지 않는다. |
| 처리하기 | 현재 실행 가능한 기능 | 실행 기능이 없으면 빈 값으로 둔다. 상태 설명을 대신 표시하지 않는다. |
| 주문일시 | 마켓 주문일시, 마켓 약자 아이콘, 스토어명 | 최신 주문 우선 조회의 기준이며 판매처 정보도 함께 확인한다. |
| 상품정보 | 썸네일, 상품명, 옵션명, 수량, 마켓 주문번호 | 한 행의 대표 주문상품 정보를 표시한다. |
| 택배정보 | 국내 택배사·송장번호, 직접전달 표시, 중국 택배사·송장번호 | 직접전달을 선택한 주문에만 `직접전달`을 표시하고 일반 주문에는 관련 문구를 표시하지 않는다. 없는 송장번호는 `-`로 표시하며 배송중·완료에서는 조회만 한다. |
| 배송정보 | 수령인명, 연락처, 주소, 개인통관부호 상태 | 수정 기능을 제공하며 통관부호 유효성을 함께 표시한다. |

판매처 전용 컬럼은 제공하지 않는다. 마켓은 `N`, `C`, `G`, `11`, `A` 약자 아이콘으로 표시하고 스토어명을 주문일시 아래에 배치한다.

### 5-2. 상품정보 규칙

- 상품명과 옵션명을 분리한다.
- 옵션이 없으면 `옵션 없음`으로 표시한다.
- 수량은 주문상품 기준 정수로 표시한다.
- 주문번호는 `마켓 주문번호 : 값`의 의미로 확인할 수 있어야 한다.
- 상품주문번호는 검색과 처리 식별에 사용하며 상세 데이터에 보존한다.
- 마켓 주문번호를 외부 링크로 사용하지 않는다.

### 5-3. 택배정보 규칙

- 국내송장은 실제 국내 배송을 추적하는 택배사와 송장번호다.
- 중국송장은 중국 판매자 출고 이후 현지 배송을 추적하는 택배사와 송장번호다.
- 발송대기 주문은 정상이라면 반드시 국내송장을 보유한다.
- 배송중·배송완료에서는 국내송장을 조회만 한다.
- 직접전달 주문도 실제 국내송장을 별도로 보유하고 조회한다.
- 직접전달을 선택한 주문에는 국내송장과 구분되는 `직접전달` 표시를 추가하고, 일반 주문에는 직접전달 관련 표시를 하지 않는다.
- 중국송장이 아직 발급되지 않았거나 외부구매 주문처럼 수집 원천이 없으면 `-`로 표시한다.
- 송장 변경 이력과 송장 변경 실행 기능은 현재 범위에 포함하지 않는다.

### 5-4. 배송정보 규칙

- 수령인명, 연락처, 우편번호, 기본주소, 상세주소, 배송메시지, 개인통관부호를 보존한다.
- 개인통관부호는 `P`와 숫자 12자리일 때 일치로 본다.
- 값이 없거나 형식이 맞지 않으면 불일치로 본다.
- 배송정보 수정 후 목록과 상세에 같은 값을 사용한다.
- 통관부호 불일치 주문은 소싱라이프 구매 진행을 차단하고 배송정보 수정으로 안내한다.

### 5-5. 진행상태 컬럼 규칙

진행상태 컬럼은 주문단계가 아니라 판매자 관점의 실제 소싱 진행상태를 우선 표시한다. 중국배송중부터 배송완료까지의 배송 배지도 이 컬럼에서 일관되게 표시한다.

| 상태 | 의미 |
|---|---|
| 소싱필요 | 소싱 상품과 옵션이 연결되지 않음 |
| 소싱필요 | 매칭 필요 또는 운영자가 입력한 소싱 정보를 검증하기 전 |
| 소싱완료 | 소싱 상품과 옵션 선택이 저장됨 |
| 결제대기 | 구매대행 신청 완료, 실제 결제 전 |
| 결제완료 | 소싱라이프 결제 또는 외부 구매처 결제 완료. 외부 구매 여부는 자세히 보기에서 구분 |
| 결제완료 | 소싱라이프 구매·결제 완료 |
| 중국배송중 | 중국 판매자 발송 또는 중국 내 배송 확인 |
| 통관 중 | 수입 통관 접수 후 국내택배 인계 전 |
| 국내 배송중 | 실제 국내 택배사 인계 후 배송 진행 |
| 배송완료 | 실제 국내송장 기준 배송 완료 |
| 구매확정 | 마켓에서 구매확정된 배송완료 주문 |
| 처리보류 | 판매자 취소 요청 후 최종 결과 대기 |

`결제완료` 이후의 상태는 관련 소싱라이프 주문을 식별할 수 있어야 한다. 마켓이 배송중이어도 실제 소싱 진행이 소싱완료, 결제완료 또는 중국배송중일 수 있으므로 두 상태를 같은 것으로 보지 않는다.

## 6. 행 확장 상세

주문 행을 열면 넓은 화면에서는 상세를 세 영역으로 제공한다.

1. 왼쪽 정보 영역: 구매자·배송정보, 택배정보
2. 가운데 상품 영역: 상품 비교, 마진계산
3. 오른쪽 처리 영역: 현재 주문에서 사용할 수 있는 처리 기능

각 영역의 내용은 위에서 아래로 표시한다. 상품 비교는 주문상품 → 소싱상품, 마진계산은 매출·정산 → 예상 소싱비용 → 예상 순이익·마진율 순으로 세로 배치한다. 작은 화면에서는 상품 영역, 왼쪽 정보 영역, 처리 영역 순서로 한 줄씩 배치한다.

### 6-1. 상세 항목

| 영역 | 항목 |
|---|---|
| 주문상품 | 상품명, 옵션명, 주문수량, 단가, 주문금액, 마켓 주문번호, 상품주문번호 |
| 구매자 | 구매자명, 연락처 |
| 배송정보 | 수령인명, 연락처, 우편번호, 주소, 배송메시지, 개인통관부호, 수정 기능 |
| 택배정보 | 국내 택배사·송장번호, 직접전달 주문의 `직접전달` 표시, 중국 택배사·송장번호 |
| 소싱상품 | 썸네일, 상품명, 옵션명, 구매수량, 소싱금액, 소싱라이프 주문번호 |
| 마진계산 | 매출·정산 → 예상 소싱비용 → 예상 순이익·마진율의 세로 구성 |
| 처리하기 | 현재 단계와 주문 조건에 따라 허용되는 실행·조회 기능 |

소싱금액은 소싱라이프에서 실제 결제한 금액을 의미한다. 예상원가나 마켓 정산금액과 혼용하지 않는다.

## 7. 주문 상태와 전환

### 7-1. 주문 상태

| 내부 상태 | 화면명 | 진입 조건 | 다음 정상 상태 |
|---|---|---|---|
| 신규주문 | 신규주문 | 결제완료 주문 수집, 판매자 확인 전 | 상품준비 |
| 상품준비 | 상품준비 | 주문확인 완료 | 발송대기 또는 자동 발송 성공 시 배송중 |
| 발송대기 | 발송대기 | 외부 구매 완료와 국내송장 확보 후 마켓 배송중 처리 전 | 배송중 |
| 배송중 | 배송중 | 마켓 발송처리 또는 직접전달, 구매와 국내송장 확보 | 배송완료 |
| 배송완료 | 배송완료 | 실제 국내송장 배송완료 | 종료 |
| 처리보류 | 전체주문의 처리보류 | 판매자 취소 요청 접수, 최종 결과 대기 | 판매자취소 또는 이전 상태 복구 |
| 판매자취소 | 전체주문의 종료 주문 | 판매자 취소 최종 확인 | 종료 |
| 취소/반품/교환 | 클레임 페이지 | 구매자 클레임 수집 | 유형별 종료 상태 |

### 7-2. 기본 주문 흐름

```text
신규주문
  └─ 주문확인 또는 소싱하기
      └─ 상품준비
          ├─ 구매 완료 + 국내송장 + 자동 발송 OFF
          │   └─ 발송대기 ─ 스토어 기본 발송 방식 확인 ─ 배송중
          ├─ 구매 완료 + 국내송장 + 자동 발송 ON 성공
          │   └─ 배송중
          └─ 배송중 처리 > 직접전달
              └─ 상품준비 유지 ─ 구매 완료 + 국내송장 ─ 발송대기 ─ 배송중 처리 재실행 ─ 배송중
배송중 ─ 실제 국내배송 완료 ─ 배송완료
```

### 7-3. 구매 방식

구매 방식은 다음 두 가지다.

1. 소싱라이프 구매
2. 외부 구매

`구매 안 함` 상태나 기능은 제공하지 않는다. 두 방식 모두 사용자 관점의 구매 완료에는 실제 국내 택배사와 국내송장번호가 필수다.

### 7-4. 저장할 수 없는 상태 조합

- 소싱라이프 구매 완료 + 국내송장 없음
- 외부 구매 완료 + 국내송장 없음
- 직접전달 + 소싱라이프 구매 완료 + 국내송장 없음
- 직접전달 + 외부 구매 완료 + 국내송장 없음
- 직접전달 + 구매 미완료 + 국내송장 있음
- 구매 안 함 + 국내송장 있음
- 내부 배송중 + 국내송장 없음
- 배송완료 + 소싱 진행상태가 중국배송중·통관 중·국내배송중
- 처리보류 + 주문확인·매칭·구매·발송·재취소 실행 가능

## 8. 주문수집 기능

### 8-1. 실행 대상

- 연결 상태가 정상이고 활성화된 계정을 대상으로 한다.
- 현재 화면의 기간·검색·마켓·스토어 필터는 실행 대상을 제한하지 않는다.
- 이미 같은 계정의 수집 작업이 진행 중이면 새 작업을 중복 생성하지 않고 기존 작업을 이어서 확인한다.

### 8-2. 실행 결과

| 결과 | 표시 내용 | 목록 처리 |
|---|---|---|
| 완료 | 신규 건수, 갱신 건수 | 목록을 다시 조회한다. |
| 부분 완료 | 신규·갱신·오류 건수 | 성공 데이터는 표시하고 오류를 안내한다. |
| 실패 | 실패 사유 | 기존 목록을 유지하고 재시도할 수 있게 한다. |
| 계속 진행 | 백그라운드 진행 안내 | 화면 대기는 종료하지만 작업은 중단하지 않는다. |

작업 접수 성공을 주문수집 완료로 표시하지 않는다.

## 9. 신규주문 기능

### 9-1. 행 기능

| 기능 | 노출 조건 | 입력 | 성공 결과 | 실패 결과 |
|---|---|---|---|---|
| 주문확인 | 신규주문, 활성 클레임 없음 | 없음 | 상품준비로 이동 | 신규주문 유지, 실패 사유 표시 |
| 매칭하기 | 신규주문, 활성 클레임 없음 | 소싱 상품, 옵션, 수량 | 매칭 저장과 주문확인을 함께 처리하고 상품준비 이동 | 저장 전 상태 유지 |
| 주문취소 | 취소 가능 상태 | 취소 사유, 상세 사유, 취소 수량 | 처리보류 후 최종 확인 시 판매자취소 | 기존 상태 유지 또는 처리보류에서 결과 확인 |

### 9-2. 일괄 기능

- 체크된 신규주문만 대상으로 한다.
- 선택이 없으면 일괄 주문확인과 일괄 주문취소를 실행할 수 없다.
- 일괄 주문취소는 각 주문의 전체 잔여수량을 대상으로 한다.
- 결과는 주문상품별 성공·실패로 나누어 표시한다.
- 성공한 주문만 다음 상태로 이동하고 실패한 주문은 기존 상태를 유지한다.
- 실패 주문만 다시 시도할 수 있어야 한다.

## 10. 상품 매칭과 소싱라이프 구매

### 10-1. 신규주문 매칭하기

필수 항목:

- 소싱 상품
- 소싱 옵션
- 마켓 판매수량에 대응하는 구매수량

확인 항목:

- 한국어 상품명
- 중국어 상품명
- 판매처
- 원화·위안화 상품원가
- 옵션별 가격과 재고
- 최소구매수량과 수량 배수

처리 규칙:

- 운영자가 새로 입력한 매칭은 검증 전 상태로 저장한다.
- 검증되지 않은 매칭으로 구매를 진행할 수 없다.
- 동일 마켓 상품·옵션의 검증된 매칭은 다음 주문에 제안할 수 있다.
- 과거 주문이 사용한 매칭은 이후 매칭 변경으로 바꾸지 않는다.
- 두 사용자가 같은 매칭을 수정하면 먼저 저장된 변경을 덮어쓰지 않고 충돌을 알린다.
- 품절, 상품 삭제, 가격 한도 초과, 제한품목은 구매를 차단하고 재매칭 대상으로 만든다.
- 신규주문 매칭 모달은 `주문확인` 바로 아래 `주문취소`를 제공한다.
- `주문취소`를 누르면 선택 중인 매칭을 저장하지 않고 소싱 모달을 닫은 뒤 판매자 주문취소 확인 모달로 전환한다. 취소 입력과 처리 결과는 14장의 판매자 직접 주문취소 규칙을 따른다.

### 10-2. 소싱하기

노출 조건:

- 상품준비 상태
- 판매자 취소나 구매자 클레임이 진행 중이지 않음
- 개인통관부호가 필요한 주문이면 유효한 통관부호 보유

처리 순서:

1. 소싱 후보를 조회하거나 키워드·상품주소로 새 후보를 찾는다.
2. 상품과 옵션을 선택한다.
3. 구매수량과 금액을 확인한다.
4. 재고, 가격, 최소수량, 제한품목을 재확인한다.
5. 구매대행 신청 내용을 확인한다.
6. 소싱라이프 결제를 진행한다.
7. 결제완료 후 선택 배송대행지 사이트를 열고 주문서를 자동입력한다.
8. `접수대기/접수신청` 단일 접수 단계를 실행하고 접수 응답에서 국내송장을 즉시 받는다.
9. 결제, 구매, 배송대행지 접수, 국내송장 수신을 각각 별도 사건으로 보존한다.
10. 실제 국내송장이 확보되면 사용자 관점의 구매 완료를 판정한다.

정상 접수는 국내송장을 즉시 반환하므로 장기 송장대기는 정상 흐름이 아니다. 접수 실패·응답 유실·송장 누락 시에는 결제 사실을 유지하면서 상품준비의 연동 오류 상태로 관리한다. 현재 프로토타입은 7~8단계를 화면으로 구현하지 않고 결제완료 클릭 시 더미 송장을 생성한다.

### 10-3. 소싱 진행상태

| 단계 | 의미 | 구매/발송 가능 여부 |
|---|---|---|
| 연결 전 | 소싱 없음 | 구매 불가 |
| 소싱 중 | 후보 확인 중 | 구매 불가 |
| 소싱필요 (`MATCH_PENDING_REVIEW`) | 운영자 소싱 저장, 검증 전 | 구매 불가 |
| 소싱완료 | 검증된 상품·옵션 저장 | 구매 전 점검 가능 |
| 결제 가능 | 구매 조건 확인 완료 | 결제 가능 |
| 결제 완료 | 소싱라이프 결제 성공 | 국내송장 전 발송 불가 |
| 국내송장 수신 | 실제 국내송장 확보 | 발송대기 또는 자동 발송 가능 |
| 처리 보류 | 오류 또는 클레임으로 중단 | 모든 구매·발송 차단 |

상태 투영 규칙:

- `PAYMENT_READY`는 항상 `결제대기`로 표시한다.
- `PAID`와 `INVOICE_RECEIVED`는 명시적인 중국 발송 이벤트가 없으면 `결제완료`로 표시한다.
- `INVOICE_RECEIVED`만으로 `중국배송중`을 추정하지 않는다.
- `EXTERNAL_PURCHASE`는 내부적으로 외부 구매경로를 유지하고 소싱라이프 결제상태로 변환하지 않는다. 목록에서는 `결제완료`로 표시하되 매칭된 소싱상품이 없으므로 자세히 보기에는 소싱상품 영역을 표시하지 않는다.
- 판매자 취소와 구매자 클레임은 주문·클레임 상태만 변경하고 기존 소싱 상태를 보존한다. 소싱 `HOLD`는 소싱 연동 자체의 보류에만 사용한다.

## 11. 외부구매 배송처리

### 11-1. 노출 조건

- 상품준비 상태
- 구매 완료 전
- 활성 클레임 또는 처리보류 상태가 아님

### 11-2. 입력 항목

| 항목 | 필수 | 규칙 |
|---|---:|---|
| 상품명·옵션·수량·마켓 주문번호 | 조회 | 현재 처리 대상을 확인한다. |
| 택배사 | 필수 | 실제 국내 택배사여야 한다. |
| 국내송장번호 | 필수 | 공백일 수 없으며 택배사와 함께 저장한다. |

구매처, 상품 URL, 구매일, 구매금액, 통화, 증빙은 입력받지 않는다. 이 기능은 직접구매 내역을 장부로 관리하는 기능이 아니라 국내송장을 등록해 발송 단계로 이동하는 기능이다.

### 11-3. 처리 결과

| 조건 | 결과 |
|---|---|
| 국내송장 없음 | 완료 차단, 상품준비 유지 |
| 자동 배송중 처리 OFF | 외부구매 상태 저장 후 발송대기 이동 |
| 자동 배송중 처리 ON, 발송 성공 | 배송중 이동 |
| 자동 배송중 처리 ON, 발송 실패 | 국내송장을 보존하고 발송대기 유지 |
| 직접전달 선처리 주문 + 국내송장 있음 | 외부구매 완료 후 내부 발송대기 이동 |
| 직접전달 선처리 주문 + 국내송장 없음 | 완료 차단, 상품준비 유지 |

## 12. 발송대기와 배송중 처리

### 12-1. 자동 배송중 처리

- 기본값은 OFF다.
- 구매 완료와 국내송장 확보 직후 발송 가능 여부를 판단한다.
- 활성 클레임, 처리보류, 직접전달 선처리 주문은 일반 자동 발송 대상에서 제외한다.
- 성공한 주문만 배송중으로 이동한다.
- 실패한 주문은 국내송장을 잃지 않고 발송대기에 남는다.
- 상품준비와 발송대기 화면은 동일한 자동 배송중 처리 설정값을 사용한다.

### 12-2. 배송중 처리 진입

소싱라이프 결제완료 주문은 즉시 내부 `배송중`에서 관리한다. 배송중 목록 `처리하기`는 비워 두고 행 자세히 보기에서 `소싱상품관리`, `배송추적`, 처리 시작 전 `운송장 수정`, 조건부 `배송중 처리`를 제공한다. 배송중 처리 명령이 접수되면 마켓 응답 대기 중에도 운송장 수정은 잠근다. 조건부 `반품·환불 신청`은 `소싱상품관리` 안에 표시한다. 외부구매 주문에는 `소싱상품관리`를 제공하지 않는다.

스마트스토어·11번가는 마켓 연동 시 `송장전송` 또는 `직접전달`을 필수 선택하고, 쿠팡·G마켓·옥션은 `송장전송`으로 고정한다. 마켓에 발송 방식을 전송한 뒤에는 상세의 내부 `운송장 수정`, `마켓에서 수정`, `수정내역 불러오기`를 모두 제공하지 않는다. 정정 명령도 자동 전송하지 않는다.

| 작업 | 조건 | 결과 |
|---|---|---|
| 배송중 처리 > 송장 | 구매 완료, 유효한 국내송장, 마켓 발송 전 | 국내송장 전송 성공 시 마켓·내부 배송중 |
| 배송중 처리 > 직접전달 | 지원 마켓. 상품준비 선처리 또는 구매·송장 완료 발송대기 | 국내송장 전송 없이 마켓 발송. 상품준비 선처리는 내부 단계 유지 |
| 배송중 처리 > 백엔드 대사 | 마켓 발송 완료 | 실제 발송 방식 확인, 마켓 재전송 없이 내부 배송중 |

### 12-3. 일괄 처리 대상

- 체크된 주문이 있으면 체크 주문을 우선한다.
- 체크 주문이 없으면 현재 필터 결과를 대상으로 할 수 있다.
- 택배 발송은 국내송장이 있고 직접전달로 처리되지 않은 주문만 실행한다.
- 조건에 맞지 않는 주문은 전체 작업을 막지 않고 제외 목록과 이유를 보여준다.
- 결과는 성공, 실패, 제외로 나누어 표시한다.

### 12-4. 직접전달 선처리

상품준비 상태에서 구매보다 먼저 마켓 발송처리만 해야 하는 예외 주문에 사용한다.

```text
상품준비
  └─ 직접전달 선처리 성공
      ├─ 마켓 관점: 배송중
      └─ 내부 관점: 상품준비 유지, 구매 미완료, 국내송장 없음
          └─ 소싱라이프 또는 외부 구매 완료 + 실제 국내송장
              └─ 내부 발송대기
                  └─ 배송중 처리 재실행
                      └─ 내부 배송중
```

- 직접전달은 실제 구매나 물류 완료를 의미하지 않는다.
- 직접전달만 성공한 주문에는 국내송장을 미리 입력하지 않는다.
- 이후 구매 완료 시 실제 국내송장이 반드시 필요하다.
- 구매와 국내송장 확보 후에는 마켓 배송중 상태를 유지한 채 내부 발송대기로 이동한다.
- 직접전달 주문은 실제 국내송장을 마켓 발송처리에 다시 사용하지 않고 내부 배송 추적에 사용한다.
- 실제 국내송장이 배송완료되면 내부 주문을 배송완료로 변경한다.

## 13. 배송중과 배송완료

### 13-1. 배송중

- 기본 조회 전용이다.
- 국내 택배사와 송장번호를 표시한다.
- 직접전달 주문도 실제 국내송장을 표시한다.
- 송장 수정·변경 전송 기능은 제공하지 않는다.
- 실제 소싱 진행상태가 국내배송보다 앞선 경우 해당 소싱상태를 사실대로 표시한다.

### 13-2. 배송완료

- 실제 국내송장의 배송완료를 기준으로 한다.
- 소싱 진행상태도 배송완료로 정리한다.
- 네이버 구매확정이 수집되면 `구매확정`을 추가 상태로 표시한다.
- 판매자가 이 메뉴에서 구매확정을 실행하지 않는다.

## 14. 판매자 직접 주문취소

판매자 직접 취소는 구매자가 신청한 취소와 다른 기능이다.

### 14-1. 노출 조건

- 신규주문 또는 취소 가능한 상품준비 주문
- 현재 반품·교환 등 활성 클레임이 없음
- 처리보류, 판매자취소, 배송중, 배송완료 상태가 아님
- 해당 마켓에서 판매자 취소 실행이 허용됨

### 14-2. 입력 항목

| 항목 | 필수 | 규칙 |
|---|---:|---|
| 취소 사유 | 필수 | 제공된 사유 중 선택한다. |
| 상세 사유 | 필수 | 공백 정리 후 2자 이상 500자 이하, 제어문자 금지 |
| 취소 수량 | 개별 취소 시 필수 | 1 이상의 정수이며 남은 주문수량을 초과할 수 없음 |

네이버 취소 사유:

- 구매 의사 취소
- 색상 및 사이즈 변경
- 다른 상품 잘못 주문
- 서비스 불만족
- 배송 지연
- 상품 품절
- 상품 정보 상이

### 14-3. 처리 상태

```text
기존 주문상태
  └─ 판매자 취소 요청 접수
      └─ 처리보류
          ├─ 최종 취소 확인 ─ 판매자취소
          └─ 실패·미적용 확인 ─ 이전 상태 복구 또는 재처리 판단
```

- 요청을 접수했다는 사실만으로 판매자취소 완료로 표시하지 않는다.
- 처리보류 중에는 주문확인, 매칭, 소싱, 외부 구매, 직접전달, 발송, 재취소를 모두 차단한다.
- 일부 주문상품만 성공하면 성공 상품만 처리보류로 이동하고 실패 상품은 기존 상태를 유지한다.
- 구매가 이미 시작됐으면 소싱 중단 또는 환불 필요 작업을 별도로 표시한다.
- 반품·교환이 진행 중이면 판매자 취소와 충돌하므로 실행하지 않는다.

## 15. 구매자 취소·반품·교환 페이지

### 15-1. 대상

- 구매자가 네이버 또는 쿠팡에서 신청한 취소·반품·교환
- 마켓에서 수집된 구매자 클레임
- 주문수집 화면에서 완료한 판매자 직접취소
- 판매자가 새로 만든 클레임은 제외

### 15-2. 페이지 논리 구성

```text
취소/반품/교환 페이지
├─ 데이터 구분 안내
├─ 조회기간
├─ 통합검색
├─ 마켓 필터
├─ 진행그룹 탭과 건수
├─ 접수 주체·유형·상태·처리기한 필터
├─ 클레임 목록
├─ 다음 목록 불러오기
└─ 취소처리·반품처리·교환처리 상세창
```

### 15-3. 조회와 필터

| 항목 | 값 | 기본값 | 규칙 |
|---|---|---|---|
| 조회기간 | 오늘, 3일, 7일, 30일, 전체 | 7일 | 신청일 기준 |
| 검색 | 상품명, 주문번호, 클레임 ID | 없음 | 부분 일치 |
| 마켓 | 전체, 네이버, 쿠팡 | 전체 | 선택 마켓만 표시 |
| 진행그룹 | 전체, 신규요청, 처리중, 완료 | 전체 | 공통 상태를 업무 단계로 묶음 |
| 접수 주체 | 전체, 구매자 신청, 판매자 직접취소 | 전체 | 취소를 시작한 주체 기준 |
| 유형 | 전체, 취소, 반품, 교환 | 전체 | 클레임 유형 기준 |
| 상태 | 공통 클레임 상태 전체 | 전체 | 정확한 상태 기준 |
| 처리기한 | 전체, 기한 초과, 24시간 이내 | 전체 | 마감이 있는 건만 계산 |

### 15-4. 진행그룹 분류

| 그룹 | 포함 상태 |
|---|---|
| 신규요청 | 요청 접수, 확인 중, 승인 대기 |
| 처리중 | 승인, 보류, 회수 대기, 회수 중, 회수 완료, 환불 대기, 교환 발송 대기 |
| 완료 | 거부, 환불 완료, 교환 발송, 철회, 처리 완료 |

각 진행그룹에는 현재 필터 전 원본 목록 기준 건수를 표시한다.

### 15-5. 클레임 목록 컬럼

| 순서 | 컬럼 | 표시 항목 |
|---:|---|---|
| 1 | 마켓 / 주문 | 마켓명, 스토어명, 주문번호 |
| 2 | 유형 / 상태 | 취소·반품·교환, 공통 처리상태, 클레임 ID |
| 3 | 접수 주체 / 사유 | 구매자 신청 또는 판매자 직접취소, 접수 사유 |
| 4 | 대상 상품 | 대표 상품명 또는 대상 상품 수, 요청 수량 |
| 5 | 처리기한 | 마감일시, 기한 초과 여부, 접수일시 |
| 6 | 처리 | 유형별 단일 진입 버튼 |

목록의 처리 버튼은 다음 세 가지로 단순화한다.

| 유형 | 목록 버튼 |
|---|---|
| 취소 | 취소처리 |
| 반품 | 반품처리 |
| 교환 | 교환처리 |
| 판매자 직접취소 | 상세보기 |

승인, 보류, 입고확인, 재배송 등 실제 작업 버튼은 목록에 노출하지 않고 처리창에서 현재 상태에 맞게 계산한다.

### 15-6. 공통 클레임 상태

| 상태 | 의미 |
|---|---|
| 요청 접수 | 구매자 요청이 처음 수집됨 |
| 확인 중 | 판매자 확인이나 출고 여부 판단 중 |
| 승인 대기 | 승인 또는 입고확인 등 판매자 작업 대기 |
| 승인 | 요청이 승인됨 |
| 거부 | 요청이 거부되어 종료됨 |
| 보류 | 추가 확인이나 구매자 안내를 위해 중단됨 |
| 회수 대기 | 상품 회수 시작 전 |
| 회수 중 | 반품·교환 상품 이동 중 |
| 회수 완료 | 판매자 또는 지정 장소에 도착 |
| 환불 대기 | 반품 승인 후 환불 결과 대기 |
| 환불 완료 | 환불 결과 확인 |
| 교환 발송 대기 | 교환품 준비·송장 등록 대기 |
| 교환 발송 | 교환품 재배송 처리 확인 |
| 철회 | 구매자가 요청을 철회함 |
| 처리 완료 | 클레임 최종 종료 |

취소에는 회수·교환발송 상태를 사용하지 않는다. 반품에는 교환발송 상태를 사용하지 않는다.

### 15-7. 처리 상세창 구성

처리 상세창은 다음 내용을 순서대로 제공한다.

1. 클레임 유형과 현재 공통 상태
2. 마켓, 스토어, 주문번호, 클레임 ID
3. 처리기한과 기한 초과 여부
4. 현재 단계
5. 다음 작업
6. 주의사항
7. 신청자와 신청 사유
8. 신청 당시 주문·배송·소싱 상태
9. 회수 배송정보
10. 교환 재배송정보
11. 대상 상품, 옵션, 주문수량, 요청수량, 상품별 상태
12. 현재 실행 가능한 처리 작업
13. 상태 이력

### 15-8. 상세 데이터 항목

| 구분 | 항목 |
|---|---|
| 식별 | 마켓, 스토어, 주문번호, 상품주문번호, 클레임 ID |

## 16. 구매자 클레임 처리 공통 규칙

### 16-1. 작업 노출 원칙

- 목록에는 유형별 단일 처리 버튼만 표시한다.
- 처리창에는 마켓, 클레임 유형, 현재 상태가 모두 맞는 작업만 표시한다.
- 조회만 가능한 단계에는 실행 버튼을 만들지 않는다.
- 처리 완료, 철회, 거부 등 종료된 건에는 실행 버튼을 만들지 않는다.
- 마켓에서 자동으로 완료한 건에는 입고확인이나 승인 버튼을 다시 만들지 않는다.
- 실행 기능이 준비되지 않았거나 계정 사용승인이 끝나지 않으면 성공을 흉내 내지 않는다.
- 사용자가 작업을 실행한 직후 임의로 완료 처리하지 않고 외부 결과가 확인된 뒤 상태를 확정한다.

### 16-2. 취소 공통 흐름

```text
취소 요청
├─ 출고 전 ─ 취소 승인 또는 출고중지 완료 ─ 취소 완료
└─ 이미 출고 ─ 이미출고 처리 ─ 반품 회수 흐름으로 전환
```

- 취소 요청 당시와 현재 출고상태를 모두 확인한다.
- 전체·부분 취소 수량을 구분한다.
- 구매가 시작되지 않았으면 구매 작업을 중단한다.
- 구매가 끝났으면 공급처 취소·환불 필요 상태를 별도로 남긴다.
- 발송과 취소가 동시에 진행되면 최신 상태를 다시 확인하고 둘 중 하나만 실행한다.

### 16-3. 반품 공통 흐름

```text
반품 요청
  └─ 접수·승인 판단
      ├─ 회수 대기 ─ 회수 중 ─ 회수 완료
      │   └─ 입고 확인 ─ 반품 승인 ─ 환불 대기 ─ 환불 완료 ─ 처리 완료
      ├─ 보류 ─ 보류 해제 ─ 이전 처리단계 복귀
      └─ 거부 ─ 종료
```

- 회수 배송과 최초 배송을 별도로 저장한다.
- 주문수량과 반품 요청수량을 함께 표시한다.
- 입고확인은 실물 도착을 확인하는 작업이고 반품 승인은 환불 진행을 승인하는 작업이다.
- `반품완료`라는 단일 공통 실행 버튼을 두지 않는다.
- 반품 승인 이후 환불·완료 결과는 후속 상태 확인으로 반영한다.
- 빠른환불이나 마켓 자동승인으로 이미 처리된 건은 다시 입고확인·승인하지 않는다.

### 16-4. 교환 공통 흐름

```text
교환 요청
  └─ 접수·승인 판단
      ├─ 회수 대기 ─ 회수 중 ─ 회수 완료
      │   └─ 입고 확인 ─ 교환품 준비 ─ 재배송 송장 등록 ─ 교환 발송 ─ 처리 완료
      ├─ 보류 ─ 보류 해제 ─ 이전 처리단계 복귀
      └─ 거부 ─ 종료
```

- 기존 상품의 회수송장과 교환품 재배송송장을 분리한다.
- 교환상품 재고와 추가 구매 필요 여부를 확인한다.
- 재배송은 택배사와 새 송장번호가 모두 있어야 실행할 수 있다.
- 교환품 품절이면 자동 완료하지 않고 보류 또는 거부 판단 대상으로 둔다.

## 18. 클레임 처리 입력 항목

| 작업 | 입력 항목 | 필수 조건 |
|---|---|---|
| 취소 승인 | 처리 대상과 수량 확인 | 현재 취소 승인 가능 상태 |
| 출고중지 완료 | 실제 미출고 여부 확인 | 물류 인계 전 |
| 이미출고 처리 | 출고 사실 확인 | 실제 물류 인계 후 |
| 반품·교환 보류 | 보류 사유, 안내 내용 | 사유 기록 필요 |
| 보류 해제 | 해제 사유 또는 확인 내용 | 보류 상태 |
| 반품·교환 거부 | 거부 사유, 확인 근거 | 거부 가능 상태와 허용 사유 |
| 반품 입고 확인 | 입고 수량, 검수 결과, 입고일시 | 요청수량을 초과할 수 없음 |
| 반품 승인 | 승인 수량, 검수 결과 | 입고 또는 승인 가능 상태 |
| 교환 수거·입고 확인 | 입고 수량, 검수 결과 | 요청수량을 초과할 수 없음 |
| 교환품 재배송 | 택배사, 새 송장번호 | 두 값 모두 필수 |

공통 입력 규칙:

- 수량은 1 이상의 정수다.
- 처리 수량은 남은 요청수량을 초과할 수 없다.
- 기타 사유를 선택하면 상세 사유를 필수로 입력한다.
- 처리 메모는 내부 운영 기록이며 구매자에게 자동 전송되는 문구로 간주하지 않는다.
- 실행 중에는 같은 작업을 다시 누를 수 없다.

## 19. 공통 처리 안전규칙

### 19-1. 실행 직전 확인

상태를 바꾸는 모든 기능은 실행 직전에 다음을 확인한다.

- 주문 또는 클레임이 아직 같은 상태인지
- 다른 사용자가 먼저 처리하지 않았는지
- 새 취소·반품·교환이 발생하지 않았는지
- 대상 수량이 남아 있는지
- 필수 입력값이 유효한지
- 현재 계정에서 해당 기능을 실행할 수 있는지

### 19-2. 중복 실행

- 더블클릭이나 반복 요청이 같은 작업을 두 번 완료시키면 안 된다.
- 이미 처리된 작업이면 현재 결과를 다시 보여주고 중복 상태를 만들지 않는다.
- 같은 주문상품·클레임·수량의 진행 중 작업은 하나만 유지한다.

### 19-3. 경합

- 주문확인 중 취소가 발생하면 취소 상태를 우선 확인한다.
- 발송 중 취소가 발생하면 실제 출고 여부를 확인한 뒤 취소 또는 반품 중 하나로 정리한다.
- 반품과 교환은 같은 주문상품·수량에서 동시에 활성화할 수 없다.
- 두 사용자가 같은 데이터를 수정하면 나중 사용자의 화면 값으로 조용히 덮어쓰지 않는다.

### 19-4. 성공·실패·결과 확인 중

| 결과 | 상태 처리 | 사용자에게 보여줄 내용 |
|---|---|---|
| 성공 확인 | 다음 상태로 변경 | 처리 작업, 결과, 처리시각 |
| 실패 확인 | 기존 상태 유지 | 실패 이유와 다음 조치 |
| 일부 성공 | 성공 대상만 변경 | 성공·실패·제외 대상별 결과 |
| 결과 확인 중 | 완료로 변경하지 않음 | 확인 중 상태와 재확인 안내 |
| 상태 변경 충돌 | 최신 데이터를 다시 조회 | 누가 또는 무엇이 먼저 변경했는지 안내 |

### 19-5. 상태 이력

상태를 변경하거나 변경을 시도한 작업은 다음 내용을 남긴다.

- 대상 주문·주문상품·클레임
- 실행 작업
- 실행 전 상태와 실행 후 상태
- 입력 사유와 수량
- 실행자
- 요청시각과 결과 확인시각
- 성공, 실패, 일부 성공, 결과 확인 중
- 실패 사유와 재처리 여부

## 22. 마켓연동 페이지

마켓연동은 주문수집과 상태변경 기능에 사용할 판매계정을 관리하는 페이지다. 연동 기술 규격은 설명하지 않고 사용자가 입력·확인·처리하는 항목만 정의한다.

### 22-1. 페이지 논리 구성

```text
마켓연동 페이지
├─ 페이지 제목
├─ 마켓 추가
├─ 활성 계정 수 / 전체 계정 수
├─ 계정 목록
├─ 계정 추가·설정 입력창
├─ 연결 확인 결과
├─ 삭제 확인
└─ 빈 상태·로딩·오류 상태
```

### 22-2. 계정 목록 컬럼

| 순서 | 컬럼 | 표시·기능 |
|---:|---|---|
| 1 | 마켓 | 스마트스토어, 쿠팡, 11번가, G마켓, 옥션 |
| 2 | 스토어명 | 주문 목록에서 판매처를 구분하는 이름 |
| 3 | 연동상태 | 연결됨, 확인 대기, 오류, 재인증 필요 |
| 4 | 활성 | 주문수집과 실행 기능 사용 여부 |
| 5 | 관리 | 연결 확인, 설정, 삭제 |

플랫폼 수수료율, 마지막 수집, 최근 결과는 현재 기본 컬럼에 포함하지 않는다.

### 22-3. 공통 입력 항목

비밀값은 저장 후 원문을 다시 표시하지 않는다. 새 비밀값을 저장하면 기존 값은 폐기하고 연결 확인이 끝날 때까지 상태변경 기능을 비활성화한다.

### 22-4. 계정 상태

| 상태 | 의미 | 활성 가능 여부 |
|---|---|---|
| 확인 대기 | 새 계정 또는 새 연결정보의 확인 전 | 주문수집·상태변경 불가 |
| 연결됨 | 계정 연결 확인 완료 | 사용자가 활성화하면 사용 가능 |
| 오류 | 연결 확인 실패 | 비활성, 설정 수정 필요 |
| 재인증 필요 | 연결정보 만료 또는 갱신 필요 | 비활성, 새 연결정보 필요 |
| 연결 해제 | 사용 중지 또는 연결 제거 | 사용 불가 |

### 22-5. 기능 규칙

| 기능 | 조건 | 결과 |
|---|---|---|
| 마켓 추가 | 필수값 입력, 중복 계정 아님 | 확인 대기 계정 생성 후 연결 확인 |
| 연결 확인 | 저장된 계정 존재 | 성공 시 연결됨, 실패 시 오류 또는 재인증 필요 |
| 활성화 | 연결됨 상태 | 주문수집과 허용된 상태변경 대상에 포함 |
| 일시정지 | 활성 계정 | 새 주문수집과 상태변경 대상에서 제외 |
| 설정 | 계정 존재 | 스토어명·사업자번호 수정, 필요한 경우 연결정보 교체 |
| 삭제 | 진행 중 작업 없음 또는 안전 종료 확인 | 목록에서 제거하고 이후 주문수집 대상에서 제외 |

- 연결됨과 활성은 다른 값이다. 연결이 정상이어도 사용자가 비활성화할 수 있다.
- 아직 실제 처리를 지원하지 않는 마켓은 계정을 저장하더라도 주문수집·상태변경 기능을 활성화하지 않는다.
- 삭제 전 해당 계정의 진행 중 수집·처리 작업을 확인한다.
- 계정을 삭제해도 이미 수집된 주문과 처리이력은 삭제하지 않는다.
- 계정 조회 실패 시 데모 계정을 실계정처럼 자동 대체하지 않는다.

| 필터 결과 0건 | 조건에 맞는 주문 또는 구매자 클레임이 없음을 표시한다. |
| 조회 실패 | 오류 이유와 다시 시도 기능을 제공한다. |
| 다음 목록 조회 중 | 기존 목록을 유지하면서 추가 조회 상태를 표시한다. |
| 상태 변경 중 | 해당 작업의 중복 실행을 차단한다. |
| 상태 변경 실패 | 입력과 현재 목록을 유지하고 실패 이유를 표시한다. |
| 권한 없음 | 실행 기능을 제공하지 않고 조회 가능 범위만 유지한다. |

## 25. 소싱 구매 신청과 결제 분리

1. `소싱하기`에서 상품·옵션·수량을 확정한다.
2. 소싱라이프에 저장된 배대지 수령 프로필을 선택한다. 자체 배대지나 창고 재고를 운영하는 기능은 아니다.
3. `구매대행 신청` 시 주문은 `PAYMENT_WAITING`으로 전환하고 결제는 실행하지 않는다.
4. 결제대기 화면에서 신청 상품·배대지 정보를 확인하고 중국 판매자에게 상품 가격·재고·중국 내 배송 조건을 채팅으로 문의할 수 있다. `깎아줘`는 가격 인하 요청을 시작하고 `깎아줘 취소`는 진행 중 요청만 철회한다. 두 액션은 채팅 메시지와 요청 상태만 변경하며 가격·결제 상태를 자동 변경하지 않는다.
5. 처리하기 컬럼의 `결제하기`를 다시 눌러 결제 화면으로 이동한다.
6. 결제 완료 전에는 소싱라이프 주문번호와 국내송장을 생성하지 않는다.
7. 결제 완료 시 선택 배송대행지 사이트를 열고 주문서를 자동입력한다.
8. `접수대기`와 `접수신청`을 동일한 접수 단계로 실행하고 즉시 발급된 택배사·국내송장번호를 주문에 저장한다.
9. 결제완료 화면에는 실제 결제정보, 소싱라이프 주문번호, 배송대행지 주문서 접수·국내송장 반영 결과와 기존 중국 판매자 채팅을 표시한다.

현재 프로토타입은 7~8의 외부 사이트 및 접수 화면을 생략하고 결제완료 시 더미 국내송장을 즉시 생성한다. 자동 배송중 처리 ON은 이 더미 송장이 마켓에 전송된 것으로 시뮬레이션하고, OFF도 내부 주문은 배송중으로 이동하되 마켓 상태는 결제완료로 유지한다.

소싱 결제완료부터 배송완료까지 행 자세히 보기의 처리하기 영역에 `소싱상품관리`와 `배송추적`을 표시한다. 목록 처리하기에는 두 조회 기능을 표시하지 않는다. 소싱상품관리 화면에서는 결제상품·결제정보와 중국 판매자 채팅을 조회·작성할 수 있으며 재결제를 허용하지 않는다.

`결제하기`는 상품준비의 결제대기 주문에서만 허용한다. 발송대기·배송중·배송완료는 소싱라이프 결제완료 또는 외부구매 완료가 필수이며, 미결제 데이터가 유입되면 배송중 전환과 송장 전송을 차단하고 `결제상태 불일치`로 표시한다.

처리하기 컬럼은 실행 버튼을 우선 표시하고, 실행 기능이 끝난 주문에서는 `처리보류`, `주문취소`, `반품완료`, `교환완료` 같은 운영 결과만 표시한다. 중국배송중, 통관 중, 국내 배송중, 배송완료, 구매확정 배지는 진행상태 컬럼에 표시한다.

## 26. 소싱환불 업무로직

### 26-1. 페이지 책임

| 페이지·영역 | 책임 |
|---|---|
| `소싱상품관리 > 구매대행 신청 상품` | `반품·환불 신청` 신규 요청과 `환불 진행`·`환불 내역` 조회 진입점 |
| 주문수집 행 자세히 보기 `소싱상품` | TaoWorld 구매 주문라인·CNY 환불금액·현재 상태·원본 상태코드 요약 |
| 취소·반품·교환 상세 | 마켓 처리와 별개인 구매 보상 상태·참조·다음 조치 표시 |
| 주문현황 `소싱 환불` 그룹 | 실제 환불 상태 8개와 미접수·반품·거절·대사 이슈 집계 |

사이드바에 소싱환불 메뉴를 추가하지 않는다. `/orders?view=claims`는 구매자 마켓 클레임과 판매자 직접취소 완료 이력을 접수 주체로 구분해 함께 표시한다.

### 26-2. 요청 처리 순서

1. 주문이 소싱라이프 `결제완료`부터 `국내 배송중` 사이이고 `sourcingLifeOrderId`를 갖는지 확인한다. `배송완료`부터 신규 요청을 차단하되 기존 환불 조회는 유지한다.
2. 외부 직접구매와 기존 환불 중복 요청을 차단한다.
3. 주문상품, 소싱 결제금액, 현재 물류 단계를 보여준다.
4. 요청 유형·사유·수량·금액·상세 사유·선택적 마켓 클레임 ID를 검증한다.
5. 마켓 취소·구매자 환불이 별도임을 사용자가 확인한다.
6. demo는 `REQUESTED` 원장을 만들고 주문 상태·마켓 클레임 상태는 변경하지 않는다.
7. 활성 상태에서는 송장 전송과 직접전달을 차단한다.
8. 소싱라이프 결과 이벤트로 반품 필요, 차감액, 예상 환불액과 최종 상태를 갱신한다.
9. 마켓·소싱 양쪽 결과를 대사하고 한쪽만 성공하면 나머지 후속 작업을 유지한다.
10. `REFUNDED`이고 국내배송 전이면 `다시 소싱하기`를 허용한다. 실행 시 현재 환불을 `sourcingRefundHistory`에 보존하고 이전 `sourcingLifeOrderId`, 결제, TaoWorld 구매라인, 매칭, 배대지, 결제대기 시각, 국내송장을 제거한 뒤 `PREPARING / NOT_LINKED / MATCH_REQUIRED`로 전환한다.
11. 재소싱 주문은 기존 `소싱하기 → 구매대행 신청 → 결제대기 → 상품 결제` 흐름을 그대로 사용하며, 새 결제 전에는 발송 처리할 수 없다.

### 26-3. 클레임 연결

`purchaseCompensationStatus`는 `NOT_REQUIRED`, `PENDING`, `IN_PROGRESS`, `SUCCEEDED`, `FAILED`, `NEEDS_ATTENTION`, `UNKNOWN`을 사용한다. 마켓 승인·거부 버튼 실행은 이 값을 자동 성공으로 만들지 않는다. `NEEDS_ATTENTION`, `FAILED`, `UNKNOWN`인 취소·반품 demo 건만 상세에서 소싱환불 후속 요청을 시작할 수 있으며, 실행 뒤에도 마켓 클레임 `normalizedStatus`는 그대로 유지한다.
