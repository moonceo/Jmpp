# 소싱하기 모달 와이어프레임

## 1. 화면 목적

소싱하기 모달은 주문 상품을 소싱라이프 상품과 매칭하고, 주문상태에 따라 주문확인 또는 소싱라이프 결제 화면 이동을 진행하는 화면이다.

## 2. 모드 기준

| 모드 | 대상 상태 | 동작 |
|---|---|---|
| `match-only` | `NEW` | 소싱 후보 확인, 매칭 저장, 주문확인 동시 처리 |
| `payment` | `PREPARING` | 소싱 후보 확인, 옵션 선택, 매칭 저장, 소싱라이프 결제 화면 이동 |

별도 독립 결제 버튼은 제공하지 않는다.

## 3. 디자인 기준

- Material UI Dialog와 MUI X Data Grid의 작업 콘솔 구조를 기준으로 한다.
- 단순 후보 카드 나열이 아니라, 좌측 주문 원본, 중앙 후보 목록, 우측 선택/진행 패널의 3분할 구조로 배치한다.
- 중앙 후보 목록은 이미지, 상품명, 옵션, 예상원가, 예상마진, 일치율을 비교할 수 있는 리스트형 데이터그리드로 표현한다.
- 우측 선택 패널에는 선택한 후보와 진행 액션을 모아 작업자가 다음 단계를 판단할 수 있게 한다.
- 후보가 없거나 적합하지 않은 경우 `후보 없음, 소싱라이프에서 찾기` 버튼을 명확히 제공한다.

## 4. 화면 구성

1. 모달 헤더
   - 제목: `소싱하기`
   - 주문상태 배지
2. 좌측 주문 원본 패널
   - 상품이미지, 상품명, 옵션명, 수량
   - 마켓, 연동 계정, 마켓 주문번호
   - 수령인명, 수령인 연락처, 개인통관부호
3. 중앙 소싱 후보 영역
   - 후보 썸네일
   - 후보 상품명
   - 후보 옵션
   - 예상원가
   - 예상마진
   - 일치율
4. 우측 선택 상품 영역
   - 선택한 소싱상품명
   - 선택 옵션
   - 수량
   - 예상 결제금액
5. 하단 버튼
   - `후보 없음, 소싱라이프에서 찾기`
   - `매칭 저장`
   - `주문확인`
   - `소싱라이프 결제 화면 이동`

## 5. 상태별 버튼 표시

| 상태 | 표시 버튼 |
|---|---|
| `NEW` | `후보 없음, 소싱라이프에서 찾기`, `매칭 저장`, `주문확인` |
| `PREPARING` | `후보 없음, 소싱라이프에서 찾기`, `매칭 저장`, `소싱라이프 결제 화면 이동` |

`NEW` 상태의 `소싱하기`는 매칭 저장과 주문확인을 함께 처리할 수 있다.
`PREPARING` 상태의 소싱라이프 결제 화면 이동은 `소싱하기` 흐름 안에서 처리한다.

## 6. 대표 더미데이터

| 항목 | 값 |
|---|---|
| 주문 상품명 | 어린이 연습용 스펀지공 안전 보관 가방 포함 |
| 주문 옵션 | 9인치 화이트 야구공 12개 |
| 후보 상품명 | PU 해면 아동 연습용 야구공 세트 |
| 후보 옵션 | 9인치 화이트 12개입 |
| 일치율 | 86% |
| 예상원가 | 14,600 |
| 예상마진 | 5,200 |

## 7. 빈 상태와 오류 상태

| 상태 | 표시 |
|---|---|
| 후보 없음 | `후보 없음, 소싱라이프에서 찾기` 버튼 표시 |
| 필수정보 누락 | 필수정보 필요 표시 |
| 소싱라이프 연동 실패 | 현재 주문상태 유지, 소싱상태 `HOLD`, 실패 사유 표시 |
