# 구매자 클레임 처리 와이어프레임

## 1. 화면 목적

네이버·쿠팡 구매자가 신청한 취소·반품·교환의 현재 단계, 처리기한, 다음 작업을 한 화면에서 확인한다. 판매자 직접 취소는 이 화면의 대상이 아니다.

## 2. 목록

```text
[취소/반품/교환]
[오늘][3일][7일][30일][전체] [검색________] [마켓]       [실데이터/데모] [새로고침]
[전체 8] [신규요청 2] [처리중 6] [완료 0]
                                           [유형] [상태] [처리기한]
┌마켓/주문┬유형/상태┬구매자 사유┬대상 상품┬처리기한┬상세┐
│ ...     │ ...     │ ...       │ ...     │ ...    │보기│
└─────────┴─────────┴───────────┴─────────┴────────┴────┘
```

페이지와 테이블의 여백, 테두리, 활성 탭 색상, 검색창 높이, 필터 배치는 주문수집 화면과 동일하게 유지한다.

기본값은 `MVP 데모`다. 데모에는 네이버·쿠팡의 취소·반품·교환 정상·예외 8건을 노출하며 모든 액션은 마켓 미전송이다. 목록의 단일 `취소처리`, `반품처리`, `교환처리` 버튼으로 공통 처리 모달에 진입한다. `실데이터 조회`는 구매자 요청만 조회하고 공식 API가 있는 세부 작업만 모달 안에 표시한다.

## 3. 상세

```text
[유형] [상태] [기한 초과]               처리기한
마켓 · 스토어 / 주문번호 / 클레임 ID

현재 단계
다음 작업
주의사항

[신청자] [신청 사유] [주문 상태] [배송 상태]
[회수 배송] [교환 재배송]
[대상 상품 / 옵션 / 요청수량]

처리 작업
- 네이버 취소: 취소 승인
- 네이버 반품: 승인 / 보류 / 보류 해제 / 거부
- 네이버 교환: 수거 완료 / 재배송 / 보류 / 보류 해제 / 거부
- 쿠팡 취소: 출고중지 완료 / 이미출고
- 쿠팡 반품: 입고 확인 / 승인
- 쿠팡 교환: 입고 확인 / 거부 / 재배송 송장

상태 이력
```

목록에는 세부 API 버튼을 직접 표시하지 않는다. 처리 모달에서 요청 사유와 주문·소싱·배송 진행상황을 먼저 확인한 후 현재 마켓 원상태에 허용된 API 버튼만 표시한다.

교환 재배송은 택배사와 새 송장번호가 모두 있어야 실행할 수 있다. 데모 액션 후에는 로컬 상태와 이벤트 이력만 바뀌며 토스트에서 마켓 미전송임을 다시 알린다.

## 4. 예외 원칙

- 처리기한 초과는 목록과 상세에서 빨간색으로 강조한다.
- 단순 조회나 판매자센터 수동 처리만 가능한 작업은 실행 버튼으로 표시하지 않는다.
- 회수 실물이나 송장을 확인하지 않은 상태에서 완료로 선반영하지 않는다.
- 실데이터의 승인·거부·입고·재배송은 provider 쓰기 UAT가 끝날 때까지 성공으로 선반영하지 않는다. 실행 어댑터 미연결 상태도 판매자센터 링크로 대체하지 않는다.
