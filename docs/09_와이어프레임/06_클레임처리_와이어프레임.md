# 취소·반품·교환 처리 와이어프레임

## 1. 화면 목적

네이버·쿠팡 구매자가 신청한 취소·반품·교환과 주문수집에서 완료한 판매자 직접취소를 한 화면에서 확인한다. 두 흐름은 접수 주체로 구분한다.

## 2. 목록

```text
[취소/반품/교환]
[오늘][3일][7일][30일][전체] [검색________] [마켓]       [실데이터/데모] [새로고침]
[전체 9] [신규요청 2] [처리중 6] [완료 1]
                           [접수 주체] [유형] [상태] [처리기한]
┌마켓/주문┬유형/상태┬접수 주체/사유┬대상 상품┬처리기한┬상세┐
│ ...     │ ...     │ ...          │ ...     │ ...    │보기│
└─────────┴─────────┴──────────────┴─────────┴────────┴────┘
```

페이지와 테이블의 여백, 테두리, 활성 탭의 흑백 명도 대비, 검색창 높이, 필터 배치는 주문수집 화면과 동일하게 유지한다.

기본값은 `MVP 데모`다. 데모에는 네이버·쿠팡 구매자 클레임 8건과 판매자 직접취소 완료 1건을 노출하며 모든 액션은 마켓 미전송이다. 구매자 신청은 `취소처리`, `반품처리`, `교환처리`로, 판매자 직접취소는 `상세보기`로 진입한다.

## 3. 상세

```text
[유형] [상태] [기한 초과]               처리기한
마켓 · 스토어 / 주문번호 / 클레임 ID

현재 단계
다음 작업
주의사항

[신청자] [신청 사유] [주문 상태] [배송 상태]
[회수 배송] [교환 재배송]
[대상 상품 / 옵션 / 요청수량]

처리 작업
- 네이버 취소: 취소 승인
- 네이버 반품: 승인 / 보류 / 보류 해제 / 거부
- 네이버 교환: 수거 완료 / 재배송 / 보류 / 보류 해제 / 거부
- 쿠팡 취소: 출고중지 완료 / 이미출고
- 쿠팡 반품: 입고 확인 / 승인
- 쿠팡 교환: 입고 확인 / 거부 / 재배송 송장

소싱 구매 후속조치
- 상태: 후속조치 없음 / 소싱환불 검토 필요 / 요청 대기 / 처리 중 / 완료 / 실패 / 결과 확인 필요
- 소싱환불 참조번호와 안내
- 취소·반품의 검토 필요 demo 건: 소싱환불 요청

상태 이력
```

목록에는 세부 API 버튼을 직접 표시하지 않는다. 처리 모달에서 요청 사유와 주문·소싱·배송 진행상황을 먼저 확인한 후 현재 마켓 원상태에 허용된 API 버튼만 표시한다.

교환 재배송은 택배사와 새 송장번호가 모두 있어야 실행할 수 있다. 데모 액션 후에는 로컬 상태와 이벤트 이력만 바뀌며 토스트에서 마켓 미전송임을 다시 알린다.

## 4. 예외 원칙

- 처리기한 초과는 목록과 상세에서 굵은 글자와 고대비 테두리로 강조한다.
- 단순 조회나 판매자센터 수동 처리만 가능한 작업은 실행 버튼으로 표시하지 않는다.
- 회수 실물이나 송장을 확인하지 않은 상태에서 완료로 선반영하지 않는다.
- 실데이터의 승인·거부·입고·재배송은 provider 쓰기 UAT가 끝날 때까지 성공으로 선반영하지 않는다. 실행 어댑터 미연결 상태도 판매자센터 링크로 대체하지 않는다.
- 마켓 `처리 작업`과 `소싱 구매 후속조치`는 별도 섹션과 상태를 사용한다. 어느 한쪽 버튼이 다른 쪽을 자동 완료하지 않는다.
