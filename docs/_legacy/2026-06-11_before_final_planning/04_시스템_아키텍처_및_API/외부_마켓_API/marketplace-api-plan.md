# 외부 마켓 API 연동 계획

## 목적

네이버 스마트스토어와 쿠팡 주문을 수집해 주문수집소싱라이프 내부 주문 관리 화면에서 일관된 형태로 처리한다.

## 관리 원칙

- 공식 문서를 통째로 복사하지 않는다.
- 프로젝트에는 공식 링크, 확인일, 구현에 필요한 핵심 판단만 남긴다.
- 개발 직전에는 각 API의 최신 문서를 다시 확인한다.
- 인증 정보, API Key, Secret, 토큰은 문서나 저장소에 기록하지 않는다.

## 1차 연동 범위

- 인증 정보 등록 및 보관 구조
- 마켓별 주문 목록 수집
- 마켓별 주문 상세 조회
- 내부 주문 모델로 정규화
- 주문 상태 매핑
- 수집 실패 로그와 재시도

## 2차 연동 후보

- 발주 확인
- 발송 처리
- 배송 지연 처리
- 취소/반품/교환 처리
- 고객 문의 수집 및 답변
- 정산 데이터 수집

## 공통 내부 모델 검토 항목

- 외부 마켓 구분
- 외부 주문 ID
- 외부 상품 주문 ID
- 주문 상태
- 결제 상태
- 클레임 상태
- 구매자 정보
- 수취인 정보
- 배송지 정보
- 상품명
- 옵션명
- 수량
- 결제 금액
- 배송비
- 택배사
- 송장번호
- 주문 생성일
- 주문 변경일
- 수집일

## 구현 순서 제안

1. 네이버/쿠팡 인증 설정 저장 구조를 만든다.
2. 마켓별 API 클라이언트를 분리한다.
3. 주문 목록 수집 API를 먼저 연결한다.
4. 주문 상세 조회로 내부 주문 모델을 채운다.
5. 마켓별 상태 코드를 내부 상태로 매핑한다.
6. 실패 로그와 재수집 기능을 만든다.
7. 발주/발송 같은 상태 변경 API는 주문 조회 안정화 후 연결한다.

## 검증 기준

- 같은 기간을 여러 번 수집해도 주문이 중복 생성되지 않는다.
- 외부 주문 변경 사항이 내부 주문에 반영된다.
- API 실패 시 운영자가 원인과 재처리 가능 여부를 확인할 수 있다.
- 개인정보는 필요한 범위만 저장하고 화면에는 필요한 곳에서만 노출한다.
