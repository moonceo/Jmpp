## 우선 검토 범위

주문 수집과 운영 자동화를 위해 우선 확인할 영역이다.

- 인증: OAuth 2.0 Client Credentials 방식 인증 토큰 발급
- 주문 조회
  - 상품 주문 목록 조회
  - 조건형 상품 주문 상세 내역 조회
  - 변경 상품 주문 내역 조회
  - 상품 주문 상세 내역 조회
- 발주/발송 처리
  - 발주 확인 처리
  - 발송 처리
  - 발송 지연 처리
  - 배송 희망일 변경 처리
- 취소/반품/교환
- 문의
  - 고객 문의 조회
  - 답변 등록/수정
- 정산

## 주문 연동 시 주의사항

- 주문 수집은 목록 조회와 상세 조회를 분리해서 설계한다.
- 변경분 수집이 필요한 경우 변경 상품 주문 내역 조회 API를 먼저 검토한다.
- 상품 주문 상세 내역 조회는 요청 가능한 상품 주문 번호 수 제한을 확인하고 배치 처리한다.
- 발주 확인, 발송 처리처럼 상태를 변경하는 API는 멱등성, 실패 재시도, 부분 실패 기록이 필요하다.
- 주문/클레임 처리 응답 구조체가 API마다 다를 수 있으므로 공통 응답으로 단정하지 않는다.

## 구현 전 체크리스트

- 애플리케이션 등록과 API 사용 권한 확보 여부
- 인증 토큰 발급/만료/재발급 방식
- 호출 제한과 재시도 정책
- 주문 상태 코드와 내부 주문 상태 매핑
- 개인정보 저장 범위와 마스킹 정책
- 실패 요청 재처리 화면 또는 운영 로그
