# 주문관리 업무 흐름

> **참조 안내**: 본 문서의 내부 상태 표와 네이버/쿠팡 매핑 표는 최종 모델 문서로 이관되었습니다.

## 목적

네이버, 쿠팡 주문을 하나의 주문관리 화면에서 처리하기 위한 내부 업무 기준을 정의한다.

이 문서는 외부 API 원문 설명이 아니라 주문수집소싱라이프에서 사용할 공통 메뉴, 내부 상태, 소싱라이프 결제 흐름, 배대지 유형, 송장 등록 기준을 정리한 프로그램 설계 기준이다.

## 주문관리 메뉴 구조

주문관리 소카테고리는 다음 구조를 기본으로 한다.

- 전체
- 신규주문
- 상품준비
- 발송대기
- 배송중
- 배송완료
- 취소/반품/교환

## 기본 업무 흐름

```text
신규주문
  -> 상품준비
  -> 발송대기
  -> 배송중
  -> 배송완료
```

클레임이 발생한 주문은 진행 단계와 별도로 취소/반품/교환 메뉴에서 확인할 수 있어야 한다.

## 메뉴별 역할

| 메뉴 | 역할 |
|---|---|
| 전체 | 모든 마켓과 모든 상태의 주문을 조회한다. |
| 신규주문 | 네이버/쿠팡에서 새로 수집된 결제완료 주문을 확인한다. |
| 상품준비 | 소싱라이프 상품매칭, 옵션/수량 확인, 원가/마진 검토, 소싱라이프 결제, 배대지 입력을 처리한다. |
| 발송대기 | 소싱라이프 결제와 배대지 입력은 끝났지만 국내송장이 없거나 마켓 송장 등록이 아직 안 된 주문을 관리한다. |
| 배송중 | 네이버/쿠팡에 송장 등록이 완료되어 배송 추적 중인 주문을 관리한다. |
| 배송완료 | 배송 완료된 주문을 관리한다. |
| 취소/반품/교환 | 취소, 반품, 교환 등 클레임 주문을 관리한다. |

## 상품준비 단계

상품준비 단계는 외부 마켓 주문을 소싱라이프 구매 흐름으로 연결하는 작업 공간이다.

주요 작업:

- 소싱라이프 상품매칭
- 옵션/수량 확인
- 원가/마진 검토
- 소싱라이프 결제
- 배대지 입력

화면 내 세부 상태 예시:

- 상품매칭 필요
- 검토 필요
- 소싱라이프 결제대기
- 소싱라이프 결제완료
- 배대지 입력대기

## 발송대기 단계

발송대기는 소싱라이프 결제와 배대지 입력 이후, 네이버/쿠팡에 등록할 국내송장을 기다리거나 등록 대기 중인 상태다.

발송대기에 남는 경우:

- 배대지 입력은 끝났지만 국내송장이 아직 발급되지 않은 경우
- 국내송장은 확보했지만 네이버/쿠팡에 아직 송장 등록을 하지 않은 경우
- 송장 등록 실패로 재처리가 필요한 경우

화면 내 세부 상태 예시:

- 국내송장 대기
- 송장등록 대기
- 송장등록 실패

## 배대지 유형

배대지는 국내송장 발급 시점에 따라 두 유형으로 구분한다.

| 배대지 유형 | 설명 | 다음 단계 |
|---|---|---|
| 즉시송장형 | 소싱라이프 결제와 배대지 입력 후 국내송장이 바로 발급된다. | 마켓 송장 등록 후 배송중 |
| 입고후송장형 | 물건이 배대지에 도착해야 국내송장이 발급된다. | 발송대기에서 국내송장 대기 |

처리 흐름:

```text
소싱라이프 결제 + 배대지 입력
  -> 국내송장 즉시 발급
    -> 네이버/쿠팡 송장 등록
    -> 배송중

소싱라이프 결제 + 배대지 입력
  -> 국내송장 미발급
    -> 발송대기
    -> 국내송장 확보
    -> 네이버/쿠팡 송장 등록
    -> 배송중
```

## 내부 상태 제안

코드 구현 시 외부 마켓 상태값을 그대로 메뉴로 사용하지 말고 내부 공통 상태를 별도로 둔다.

| 내부 상태 | 화면 표시 | 메뉴 |
|---|---|---|
| `NEW` | 신규주문 | 신규주문 |
| `SOURCING_MATCH_REQUIRED` | 상품매칭 필요 | 상품준비 |
| `SOURCING_REVIEW_REQUIRED` | 검토 필요 | 상품준비 |
| `SOURCING_PAYMENT_PENDING` | 소싱라이프 결제대기 | 상품준비 |
| `SOURCING_PAYMENT_COMPLETED` | 소싱라이프 결제완료 | 상품준비 |
| `FORWARDER_INPUT_PENDING` | 배대지 입력대기 | 상품준비 |
| `DOMESTIC_TRACKING_PENDING` | 국내송장 대기 | 발송대기 |
| `MARKET_INVOICE_PENDING` | 송장등록 대기 | 발송대기 |
| `MARKET_INVOICE_FAILED` | 송장등록 실패 | 발송대기 |
| `SHIPPING` | 배송중 | 배송중 |
| `DELIVERED` | 배송완료 | 배송완료 |
| `CLAIM` | 취소/반품/교환 | 취소/반품/교환 |
| `CANCELED` | 취소완료 | 취소/반품/교환 |

## 네이버 상태 매핑

| 내부 메뉴 | 네이버 상태 기준 |
|---|---|
| 신규주문 | `PAYED` + 내부 미처리 |
| 상품준비 | `PAYED` + 내부 소싱라이프 준비 상태 |
| 발송대기 | `PAYED` + 국내송장 대기 또는 마켓 송장등록 대기 |
| 배송중 | `DELIVERING` |
| 배송완료 | `DELIVERED` |
| 취소/반품/교환 | `claimType`, `claimStatus` 기준 |

주의:

- 네이버는 발주확인을 해도 상품주문상태가 계속 `PAYED`일 수 있다.
- 따라서 네이버 주문은 외부 상태값만으로 신규주문, 상품준비, 발송대기를 구분하면 안 된다.
- 소싱라이프 진행 상태와 마켓 송장 등록 여부를 내부 상태로 관리해야 한다.

## 쿠팡 상태 매핑

| 내부 메뉴 | 쿠팡 상태 기준 |
|---|---|
| 신규주문 | `ACCEPT` |
| 상품준비 | `INSTRUCT` + 내부 소싱라이프 준비 상태 |
| 발송대기 | `INSTRUCT` + 국내송장 대기 또는 마켓 송장등록 대기 |
| 배송중 | `DEPARTURE`, `DELIVERING`, `NONE_TRACKING` |
| 배송완료 | `FINAL_DELIVERY` |
| 취소/반품/교환 | 반품/취소/교환 API 기준 |

주의:

- 쿠팡 송장 업로드는 `INSTRUCT` 상태에서만 가능하다.
- `ACCEPT` 상태 주문은 상품준비중 처리 후 소싱라이프 결제/송장 등록 흐름으로 진행한다.
- 결제완료 상태에서 고객이 배송지를 변경할 수 있으므로 상품준비중 처리 이후 발주서 단건 조회로 배송지 재확인이 필요하다.

## 운영 기준

- 신규주문은 새 주문을 접수하고 처리 시작 여부를 판단하는 메뉴로 유지한다.
- 상품준비는 소싱라이프 결제와 배대지 입력까지의 작업 공간으로 본다.
- 발송대기는 국내송장 대기 또는 마켓 송장등록 대기 공간으로 본다.
- 배송중은 네이버/쿠팡에 송장 등록이 끝난 주문만 포함한다.
- 배송완료는 외부 마켓 배송완료 상태와 내부 배송완료 상태를 함께 확인한다.
- 취소/반품/교환은 정상 배송 흐름과 분리해서 운영자가 즉시 확인할 수 있어야 한다.
