# 주문팡팡 내부 주문 상태 정의서 (Single Source of Truth)

## 1. 문서 목적

본 문서는 주문팡팡의 **내부 주문 상태**를 정의하는 원본 문서다.
다른 모든 문서(기능명세, UI 명세, API 매핑, 프론트엔드 가이드, 운영 매뉴얼)는 본 문서의 상태 코드와 라벨을 그대로 사용하며, 상태를 새로 정의하지 않는다.

핵심 원칙:
- **마켓 주문 상태와 내부 주문 상태는 분리한다.** 화면 메뉴, 처리 가능 액션, 필터는 모두 내부 상태를 기준으로 한다.
- 내부 상태는 **모든 마켓(네이버, 쿠팡, 11번가, 지마켓, 옥션)에 공통**으로 적용된다.
- 마켓별 API 상태는 내부 상태로 매핑한다. 매핑표는 `04_시스템_아키텍처_및_API/공통_주문모델_및_마켓어댑터.md`에서 관리한다.
- 상태는 **주문상품(라인) 단위**로 관리한다. 한 주문에 여러 상품이 있으면 상품별로 상태가 다를 수 있다.

## 2. 내부 상태 전체 목록

### 2.1 정상 진행 상태군

| 내부 상태 코드 | 라벨 | 소속 메뉴 | 의미 |
|---|---|---|---|
| `NEW` | 신규주문 | 신규주문 | 마켓에서 수집된 결제완료 주문. 발주확인 전 |
| `ORDER_CONFIRMED` | 발주확인 완료 | 상품준비 | 마켓 발주확인 API 호출 성공 |
| `SOURCING_REQUIRED` | 소싱 매칭 필요 | 상품준비 | 소싱라이프 상품 매칭/검토가 필요한 상태 |
| `SOURCING_PAYMENT_PENDING` | 소싱라이프 결제대기 | 상품준비 | 소싱 상품 확정 후 소싱라이프 결제 전 |
| `SOURCING_PAYMENT_COMPLETED` | 소싱라이프 결제완료 | 상품준비 | 소싱라이프 결제/주문 완료 |
| `DOMESTIC_TRACKING_PENDING` | 국내송장 대기 | 상품준비 | 국내송장 발급을 기다리는 상태 |
| `MARKET_INVOICE_PENDING` | 송장전송 대기 | 발송대기 | 국내송장 확보 완료, 마켓 송장전송 전 |
| `MARKET_INVOICE_FAILED` | 송장전송 실패 | 발송대기 | 마켓 송장전송 API 실패. 재시도 대상 |
| `SHIPPING` | 배송중 | 배송중 | 마켓 송장 등록 성공, 배송 추적 중 |
| `DELIVERED` | 배송완료 | 배송완료 | 마켓 기준 배송 완료 |
| `PURCHASE_CONFIRMED` | 구매확정 | 배송완료 | 구매자 구매확정 (정산 대상) |

### 2.2 클레임 상태군

| 내부 상태 코드 | 라벨 | 소속 메뉴 | 의미 |
|---|---|---|---|
| `CANCEL_REQUESTED` | 취소요청 | 취소/반품/교환 | 구매자 취소 요청 인입 |
| `CANCELED` | 취소완료 | 취소/반품/교환 | 마켓 취소 처리 완료 |
| `RETURN_REQUESTED` | 반품요청 | 취소/반품/교환 | 구매자 반품 요청 인입 |
| `RETURN_IN_PROGRESS` | 반품진행중 | 취소/반품/교환 | 반품 수거/검수 진행 |
| `RETURN_COMPLETED` | 반품완료 | 취소/반품/교환 | 반품 승인 및 환불 완료 |
| `EXCHANGE_REQUESTED` | 교환요청 | 취소/반품/교환 | 구매자 교환 요청 인입 |
| `EXCHANGE_IN_PROGRESS` | 교환진행중 | 취소/반품/교환 | 교환 수거/재발송 진행 |
| `EXCHANGE_COMPLETED` | 교환완료 | 취소/반품/교환 | 교환 처리 완료 |

### 2.3 예외 상태

| 내부 상태 코드 | 라벨 | 소속 메뉴 | 의미 |
|---|---|---|---|
| `UNKNOWN` | 알 수 없음 | 전체 | 마켓 상태를 내부 상태로 매핑하지 못한 경우. 운영자 확인 필요 |

`UNKNOWN`은 정상 흐름에 존재해서는 안 되는 상태다. 발생 시 수집 원문과 함께 실패 로그에 기록하고, 매핑표 보완 후 재처리한다.

## 3. 상태 전환 규칙

### 3.1 정상 흐름 전환도

```text
NEW
 └─[발주확인 성공]→ ORDER_CONFIRMED
     └─[소싱 매칭 필요 판정(자동)]→ SOURCING_REQUIRED
         └─[소싱 상품 확정]→ SOURCING_PAYMENT_PENDING
             └─[소싱라이프 결제 완료]→ SOURCING_PAYMENT_COMPLETED
                 └─[국내송장 미발급]→ DOMESTIC_TRACKING_PENDING
                 └─[국내송장 즉시 발급]→ MARKET_INVOICE_PENDING
DOMESTIC_TRACKING_PENDING
 └─[국내송장 확보(수집 또는 수동입력)]→ MARKET_INVOICE_PENDING
MARKET_INVOICE_PENDING
 └─[마켓 송장전송 성공]→ SHIPPING
 └─[마켓 송장전송 실패]→ MARKET_INVOICE_FAILED
MARKET_INVOICE_FAILED
 └─[재시도 성공]→ SHIPPING
SHIPPING
 └─[마켓 배송완료 확인]→ DELIVERED
DELIVERED
 └─[마켓 구매확정 확인]→ PURCHASE_CONFIRMED
```

### 3.2 전환 조건 상세

| 전환 | 트리거 | 조건 |
|---|---|---|
| `NEW` → `ORDER_CONFIRMED` | 운영자 [발주확인] 버튼 또는 자동 발주확인 설정 | 마켓 발주확인 API 호출이 성공했을 때만 전환. API 실패 시 `NEW` 유지 + 실패 로그 |
| `ORDER_CONFIRMED` → `SOURCING_REQUIRED` | 발주확인 직후 시스템 자동 | 소싱 매칭 정보가 없는 경우. 이미 매칭 정보가 있으면 `SOURCING_PAYMENT_PENDING`으로 직행 |
| `SOURCING_REQUIRED` → `SOURCING_PAYMENT_PENDING` | 운영자 [소싱 확정] | 소싱 상품/옵션/수량이 확정되고 마진 검토가 끝났을 때 |
| `SOURCING_PAYMENT_PENDING` → `SOURCING_PAYMENT_COMPLETED` | 소싱라이프 결제 완료 확인 | 소싱라이프(외부 서비스)에서 결제 완료가 확인됐을 때. 연동 콜백 또는 상태 조회 기준 |
| `SOURCING_PAYMENT_COMPLETED` → `DOMESTIC_TRACKING_PENDING` | 시스템 자동 | 배대지 유형이 입고후송장형이거나 국내송장이 아직 없는 경우 |
| `SOURCING_PAYMENT_COMPLETED` → `MARKET_INVOICE_PENDING` | 시스템 자동 | 즉시송장형 배대지로 국내송장이 함께 확보된 경우 |
| `DOMESTIC_TRACKING_PENDING` → `MARKET_INVOICE_PENDING` | 국내송장 수집(자동) 또는 운영자 수동 입력 | 택배사 코드 + 송장번호가 모두 확보됐을 때 |
| `MARKET_INVOICE_PENDING` → `SHIPPING` | 운영자 [송장전송] 또는 자동 전송 | **마켓 송장전송 API가 성공 응답을 반환했을 때만** 전환 |
| `MARKET_INVOICE_PENDING` → `MARKET_INVOICE_FAILED` | 송장전송 API 실패 | 실패 사유 코드와 원문을 함께 기록 |
| `MARKET_INVOICE_FAILED` → `SHIPPING` | 운영자 [재시도] 또는 자동 재시도 | 재시도 성공 시 |
| `SHIPPING` → `DELIVERED` | 주기 수집 시 마켓 상태 확인 | 마켓이 배송완료 상태를 반환했을 때 |
| `DELIVERED` → `PURCHASE_CONFIRMED` | 주기 수집 시 마켓 상태 확인 | 마켓이 구매확정 상태를 반환했을 때 |

### 3.3 클레임 전환 규칙

- 클레임 상태는 정상 진행 상태와 **별도 축**으로 인입된다. 어떤 정상 상태에서든 마켓에서 취소/반품/교환 요청이 수집되면 해당 클레임 상태로 전환된다.
- 클레임 전환 시 **직전 정상 상태를 보존**한다(`previousStatus`). 클레임 철회 시 직전 상태로 복원하기 위함이다.
- 송장전송 이전(`NEW` ~ `MARKET_INVOICE_PENDING`)의 취소 요청: 소싱라이프 결제 여부에 따라 운영자 판단이 필요하므로 자동 승인하지 않는다. (상세: 03_기능명세서 F7)
- `SHIPPING` 이후의 취소 요청은 마켓 정책상 반품 흐름으로 처리된다.

### 3.4 금지 전환

다음 전환은 시스템이 차단한다.

| 금지 전환 | 사유 |
|---|---|
| `NEW` → `SOURCING_*` (발주확인 생략) | 발주확인 없이 상품준비 진행 불가 |
| `*` → `SHIPPING` (송장전송 성공 없이) | 송장전송 성공 응답이 유일한 `SHIPPING` 진입 조건 |
| 국내송장 미확보 상태에서 `MARKET_INVOICE_PENDING` 진입 | 국내송장이 없으면 마켓 송장전송을 할 수 없다 |
| `CANCELED` / `RETURN_COMPLETED` → 정상 상태 | 종결 상태는 복원 불가. 오처리 시 신규 수집으로 처리 |
| `SHIPPING` → `MARKET_INVOICE_PENDING` (역행) | 역행 불가. 송장 수정은 별도 기능(송장 수정 전송)으로 처리 |

## 4. 상태 변경 이력 기록 정책

모든 상태 변경 시 다음을 주문 히스토리에 기록한다.

| 필드 | 설명 |
|---|---|
| `orderItemId` | 주문상품 식별값 |
| `fromStatus` / `toStatus` | 변경 전/후 내부 상태 코드 |
| `trigger` | `USER`(운영자 수동) / `SYSTEM`(자동 전환) / `MARKET_SYNC`(마켓 수집 반영) / `SOURCING_SYNC`(소싱라이프 연동 반영) |
| `actor` | 수행 계정 (시스템 전환 시 `system`) |
| `reason` | 실패 사유, 클레임 사유 등 부가 정보 |
| `occurredAt` | 발생 시각 |

- 이력은 삭제하지 않는다. 정정이 필요하면 새 이력을 추가한다.
- 마켓 원본 상태가 변경된 경우 내부 상태 변경이 없어도 원본 상태 변경 이력을 기록한다.

## 5. 마켓 상태와의 관계

- 수집 시 마켓 원본 상태(`marketStatus`)는 항상 원문 그대로 별도 저장한다.
- 내부 상태는 마켓 상태 매핑 결과 + 내부 처리 진행 상태(소싱/송장)의 조합으로 결정된다.
  - 예: 네이버는 발주확인 후에도 마켓 상태가 `PAYED`로 유지될 수 있다. 이때 내부 상태는 `ORDER_CONFIRMED` 이후 단계이며, 마켓 상태만으로 내부 상태를 되돌리지 않는다.
- **내부 상태가 마켓 상태보다 앞서 있는 경우(소싱/송장 진행 중) 마켓 수집이 내부 상태를 후퇴시켜서는 안 된다.** 마켓 수집이 내부 상태를 변경할 수 있는 경우는 다음뿐이다.
  1. `SHIPPING` → `DELIVERED` → `PURCHASE_CONFIRMED` 진행 방향 갱신
  2. 클레임 상태 인입
  3. `NEW` 상태 주문의 마켓 측 취소 반영
