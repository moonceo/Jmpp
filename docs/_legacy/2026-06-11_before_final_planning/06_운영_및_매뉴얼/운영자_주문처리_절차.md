## 1. 일일 표준 처리 순서

매일 아래 순서로 처리한다. 각 단계는 해당 메뉴의 처리 대기 건수 뱃지를 기준으로 확인한다.

| 순서 | 메뉴 | 할 일 | 완료 기준 |
|---|---|---|---|
| 1 | 취소/반품/교환 | **클레임 먼저 확인.** 신규 취소요청 중 소싱 결제 전 건은 즉시 [취소 승인] | 클레임 요청 상태 0건 또는 판단 보류 사유 메모 |
| 2 | 신규주문 | 수집 주문 확인 → 이상 없으면 [선택 발주확인] | `NEW` 0건 |
| 3 | 상품준비 | [소싱 매칭] → 마진 확인 → [소싱 확정] → [소싱라이프 결제] | `SOURCING_REQUIRED`, `SOURCING_PAYMENT_PENDING` 0건 |
| 4 | 상품준비 | 국내송장 대기 건 확인. 지연 건은 소싱라이프에서 배송 상태 확인 | 지연 기준 초과 건 없음 (3장) |
| 5 | 발송대기 | [선택 송장전송] → 실패 건 [재시도] | `MARKET_INVOICE_PENDING`, `MARKET_INVOICE_FAILED` 0건 |
| 6 | 배송중/배송완료 | 배송 지연·미추적 건 확인 | - |

처리 원칙:
- **클레임을 발주확인보다 먼저 본다.** 발주확인 전 취소 요청은 즉시 승인할 수 있어 패널티와 소싱 비용 손실을 막는다.
- 발주확인은 마켓 발송기한 패널티 기준으로 **주문 수집 후 24시간 이내** 처리한다.
- 송장전송은 국내송장 확보 즉시 처리한다. 송장전송이 돼야 내부 상태가 배송중으로 바뀌고 마켓 발송기한을 충족한다.

## 2. 예외 상황 대응

### 2.1 주문 수집 실패
- **증상**: 마켓 연동 카드에 `재인증 필요` 또는 수집 실패 알림.
- **대응**:
  1. [내정보 > 마켓 연동]에서 연동 상태 확인.
  2. 인증 만료 → [재인증] 후 [주문 불러오기]로 수동 수집.
  3. 재인증 후에도 실패 → 마켓 API 공지(점검/스펙 변경) 확인 후 개발팀 전달.
- **주의**: 수집 중단 기간의 주문은 재연동 후 기간 지정 재수집으로 보충한다. 중복 수집은 시스템이 자동 방지한다.

### 2.2 소싱라이프 결제 실패
- **증상**: 상품준비 화면 `소싱 실패` 빨강 뱃지.
- **대응**: [재시도] → 반복 실패 시 소싱라이프에서 직접 주문 상태 확인 → 소싱라이프 측에서 수동 처리한 경우 주문 메모에 기록.
- **기준**: 결제 후 24시간 내 결제완료 확인이 안 되면 `확인 필요` 뱃지가 표시된다. 당일 내 소싱라이프에서 확인한다.

### 2.3 국내송장 지연
- **기준**: 입고후송장형 배대지 기준, 소싱라이프 결제완료 후 **7일** 경과 시 지연으로 본다.
- **대응**: 소싱라이프에서 현지 배송/입고 상태 확인 → 마켓 발송기한 임박 시 발송지연 처리(마켓 판매자센터 또는 발송지연 API) → 고객 안내.

### 2.4 송장전송 실패
- **증상**: 발송대기 화면 상단 실패 배너.
- **대응** (실패 사유별):

| 실패 사유 | 대응 |
|---|---|
| 일시 오류(타임아웃 등) | 자동 재시도 대기 (10분 간격 3회). 이후에도 실패 시 [재시도] |
| 송장번호 오류 | 행 확장 → 송장번호 확인 → [송장 수정] 후 [재시도] |
| 택배사 코드 미지원 | 개발팀에 마켓 택배사 코드 매핑 추가 요청 |
| 마켓 상태 불일치 (쿠팡 `ACCEPT` 등) | 발주확인 먼저 처리 후 재시도 |
| 이미 발송 처리됨 | 마켓 판매자센터에서 상태 확인. 일치하면 정상 (시스템이 성공 처리) |

### 2.5 배송지 변경 감지 (쿠팡)
- **증상**: 신규주문/상품준비 행에 `배송지 변경됨` 뱃지.
- **대응**: 행 확장에서 변경 전/후 주소 확인 → 소싱라이프 주문 생성 전이면 그대로 진행, 이미 생성했으면 소싱라이프 측 수령지 변경 가능 여부 확인.

### 2.6 취소 요청 인입 (소싱 결제 완료 후)
- 자동 승인되지 않는다. 운영자가 판단한다.
  1. 소싱라이프에서 소싱 주문 취소 가능 여부 확인.
  2. 취소 가능 → [취소 승인] (소싱 취소 동시 요청).
  3. 취소 불가(이미 현지 발송) → 비용 비교 후 [취소 승인](재고 처리) 또는 [취소 거부](발송 진행) 선택. 거부 시 마켓 표준 사유 선택.
- 처리 결과와 사유를 주문 메모에 남긴다.

### 2.7 `UNKNOWN`(알 수 없음) 상태
- 마켓 상태 매핑 실패 건. 액션 버튼이 모두 비활성화된다.
- 마켓 판매자센터에서 실제 상태 확인 → 개발팀에 원문 로그와 함께 전달 → 매핑 보완 후 재수집으로 정상화.

## 3. 재시도·에스컬레이션 기준 요약

| 항목 | 자동 재시도 | 운영자 개입 시점 | 에스컬레이션 |
|---|---|---|---|
| 주문 수집 | 다음 주기 자동 | 3회 연속 실패 알림 시 | 재인증 후에도 실패 → 개발팀 |
| 발주확인 | 없음 (수동) | 실패 즉시 | 동일 사유 반복 → 개발팀 |
| 소싱라이프 결제 확인 | 5분 주기 조회 | 24시간 미확인 | 소싱라이프 CS |
| 송장전송 | 일시 오류만 3회 | 자동 재시도 소진 시 | 택배사 코드/스펙 문제 → 개발팀 |
| 클레임 동기화 | 다음 주기 자동 | 마켓과 상태 불일치 발견 시 | 개발팀 |

## 4. 운영 점검 체크리스트 (일일 마감)

- [ ] `NEW` 잔여 0건 (또는 보류 사유 메모)
- [ ] `MARKET_INVOICE_FAILED` 잔여 0건
- [ ] 클레임 요청(`*_REQUESTED`) 잔여 0건 또는 처리 방침 메모
- [ ] `UNKNOWN` 0건
- [ ] 마켓 연동 상태 전체 `연동됨`
- [ ] 국내송장 지연 기준(7일) 초과 건 확인
