# [Step 2] 주문 수집 상세 가이드 (Order Sync)

마켓 연동이 완료된 후, 실제로 쇼핑몰의 판매 데이터를 주문팡팡 시스템으로 가져와 관리하는 단계입니다. 개발자는 주문의 '생성'부터 '취소/반품/교환'까지의 전 과정을 데이터베이스에 동기화해야 합니다.

---

## 1. 주문 데이터 수집 항목
마켓 API 호출 시 반드시 수집하여 주문팡팡 표준 DB에 저장해야 하는 항목입니다.

### 1.1 마켓 정보 (Platform Info)
- **마켓 주문번호**: 쇼핑몰이 부여한 고유 번호 (중복 체크 키)
- **상점명**: 연동 시 설정한 스토어명 (내 정보 > 마켓 연동 정보)

### 1.2 주문 및 상품 정보 (Order & Product)
- **주문 일시**: 주문이 발생한 시점 (YYYY-MM-DD HH:mm:ss)
- **상품명 / 옵션**: 고객이 실제 구매한 상품명 및 옵션 명칭
- **수량 / 가격**: 구매 수량 및 고객 결제 금액 (판매가)

### 1.3 배송지 정보 (Shipping Info)
- **수령인명**: 물건을 받을 사람의 이름
- **연락처**: 수령인 휴대폰 번호 (하이픈 제거 저장 권장)
- **배송지 주소**: 고객이 입력한 우편번호 및 주소 전문
- **배송 메시지**: "문 앞에 놓아주세요" 등 고객 요청 사항
- **통관부호(PCCC)**: 마켓에서 수집된 통관부호 (누락 시 추후 수집 필요)

### 1.4 채널 공통 컬럼 표준 (네이버/쿠팡/11번가/ESM)
신규 주문 수집 시 채널별 응답을 아래 공통 스키마로 정규화합니다.

## 2. 클레임 관리 (Claims Handling)
단순 주문뿐만 아니라, 고객의 변심이나 오류로 발생하는 클레임을 실시간으로 반영해야 합니다.

| 클레임 종류 | 발생 시점 | 개발자 구현 로직 |
| :--- | :--- | :--- |
| **취소 (Cancel)** | 발송 전 고객 요청 | 마켓 상태가 '취소'로 변경되면, 즉시 소싱/발주 프로세스를 중단시키고 상태 동기화 |
| **반품 (Return)** | 배송 중/완료 후 요청 | 반품 사유(단순변심, 파손 등)를 수집하고 수거지 주소를 확인 |
| **교환 (Exchange)** | 옵션 변경 등 요청 | 기존 주문을 '교환 요청' 상태로 변경하고, 필요 시 교환용 신규 주문 레코드 생성 |

## 3. 주문 조회 및 필터링 (Lookup)
개발자는 수집된 데이터를 사용자가 쉽게 찾을 수 있도록 강력한 검색 기능을 제공해야 합니다.

- **통합 검색**: 주문번호, 수령인명, 연락처, 상품명을 하나의 검색창에서 검색 (OR 조건 인덱싱 필요)
- **날짜 필터**: 주문일자 기준으로 기간별(오늘, 1주일, 1개월) 조회
- **상태별 탭**: 신규 주문, 발송 대기, 배송중, 클레임완료 등 각 단계별로 데이터를 분류하여 노출

## 4. 개발자 구현 순서

### STEP 1: 주문 동기화 API 개발
- 각 마켓별 주문 목록 조회 API를 매핑하여 `fetchOrders` 함수를 구현합니다.
- 중복 수집을 방지하기 위해 '마켓 주문번호'를 유니크 키로 사용하여 `upsert` 로직을 적용합니다.

### STEP 2: 상태 자동 매핑
- 마켓별 상태값(예: 11번가 '결제완료' vs 쿠팡 '배송지시')을 주문팡팡의 표준 상태(Standard Status)로 변환하는 컨버터를 연동합니다.

### STEP 3: 배치(Batch) 작업 설정
- 사용자가 버튼을 누르지 않아도 자동으로 1시간마다 신규 주문과 클레임 내역을 체크하는 스케줄러를 등록합니다.

## 5. 구현 팁 (Implementation Tip)
> [!IMPORTANT]
> - **클레임 우선주의**: 이미 타오바오 등에 결제가 완료된 뒤에 취소가 들어올 경우 손해가 발생하므로, 신규 주문보다 **취소/반품 클레임 데이터를 먼저 동기화**하는 것이 운영 안정성에 유리합니다.
> - **데이터 마스킹**: 고객의 개인정보(연락처, 주소)는 화면 노출 시 필요에 따라 마스킹 처리하고, 특정 관리자만 원본을 볼 수 있도록 권한을 관리하세요.
