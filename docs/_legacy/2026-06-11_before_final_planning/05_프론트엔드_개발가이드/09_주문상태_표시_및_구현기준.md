# 주문상태 표시 및 화면 구현 기준 (최종 모델)

## 0. 문서 기준

- 내부 상태 코드/라벨/전환 규칙 원본: `../07_주문팡팡개별/02_주문팡팡_내부주문상태_정의.md`
- 화면/버튼/메시지 문안: `../02_UI_UX_명세서/주문관리_화면_UI_명세.md`
- 본 문서는 프론트엔드가 상태·테이블·필터·버튼을 구현할 때 따라야 할 데이터 표시 규칙을 정의한다.
- 기존 코드의 42개 상태(ORDER_STATUSES) 상수는 최종 모델 내부 상태 체계로 대체 대상이다.

## 1. 상태 상수 구현 기준

- 내부 상태 코드는 서버와 프론트가 **동일한 문자열 enum**을 사용한다. 프론트에서 임의 상태를 추가하지 않는다.
- 상태 → 라벨/색상 매핑은 단일 모듈(예: `constants/order-status.ts`)에서만 관리한다. 화면별 하드코딩 금지.
- 매핑에 없는 상태 코드를 수신하면 `UNKNOWN` 뱃지(빨강 외곽선)로 표시하고 콘솔 경고를 남긴다. 화면 크래시 금지.

```ts
// 형태 예시 (라벨/색상 값은 02 UI 명세 3장이 원본)
type InternalOrderStatus =
  | 'NEW' | 'ORDER_CONFIRMED'
  | 'SOURCING_REQUIRED' | 'SOURCING_PAYMENT_PENDING' | 'SOURCING_PAYMENT_COMPLETED'
  | 'DOMESTIC_TRACKING_PENDING'
  | 'MARKET_INVOICE_PENDING' | 'MARKET_INVOICE_FAILED'
  | 'SHIPPING' | 'DELIVERED' | 'PURCHASE_CONFIRMED'
  | 'CANCEL_REQUESTED' | 'CANCELED'
  | 'RETURN_REQUESTED' | 'RETURN_IN_PROGRESS' | 'RETURN_COMPLETED'
  | 'EXCHANGE_REQUESTED' | 'EXCHANGE_IN_PROGRESS' | 'EXCHANGE_COMPLETED'
  | 'UNKNOWN';
```

## 2. 메뉴별 필터 범위 (라우트 ↔ 상태 그룹)

| 라우트 | 상태 그룹 상수 | 포함 상태 |
|---|---|---|
| `/orders` | `ORDER_STATUS_GROUPS.ALL` | 전체 |
| `/orders/new` | `ORDER_STATUS_GROUPS.NEW` | `NEW`, `UNKNOWN` |
| `/orders/preparing` | `ORDER_STATUS_GROUPS.PREPARING` | `ORDER_CONFIRMED`, `SOURCING_REQUIRED`, `SOURCING_PAYMENT_PENDING`, `SOURCING_PAYMENT_COMPLETED`, `DOMESTIC_TRACKING_PENDING` |
| `/orders/waiting` | `ORDER_STATUS_GROUPS.WAITING` | `MARKET_INVOICE_PENDING`, `MARKET_INVOICE_FAILED` |
| `/orders/shipping` | `ORDER_STATUS_GROUPS.SHIPPING` | `SHIPPING` |
| `/orders/delivered` | `ORDER_STATUS_GROUPS.DELIVERED` | `DELIVERED`, `PURCHASE_CONFIRMED` |
| `/orders/claims` | `ORDER_STATUS_GROUPS.CLAIMS` | 클레임 상태군 전체 |

- 상태 필터 팝오버에는 해당 그룹의 상태만 노출한다.
- 서버 조회 파라미터도 동일 그룹 기준으로 전달한다. 클라이언트에서 전체 데이터를 받아 필터링하지 않는다.

## 3. 테이블 표시 규칙

| 컬럼 | 데이터 소스 | 규칙 |
|---|---|---|
| 주문일시 | `order.orderedAt` | `YYYY-MM-DD HH:mm` + 상대시간(24시간 이내만) |
| 마켓 | `order.marketCode`, `order.storeName` | 마켓 아이콘은 marketCode 기준 매핑. 미지원 코드도 텍스트로 표시 |
| 상품정보 | `item.thumbnailUrl`, `productName`, `optionName`, `quantity`, `order.marketOrderNo` | 썸네일 로드 실패 시 플레이스홀더. 옵션 없으면 미표시 |
| 처리상태 | `item.internalStatus` | 상태 뱃지 모듈 사용 |
| 소싱 | `sourcingLink.sourcingStatus` | `NONE`이면 `-` 표시 |
| 수령자 | `order.receiverName`, `receiverPhone`, `pccc` | 연락처 마스킹 표시(목록), 확장 영역에서 전체 표시. PCCC 미수집 시 `PCCC 미수집` 회색 뱃지 |
| 금액 | `item.itemPaymentAmount`, 예상 마진율 | 통화 천 단위 콤마. 마진 < 0 시 `text-red` 강조. 마진 미산출 시 `-` |
| 송장 (배송중 이후) | `domesticInvoice.courierName`, `trackingNo` | 송장번호 클릭 → 택배사 배송조회 새 창 |

- 주문(Order) 하나에 여러 주문상품(OrderItem)이 있으면 **라인 단위 행**으로 표시하고, 같은 주문은 주문번호로 그룹 표시한다.
- 목록 갱신: 수동 수집 완료, 액션(발주확인/송장전송 등) 완료 시 해당 행만 갱신(낙관적 갱신 금지 — 서버 응답 후 반영).

## 4. 버튼 활성/비활성 조건

버튼 노출·활성 여부는 **internalStatus + 전제조건 데이터**로 결정한다. 서버도 동일 조건을 검증하므로 프론트 조건은 UX용 사전 차단이다.

| 버튼 | 노출 조건 | 활성 조건 | 비활성 시 툴팁 |
|---|---|---|---|
| [발주확인] | `internalStatus === 'NEW'` | 마켓 연동 정상 | "마켓 연동을 확인해주세요." |
| [소싱 매칭] | `SOURCING_REQUIRED` | 항상 | - |
| [소싱라이프 결제] | `SOURCING_PAYMENT_PENDING` | `sourcingStatus !== 'FAILED'` 또는 재시도 | - |
| [송장 입력] | `DOMESTIC_TRACKING_PENDING` | 항상 | - |
| [송장전송] | `MARKET_INVOICE_PENDING` | `domesticInvoice` 존재 | "국내송장이 등록되어야 전송할 수 있습니다." |
| [재시도] | `MARKET_INVOICE_FAILED` | 항상 | - |
| [송장 수정] | `SHIPPING` | 마켓이 송장 수정 지원 | "마켓 판매자센터에서 직접 수정해야 합니다." |
| [취소 승인]/[취소 거부] | `CANCEL_REQUESTED` | 항상 | - |
| 일괄 버튼 | 선택 행 ≥ 1 | 선택 행이 모두 동일 액션 가능 상태 | "처리할 수 없는 주문이 포함되어 있습니다." |

## 5. 상세(Expand) 영역 표시 규칙

섹션 순서 고정:
1. **수령 정보**: 구매자/수령인, 연락처(전체), 주소, 배송 메모, PCCC(수정 가능)
2. **소싱 정보**: 소싱 상태, `sourcingOrderId`, 소싱 원가(외화) + 적용 환율 + 원화 환산
3. **송장 정보**: 국내 택배사/송장번호/확보 경로(자동·수동), 마켓 전송 이력(시도 회차/결과/오류 메시지)
4. **비용/마진**: 결제금액 → 수수료 → 정산예상 → 매입가 → 배송비 → 최종마진 순 (산식은 03 기능명세 기준)
5. **내부 메모**: 입력 + [저장]
6. **이력**: [히스토리] 버튼 → 타임라인 모달

- 클레임 상태 주문은 최상단에 클레임 사유/요청일/`previousStatus`(인입 전 상태)를 경고 박스로 표시한다.

## 6. 오류·로딩 처리

- 액션 API 실패 시: 02 UI 명세 4.2의 문안으로 토스트 표시 + 행 상태는 서버 응답 기준 유지.
- 일괄 액션 진행 중: 진행률 표시(처리 중 N/M). 완료 후 결과 요약 모달.
- 목록 로딩: 스켈레톤. 수집 진행 중 [주문 불러오기] 버튼 스피너 + 비활성.
- `UNKNOWN` 상태 행: 액션 버튼 전체 비활성, "운영자 확인 필요" 안내.
