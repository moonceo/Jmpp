# [기획서] 2.0 문의관리 (Inquiry Management)

## 1. 개요 (Overview)
여러 마켓(스마트스토어 등)에 흩어져 있는 고객 문의(Q&A)를 통합 수집하여 한 화면에서 확인하고 답변할 수 있는 **CS 통합 센터**이다. 신속한 고객 응대를 통해 마켓 페널티를 예방하고 운영 효율을 높이는 것을 목적으로 한다.

## 2. 화면 구성 (UI Layout) (Verified)
화면은 상단의 **현황판 & 필터**, 중단의 **리스트**, 그리고 리스트가 없을 경우의 **Empty State**로 구성된다.

![문의관리_메인_미답변](../_assets/문의관리_메인_미답변_데이터없음.png)

### 2.1 주요 영역 구분
1.  **Header**: 페이지 타이틀 "문의관리" 및 서브 텍스트 "여러 마켓의 고객 문의를 한 곳에서 관리하세요".
2.  **CS 현황판 (Status Dashboard)**: 상단 4개의 카드로 구성된 요약 통계.
3.  **컨트롤 바 (Control Bar)**: 문의 불러오기(Sync), 날짜 필터, 검색창으로 구성.
4.  **탭 네비게이션 (Tab Nav)**: 처리 상태(미답변/답변완료)에 따른 뷰 전환.
5.  **콘텐츠 영역 (Contents Area)**: 문의 리스트 또는 안내 화면(Empty State).

## 3. 상세 기능 명세 (Detailed Specifications)

### A. CS 현황판 (Status Dashboard) (Verified)
상단에 고정 노출되는 4개의 핵심 지표 카드이다.
*   **미답변 문의**: 현재 `답변대기` 상태인 문의 총 건수. (Red Dot 강조)
*   **답변완료**: 이번 달(또는 지정 기간) 처리 완료된 문의 건수. (Green Color)
*   **전체 문의**: 누적 수집된 총 문의 건수.
*   **연동 스토어**: 현재 정상 API 연결 상태인 마켓 수.

### B. 컨트롤 바 (Control Bar) (Verified)
1.  **문의 불러오기 (Sync Button)**
    *   *Function*: 연동된 모든 마켓의 최신 문의 내역을 수동으로 수집(Scraping/API) 한다.
    *   *Interaction*: 클릭 시 로딩 스피너 작동 -> 완료 시 툴팁으로 `마지막 업데이트` 시간 갱신.
    *   *Toast Msg*: 불러오기 성공 시 "N건의 새로운 문의를 가져왔습니다." / 실패 시 "문의 동기화에 실패했습니다."
    *   **[중요] 제약 사항**: **ESM(지마켓/옥션) 및 11번가**는 마켓 정책상 **문의 수집을 지원하지 않습니다.** (스마트스토어, 쿠팡 등만 수집 가능)
        - 개발 시 해당 마켓 주문에 대해서는 '문의하기' 시 외부 링크로 이동 처리 필요.
2.  **기간 필터 (Date Range Picker)**
    *   *Options*: `최근 1주일`, `최근 1개월`(Default), `최근 3개월`.
    *   *Action*: 선택 시 하단 리스트가 해당 기간 생성된 문의만 필터링되어 다시 로드된다.
3.  **통합 검색 (Integrated Search)**
    *   *Placeholder*: "문의 내용, 상품명, 주문번호..."
    *   *Logic*: 키워드 입력 후 Enter 시, 문의 본문/상품명/주문번호/작성자ID 필드에 대해 `OR` 조건 검색.

### C. 탭 및 리스트 (List & Tabs)
*   **Tabs**: `미답변` (Primary View) / `답변완료` (Archive View)
*   **미답변 리스트 구조**: 
    *   [마켓 아이콘] [상태 배지]
    *   **상품 정보**: 썸네일 + 상품명(링크) + 옵션명
    *   **문의 내용**: 문의 유형(배송/상품 등) + 본문 미리보기(2줄 말줄임)
    *   **작성 정보**: 작성자ID(마스킹) + 작성일시
    *   **Action**: `답변하기` 버튼 (클릭 시 상세 모달 오픈)
*   **답변완료 리스트 구조 (Verified)**:
    ![문의관리_메인_답변완료](../_assets/문의관리_메인_답변완료.png)
    *   **컬럼 구성**:
        - **마켓**: 마켓 로고 및 마켓명(상점명)
        - **문의일시**: YYYY. MM. DD. HH:MM 형식
        - **유형**: 고객문의/상품문의 등 구분 배지
        - **문의 내용**: 제목 및 본문 요약
        - **상품 정보**: 상품명 및 옵션 정보
        - **주문번호**: 연동된 마켓 주문번호
        - **액션**: `답변완료` (비활성 배지 또는 상세 보기 버튼)

### D. Empty State (데이터 없음) (Verified)
현재 계정과 같이 표시할 문의가 없는 경우 노출되는 화면이다.

![문의관리_메인_답변완료_Empty](../_assets/문의관리_메인_답변완료_데이터없음.png)

*   **조건**: 기간 필터 및 검색 조건에 해당하는 데이터 count == 0 일 때.
*   **UI 요소**:
    *   중앙 정렬된 일러스트(또는 아이콘).
    *   상태별 안내 문구:
        *   (미답변 탭) "미답변 문의가 없습니다. 모든 문의를 처리하셨군요! 👍"
        *   (검색 결과 없음) "검색 결과가 없습니다."
    *   **Call To Action**: "문의 불러오기" 버튼을 중앙에 크게 배치하여 데이터 갱신 유도.

### E. 문의 상세보기 모달 (Verified)
문의 내용을 상세히 확인하고 주문 정보와 연계하여 답변을 검토할 수 있는 모달이다.

![문의관리_모달_답변완료](../_assets/문의관리_모달_답변완료.png)

1.  **Header**: [문의 상세보기] 타이틀, 마켓 로고, 문의 유형 배지, 주문번호 표시.
2.  **왼쪽 영역 (주문/배송 정보)**:
    *   **결제/배송 상태**: 현재 주문 상태(결제대기/배송중 등)와 일시, 상세 주문번호.
    *   **주요 버튼**: `배송 추적`, `히스토리`, `소싱주문 관리`.
    *   **주문 상품**: 상품 이미지, 상품명(링크), 옵션, 수량, 단가.
    *   **금액 정보**: 결제가격, 플랫폼 수수료, 정산예상금액.
    *   **구매자 정보**: 주문자 이름, 연락처.
    *   **수취인 정보**: 수취인 이름, 연락처, 주소, 배송 메모, 통관부호 및 확인 배지.
3.  **오른쪽 영역 (문의 내용)**:
    *   **문의 일시 및 작성자**: 문의가 접수된 시각과 작성자 성함(마스킹).
    *   **제품문의**: 고객이 작성한 문의 제목 및 본문 내용.
    *   **판매자 답변 (답변완료 시)**: 판매자가 등록한 답변 내용 및 답변 등록 시각.
4.  **Footer**: "답변은 스마트스토어에 직접 등록됩니다" 안내 문구 및 `닫기` 버튼.

## 4. 데이터 로직 & 정책 (Logic & Policy)
1.  **답변 정책**:
    *   플랫폼 정책상, 한 번 등록된 답변은 **수정/삭제가 불가능**한 경우가 많으므로, 답변 전송(Submit) 시 `Confirm Modal`을 반드시 띄워 사용자의 최종 확인을 받아야 한다.
2.  **개인정보처리**:
    *   고객의 작성자 ID, 전화번호 등 민감 정보는 마스킹(`k***d`) 처리하여 UI에 노출한다.
3.  **동기화 주기**:
    *   자동 동기화: 서버 스케줄러에 의해 N시간마다 자동 수행.
    *   수동 동기화: 사용자가 버튼 클릭 시 즉시 수행 (Rate Limit 주의).

## 5. 예외 처리 (Exception Handling)
*   **연동 오류**: 특정 마켓의 API 키 만료 등으로 동기화 실패 시, 현황판 '연동 스토어' 섹션에 `!` 아이콘 표시 및 툴팁으로 오류 원인 안내.


# [역기획] 문의관리

## 1. 개요
여러 오픈마켓의 고객 문의사항을 한곳에 수집하여 처리를 자동화하는 문의통합 인박스 정책입니다.

## 2. 운영/기획 결정 필요 사항
### 2.1 미지원 마켓 예외 처리 및 수집 한계
- 스크래핑/API 미지원 쇼핑몰(11번가 등)은 문의를 못 가져올 때 아웃링크로 돌릴 것인지 처리 한계 선 긋기.
- 마켓별 파일 첨부 정책 차이에 따른 시스템 허용 이미지 포맷 및 사이즈의 다운사이징(비용 이슈) 정책.
### 2.2 시스템 부하 방지 및 전송 리스크
- 시간당 전송량 제한 회피, 그리고 딜레이 서버 오류 시 고객(셀러)에게 응답이 안 갔음을 재알림(Retry System)하는 정책.
### 2.3 민감 데이터 보존 및 필터 운영
- 답변이 '완료'된 게시글에 대해 개인정보(연락처 등) 삭제 처리(마스킹) 시점과 검색을 위한 암호화 필터 유지 정책.
