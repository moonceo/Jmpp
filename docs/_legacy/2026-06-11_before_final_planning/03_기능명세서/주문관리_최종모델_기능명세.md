## F1. 주문수집

### F1-1. 자동 수집
- **트리거**: 스케줄러. 마켓별 수집 주기 기본 10분 (마켓별 호출 제한에 따라 차등 설정 가능).
- **대상**: 연동 상태가 정상인 모든 셀러 계정.
- **동작**:
  1. 어댑터 `fetchOrders` 호출 (직전 수집 시각 이후 변경분).
  2. 공통 주문 모델로 정규화.
  3. 유니크 키(`marketCode + sellerAccountId + marketOrderItemNo`) 기준 신규/갱신 판정.
  4. 신규 → 내부 상태 `NEW` 생성. 갱신 → 마켓 상태 반영 (내부 상태 후퇴 금지).
  5. 마켓 상태 매핑 후 클레임 인입 여부 판정 (F7 연계).
- **출력**: 수집 결과 요약 (신규 N건 / 갱신 N건 / 실패 N건), 수집 로그.
- **예외**:
  - API 인증 실패: 해당 계정 수집 중단, 마켓 연동 화면에 `재인증 필요` 표시, 운영자 알림.
  - 호출 제한 초과: 다음 주기로 자동 이월. 3회 연속 실패 시 운영자 알림.
  - 정규화 실패(필수 필드 누락, 매핑 불가): 해당 건을 실패 목록으로 분리, 원문 보관, 내부 상태 `UNKNOWN`.

### F1-2. 수동 수집 ([주문 불러오기] 버튼)
- **트리거**: 운영자가 주문관리 화면 우측 상단 [주문 불러오기] 클릭.
- **동작**: 자동 수집과 동일 로직을 즉시 1회 실행. 진행 중 버튼 비활성화 + 로딩 표시.
- **완료 시**: "신규 N건, 갱신 N건 수집되었습니다." 토스트. 마지막 수집 시각 갱신.

### F1-3. 수집 기간 정책
- 기본: 직전 수집 시각 이후 변경분.
- 최초 연동 시: 최근 30일 주문 일괄 수집.
- 운영자가 기간 지정 재수집 가능 (최대 31일 단위 분할 호출).

## F2. 내부 주문 상태 관리

- 모든 메뉴/필터/액션 노출 조건은 내부 상태를 기준으로 한다. 상태 목록·전환 규칙·금지 전환은 상태 정의서를 따른다.
- 상태 변경은 반드시 다음 세 가지 경로로만 발생한다.
  1. 운영자 액션 (발주확인, 송장전송 등 버튼)
  2. 시스템 자동 전환 (수집 반영, 소싱라이프 콜백)
  3. 관리자 수동 보정 (사유 입력 필수, 이력 기록)
- 금지 전환 시도 시: 서버가 거부하고 "현재 상태에서 처리할 수 없는 작업입니다." 오류 반환. 화면은 해당 버튼을 비활성화로 사전 차단한다.

## F3. 발주확인

### 동작 정의
- **버튼**: 신규주문 화면 [발주확인] (행 단위) / [선택 발주확인] (일괄).
- **전제조건**: 내부 상태 = `NEW`.
- **동작**:
  1. 어댑터 `confirmOrder` 호출 (네이버: 발주 확인 처리, 쿠팡: 상품준비중 처리).
  2. 성공 라인 → `ORDER_CONFIRMED` 전환 후 즉시 소싱 매칭 판정: 매칭 정보 없으면 `SOURCING_REQUIRED`, 있으면 `SOURCING_PAYMENT_PENDING`.
  3. 실패 라인 → `NEW` 유지, 실패 사유 기록, 화면에 실패 뱃지.
- **일괄 처리**: 라인 단위 부분 성공 허용. 결과 요약 모달 표시 (성공 N / 실패 N + 실패 사유).
- **멱등성**: 마켓이 "이미 발주확인됨"을 반환하면 성공으로 처리.

### 쿠팡 배송지 재확인 (필수)
- 쿠팡 상품준비중 처리 성공 직후 발주서 단건 조회로 배송지를 재확인한다.
- 수집본과 다르면: 주문 정보 갱신 + 주문 이력 기록 + 해당 주문에 `배송지 변경됨` 알림 뱃지 표시.

### 자동 발주확인 (설정 옵션)
- 내정보 > 설정에서 마켓별 ON/OFF. ON이면 수집 직후 자동 실행.
- 기본값 OFF. (취소 요청 인입 전 발주확인이 클레임 처리를 복잡하게 만들 수 있으므로 운영자 선택)

## F4. 소싱라이프 연동

소싱라이프는 외부/별도 서비스다. 본 기능의 범위는 **소싱 주문 생성 요청, 결제 상태 추적, 국내송장 수신**이며, 소싱라이프 내부 구매 프로세스는 범위 외다.

### F4-1. 소싱 매칭/확정
- **화면**: 상품준비 메뉴, 내부 상태 `SOURCING_REQUIRED`.
- **버튼**: [소싱 매칭] → 소싱 상품 검색/선택 + 마진 검토 → [소싱 확정].
- **[소싱 확정] 조건**: 소싱 상품/옵션/수량 선택 완료. 마진 검토 값(소싱 원가, 환율, 예상 마진) 확인.
- **결과**: `SourcingLink` 생성 (`sourcingStatus = MATCHED`), 내부 상태 `SOURCING_PAYMENT_PENDING` 전환.
- 마진이 음수인 경우: 확정은 가능하되 경고 확인 모달 필수. "예상 마진이 마이너스입니다. 그래도 확정하시겠습니까?"

### F4-2. 소싱라이프 결제/주문
- **버튼**: [소싱라이프 결제] — 내부 상태 `SOURCING_PAYMENT_PENDING`에서만 활성화.
- **동작**:
  1. 소싱라이프에 소싱 주문 생성 요청 (`sourcingOrderId` 수신, `sourcingStatus = ORDERED`).
  2. 결제는 소싱라이프 측에서 진행 (외부 화면 이동 또는 연동 결제).
  3. 결제 완료 확인(콜백 또는 주기 조회 5분 간격) 시 `sourcingStatus = PAID`, 내부 상태 `SOURCING_PAYMENT_COMPLETED` 전환.
- **결제 완료 직후 분기** (배대지 유형 `forwarderType` 기준):
  - `INSTANT`(즉시송장형): 국내송장 즉시 수신 → `MARKET_INVOICE_PENDING`.
  - `AFTER_ARRIVAL`(입고후송장형): `DOMESTIC_TRACKING_PENDING`.
- **예외**:
  - 소싱 주문 생성 실패: `sourcingStatus = FAILED`, 내부 상태 `SOURCING_PAYMENT_PENDING` 유지, [재시도] 노출.
  - 결제 후 24시간 내 상태 확인 불가: 운영자 알림 + 상품준비 화면 `확인 필요` 뱃지.

### F4-3. 소싱 주문 취소
- 클레임 처리(F7) 중 소싱라이프 결제가 이미 완료된 주문은 [소싱 주문 취소] 요청을 함께 처리한다.
- 소싱라이프 취소 불가(이미 발송 등) 응답 시: 운영자에게 "소싱 취소 불가 — 재고 처리 필요" 안내. 클레임 승인 여부는 운영자가 판단.

## F5. 국내송장 처리

### F5-1. 자동 수집
- **트리거**: 소싱라이프 연동(콜백 또는 주기 조회)으로 국내송장 정보 수신.
- **조건**: 내부 상태 = `DOMESTIC_TRACKING_PENDING`, 택배사 코드 + 송장번호 모두 존재.
- **동작**: `DomesticInvoice` 생성 (`source = SOURCING_SYNC`) → 내부 상태 `MARKET_INVOICE_PENDING` 전환.
- **검증**: 택배사 코드가 내부 택배사 마스터에 존재해야 한다. 미존재 시 전환하지 않고 `송장 확인 필요` 실패 목록에 기록.

### F5-2. 수동 입력
- **버튼**: 상품준비/발송대기 화면 [송장 입력].
- **입력**: 택배사 선택(드롭다운, 내부 택배사 마스터) + 송장번호 (숫자/하이픈, 9~14자리 형식 검증).
- **결과**: `DomesticInvoice` 생성 (`source = MANUAL`) → `MARKET_INVOICE_PENDING` 전환.
- **수정**: 송장전송 전(`MARKET_INVOICE_PENDING`)에는 수정 가능. 송장전송 성공 후에는 송장 수정 전송 기능(F6-3)으로만 변경.

## F6. 마켓 송장전송

### F6-1. 전송
- **버튼**: 발송대기 화면 [송장전송] (행 단위) / [선택 송장전송] (일괄).
- **전제조건** (모두 충족해야 버튼 활성화):
  1. 내부 상태 = `MARKET_INVOICE_PENDING` 또는 `MARKET_INVOICE_FAILED`
  2. 국내송장(택배사 + 송장번호) 존재 — **국내송장이 없으면 송장전송 불가**
  3. 마켓 측 전송 가능 상태 (쿠팡: `INSTRUCT`. `ACCEPT`이면 발주확인 선행 안내)
- **동작**:
  1. 내부 택배사 코드 → 마켓별 택배사 코드 변환.
  2. 어댑터 `uploadInvoice` 호출.
  3. **성공 → 내부 상태 `SHIPPING` 전환** (이것이 `SHIPPING` 진입의 유일한 경로).
  4. 실패 → `MARKET_INVOICE_FAILED` 전환, 오류 코드/메시지 기록.
- **일괄 처리**: 라인 단위 부분 성공. 결과 요약 모달 (성공 N / 실패 N + 사유별 그룹).

### F6-2. 재시도
- **수동**: `MARKET_INVOICE_FAILED` 행의 [재시도] 버튼.
- **자동**: 일시 오류(타임아웃, 5xx, 호출 제한)는 10분 간격 최대 3회 자동 재시도. 영구 오류(잘못된 송장번호, 상태 불일치, 권한 오류)는 자동 재시도하지 않고 운영자 처리 대기.
- 3회 자동 재시도 실패 시: 운영자 알림 + 발송대기 화면 상단 실패 건수 배너.

### F6-3. 송장 수정 전송
- `SHIPPING` 상태에서 송장 오기입 발견 시 [송장 수정] 버튼으로 처리.
- 마켓이 송장 수정 API를 지원하는 경우에만 활성화. 미지원 마켓은 "마켓 판매자센터에서 직접 수정해야 합니다." 안내.
- 수정 성공 시 내부 상태는 `SHIPPING` 유지, 이력만 기록.

## F7. 클레임 처리

### F7-1. 클레임 수집
- **트리거**: 주문수집(F1) 주기마다 어댑터 `fetchClaims` 호출.
- **동작**: 클레임 유형/단계를 내부 클레임 상태로 매핑 → 해당 주문상품 상태 전환 + `previousStatus` 보존 → 취소/반품/교환 메뉴 노출 + 운영자 알림.

### F7-2. 취소 요청 처리
- **분기 기준**: 클레임 인입 시점의 `previousStatus`.

| 직전 상태 | 처리 |
|---|---|
| `NEW` (발주확인 전) | 마켓에서 자동 환불될 수 있음. 수집 반영 시 `CANCELED` 처리 |
| `ORDER_CONFIRMED` ~ `SOURCING_PAYMENT_PENDING` (소싱 결제 전) | [취소 승인] 즉시 가능. 승인 → 마켓 취소 승인 API → `CANCELED` |
| `SOURCING_PAYMENT_COMPLETED` 이후 (소싱 결제 완료) | **자동 승인 금지.** 운영자가 소싱 주문 취소 가능 여부(F4-3) 확인 후 [취소 승인] 또는 [취소 거부(발송 진행)] 선택 |
| `SHIPPING` 이후 | 마켓 정책상 반품 흐름으로 전환 안내 |

- **버튼**: [취소 승인] / [취소 거부]. 거부 시 사유 선택 필수 (이미 발송됨 등 마켓 표준 사유).
- 승인/거부 결과는 마켓 API 호출 성공 시에만 내부 상태에 반영한다.

### F7-3. 반품/교환 처리
- 반품: [반품 승인] → `RETURN_IN_PROGRESS` → 회수 완료 확인 후 [반품 완료] → `RETURN_COMPLETED`.
- 교환: [교환 승인] → `EXCHANGE_IN_PROGRESS` → 재발송 송장 등록(F5/F6 재사용) → `EXCHANGE_COMPLETED`.
- 해외소싱 특성상 반품 수거지/재발송 정책은 운영 매뉴얼(`../06_운영_및_매뉴얼/운영자_주문처리_절차.md`)의 기준을 따른다.
- 소싱라이프 결제 완료 건의 반품 승인 시 소싱 측 환불 가능 여부를 함께 표시한다 (F4-3 연계).

## F8. 주문 이력 관리

- 기록 대상: 상태 변경(자동/수동), 발주확인, 소싱 확정/결제, 송장 입력/전송/실패/재시도, 클레임 인입/처리, 메모 저장, 배송지 변경 감지.
- 기록 형식: 상태 정의서 4장의 이력 스키마를 따른다.
- 화면: 주문 행 확장 영역 또는 [히스토리] 버튼 → 수직 타임라인 (시각, 작업, 수행자, 사유).
- 이력은 수정/삭제 불가. 정정은 새 이력 추가로만 한다.

## 9. 기능별 단계 도입 순서 (문서 디벨롭 기준)

최종 모델은 위 전체이며, 구현은 아래 순서로 단계 도입한다. 단계가 추가될 때마다 본 문서의 해당 기능 섹션을 상세화한다.

1. F1 주문수집 (네이버) → F1 (쿠팡)
2. F2 상태 관리 + F3 발주확인
3. F4 소싱라이프 연동
4. F5 국내송장 + F6 송장전송
5. F7 클레임 + F8 이력 고도화
6. 11번가 → 지마켓/옥션 어댑터 확장
