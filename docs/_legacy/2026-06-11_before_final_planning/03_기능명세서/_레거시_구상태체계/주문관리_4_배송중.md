# 주문관리: 4. 배송중 (Shipping)

## 1. 개요
현지 운송장이 등록된 시점부터 국내 고객에게 배송이 완료될 때까지의 물류 전 과정을 관리한다.

*   **URL**: `/orders/shipping`
*   **공통 UI 적용**: [0_공통.md](file:///f:/dev4/jumumpangpang/docs/주문관리_0_공통.md)의 규격을 따른다.

## 2. 포함 상태 (Status Scope)
거의 모든 물류 단계를 포괄한다.

### 2.1 상태 필터 (Status Filters)
#### 현지 물류
*   `현지 발송 대기중`: 셀러가 상품을 준비 중인 상태.
*   `현지 배송중`: 현지 택배사를 통해 배대지로 이동 중인 상태.

#### 배대지 입고/출고
*   `입고 대기`: 배대지에 도착 예정 정보가 등록된 상태.
*   `오류입고`: 입고 과정에서 문제(파손, 오배송 등)가 발생한 상태.
*   `입고중`: 배대지에서 물건을 스캔하고 검수 중인 상태.
*   `견적 완료`: 무게 측정이 끝나고 배송비가 책정된 상태.
*   `배송비 결제 완료`: 배송비 결제가 확인된 상태.
*   `출고 준비`: 출고를 위해 포장 중인 상태.
*   `출고 완료`: 배대지에서 국내로 발송된 상태.

#### 통관 및 국내 배송
*   `국내 입항`: 세관에 도착하여 통관 진행 중인 상태.
*   `국내 배송중`: 통관 완료 후 국내 택배사가 배송 중인 상태.
*   `배송 완료`: 고객에게 상품이 전달된 상태.
*   `구매 확정 대기`: 배송 완료 후 일정 기간이 지난 상태.
*   `구매 확정`: 정산이 완료된 최종 상태.

## 3. 페이지 특화 기능

### 3.1 상세 정보 (확장 레이아웃)
*   **동적 섹션 렌더링**: 주문의 세부 상태(운송장 유무)에 따라 정보 노출을 최적화하며, 배송 단계에서는 AI 예상 마진 대신 실제 소싱 및 물류 정보를 강조한다.
    *   **좌측 컬럼 (Info & Tracking)**:
        *   기본 주문자/수령인 정보 및 통관부호 상단 배치.
        *   **국내 배송 출발 (송장 정보)**: 하단에 박스 형태로 배치.
            *   **노출 조건**: 송장이 발급된 상태 (`배송중`, `출고완료` 등).
            *   **비노출 조건**: `결제 대기` 등 송장 미발급 상태.
            *   **구성**: 택배사명, 송장번호 (굵은 폰트), `국내 송장 확인` 버튼, 마지막 확인 시각.
    *   **중앙 컬럼 (Order & Sourcing History)**:
        *   **결제 대기 (소싱 전)**: 'AI 예상 마진' 카드 노출.
        *   **결제 대기 (소싱 후)**: '마진 분석' 상세 테이블 노출.
        *   **배송중 공통**: '상세 내역' (주문 상품) 및 '이전 소싱 이력' 타임라인.
    *   **우측 컬럼 (Actions & Memo)**:
        *   **버튼 표준화**: 모든 버튼은 아이콘/이모지를 제거하고 텍스트를 중앙에 정렬 (`justify-center`) 하여 일관성을 확보한다.
        *   **작업 섹션**: 헤더 명칭을 '작업'으로 통일한다.
        *   **버튼 순서 (결제 완료 이후)**: 핵심 동작(h-11, 블랙)과 보조 동작(h-9, 화이트/아웃라인)을 평탄화하여 아래 순서로 배치한다.
            1.  `국내 송장 확인` (송장 존재 시, h-11 블랙)
            2.  `추가 소싱하기` (h-9)
            3.  `배송대행지 관리` (오류 대응 필요 시 h-11 레드, 정상 시 h-9)
            4.  `소싱주문 관리` (h-9)
            5.  `주문 히스토리 보기` (h-9)
            6.  `결제하기` (배송비 결제 대기 시, h-11 블랙)
            7.  `배송 추적` (h-9)
        *   **취소 버튼 정책**: 배송 단계(현지 발송 이후)에서는 `주문 취소하기` 버튼을 노출하지 않는다.

### 3.2 배대지(업무) 연동
*   배대지 사이트 이동 없이 **검수 사진 확인, 추가 서비스 신청, 배송비 결제**를 내부 모달에서 원스톱으로 처리한다.
*   **버튼 그룹화 및 강조 전략**:
    *   **결제 대칭**: `결제 대기` 상태에서는 중앙 컬럼이 정산 명세 테이블 위주로 단순화되며, 우측 액션은 `주문 히스토리 보기`(상단)와 `결제하기`(하단)로만 제한하여 노이즈를 줄인다.
    *   **배송중 공통**: 사용자 요청에 따른 7단계 표준 순서를 적용하여 운영 효율을 높인다.
    *   **UI 유형 통일**: 모든 버튼은 Dark/Zinc 테마를 기본으로 하며, 긴급 상황(오류입고 등)에서만 레드(Red) 테마를 예외적으로 허용한다.

## 4. 핵심 액션 (6대 워크플로우)
배송중 메뉴는 시스템의 모든 운영 도구가 집약된 섹션이다.

### 4.1 국내 송장 확인 모달 (DomesticTrackingConfirmModal)
-   **진입 경로**: 확장 영역의 `국내 송장 확인` 버튼 클릭.
-   **목적**: 국내 택배사 정보를 확인하고 외부 추적 사이트로 이동.
-   **UI 구성**:
    -   **헤더**: 모달 제목 "국내 송장 확인", 마켓 주문번호 표시.
    -   **본문**:
        -   **택배사 정보**: 택배사 아이콘 및 이름 (예: CJ대한통운), 상태 배지 (송장 등록됨).
        -   **송장번호**: 큰 폰트로 번호 표시, `복사` 버튼 제공.
        -   **마지막 업데이트**: 송장 정보가 마지막으로 갱신된 시각.
        -   **수령인 간략 정보**: 성함, 주소 표시.
-   **액션 버튼**:
    -   `닫기`: 모달 종료.
    -   `택배사 조회`: 해당 택배사 공식 추적 페이지로 외부 링크 (새 탭).
    -   `전체 배송 추적`: 4단계 배송 추적 모달로 이동.

### 4.2 추가 소싱 모달 (AddSourcingModal)
-   **진입 경로**: 확장 영역의 `추가 소싱하기` 버튼 클릭.
-   **목적**: 기존 주문에 새로운 소싱 상품을 추가 등록.
-   **UI 구성**:
    -   **좌측 패널**: 현재 주문 정보 (마켓 주문 요약, 기존 소싱 상품 목록).
    -   **중앙 패널**: AI 추천 소싱 상품 리스트 (매칭률, 가격, 옵션).
    -   **우측 패널**: 선택한 상품의 상세 정보 및 마진 분석.
-   **액션 버튼**: `취소`, `소싱 상품 추가`.

### 4.3 배송대행지 관리 모달 (WarehouseModal)
-   **진입 경로**: 확장 영역의 `배송대행지 관리` 버튼 클릭.
-   **목적**: 배대지 입고 현황, 검수 사진, 부가서비스 신청, 배송비 결제를 통합 처리.
-   **UI 구성 (3단 레이아웃)**:
    -   **좌측 (비용 및 사진)**:
        -   **비용 명세**: 배대지 수수료, 검수비, 포장비 항목별 금액.
        -   **검수 사진 갤러리**: 8장 이상의 실사 이미지 (확대 가능).
    -   **중앙 (주문 정보)**:
        -   **주문 상태**: 현재 처리 상태 배지.
        -   **소싱 상품 정보**: 상품명, 옵션, 수량.
        -   **통관 정보**: HS Code, 통관 방식.
        -   **부가 서비스 체크박스**: 정밀검수, 작동검수, 에어캡, 코너보호 등.
    -   **우측 (채팅)**:
        -   **리펀디 상담**: 배대지 담당자와 실시간 채팅 인터페이스.
        -   **입력 필드**: 메시지 입력 및 전송 버튼.
-   **하단 액션 버튼**:
    -   `합배송 하기`: 여러 주문 통합.
    -   `배대지 주문서 분할 관리`: 주문 분리.
    -   `반품신청서 작성`: 반품 프로세스 시작.
    -   `포장 보완 요청`: 추가 포장 서비스 요청.

### 4.4 소싱 주문 관리 모달 (SourcingManagementModal)
-   **진입 경로**: 확장 영역의 `소싱주문 관리` 버튼 클릭.
-   **목적**: 중국 셀러와의 커뮤니케이션 및 발주 상태 관리.
-   **UI 구성 (3단 레이아웃)**:
    -   **좌측 (마켓 주문 정보)**: 수령인, 상품명, 정산 예정액 표시.
    -   **중앙 (소싱 상품 정보)**:
        -   **상품 상세**: 타오바오/티몰 링크, 가격(CNY/KRW).
        -   **마진 분석 패널**: 정산액, 소싱비용, 예상 순이익 계산.
    -   **우측 (셀러 채팅)**:
        -   **자동 번역 채팅**: 중국어-한국어 실시간 번역.
        -   **빠른 액션 버튼**: `재발송 요청`, `환불 요청`.
-   **액션 버튼**: `닫기`.

### 4.5 주문 히스토리 모달 (OrderHistoryModal)
-   **진입 경로**: 확장 영역의 `주문 히스토리` 버튼 클릭.
-   **목적**: 주문 생성부터 현재까지 모든 변경 이력 조회.
-   **UI 구성**:
    -   **수직 타임라인**: 시점별 로그 (상태 변경, 소싱 등록, 메모 저장, 송장 업데이트 등).
    -   **각 항목 구성**: 발생 시간 (상대 시간 포함), 작업 내용, 수행자 (AI/셀러/시스템).
-   **액션 버튼**: `닫기`.

### 4.6 배송 추적 모달 (TrackingModal)
-   **진입 경로**: 확장 영역의 `배송 추적` 버튼 또는 국내 송장 확인 모달의 `전체 배송 추적` 버튼 클릭.
-   **목적**: 중국 현지 출발부터 국내 배송 완료까지 전 구간 실시간 추적.
-   **UI 구성 (4단계 아코디언)**:
    -   **1단계 (중국 현지 배송)**:
        -   **구성**: 현지 택배사명, 운송장번호 (복사 가능), 타임라인 이력.
        -   **상태 예시**: 간선 하차 → 배달 완료.
    -   **2단계 (배송대행지 처리)**:
        -   **구성**: 5단계 수평 진행 바 (입고대기 → 입고중 → 견적완료 → 출고준비 → 출고완료).
        -   **시각화**: 완료된 단계에 체크 아이콘 표시.
    -   **3단계 (통관 처리)**:
        -   **구성**: 화물관리번호, 통관 상태 배지 (통관완료/진행중).
        -   **유니패스 연동**: 10단계 상세 통관 절차 표시.
    -   **4단계 (국내 배송)**:
        -   **구성**: 국내 택배사명, 송장번호 (복사 가능), 타임라인 이력.
        -   **강조 표시**: 현재 활성 단계는 파란색 배경으로 구분.
-   **헤더 액션**: `화면 공유` 버튼 (고객에게 추적 화면 공유용).
-   **푸터 안내**: "배송 데이터는 실시간 수집되며 실제와 약간의 시차가 있을 수 있습니다."



# [역기획] 주문관리: 4. 배송중 (Shipping)

## 1. 개요
해외 현지 발송부터 입출고, 국내 통관 및 배송 완료까지의 관제 과정 타임라인에 관한 정책입니다.

## 2. 운영/기획 결정 필요 사항
### 2.1 트래킹 주기 및 타임라인 동기화
- 중국 내륙/배대지/관세청/국내 택배 4단계 트래킹 스케줄 폴링 텀(예: 2시간 일괄 업데이트) 정책 대비 API 비용 산정.
### 2.2 배대지 오류/파손 책임 소재
- 파손 사진 수집 시 주문팡팡이 즉각 반품을 중국 셀러에 지시하는 권한 한도 및 그에 따른 운송비 부과 귀책 여부(약관).
### 2.3 소싱처 채팅 통신 구현 허들
- 타오바오 등 해외 마켓의 폐쇄적인 메시징 인터페이스 제약을 극복할 RPA 챗 연계 필요.
### 2.4 상태 전이 완전 자동화 여부
- 배대지 출고 및 국내 택배 도착 즉각 반응 실송장 체인지 100% 자동 적용 또는 사용자 확인 인지 거침 등 정책 판단.
