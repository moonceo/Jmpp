# 주문관리: 0. 공통 명세 (Common)

## 1. 개요
주문관리 시스템의 모든 서브 메뉴(`전체`, `신규`, `발주대기`, `배송중`, `클레임`)에서 공통적으로 사용하는 UI 구성 요소와 데이터 표준을 정의한다.

## 2. 정보 구조 및 네비게이션 (IA & Navigation)
사용자는 좌측 사이드바의 **[주문관리]** 메뉴 하위에서 다음의 5가지 핵심 서브 메뉴를 이동한다.
*   **전체**: `/orders`
*   **신규주문**: `/orders/new`
*   **발송대기**: `/orders/waiting`
*   **배송중**: `/orders/shipping`
*   **반품/교환/취소**: `/orders/claims`

## 3. 공통 UI 구성 요소 (Shared UI Components)

### 3.1 상단 도구 모음 (Top Toolbar)
*   **통합 검색바**: 상품명, 마켓 주문번호, 수령인명 동시 검색.
*   **마켓 필터 (Market Filter)**:
    *   **UI**: 상점 아이콘(`Store`) 버튼 클릭 시 팝오버 노출.
    *   **옵션**: 전체, 네이버, 쿠팡, 11번가 (추후 ESM, G마켓 등 확장).
*   **처리 상태 필터 (Status Filter)**:
    *   **UI**: 필터 아이콘(`Filter`) 버튼 클릭 시 체크박스 팝오버 노출.
    *   **기능**: 다중 선택 가능. 선택된 개수가 버튼 상단에 배지로 표시됨.
    *   **페이지별 필터 범위**: 각 페이지는 해당 단계에 맞는 상태만 필터에 노출한다.
        *   `/orders` (전체): 42개 전체 상태 (`ORDER_STATUSES.ALL`)
        *   `/orders/new` (신규): `신규 주문`, `알 수 없는 상태` (`ORDER_STATUSES.NEW`)
        *   `/orders/waiting` (발송대기): `통관부호 수집중` ~ `결제 완료` 등 5개 (`ORDER_STATUSES.WAITING`)
        *   `/orders/shipping` (배송중): `현지 발송 대기중` ~ `구매 확정` 등 14개 (`ORDER_STATUSES.SHIPPING`)
        *   `/orders/claims` (클레임): 취소/반품/교환 관련 18개 상태 (`ORDER_STATUSES.CLAIMS`)
*   **주문 불러오기 (Sync Button)**: 우측 상단 배치. 마우스 호버 시 `마지막 업데이트` 시간이 툴팁으로 노출됨.

### 3.2 공통 데이터 테이블 (Order Table Standard)
주문 목록을 표시하는 표준 Grid 규격이다. **행(Row) 배경 클릭 시 상세 내역(Expand)이 토글된다.**
| 컬럼명 | 표시 데이터 | 비고 |
| :--- | :--- | :--- |
| **선택 (Check)** | 체크박스 | 전체 선택/행 선택 지원 | 신규주문 페이지에서만 표시 |
| **확장 (Expand)** | 접기/펼치기 아이콘 | 상세 내역(Expand) 토글 |
| **작업 (Action)** | 페이지별 주요 버튼 (마진 검토, 결제 등) | 단계별 우선순위에 따른 배치 |
| **주문일시** | `YYYY-MM-DD HH:mm` | 상대 시간(n분 전) 병행 표기 |
| **상품정보** | [썸네일] [상품명] [옵션] [마켓주문번호] | AI 옵션 이미지 배지 포함 |
| **처리상태** | 상태별 컬러 배지 | 42개 상세 상태 (ORDER_STATUSES) |
| **수령자** | [성함] [연락처] [PCCC 배지] | 클릭 시 **통관부호 정보 모달** 노출 |
| **결제/마진** | 판매가 / 예상 마진율(%) | 마진 < 0% 시 Red 강조 |
| **마켓** | [아이콘] [스토어명] | - |
| **메모** | [아이콘] [텍스트 요약] | 내부 관리용 메모 (2줄 요약) |

*   **데이터 없음**: "주문이 없습니다." 안내 문구 노출.
*   **페이지네이션**: 화살표 아이콘([<], [>]) 버튼 및 선택된 행 정보(`총 N개 중 M개 선택됨`) 표시.

## 4. 공통 상세 레이아웃 (Expandable Row)
### 4.1 정보 섹션 (Information)
*   **인적 정보**: 구매자/수령인 성함, 연락처, 주소.
*   **PCCC 관리**: 번호 확인 및 즉시 수정 기능.
*   **내부 관리 메모**: 운영자 전용 메모 입력 및 [저장] 버튼을 통한 시점별 기록.

### 4.2 비용 상세 (Financials)
*   고객 총 결제 금액, 마켓 판매 수수료, 소싱 비용, 물류 비용을 합계하여 **정산예상금** 및 **최종 마진** 도출.

### 4.3 상세 데이터 항목 정의 (Data Specification: Financials)
주문 상세 및 마진 검토 시 사용되는 주요 수치 데이터의 정의입니다.

| 항목명 | 데이터 타입 | 통화 단위 | 설명 | 비고 |
| :--- | :--- | :---: | :--- | :--- |
| **고객 총 결제 금액** | Currency | KRW | 고객이 마켓에서 실제 결제한 총액 (배송비 포함) | 수집 데이터 원천 |
| **마켓 판매 수수료** | Currency | KRW | 오픈마켓 플랫폼 이용 수수료 합계 | 마켓별 요율 적용 |
| **정산예상금** | Currency | KRW | **`고객 총 결제 금액 - 마켓 판매 수수료`** | 실입금 예상액 (개별건) |
| **소싱 원가** | Currency | CNY | 타오바오 등 해외 소싱처 결제 금액 | 외화 기준 |
| **적용 환율** | Exchange Rate | - | 소싱/배대지 결제 시점의 전산 환율 | 고정/실시간 선택 |
| **매입가(원화)** | Currency | KRW | 소싱 원가 * 적용 환율 | 원화 환산 매입비용 |
| **배송비 합계** | Currency | KRW | 해외 물류비 + 배대지 부가서비스 + 국내 배송비 | 전체 물류 비용 |
| **최종 마진** | Currency | KRW | 정산예상금 - (매입가 + 배송비 합계) | 최종 순이익 |
| **마진율** | Percentage | % | (최종 마진 / 정산예상금) * 100 | - |

## 5. 데이터 규칙
1.  **상태 분류**: `ORDER_STATUSES` 상수(All, New, Waiting, Shipping, Claims)를 기준으로 필터링.
2.  **마진 계산**: `정산예상금 - (매입가 + 배송비 + 수수료)`

## 6. 공통 모달 (Common Modals)
주문 관리 전반에서 공통적으로 사용되는 팝업 UI이다.

### 6.1 통관부호 정보 모달 (PCCC Info)
고객의 개인통관고유부호를 확인하고 관리하기 위한 전용 모달이다.

*   **진입 경로**: 
    1. 데이터 테이블의 `수령자` 컬럼 내 배지/번호 클릭.
    2. 확장 영역(Expand) 내의 통관부호 영역 클릭.
*   **핵심 기능**:
    *   **고객 입력 링크**: 고객에게 전달할 전용 입력 페이지 링크 생성 및 복사 기능.
    *   **수령인 상세**: 성함, 연락처, 주소, 배송 메시지 상세 조회.
    *   **통관부호 상태**: 확인완료/미수집 상태 표시 및 번호 조회.
    *   **변경 이력**: 통관부호 수동 입력, 링크 생성 등 시점별 로그 기록.

![로컬 구현: 통관부호 정보](../_assets/주문관리_신규주문_통관부호정보_모달_최종검증.png)

### 6.2 마진 검토 모달 (Margin Review)
추천 소싱 상품을 비교하고 수익성을 시뮬레이션하는 모달이다.

*   **3단 레이아웃**: 상품 선택 시 우측 상세 분석 패널이 추가되는 동적 레이아웃.
    1. **좌측 (주문 상품)**: 마켓 주문 금액 및 정산 예상액.
    2. **중앙 (추천 상품)**: AI 매칭 상품 리스트 및 옵션/수량 선택.
    3. **우측 (상세 분석)**: 선택 상품 상세, 배송 무게 입력, 실시간 마진 분석(순이익/마진율).
*   **핵심 액션**: 상품별 [소싱 확정] 시 해당 데이터가 주문 정보에 바인딩됨.

![로컬 구현: 마진 검토](../_assets/주문관리_신규주문_마진검토_모달_3단_최종.png)

### 6.3 주문 히스토리 모달 (Order History)
해당 주문의 생성부터 완료까지 모든 이력을 수직 타임라인으로 표시한다.

*   **항목**: 상태 변경, 소싱 이력, 메모 저장, 통관부호 링크 생성 등 모든 로그.
*   **구성**: 시점(Date/Time), 수행한 작업 내용, 담당자 정보.

![로컬 구현: 히스토리](../_assets/주문관리_신규주문_히스토리_모달_구현.png)

### 6.4 주문 취소 모달 (Order Cancel)
주문 취소 시 사유를 선택하고 최종 확인하는 절차이다.

*   **취소 사유**: 고객 변심, 품절, 오배송 등 마켓별 표준 사유 선택 가능.
*   **주의사항**: 취소 후 마켓 상태와 동기화되는 시점이 별도로 안내됨.

# [역기획] 주문관리: 0. 공통 명세 (Common)

## 1. 개요
주문관리 시스템의 전체 서브메뉴(전체/신규/발송대기/배송중/클레임)에서 보편적으로 사용되는 기능 정책입니다.

## 2. 운영/기획 결정 필요 사항
### 2.1 상태 매핑 통일화(Status Mapping Matrix)
- 다수 오픈마켓의 상이한 주문 코드를 주문팡팡 내부 규격화된 42개 상태(ORDER_STATUSES)로 자동 맵핑전환하는 매트릭스.
### 2.2 폴링 전략 및 Lazy Loading(Sync & Load Policies)
- 주문 데이터 대량 적재 시의 그리드(Grid) 부하 감소를 위한 페이징/무한 스크롤 및 마켓별 호출 차등화 시간 간격.
### 2.3 민감 정보 보완 및 PCCC 정책(Personal Information Handling)
- 개인통관고유부호, 일반 연락처, 주소 등의 데이터 저장, 폐기 기한 및 안전한 마스킹 로직 구축(법적 준수).
### 2.4 핵심 마진 계산 규정 확립 및 엑셀 장부 연계
- 실시간으로 계산되는 예상 순이익(정산예상액 - (매입가 + 통화별 환율 + 비용)) 알고리즘 시뮬레이션 정책.
- 엑셀 장부와 맞출 수 있도록 최종마진(KRW) = 정산예상액(KRW) - 총비용(소싱 결제 금액 + 배대지 배송비 및 부가비용) 공식을 기반으로 적용환율(CNY/KRW)을 실시간 반영해 합산합니다.

### 2.5 워크플로우(결재/취소) 패널티 방어(Modal Approval)
- 배송오류나 변심 취소 시 쇼핑몰 셀러 스토어에 가해지는 패널티를 예방하기 위한 승인-모달 안전장치 여부.
