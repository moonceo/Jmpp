# 주문관리: 1. 전체 (All)

## 1. 개요
서비스 내 모든 상태의 주문을 통합 조회하고 검색할 수 있는 "Control Tower" 역할을 수행한다. 

*   **URL**: `/orders` (전체 메뉴 진입 시 기본 페이지)
*   **주 UI 구성**: `0_공통.md` 명세에 정의된 **공통 상단 도구 모음** 및 **표준 데이터 테이블** 사용.

## 2. 페이지 특화 기능

### 2.1 통합 상태 필터 (Full Status Scope)
다른 페이지(신규, 배송중 등)와 달리, 시스템 내 존재하는 **모든 주문 상태**를 필터링할 수 있다.
*   **필터 범위**: `ORDER_STATUSES.ALL` (신규, 발송대기, 배송중, 클레임, 배송완료 등 40여 개 상태 전체).
*   **기본값**: 전체 상태 선택 (정렬: 주문일시 최신순).

### 2.2 상태 필터 목록 (Status Filter Options)
상단 도구 모음의 '상태 필터' 드롭다운에서 선택 가능한 **전체 옵션**:

| 분류 | 상태명 |
| :--- | :--- |
| **신규** | `신규 주문` |
| **발송대기** | `통관부호 수집중`, `소싱상품 선택대기`, `결제 대기`, `결제 완료` |
| **배송중 (현지)** | `현지 발송 대기중`, `현지 배송중` |
| **배송중 (배대지)** | `입고 대기`, `오류입고`, `입고중`, `견적 완료`, `배송비 결제 완료`, `출고 준비`, `출고 완료` |
| **배송중 (국내)** | `국내 입항`, `국내 배송중`, `배송 완료`, `구매 확정 대기`, `구매 확정` |
| **클레임 (취소)** | `취소 요청`, `취소 처리중`, `취소 완료`, `취소 거부`, `주문 취소됨` |
| **클레임 (반품)** | `반품 요청`, `반품 수거중`, `반품 수거 완료`, `반품 처리중`, `반품 완료`, `반품 거부` |
| **클레임 (교환)** | `교환 요청`, `교환 수거중`, `교환 수거 완료`, `교환 처리중`, `교환 재배송중`, `교환 완료`, `교환 거부` |
| **기타** | `알 수 없는 상태` |

### 2.3 동적 액션 (Dynamic Action Buttons)
'전체' 페이지의 **작업(Action)** 컬럼은 행별 주문 상태에 따라 `0_공통.md`의 [3.4 작업 컬럼 버튼 정의] 매트릭스에 맞춰 버튼이 실시간으로 변경되어야 한다.

*   **예시**:
    *   상태가 '신규 주문'인 행 → `발주 확인하기`, `마진 검토하기` 노출.
    *   상태가 '배송중'인 행 → `국내 송장 확인`, `추가 소싱하기` 등 노출.

## 3. 화면 배치 레이아웃
1.  **최상단**: 페이지 타이틀 ("전체 주문 관리") 및 설명.
2.  **검색/필터 영역**: 공통 검색바, **전체 상태 필터**, 주문 불러오기 버튼.
3.  **메인 영역**: 공통 주문 테이블 (확장 레이아웃 및 **공통 모달** 통합).
    *   **통관부호 관리**: 목록 배지 클릭 시 `통관부호 정보 모달` 호출.
    *   **마진 및 히스토리**: 작업 버튼 클릭 시 각 상태에 맞는 `마진 검토`, `주문 히스토리` 모달 즉시 연동.


# [역기획] 주문관리: 1. 전체 (All Orders)

## 1. 개요
쇼핑몰 전체 주문 건의 거시적 필터링 및 대량 작업 지원을 위한 정책 결정 가이드입니다.

## 2. 운영/기획 결정 필요 사항
### 2.1 디폴트 검색 기간
- 조회 진입 시 리소스를 위해 초기 로딩할 과거의 데이터 기간(최근 1주, 1개월 기준) 확립.
### 2.2 동적 렌더링 우선순위
- 각 상태(마진 검토, 신규, 배송, 발송)별로 혼합되어 있는 액션 버튼들의 위치 및 팝오버 크기 동적 조절 정책.
### 2.3 상태 수동 오버라이드
- API에서 '알 수 없는 상태'가 반환될 때 셀러가 임의로 주문 상태를 강제 오버라이딩(수정) 할 체제 허용 권리.
### 2.4 대량 액션 제한(Bulk Action Limiter)
- '전체 선택' 기능에서 최대 허용되는 일일 Bulk 전송(API Call Limit) 수 조절 및 실패 롤백 단위 구축.
