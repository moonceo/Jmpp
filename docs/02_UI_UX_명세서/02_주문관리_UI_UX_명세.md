# 주문관리 UI/UX 명세

## 1. 화면 구성 원칙

- 커머스라이프는 독립 주문관리 서비스로 제공한다.
- 주문관리 화면은 마켓별 차이 없이 동일한 구조로 동작한다.
- 전체 UI는 검정·흰색과 무채색 명도만 사용하는 shadcn/ui semantic token 체계를 따른다. 상태와 우선순위는 유채색이 아닌 채움, 테두리, 글자 굵기, 명도 대비로 구분한다.
- 색상만 모노크롬으로 바꾸는 방식이 아니라 전체 화면을 공통 대시보드 앱 셸과 기능별 작업 패널 구조로 재구성한다.
- 좌측 메뉴는 주문관리 하위 업무 기준으로 구성하고, 주문수집 내부 상태는 본문 상단 탭으로 제공한다.
- 일반 본문과 컨트롤은 14px을 기본으로 하며 캡션·시간·배지·보조 메타데이터만 12px까지 축소할 수 있다. 12px 미만 텍스트는 사용하지 않는다.
- 앱 본문은 사이드바 오른쪽의 왼쪽 기준점에서 시작해 남은 가용 너비 전체를 사용하며, 중앙 고정폭 페이지 프레임을 기본으로 사용하지 않는다.
- 운영자가 다음 단계로 넘어갈 액션이 한눈에 보이게 한다.
- 주문수집 목록은 마켓에서 수집된 주문만 대상으로 하며, 소싱라이프에서 직접 생성하거나 주문한 내역은 포함하지 않는다.
- 소싱라이프 연동으로 수신한 구매, 검수, 입고, 물류 상태와 결과는 커머스라이프 내부 화면에서 조회한다. 소싱라이프 주문내역으로 이동하는 링크는 제공하지 않는다.

## 2. 핵심 레이아웃

1. 공통 대시보드 앱 셸
   - 좌측: `커머스라이프` 브랜드와 주문 운영·연동 설정으로 구분한 접이식 사이드바
   - 상단: 사이드바 트리거, 브레드크럼, `독립 주문관리` 서비스 표식, 서비스 상태 표시
   - 본문: 연한 무채색 배경 위에 페이지 헤더와 카드형 작업 패널을 왼쪽 정렬하고 전체 가용 너비로 배치
   - 모바일: shadcn/ui Sidebar의 Sheet 동작으로 메뉴를 열고 라우트 이동 후 닫음

2. 페이지 헤더
   - 제목: 일반 주문수집 화면은 `주문관리`, 클레임 화면은 `취소/반품/교환`
   - 영문 업무 영역 키커, 제목, 한 줄 업무 설명, 필요한 경우 우측 주요 액션으로 구성한다.

3. 검색/필터 영역
   - 주문 검색어: 마켓 주문번호, 상품주문번호, 상품명, 구매자명, 수령인명, 구매자 연락처, 수령인 연락처, 개인통관부호
   - 기간 필터: 오늘, 3일, 7일, 30일, 직접 입력
   - 직접 입력 클릭 시 작은 팝오버에서 시작날짜와 끝나는날짜를 선택한다.
   - 마켓/스토어 필터: 아이콘 버튼 하나로 제공하며 마켓과 스토어를 각각 중복 선택할 수 있다.
   - 스토어 항목은 마켓 아이콘 + 스토어명 형식으로 제공한다.
   - 주문수집 버튼은 검색/필터 영역 우측 공통 액션으로 표시한다.

4. 메뉴별 기능 영역
   - 검색/필터 아래, 테이블 위에 한 줄 도구 영역으로 표시한다.
   - 현재 단계의 처리 액션 버튼은 왼쪽에 정렬한다.
   - 판매처·상태·송장·클레임 유형 필터는 오른쪽에 정렬한다.
   - 자동 배송중 처리 토글은 필터와 함께 오른쪽 설정 영역에 정렬한다.
   - 현재 소메뉴에 필요한 기능만 노출한다.
   - 신규주문: `주문확인`, `주문취소`
   - 상품준비: `자동 배송중 처리` 토글
   - 발송대기: `자동 배송중 처리`, 일괄 `배송중 처리`

5. 주문 테이블
   - 전체 선택 체크박스
   - 주문 처리에 필요한 주요 정보만 테이블 컬럼으로 우선 노출
   - 주문 행 클릭 시 행 아래 자세히 보기 영역을 펼쳐 목록에 없는 상세 정보를 표시
   - 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위만 담당
   - 좌측 메뉴에서 선택한 주문 그룹과 상태에 따라 표시 데이터 집합이 달라짐
   - 테이블 하단의 건수와 페이지 이동 버튼은 테이블 박스 밖 하단에 표시한다.

6. 테이블 설계 원칙
   - 반복 처리 속도를 위해 목록은 핵심 컬럼만 노출하고, 상세 정보는 행 확장으로 보완한다.
   - 한 컬럼 안에 서로 다른 업무 목적을 섞지 않는다.
   - 상품, 구매자, 수령인, 소싱, 송장, 처리 액션은 각각 별도 컬럼으로 분리한다.
   - 검색·필터·상태 탭·단계별 액션·테이블은 하나의 shadcn/ui `Card` 작업 패널 안에서 헤더와 본문 영역으로 구분한다.
   - 모든 조작 요소는 공식 shadcn/ui primitive로 구성한다. 필터 전환은 `ToggleGroup`/`Tabs`, 폼은 `Field`, 상태 안내는 `Alert`, 빈 화면은 `Empty`, 반복 항목은 `Item`을 우선 사용한다.
   - 대응 shadcn 컴포넌트가 있는 raw 버튼·입력·선택·테이블·대화상자는 허용하지 않는다. 시맨틱 문서 구조와 순수 배치를 위한 HTML만 예외로 둔다.

## 3. 사이드바 메뉴 기준

- 서비스명은 `커머스라이프`로 표시한다.
- 사이드바는 독립 주문관리 업무만 제공하며 타오바오/1688 전환을 표시하지 않는다.
- 아이템 검색, 찜 리스트, 장바구니, 주문 내역, 배송 조회, 통관고유부호 메뉴는 제공하지 않는다.
- 주문관리
  - 주문수집
  - 취소/반품/교환
  - 문의관리
  - 마켓연동

주문수집 내부에는 본문 상단 탭으로 전체, 신규주문, 상품준비, 발송대기, 배송중, 배송완료를 제공한다. 전체 탭은 처리보류 주문이 단계별 탭에서 사라지지 않도록 하는 운영 진입점이다.

### 상단 상태 탭 건수 표시 기준

- 주문수집 본문 상단 상태 탭에 단계별 주문 건수를 표시한다.
- 0건 표시 여부는 화면 밀도에 따라 숨김 처리하거나 낮은 강조로 표시할 수 있다.
- 처리 필요성이 높은 단계는 검정 채움과 흰색 글자의 고대비 스타일을 적용한다.
- 일반 주문 그룹의 신규주문, 상품준비, 발송대기와 클레임 그룹의 취소/반품/교환은 우선 처리 대상으로 강한 명도 대비를 적용한다.
- 배송중, 배송완료는 조회성 상태이므로 무채색 배경과 테두리 중심의 낮은 강조를 적용한다.
- 상태 탭 클릭 시 해당 상태 목록을 보여준다.
- 일반 주문 전체 처리 대기 합계는 신규주문, 상품준비, 발송대기 건수를 합산한다.
- 클레임 처리 대기 건수는 취소/반품/교환 그룹에서 별도로 표시한다.

### 단계별 판매처/상태 필터

- 전체, 신규주문, 상품준비, 발송대기, 배송중, 배송완료 각 탭에서 `판매처`, `상태` 드롭다운 필터를 제공한다.
- 판매처는 현재 탭에 존재하는 마켓·스토어만 표시하고, 각 옵션은 마켓별 네모 약자 아이콘과 스토어명 순서로 표기한다.
- 마켓 약자는 스마트스토어 `N`, 쿠팡 `C`, 11번가 `11`, G마켓 `G`, 옥션 `A`를 사용한다.
- 상태 필터는 현재 주문 데이터의 보유 여부와 관계없이 `전체`와 해당 주문 단계에서 조회 가능한 상태를 모두 제공한다.
- 단계별 상태 범위는 신규주문 `소싱필요`, 상품준비 `소싱필요·소싱완료·결제대기`, 발송대기/배송중 `결제완료·중국배송중·통관 중·국내 배송중`, 배송완료 `배송완료·구매확정`으로 고정한다. 수동 검증 전 단계는 `소싱필요`, 외부 구매 완료는 `결제완료` 필터에 함께 포함한다.
- 배송완료 주문이 구매확정되면 대표 진행상태를 `구매확정`으로 표시하되 배송완료 탭에는 계속 포함한다.
- `ON_HOLD / CANCEL_REQUESTED`는 진행상태 필터와 배지에서 제외한다. 주문은 전체 탭에 유지하고 처리 차단 여부와 취소 대기 정보는 처리 결과와 상세 화면에서 확인한다.
- 단계별 필터는 상단 마켓/스토어 검색 필터와 함께 적용한다.

## 3-1. 마켓 계정 등록 화면 기준

- 위치: 주문관리 > 마켓연동
- 최종 등록 대상: 스마트스토어, 쿠팡, 11번가, G마켓, 옥션
- 화면 등록 대상: 스마트스토어, 쿠팡, 11번가, G마켓, 옥션
- 실제 API 안정화 우선순위는 스마트스토어, 쿠팡을 먼저 검증하고 11번가, G마켓, 옥션 순서로 확장한다.
- 최종적으로 사용자는 등록 대상 마켓에서 운영 중인 판매자 계정 또는 스토어를 개수 제한 없이 등록할 수 있다.
- 계정 목록에는 마켓, 스토어명, 연동상태, 활성, 관리 액션을 표시한다.
- 관리 영역의 `설정` 버튼은 마켓 추가와 동일한 형식의 계정 수정 모달을 연다.
- 삭제는 관리 영역의 삭제 버튼에서 삭제 확인 모달을 거친 뒤 처리한다.
- 특정 판매처만 주문수집하거나 특정 계정만 주문수집하는 버튼은 초기 화면 범위에서 제외한다.
- 주문수집 화면에는 마켓별 필터와 스토어별 필터를 함께 제공한다.

## 3-2. 주문수집 필터 기준

- 주문 검색
  - 마켓 주문번호
  - 상품주문번호
  - 상품명
  - 구매자명
  - 수령인명
  - 구매자 연락처
  - 수령인 연락처
  - 개인통관부호
- 기간 필터
  - 오늘
  - 3일
  - 7일
  - 30일
  - 직접 입력
- 마켓 필터
  - 스마트스토어
  - 쿠팡
  - 11번가
  - G마켓
  - 옥션
- 스토어 필터
  - 플랫폼 아이콘 + 사용자가 연동한 스토어명
- 마켓 필터를 선택하면 선택된 마켓의 주문만 표시하며, 여러 마켓을 중복 선택할 수 있다.
- 스토어 필터를 선택하면 선택된 스토어에서 수집된 주문만 표시하며, 여러 스토어를 중복 선택할 수 있다.
- 마켓 또는 스토어 필터의 선택을 모두 해제하면 전체 주문을 표시한다.
- 주문 검색어, 기간 필터, 마켓 필터, 스토어 필터를 함께 선택하면 모든 조건을 만족하는 주문만 표시한다.
- 필터는 주문 목록 조회 조건이며, 주문수집 실행 범위를 제한하지 않는다.
- 내부 주문 단계 상태 필터는 제공하지 않는다. 좌측 메뉴에서 선택한 단계가 목록 기준이 되며, 각 단계 안에서는 별도 `상태` 필터로 소싱 진행 상태와 구매확정 상태를 좁힌다.

## 4. 좌측 메뉴 상태 기준

| 그룹 | 메뉴 | 상태 코드 | 화면 정의 |
|---|---|---|---|
| 일반 주문 | 신규주문 | NEW | 수집 완료 + 주문확인 전 |
| 일반 주문 | 상품준비 | PREPARING | 주문확인 완료, 소싱 처리 단계 |
| 일반 주문 | 발송대기 | READY_TO_SHIP | 외부 구매 등 호환 흐름에서 국내송장 저장 후 마켓 발송 처리 전 |
| 일반 주문 | 배송중 | SHIPPING | 소싱라이프 결제완료부터 실제 배송완료 전까지. 마켓 발송 전·후를 모두 포함 |
| 일반 주문 | 배송완료 | DELIVERED | 마켓 배송완료 또는 구매확정 주문 |
| 클레임 | 취소/반품/교환 | CLAIM | 취소/반품/교환 진입 주문 |

주문수집 목록은 아래 컬럼을 기준으로 구성한다.

### 5-1. 컬럼 표시 원칙

- 각 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 주문수집 목록은 반복 처리 속도를 우선하므로 관련 정보는 업무 단위로 병합할 수 있다.
- 상품이미지, 상품명, 옵션명, 마켓 주문번호는 `상품정보` 컬럼에 함께 표시한다.
- 마켓과 스토어명은 주문일시 아래에 `N`, `C`, `G`, `11`, `A` 약자 아이콘과 스토어명 형식으로 표시한다.
- 별도 `판매처` 컬럼은 표시하지 않는다.
- 주문확인, 소싱하기, 배송중 처리, 주문취소는 주문 상태별 고빈도에 따라 `처리하기` 컬럼에 표시한다. 상품준비 상세와 발송대기 목록·상세 모두 발송 액션 명칭은 `배송중 처리`로 통일한다.
- 수량은 `상품정보` 컬럼에 함께 표시한다.
- 구매자명, 구매자 연락처는 행 확장 자세히 보기의 `구매자` 영역에 표시한다.
- 수령인, 연락처, 주소, 개인통관부호는 `배송정보` 컬럼과 행 확장 자세히 보기의 `배송정보` 영역에 표시한다.
- 개인통관부호가 비어 있거나 형식이 맞지 않으면 모두 `통관부호 불일치`로 표시하고, 형식이 맞으면 `통관부호 일치`로 표시한다.
- 배송정보 컬럼의 `수정` 버튼으로 수령인 배송정보와 개인통관부호를 함께 수정할 수 있다.
- 배송정보 수정 모달에서도 개인통관부호 입력값의 `통관부호 일치/불일치` 상태를 표시한다.
- 국내송장 컬럼명은 `택배정보`이며 `국내 송장번호`, 직접전달 표시, `중국 송장번호`를 구분해 표시한다.
- 국내·중국 송장번호가 있으면 택배사와 번호를 함께 확인할 수 있게 하고, 아직 수신하지 않은 번호는 `-`로 표시한다.
- 직접전달을 선택한 주문에만 `직접전달`을 표시한다. 일반 주문에는 직접전달 관련 행이나 문구를 표시하지 않는다.
- 배송중 처리 완료 여부는 별도 컬럼으로 표시하지 않고 주문상태가 배송중으로 바뀌는 것으로 표현한다.
- 화면 전체에는 좌우 스크롤이 생기지 않게 하고, 필요 시 주문 테이블 내부에서만 가로 스크롤을 허용한다.
- 일반 주문수집 메뉴 간 같은 컬럼은 동일한 폭을 유지한다.
- 컬럼 폭은 내용 길이에 따라 메뉴별로 흔들리지 않도록 고정 폭 기준을 사용한다.
- 주문상태 컬럼은 본문 상단 상태 탭과 중복되므로 주문수집 목록에서 제거한다.
- 마켓 주문번호는 `상품정보` 컬럼 안에서 `마켓 주문번호 : 주문번호` 형식의 일반 텍스트로 표시하며 클릭 링크나 주문상세 모달은 제공하지 않는다.

### 5-2. 목록 스크롤 기준

- 전체 페이지에는 좌우 스크롤이 생기지 않게 한다.
- 주문 테이블 내부는 컬럼 수가 늘어날 경우 가로 스크롤을 허용한다.
- 기본 목록은 압축 컬럼을 사용해 데스크톱 화면에서 핵심 처리 흐름이 한눈에 보이도록 한다.

### 5-3. 상품 이미지/상품명 인터랙션

- 상품이미지 컬럼의 썸네일을 클릭하면 이미지 크게 보기 모달을 연다.
- 이미지 크게 보기 모달에는 이미지 복사 버튼을 제공한다.
- 이미지 복사 버튼은 현재 표시 중인 상품 이미지를 클립보드에 복사한다.
- 상품명 컬럼을 클릭하면 새 창 또는 새 탭으로 오픈마켓 상품 상세 페이지를 연다.
- 상품 상세 링크가 없는 주문은 상품명을 일반 텍스트로 표시한다.

### 5-4. 주문번호 표시 기준

- 마켓 주문번호 클릭 링크와 주문상세 모달은 제공하지 않는다.
- 목록에서 숨긴 원천 데이터는 데이터 모델에 유지하며, 필요 시 별도 화면 또는 컬럼으로 다시 노출할 수 있다.

`처리하기` 컬럼에는 실행 가능한 버튼만 표시한다. 조회 전용 주문은 상태 텍스트나 대시를 표시하지 않고 빈 셀로 둔다.

상품별 처리 흐름을 확인하는 `주문 히스토리`는 행 자세히 보기의 `처리하기`에만 표시한다. 히스토리 모달은 예정 단계를 미리 나열하지 않고 현재까지 실제 데이터가 확인된 이력만 표시한다. 각 이력에는 수집·처리 시각과 함께 주문번호·판매처·매칭상품·결제금액·소싱 주문번호·택배사·송장번호 등 해당 단계에서 확보된 데이터를 표시하며, 미수신 값은 임의로 생성하지 않는다. 취소·처리보류 주문은 중단 사유를 함께 표시한다.

### 5-4-1. 주문관리 단계별 목록·상세 표시 항목

모든 일반 주문 단계의 목록에는 `선택`, `처리하기`, `주문일시`, `진행상태`, `상품정보`, `택배정보`, `배송정보`를 같은 순서와 폭으로 표시한다. 주문일시에는 마켓 약자 아이콘과 스토어명을 함께 표시하며, 단계별 차이는 진행상태 값, 택배정보의 입력 여부, 처리하기 액션에만 둔다.

모든 단계의 자세히 보기에는 아래 공통 항목을 표시한다.

1. 주문상품: 썸네일, 상품명, 옵션명, 수량, 단가, 마켓 결제금액, 주문일시, 마켓, 스토어명
2. 소싱상품: 매칭된 경우 주문상품 아래에 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호 또는 외부구매 표시
3. 마진계산: 매칭된 경우 매출·정산 → 예상 소싱비용 → 예상 순이익·마진율 순으로 세로 표시
4. 구매자·배송정보: 구매자 이름·연락처, 수령인 이름·연락처·우편번호·주소·개인통관부호·일치 여부
5. 택배정보: 국내 택배사·송장번호, 직접전달 주문에만 `직접전달`, 중국 택배사·송장번호
6. 처리하기: 넓은 화면에서는 오른쪽에 두고, 현재 단계와 주문 조건에 맞는 실행·조회 버튼을 위에서 아래로 표시

| 주문관리 단계 | 목록에서 확인하는 항목 | 목록 `처리하기` | 자세히 보기에서 추가로 확인·처리하는 항목 |
|---|---|---|---|
| 신규주문 | 진행상태 `소싱필요`, 주문일시 아래 마켓·스토어, 주문상품, 국내·중국 송장 미등록, 수령·통관정보 | `주문확인`, `매칭하기`, `주문취소` | 공통 상세 중 주문상품과 구매자·배송정보 중심. `주문확인`, `매칭하기`, `주문취소`, `배송정보 수정` |
| 상품준비 | `소싱필요`, `소싱완료`, `결제대기` 중 현재 진행상태, 주문일시 아래 마켓·스토어, 주문상품, 국내·중국 송장 수신 여부와 직접전달 여부, 수령·통관정보 | `소싱하기`, `주문취소` | 매칭된 소싱상품과 예상 마진. 진행단계별 결제, `외부구매 배송처리`, 지원 마켓의 `배송중 처리`(직접전달), `배송정보 수정`. 통관부호 불일치 시 소싱·결제 액션을 숨기고 배송정보 수정을 유지 |
| 발송대기 | `결제완료` 등 실제 소싱 진행상태, 주문일시 아래 마켓·스토어, 주문상품, 국내 송장번호·직접전달 여부·수신된 중국 송장번호, 수령·통관정보 | 실행 조건을 충족한 주문의 `배송중 처리` | 소싱상품, 마진, 저장된 택배정보와 스토어 기본 발송 방식. 마켓 미발송이면 `배송중 처리`, 송장만 누락된 결제완료 건은 `택배정보 등록`, 미결제 비정상 건은 `결제상태 불일치` |
| 배송중 | `결제완료`, `중국배송중`, `통관 중`, `국내 배송중` 중 실제 진행상태, 주문일시 아래 마켓·스토어, 주문상품, 국내 송장번호·직접전달 여부·중국 송장번호, 수령·통관정보 | 없음 | 실제 소싱 결제·상품·마진, 누적 배송 이력과 판매자 채팅. 상세 `소싱상품관리` 안에서 환불 신청·진행·내역 조회. 배송중 처리 시작 전 `운송장 등록/수정`, 조건부 배송중 처리, 환불완료 후 재소싱 액션 |
| 배송완료 | `배송완료` 또는 `구매확정`, 주문일시 아래 마켓·스토어, 주문상품, 최종 국내 송장번호·직접전달 여부·중국 송장번호, 수령·통관정보 | 없음 | 최종 상품·결제·마진과 누적 배송 이력, 판매자 채팅. 상세 `소싱상품관리` 안에서 기존 환불 내역 조회. 신규 환불 신청과 판매자 구매확정 액션 없음 |

`전체주문`은 별도 표시 규칙을 만들지 않고 각 주문의 현재 단계 규칙을 그대로 사용한다. `처리보류` 주문은 공통 정보와 보류·실패 사유를 조회할 수 있지만 실행 액션은 제공하지 않는다.

### 5-5. 국내송장 표시/정정

- `NEW`, `PREPARING`, `DELIVERED`: 표시값 고정
- `READY_TO_SHIP`: 외부 구매 완료 시 저장된 값을 표시하며 오입력 정정 가능
- `SHIPPING`: 상세 `처리하기`에서 `운송장 등록/수정`을 제공한다. 단, 마켓 제출 이후에는 정정 API가 연결되기 전까지 수정할 수 없다.
- `택배정보`에서는 국내 송장번호와 중국 송장번호를 같은 순서로 표시하고, 직접전달 주문일 때만 두 번호 사이에 `직접전달`을 표시한다.
- 국내·중국 송장번호가 있으면 해당 택배사와 함께 표시하고, 수신 전이면 `-`로 표시한다.
- `택배정보`는 배송방법 선택과 무관하게 소싱라이프에서 수집한 실제 국내 택배사와 송장번호를 유지한다.
- 외부구매 주문의 최초 국내송장 입력은 `외부구매 배송처리` 화면에서 수행한다.
- 발송대기에서 정정한 국내송장은 즉시 자동저장된다.
- 번호 입력은 숫자만 허용
- 외부구매 배송처리 화면 내 직접 입력 placeholder: `국내송장번호`

### 5-6. 처리작업

- NEW: 목록과 상세 처리하기에는 `주문확인`, `매칭하기`, `주문취소`를 표시한다. `배송정보 수정`은 왼쪽 구매자·배송정보 영역에서만 제공한다.
- PREPARING: 목록에는 `소싱하기`, `주문취소`만 표시한다. 결제대기도 목록에서는 `소싱하기`로 표시하고 상세 처리하기에서 `결제하기`를 제공한다. 상세에는 `외부구매 배송처리`, 지원 마켓의 `배송중 처리`를 추가한다. `배송정보 수정`은 왼쪽 구매자·배송정보 영역에서만 제공한다.
- `외부구매 배송처리`는 소싱라이프를 사용하지 않고 직접 구매한 주문의 택배사와 국내송장번호를 저장한다.
- PREPARING: 개인통관부호가 불일치하면 `소싱하기`와 `결제하기`를 숨기고 왼쪽 구매자·배송정보 영역의 수정 기능으로 통관부호를 바로잡도록 안내한다.
- `외부구매 배송처리`는 택배사와 국내송장번호가 모두 입력된 경우에만 활성화한다.
- 외부 구매 완료 시 국내송장을 저장하고 `자동 배송중 처리` 설정을 적용한다. OFF이면 발송대기, ON이면 마켓 발송 성공 후 마켓과 내부 주문을 배송중으로 변경한다. 송장번호가 없으면 완료 처리를 차단한다.
- 직접전달 처리 완료 주문에서 외부 구매를 진행해도 국내송장은 필수다. 송장이 없으면 완료 버튼을 활성화하지 않으며 발송대기로 이동하지 않는다.
- PREPARING: 기본 발송 방식이 `직접전달`인 스마트스토어·11번가 상세에 `배송중 처리`를 제공한다. 직접전달 성공 시 마켓 상태만 배송중으로 바꾸고 내부 주문은 구매 완료 전까지 상품준비에 유지한다.
- READY_TO_SHIP: `배송중 처리` 하나를 제공한다. 미발송 주문은 모달에서 저장 송장 또는 지원 마켓의 직접전달을 선택하고 성공 시 내부 주문도 배송중으로 이동한다.
- READY_TO_SHIP: 이미 발송된 주문은 선택 모달을 생략한다. 백엔드가 실제 송장/직접전달 상태를 확인해 마켓에 다시 보내지 않고 내부 단계만 배송중으로 변경한다.
- 발송방법은 사전에 따로 저장하거나 변경하지 않는다. 마켓 API 전송 성공 시에만 `DELIVERY` 또는 `DIRECT_DELIVERY`로 저장한다.
- 데모 주문의 `배송중 처리` 모달은 판매처와 관계없이 `송장으로 처리`, `직접전달로 처리`를 모두 선택할 수 있다. 실주문은 직접전달 API가 검증된 마켓 계정에서만 직접전달 선택을 활성화한다.
- 직접전달만 먼저 처리한 주문은 구매 완료 전까지 국내송장 없이 상품준비에 유지한다. 이후 소싱라이프 또는 외부 구매가 완료되면 필수 국내송장을 저장하고 내부 `발송대기`로 이동한다.
- `구매 안 함` 선택지는 제공하지 않으며, 구매 미완료 + 국내송장 보유 조합도 정상 목록 상태로 생성하지 않는다.
- 직접전달 주문이 실제 국내송장 기준 배송완료되면 주문은 내부 `배송완료` 탭으로 이동한다. 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않으며, 직접전달 여부는 택배정보의 `직접전달` 표시로 확인한다.
- 국내송장번호만 입력하면 송장번호만 저장하고 발송대기에 남긴다.
- `배송중 처리`에서 송장을 선택하면 현재 국내송장을 마켓에 전송하면서 배송중으로 이동한다.
- SHIPPING: 조회 전용이며 변경된 송장번호 항목은 제공하지 않는다.
- DELIVERED: 조회 전용
- ON_HOLD: 전체주문에서 조회하며 주문확인·매칭·소싱·외부구매·직접전달·발송·재취소 액션을 모두 숨긴다.
- CLAIM: `취소처리`, `반품처리`, `교환처리`
- `주문취소`는 신규주문, 상품준비, 발송대기에서 제공하되 마켓 직접전달 주문에는 노출하지 않는다. 발송대기에서는 자세히 보기의 처리하기 섹션에만 표시한다.
- 신규주문에서는 체크된 주문을 대상으로 상단 전역 `주문취소`도 제공한다.

### 5-7. 주문확인 일괄처리

- 신규주문 메뉴에서 여러 주문을 체크박스로 선택할 수 있다.
- 상단 전역 주문확인 버튼명은 `주문확인`으로 고정한다.
- 체크박스로 선택된 주문이 없으면 `주문확인` 버튼은 비활성화한다.
- 상단 `주문확인`은 체크된 NEW 상태 주문에만 적용한다.
- 일괄 처리 후 성공한 주문은 상품준비로 이동한다.
- 실패한 주문은 신규주문에 남기고 실패 사유를 표시한다.

### 5-8. 주문취소 일괄처리

- 신규주문 메뉴에서 여러 주문을 체크박스로 선택해 `주문취소`를 일괄 실행할 수 있다.
- 체크박스로 선택된 주문이 없으면 `주문취소` 버튼은 비활성화한다.
- 개별 주문취소와 일괄 주문취소 모두 확인 모달에서 스마트스토어 공식 7개 사유와 2~500자 상세 사유를 입력한다.
- 개별 취소는 1개 이상 주문수량 이하의 부분수량을 허용하고, 일괄 취소는 선택된 각 주문의 전체수량으로 별도 명령을 만든다.
- 실주문은 계정별 `SELLER_CANCEL` UAT가 `PASSED`인 경우에만 명령을 접수하며, 화면은 접수 직후 취소 성공 상태를 만들지 않는다. UAT 전에는 `MANUAL_FALLBACK` 오류와 다음 조치를 표시한다.
- 명령 접수 성공은 `ON_HOLD / CANCEL_REQUESTED`로 표시하고 전체주문 화면에 유지한다. provider 상품주문 최종 `CANCELED`를 확인한 뒤에만 판매자취소 종료 상태로 바꾼다.
- 현재·과거 취소 흔적과 명령의 인과가 증명되지 않은 `UNKNOWN`은 창이나 목록에서 성공으로 바꾸지 않으며 자동 재호출하지 않고 수동 대사 대상으로 안내한다.
- 일괄 접수가 일부 실패하면 모달을 닫지 않고 최대 3개 실패 주문번호·사유와 나머지 실패 건수를 표시한다. 같은 멱등키로 재시도해 이미 접수된 주문에 중복 효과가 생기지 않게 한다.
- 실제 취소 반영은 worker 대사와 다음 주문·클레임 재수집 결과로 확인한다. 주문을 목록에서 임의 삭제하지 않으며, provider claim이 수집되면 실클레임 작업함에서 조회한다.
- 데모 주문만 로컬 시연 상태로 즉시 변경하며 목록 상단에 데이터 원천을 설명하는 별도 안내 문구는 표시하지 않는다.

### 5-9. 실클레임 작업함

- `/orders?view=claims`는 구매자가 마켓에서 신청한 클레임과 판매자가 주문수집에서 직접 취소한 내역을 함께 보는 작업함이다. 화면 제목은 주문수집 메뉴명과 동일하게 `취소/반품/교환`으로 표시한다.
- 클레임 작업함은 주문수집 화면과 동일한 시각 구조를 사용한다. 흰 배경, 24px 페이지 제목, 얇은 하단 경계, 기간·검색 도구줄, 검정 활성 탭, 우측 상태 필터, 조밀한 테이블을 유지한다.
- 클레임 전용 대형 요약 카드와 별도 영문 키커는 사용하지 않는다. 테이블 헤더·행 높이·교차행 배경·hover 색·버튼 크기는 주문수집 테이블과 맞춘다.
- 주문수집의 상태 탭에 대응해 클레임은 `전체`, `신규요청`, `처리중`, `완료` 탭과 건수를 표시한다.
- 상단에서 `MVP 데모`와 `실데이터 조회`를 명확히 전환한다. 데모는 기본 선택이며 테두리와 무채색 배경의 안내 영역에 `마켓 미전송`을 표시한다.
- 데모 목록은 네이버·쿠팡의 구매자 취소·반품·교환 정상·예외 8건과 판매자 직접취소 예시를 제공해 API 자격증명 없이 전체 흐름을 확인할 수 있어야 한다.
- 목록은 마켓·스토어·주문번호, 유형/상태, 접수 주체/사유, 대상 상품/수량, 접수시각과 처리기한을 표시한다.
- 상세 상단은 `현재 단계 → 다음 작업 → 주의사항` 순서로 운영자가 바로 판단할 수 있게 한다.
- 회수 배송과 교환 재배송은 기존 주문 배송과 구분된 카드로 표시한다. 교환 재배송은 택배사와 새 송장번호 입력을 요구한다.
- 데모 작업은 로컬 상태와 이벤트 이력만 갱신하고 성공 토스트에 `마켓에는 전송되지 않았습니다`를 포함한다.
- 접수 주체 필터는 `전체`, `구매자 신청`, `판매자 직접취소`를 제공한다. 실데이터는 접수 주체 전체를 조회하되 provider 쓰기 UAT 전에는 앱 내부 성공 상태를 만들지 않는다.
- 목록의 마지막 컬럼에는 구매자 신청 건의 `취소처리`, `반품처리`, `교환처리`와 판매자 직접취소 완료 건의 `상세보기`를 표시한다. 목록에서 승인·거부·입고·송장 버튼을 직접 나열하지 않는다.
- 진입 버튼은 공통 처리 모달을 열고, 모달 안에서 주문·소싱·배송 진행상황과 구매자 사유를 먼저 확인한 뒤 마켓·원상태에 맞는 실제 API 버튼만 노출한다.
- 실데이터 상세에는 공식 API가 존재하는 세부 작업만 표시한다. 네이버 취소 거부, 단순 회수조회, 분쟁·배송비 예외처럼 API 실행 대상이 아닌 작업은 버튼으로 만들지 않는다.
- 실행 어댑터 미연결 또는 계정 UAT 미통과 버튼은 성공 처리나 판매자센터 이동으로 대체하지 않고 연결 필요 상태를 안내한다.
- 판매자 직접 주문취소는 전체주문에서 `판매자취소` 상태를 유지하면서 이 작업함의 `취소·완료`에도 표시한다. 구매자 신청과는 `접수 주체`로 구분하고 취소 승인 버튼을 제공하지 않는다.
- 모바일은 공통 사이드바 버튼을 항상 노출하고, 메뉴의 `닫기`와 링크 이동 시 sheet를 닫는다.

## 6. 메뉴별 전역 액션

| 메뉴 | 전역 액션 |
|---|---|
| 신규주문 | `주문확인`, `주문취소` |
| 상품준비 | `자동 배송중 처리 ON/OFF` |
| 발송대기 | `자동 배송중 처리 ON/OFF`, 일괄 `배송중 처리` |
| 배송중 | 조회 전용 |
| 배송완료 | 조회 전용 |
| 취소/반품/교환 | 현재 실원장 조회·필터·상세·이력, 실계정 UAT 후 지원 액션만 활성화 |

- 구매 완료 주문은 국내송장을 필수로 보유하므로 발송대기 송장 유무 필터는 제공하지 않는다.
- 발송대기의 `배송중 처리`는 구매 완료와 국내송장이 확인된 주문만 대상으로 한다.
- 체크박스로 조건에 맞지 않는 주문이 함께 선택되어도 배송중 처리 대상에서 제외한다.
- 수동 입력은 운영자가 국내송장 컬럼에서 택배사와 송장번호를 직접 입력하는 기능이다.
- 수동 입력은 국내송장 값이 입력된 것으로 보고 자동저장한다.
- 자동 배송중 처리 ON이면 구매 완료와 국내송장 저장 직후 마켓 배송중 처리를 시도한다.

## 7. 상태별 안내문

- 신규주문: 주문확인하면 상품준비로 이동
- 신규주문: 매칭하기로 소싱라이프 후보와 옵션을 저장한 뒤 주문확인까지 처리
- 상품준비: 소싱하기로 소싱라이프 상품 매칭, 옵션 선택, 결제를 진행
- 발송대기: 구매 완료 시 저장된 국내송장을 확인하고 배송중 처리에 사용
- 배송중: 배송중 처리 완료된 주문
- 배송완료: 마켓 배송완료 또는 구매확정 주문
- 취소/반품/교환: 클레임 확인 및 분기 대상

## 8. 소싱 관련 화면/모달

### 소싱하기 모달(행단위)

- 제목: `소싱하기`

실데이터 전환 단계에서는 다음 경계를 적용한다.

- PostgreSQL 실주문은 `매핑 관리`에서 타오바오/티몰 상품 URL, 상품 ID, 정확 SKU, 옵션 속성, CNY 단가, 재고, 최소·단위수량, 중국 배송비를 수동 초안으로 저장할 수 있다.
- 수동 초안은 진행상태를 `소싱필요`로 표시하되, 소싱라이프 trusted connector가 가격·재고·SKU·금지품목을 재검증하기 전에는 구매신청·결제 버튼을 표시하지 않는다. 내부 `MATCH_PENDING_REVIEW` 값은 검증 제어용으로 유지한다.
- demo 주문의 추천 후보·결제 모달과 실주문 매핑 초안을 혼용하지 않는다.
- 모드별 흐름
  - `match-only`(신규주문): 매칭 저장 + 주문확인 동시 처리. 오른쪽 하단에 검정 채움의 `주문확인`을 주 액션으로 두고, 바로 아래에 테두리형 `주문취소` 보조 액션을 둔다.
  - `payment`(상품준비): 매칭 저장 후 결제 화면 이동
- 신규주문 매칭 모달의 `주문취소`를 누르면 매칭 모달을 닫고 기존 판매자 주문취소 확인 모달을 연다. 취소 사유, 상세 사유, 취소 수량 입력과 처리 결과는 목록의 개별 주문취소와 동일하다.
- 표시 항목
  - 현재 주문 정보(상품명, 옵션명, 주문 유입 마켓 배지, 주문번호, 수령인, 결제금액)
- 추천 소싱 상품 리스트(후보 20개)는 한 줄에 2개 상품을 표시하는 2열 카드 그리드로 구성한다.
- 후보별 썸네일, 한국어 상품명 값, 중국어 상품명 값, 판매처를 표시한다. 옵션 선택 전의 기본 가격은 카드 상단에 중복 표시하지 않는다.
- 후보 카드에는 `한국어 상품명`, `중국어 상품명` 타이틀 라벨을 표시하지 않고 상품명 값만 표시한다.
- 각 후보 카드 하단에는 상품별 옵션 드롭다운, `옵션가격(재고)` 라벨 아래 원화 금액과 재고 수량, 수량 증감 컨트롤을 표시한다. 드롭다운 항목은 한국어명, 중국어명, 원화 가격, 재고/품절을 제공하며 옵션 또는 수량을 변경하면 해당 후보 상품도 함께 선택한다. 카드 요약에는 위안화 개당 가격을 중복 표시하지 않는다.
- 추천 상품 카드는 상품명 길이와 관계없이 동일한 높이를 유지하고 옵션·수량 컨트롤의 수직 위치를 맞춘다.
- 옵션 선택 드롭다운은 한국어 옵션명 아래 중국어 옵션명을 함께 표시한다.
- 옵션 선택 요약 상단에는 현재 선택한 소싱 상품 썸네일과 상품명만 표시한다. 주문 유입 마켓 배지는 왼쪽 현재 주문 상품정보에 표시한다.
- 비용 구성에는 상품 금액(원/위안), 소싱처 이용료, 통화 환전 수수료, 소싱 총비용을 표시하며 `최대 할인 적용 시` 문구는 사용하지 않는다.
- 마진 분석은 결제 금액을 기준으로 판매 수수료·상품 금액·소싱처 이용료·환전 수수료·예상 배대지 운임을 각각 직접 차감해 예상 순이익과 결제 금액 대비 마진율을 표시한다. 음수 순이익과 마진율은 굵은 글자와 고대비 테두리로 강조한다.
- 배대지 선택 단계의 왼쪽 본문은 `주문상품 → 소싱상품 → 마진분석 → 배송대행지 선택` 순서의 독립 섹션으로 구성한다. 주문상품에는 유입 마켓·마켓 주문번호·주문 옵션·수량·결제금액을, 소싱상품에는 선택한 상품·옵션·수량·위안/원화 소계를 표시한다. 오른쪽 요약 카드에는 소싱 총비용과 실행 버튼을 표시하고, 신청 후 결제대기에 머문다는 안내를 카드 최하단에 배치한다. 옵션 선택과 최종 결제 단계의 상세 비용 구성은 유지한다.
- 재고는 추천 소싱 상품 카드의 선택 옵션 요약과 드롭다운 항목에서만 표시하고 오른쪽 선택 상품 영역에는 중복 표시하지 않는다. 카드별 옵션과 수량은 다른 상품을 선택한 뒤 돌아와도 유지한다.
- 소싱 모달의 3개 섹션 타이틀은 `현재 주문`, `추천 소싱 상품`, `선택 상품`으로 통일한다. 데스크톱에서는 약 19:56:25 비율로 배치해 추천 목록을 가장 넓게 유지하고 비용 분석이 있는 선택 상품 영역을 현재 주문보다 넓게 제공한다.
- 선택 상품/옵션, 상품 단가, 상품 원가 합계, 결제금액 - 상품원가
- 필수정보 체크
  - 수령인명, 수령인 연락처, 우편번호, 주소, 개인통관부호
- 미매칭 케이스
  - 입력 placeholder: `키워드 또는 타오바오/소싱라이프 상품 URL 입력`
  - 키워드 찾기: 새 검색 후보 20개를 기존 이미지 매칭 후보 목록 상단에 추가한다.
  - URL 찾기: 타오바오 또는 소싱라이프 URL만 허용하며, 허용 URL이면 해당 상품 1개를 기존 후보 목록 상단에 추가한다.

### 결제 화면 연동

- 상품준비 단계에서 소싱라이프 결제 화면 이동은 별도 독립 버튼이 아니라 `소싱하기` 흐름 안에서 처리한다.
- `소싱하기`를 누르면 소싱 후보 확인, 옵션 선택, 결제 화면 이동까지 이어진다.
- 소싱 화면은 주문관리 모달 안에서 `상품·옵션 선택 → 배대지 수령 프로필 선택 → 구매대행 신청 → 결제대기` 순으로 진행한다.
- 결제대기와 결제완료는 동일한 `결제·채팅` 모달 골격을 사용한다. 공통 헤더에는 현재 상태와 마켓 주문번호를 표시하고, 데스크톱 본문은 왼쪽 결제 업무정보와 오른쪽 고정 중국 판매자 채팅 패널의 2열 구조로 구성한다. 모바일에서는 업무정보 다음에 채팅 패널이 이어지는 세로 구조를 사용한다.
- 결제대기 왼쪽에는 별도 접수 단계 안내 카드 없이 `원주문 상품과 소싱상품 비교`, `예상 비용 및 수익`, 선택 배송대행지를 순서대로 표시한다. 상품 비교는 두 상품의 이미지·상품명·옵션·수량과 판매 결제금액·상품원가를 나란히 보여준다. 비용·수익 영역은 상품원가·소싱처 이용료·환전 수수료·예상 배송비·예상 총비용과 정산예상금액·판매 수수료·예상 순이익·마진율을 표시하고, 수익 예상과 역마진 예상을 텍스트 배지로 구분한다. 하단 고정 작업 영역에는 `주문 취소하기`와 금액을 포함하지 않은 `상품 결제하기`를 한 줄로 배치한다. `주문 취소하기`는 모달을 닫고 기존 판매자 주문취소 확인 절차를 연다.
- 오른쪽 중국 판매자 채팅 패널은 결제대기와 결제완료 모두 같은 위치와 구성으로 유지한다. 채팅 가능 상태, 발신자 구분이 있는 메시지 내역, 메시지 입력, 전송 버튼, 민감정보 입력 금지 안내를 표시하며 결제대기의 메시지를 결제완료에서도 이어서 보여준다. 결제대기에서는 `깎아줘`, `깎아줘 취소` 버튼과 가격 협상 상태를 추가로 표시한다. 요청 중에는 `깎아줘`와 하단 `결제하기`를, 요청 전·취소 후에는 `깎아줘 취소`를 비활성화한다. 결제완료에서는 두 협상 버튼을 표시하지 않는다.
- 구매대행 신청 시 결제를 자동 완료하지 않는다. 상품준비 목록은 계속 `소싱하기`로 표시하고, 행 자세히 보기의 `처리하기`에서 `결제하기`를 제공한다.
- `결제하기`는 상품준비의 결제대기 주문에만 표시한다. 발송대기·배송중·배송완료에서 미결제가 발견되면 결제 버튼 대신 `결제상태 불일치` 안내를 표시한다.
- 실서비스에서 결제완료가 확인되면 선택한 배송대행지 사이트를 열고 주문서를 자동입력한다. `접수대기`와 `접수신청`은 동일 단계이며 접수와 동시에 발급된 국내 택배사·송장번호를 주문에 저장한다.
- 현재 프로토타입은 외부 배송대행지 사이트, 주문서 자동입력, 접수 화면을 구현하지 않는다. 결제완료 버튼 클릭 시 중간 단계를 성공한 것으로 간주해 더미 국내송장을 즉시 생성하고 결제완료 조회 화면으로 전환한다.
- 결제완료 조회 화면은 같은 `결제·채팅` 모달을 조회·채팅 모드로 사용한다. 왼쪽에는 신청 상품, 실제 결제금액·결제일시, 소싱라이프 주문번호, 선택 배송대행지, 주문서 접수 및 국내송장 반영 결과를 표시하고 결제 CTA는 제거한다. 오른쪽 중국 판매자 채팅 패널은 입력과 전송을 계속 허용하며 재결제는 제공하지 않는다.
- 배송·구매 진행 배지는 진행상태 컬럼에 표시한다. 소싱 결제완료부터 배송완료까지 행 자세히 보기의 `처리하기`에 `소싱상품관리`와 `배송추적`을 유지한다. 배송중과 배송완료 목록 처리하기에는 조회 버튼, 처리이력과 운영 결과 문구를 표시하지 않고 빈 셀로 둔다.
- 상품준비 메뉴 상단에는 `자동 배송중 처리` 토글을 제공한다.
- 토글 OFF 상태에서 배송대행지 접수 응답으로 국내송장이 수신되면 송장번호가 입력된 상태로 발송대기에 남긴다. 이 시점에는 마켓 배송중 처리를 실행하지 않는다.
- 토글 ON 상태에서 소싱라이프 또는 외부 구매가 완료되고 국내송장이 확보되면 마켓 발송 API를 자동 호출한다. 성공 시 마켓과 내부 주문을 모두 배송중으로 변경한다.
- 마켓 발송 API가 실패하면 내부 주문은 송장이 있는 발송대기에 남기고 실패 사유와 재처리 버튼을 표시한다.
- 배송대행지 접수 응답에 국내송장이 없으면 결제 성공은 유지하되 발송 단계 완료로 처리하지 않고 접수 결과 오류로 안내한다.
- 마켓 직접전달 처리 여부와 관계없이 소싱라이프 구매 완료에는 국내송장이 필수다. 직접전달 완료 주문에서 송장이 누락돼도 상품준비 상태를 유지하고 연동 오류를 표시한다.

### 자동 배송중 처리 ON/OFF

- 위치: 상품준비 및 발송대기 메뉴 상단 전역 액션 영역
- 발송대기 상태에서는 소싱라이프 송장 자동 수집 토글을 제공하지 않는다.
- 자동 배송중 처리 ON은 국내송장이 입력되는 즉시 배송중 처리를 자동 시도하고 배송중 전환을 진행한다.
- 자동 배송중 처리 OFF 상태에서는 국내송장이 입력되어도 운영자가 `배송중 처리` 버튼으로 직접 전송한다.
- 자동 배송중 처리는 소싱라이프 또는 외부 구매 완료 시 국내송장이 확보되면 동작한다.
- 자동 배송중 처리 실패 건은 발송대기에 남기고 실패 사유를 표시한다.
- 상품준비와 발송대기의 자동 배송중 처리 토글은 동일한 저장값을 사용한다. 한 화면에서 변경한 ON/OFF 상태를 다른 화면에서도 유지한다.

### 마켓연동 설정

- 위치: 주문관리 > 마켓연동
- 마켓별 인증 정보와 스토어명을 입력/수정한다.
- 플랫폼 수수료율은 주문수집 MVP 화면에서 제공하지 않는다.
- 마켓 추가/수정/삭제는 각각 별도 모달 화면 기준을 가진다.

### 소싱 후보 표시

- 소싱 후보 리스트에서는 구매 1회, AI 매칭률, 별점, 배송일수 정보를 표시하지 않는다.
- 주문 테이블에는 후보 일치율 또는 매칭률 컬럼을 표시하지 않는다.

## 9. 행 확장 상세 기준

- 주문 행을 클릭하면 목록 아래에 자세히 보기 영역을 펼친다.
- 소싱상품 매칭이 완료된 주문은 자세히 보기의 첫 영역을 `상품 비교`로 구성하고 화면 크기와 관계없이 주문상품 아래에 소싱상품을 표시한다. 두 상품의 이미지·상품명·옵션·수량·금액을 위에서 아래로 비교할 수 있어야 한다. 아직 매칭된 소싱상품이 없으면 소싱상품 카드와 빈 상태 안내를 모두 숨기고 주문상품만 표시한다.
- 매칭된 소싱상품이 있으면 상품 비교 아래에 `마진계산`을 표시한다. 마진계산 안에서는 매출·정산 아래에 예상 소싱비용을 배치하고, 그 아래에 예상 순이익·마진율을 표시한다. `수익 예상` 또는 `역마진 예상`을 텍스트 배지로 구분하며, 매칭상품 원가가 없으면 임의 계산하지 않고 계산 대기 안내를 표시한다.
- 넓은 화면의 왼쪽에는 `구매자 · 배송정보`를 배치하고 카드 안에서 구매자와 수령 정보를 위에서 아래로 표시한다. 택배정보는 같은 왼쪽 영역에서 그 아래에 표시한다.
- 넓은 화면의 상세는 왼쪽 정보 22%, 가운데 상품 60%, 오른쪽 처리 18%를 기준으로 배치한다. 왼쪽과 오른쪽은 각각 최소 320px, 260px을 확보해 주소와 버튼이 지나치게 눌리지 않게 한다. 화면이 좁으면 상품 비교·마진계산, 구매자·배송정보·택배정보, 처리하기 순서로 한 줄씩 배치하고 버튼의 세로 배치는 유지한다.
- `배송추적` 모달은 결제완료 → 중국배송 → 통관 → 국내배송 → 배송완료의 완료·진행 중·예정 단계와 연동사가 제공한 누적 이벤트 일시·위치·택배사·송장번호를 보여준다. 배송완료에서도 버튼을 유지하며, 반품완료·교환완료에서는 최초 배송 뒤에 반품 회수·반송 또는 교환 회수·재배송 이력을 이어서 표시한다. 상세 이벤트가 없으면 결제완료·국내송장 수신·마켓 배송중 처리처럼 실제 저장된 사건만 표시하고 임의 시각을 생성하지 않는다.
- 배송상태 모달은 조회 전용이며 배대지 CS, 검수, 입출고, 창고 관리 기능을 제공하지 않는다. 배대지 관련 범위는 소싱 단계에서 기존 저장 프로필을 선택하는 기능으로 제한한다.
- 배송정보는 자세히 보기에서도 수정할 수 있다.
- 매칭된 소싱상품은 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호를 표시한다. 외부 구매처럼 매칭상품이 없는 주문은 소싱상품 영역을 표시하지 않는다. 실행·조회 버튼은 소싱상품에 중복 배치하지 않고 오른쪽 `처리하기` 영역에 모은다.
- 주문일시와 마켓/스토어명은 주문상품 영역에 함께 표시한다.

## 10. 실패 사유 기준

### 실패 사유

- 실패 사유는 정상 처리가 되지 않은 주문에만 표시한다.
- 대상 실패는 주문수집 실패, 주문확인 실패, 소싱라이프 연동 실패, 결제 상태 반영 실패, 배송중 처리 실패, 클레임 처리 실패다.
- 정상 주문은 실패 사유 컬럼을 비워둔다.

### 처리이력 제외

- 처리이력은 초기버전 주문관리 화면에서 제공하지 않는다.
- 주문별 상태 변경 로그와 작업 로그는 추후 기능으로 분리한다.

## 11. 운영 개요·주문현황

### 11-1. 대시보드

- 루트(`/`)는 `/dashboard`로 이동한다.
- 상단에는 월간 기준과 `확정 마진만`, `취소·반품 제거`, `직접 입력 비용 반영` 토글을 배치한다.
- 핵심 지표, 처리할 작업, 일별 매출, 공지 영역을 공통 앱 셸의 전체 가용 너비에 표시한다.
- `주문현황 열기`는 `/journey`의 이슈 작업함으로 이동한다.

### 11-2. 주문현황

- 6개 그룹과 32개 세부 상태 타일을 표시하며 타일에는 전체 건수와 처리 필요 건수를 함께 표시한다.
- 검색, 이슈만 보기, 수동 새로고침, 이슈 기준 설정을 상단 작업 도구로 제공한다.
- 타일을 선택하면 하단 목록이 같은 화면에서 갱신되고, 주문 상세 처리 화면으로 이동할 수 있다.
- 이슈 주문은 `이슈 아님` 또는 `2시간 미루기`로 현재 검수 세션에서 정리할 수 있다.
- 배대지 세부 상태는 외부 상태를 보여주는 조회 정보이며 내부 창고 작업 버튼을 제공하지 않는다.

## 12. 알림·문의·장부 보강

- `/me/notifications`는 고객 알림과 셀러 알림을 분리하고, 고객 발송 시간대·통관 안내 옵션·메시지 미리보기를 제공한다.
- 현재 알림 설정 화면에는 `정책 데모` 안내를 고정 표시하며 저장 시 외부 메시지를 발송하지 않는다.
- 문의 답변 모달의 `AI 초안 만들기`는 주문번호와 문의 내용을 바탕으로 검토 가능한 문구를 채운다. 사용자가 편집한 후 기존 전송 절차를 사용한다.
- 장부의 `직접 입력 비용 반영`이 켜지면 직접 지출·수입과 실제마진 컬럼을 추가하고 요약 마진을 같은 기준으로 계산한다.

## 13. 소싱환불 UI 배치와 상호작용

### 13-1. 주문 상세

- 신규 사이드바 메뉴를 추가하지 않는다. TaoWorld 구매 주문라인이 연결된 소싱상품은 `결제완료`부터 `국내 배송중`까지 `소싱상품관리`의 구매대행 신청 상품 영역에 `반품·환불 신청`을 표시한다. 목록과 상세 `처리하기`에는 별도 환불 버튼을 표시하지 않는다.
- 환불이 이미 있으면 `소싱상품관리`의 같은 위치에서 버튼을 활성 상태에는 `환불 진행`, 완료·거절 상태에는 `환불 내역`으로 바꾸고 같은 모달을 조회 모드로 연다. 배송완료 후에는 신규 신청을 숨기되 기존 요청의 조회 버튼은 유지한다.
- 환불 상태가 `소싱환불 완료`이고 국내배송 전이면 상세 `처리하기`에 `다시 소싱하기`를 함께 표시한다. 버튼을 누르면 과거 환불 내역을 보존한 채 기존 매칭을 선택값으로 사용하지 않는 `소싱하기` 모달을 열고, 새 후보 상품·판매처를 고른 뒤 배대지 선택과 소싱상품 결제로 이어간다. 목록 행에는 이 버튼을 표시하지 않는다.
- 상품 비교의 `소싱상품`에는 CNY 요청금액·`refundId`와 현재 환불 상태를 요약한다. 외부구매 주문에는 소싱환불 버튼과 상태를 표시하지 않는다.
- 활성 환불 또는 재소싱 전 환불완료 상태이면 `배송중 처리`와 `마켓 직접전달`을 숨기거나 비활성화해 과거 소싱 건의 출고를 막는다.

### 13-2. 환불 요청 모달

- 상단에 `마켓 취소·반품과 별도 흐름`임을 고정 안내한다.
- TaoWorld 구매주문 ID, 구매 주문라인 ID, CNY 결제금액과 국내 결제 참고금액을 먼저 보여준다.
- 첫 카드는 `/order/refund/render` 단계다. `refundType(1/2)`, `goodsStatus(1~6)`를 고르면 mock render 응답의 동적 `reasonId`, `maxRefundFee`, 통화를 표시한다.
- 두 번째 카드는 `/order/refund/submit` 단계다. `refundFee`는 CNY로 입력하고 `refundDesc`, 선택적 `refundImages`, 내부 연결용 마켓 클레임 ID를 제공한다. 별도 환불 수량 입력은 제공하지 않는다.
- 요청 금액은 render 응답의 최대 CNY 금액 이하여야 하며, 사유는 현재 render 응답에 포함된 ID만 선택할 수 있다.
- 반품형이 `RETURN_REQUIRED`에 도달하면 `/render/logistics`의 택배사 코드, 송장번호, 반품자 전화번호, 설명을 입력하는 `/submit/logistics` 카드를 표시한다.
- 진행 화면은 `refundId`, 원본 `refundStatus` 코드, 구매 주문라인, 상품 상태, CNY 요청·승인금액과 국내 예상 환급액을 함께 표시한다.
- `message_type=9 수신·query 데모`는 webhook 성공으로 선반영하지 않고 `/order/refund/query` 결과를 적용하는 상태 전이를 시뮬레이션한다.
- 요청 전 `마켓 주문 취소·구매자 환불은 자동 처리되지 않음` 확인 체크를 필수로 한다.
- 실주문은 TaoWorld 어댑터·멱등·message/query 대사 연결 전 `실전송 비활성`으로 실행을 차단한다.

### 13-3. 클레임 상세와 주문현황

- 구매자 클레임 상세의 기존 `처리 작업` 아래에 `소싱 구매 후속조치`를 별도 섹션으로 둔다. 마켓 버튼과 소싱환불 버튼을 한 작업으로 합치지 않는다.
- 주문현황의 소싱 환불 상태는 실제 `sourcingRefund` 값이 있을 때만 표시한다. 결제완료 주문이 취소됐지만 환불 요청이 없으면 마켓 취소 상태를 유지하고 `소싱환불 요청 필요` 이슈를 표시한다.
- 소싱 환불 표시 상태는 `소싱환불 승인대기`, `소싱반품 송장필요`, `소싱반품 배송중`, `소싱환불 처리중`, `소싱환불 완료`, `소싱환불 거절`, `소싱환불 확인필요`의 7개다. 내부 `REQUESTED`와 `PROVIDER_REVIEW`는 모두 `소싱환불 승인대기`로 표시하며, 활성 소싱 환불이 있으면 기본 소싱 상태 대신 해당 상태 하나를 진행상태 컬럼에 표시한다.
