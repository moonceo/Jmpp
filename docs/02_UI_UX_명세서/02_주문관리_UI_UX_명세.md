# 주문관리 UI/UX 명세

## 1. 화면 구성 원칙

- 주문관리 화면은 마켓별 차이 없이 동일한 구조로 동작한다.
- 좌측 메뉴는 주문관리 하위 업무 기준으로 구성하고, 주문수집 내부 상태는 본문 상단 탭으로 제공한다.
- 운영자가 다음 단계로 넘어갈 액션이 한눈에 보이게 한다.

## 2. 핵심 레이아웃

1. 페이지 헤더
   - 제목: 일반 주문수집 화면은 `주문관리`, 클레임 화면은 `취소/반품/교환`
   - 상태 설명 문구는 본문에서 노출하지 않는다.

2. 검색/필터 영역
   - 주문 검색어: 마켓 주문번호, 상품주문번호, 상품명, 구매자명, 수령인명, 구매자 연락처, 수령인 연락처, 개인통관부호
   - 기간 필터: 오늘, 3일, 7일, 30일, 직접 입력
   - 직접 입력 클릭 시 작은 모달에서 시작날짜와 끝나는날짜를 선택한다.
   - 마켓/스토어 필터: 아이콘 버튼 하나로 제공하며 마켓과 스토어를 각각 중복 선택할 수 있다.
   - 스토어 항목은 마켓 아이콘 + 스토어명 형식으로 제공한다.
   - 주문수집 버튼은 검색/필터 영역 우측 공통 액션으로 표시한다.

3. 메뉴별 기능 영역
   - 검색/필터 아래, 테이블 위에 좌측 정렬로 표시한다.
   - 현재 소메뉴에 필요한 기능만 노출한다.
   - 신규주문: `주문확인`, `주문취소`
   - 상품준비: `소싱라이프 송장 수신 시 자동 배송중 처리` 토글
   - 발송대기: 송장 상태 드롭다운(`전체`, `송장 있음`, `송장 없음`), `소싱라이프 송장 자동 수집`, `자동 배송중 처리`, `소싱라이프 송장 수집`, `배송중 처리`

4. 주문 테이블
   - 전체 선택 체크박스
   - 주문 처리에 필요한 주요 정보만 테이블 컬럼으로 우선 노출
   - 주문 행 클릭 시 행 아래 자세히 보기 영역을 펼쳐 목록에 없는 상세 정보를 표시
   - 하나의 컬럼은 하나의 업무 목적 또는 하나의 기능 단위만 담당
   - 좌측 메뉴에서 선택한 주문 그룹과 상태에 따라 표시 데이터 집합이 달라짐
   - 테이블 하단의 건수와 페이지 이동 버튼은 테이블 박스 밖 하단에 표시한다.

5. 테이블 설계 원칙
   - 반복 처리 속도를 위해 목록은 핵심 컬럼만 노출하고, 상세 정보는 행 확장으로 보완한다.
   - 한 컬럼 안에 서로 다른 업무 목적을 섞지 않는다.
   - 상품, 구매자, 수령인, 소싱, 송장, 처리 액션은 각각 별도 컬럼으로 분리한다.

## 3. 사이드바 메뉴 기준

- 주문관리
  - 주문수집
  - 취소/반품/교환
  - 문의관리
  - 마켓연동

주문수집 내부에는 본문 상단 탭으로 신규주문, 상품준비, 발송대기, 배송중, 배송완료를 제공한다.

### 상단 상태 탭 건수 표시 기준

- 주문수집 본문 상단 상태 탭에 단계별 주문 건수를 표시한다.
- 0건 표시 여부는 화면 밀도에 따라 숨김 처리하거나 낮은 강조로 표시할 수 있다.
- 처리 필요성이 높은 단계는 강조 색상을 적용한다.
- 일반 주문 그룹의 신규주문, 상품준비, 발송대기와 클레임 그룹의 취소/반품/교환은 우선 처리 대상 색상을 적용한다.
- 배송중, 배송완료는 조회성 상태이므로 낮은 강조 색상을 적용한다.
- 상태 탭 클릭 시 해당 상태 목록을 보여준다.
- 일반 주문 전체 처리 대기 합계는 신규주문, 상품준비, 발송대기 건수를 합산한다.
- 클레임 처리 대기 건수는 취소/반품/교환 그룹에서 별도로 표시한다.

## 3-1. 마켓 계정 등록 화면 기준

- 위치: 주문관리 > 마켓연동
- 최종 등록 대상: 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션
- 화면 등록 대상: 스마트스토어, 쿠팡, 11번가, 지마켓, 옥션
- 실제 API 안정화 우선순위는 스마트스토어, 쿠팡을 먼저 검증하고 11번가, 지마켓, 옥션 순서로 확장한다.
- 최종적으로 사용자는 등록 대상 마켓에서 운영 중인 판매자 계정 또는 스토어를 개수 제한 없이 등록할 수 있다.
- 계정 목록에는 마켓, 스토어명, 연동상태, 활성, 관리 액션을 표시한다.
- `관리`는 마켓 추가와 동일한 형식의 계정 수정 모달을 연다.
- 삭제는 관리 영역의 삭제 버튼에서 삭제 확인 모달을 거친 뒤 처리한다.
- 특정 판매처만 주문수집하거나 특정 계정만 주문수집하는 버튼은 초기 화면 범위에서 제외한다.
- 주문수집 화면에는 마켓별 필터와 계정별 필터를 함께 제공한다.

## 3-2. 주문수집 필터 기준

- 주문 검색
  - 마켓 주문번호
  - 상품주문번호
  - 상품명
  - 구매자명
  - 수령인명
  - 구매자 연락처
  - 수령인 연락처
  - 개인통관부호
- 기간 필터
  - 오늘
  - 3일
  - 7일
  - 30일
  - 직접 입력
- 마켓 필터
  - 스마트스토어
  - 쿠팡
  - 11번가
  - 지마켓
  - 옥션
- 계정 필터
  - 플랫폼 아이콘 + 사용자가 연동한 스토어명
- 마켓 필터를 선택하면 선택된 마켓의 주문만 표시하며, 여러 마켓을 중복 선택할 수 있다.
- 계정 필터를 선택하면 선택된 연동 계정에서 수집된 주문만 표시하며, 여러 계정을 중복 선택할 수 있다.
- 마켓 또는 계정 필터의 선택을 모두 해제하면 전체 주문을 표시한다.
- 주문 검색어, 기간 필터, 마켓 필터, 계정 필터를 함께 선택하면 모든 조건을 만족하는 주문만 표시한다.
- 필터는 주문 목록 조회 조건이며, 주문수집 실행 범위를 제한하지 않는다.
- 상태 필터는 제공하지 않는다. 좌측 메뉴에서 선택한 상태가 목록 상태 기준이 된다.

## 5. 테이블 컬럼 정의

주문수집 목록은 아래 컬럼을 기준으로 구성한다.

| 순서 | 컬럼명 | 기능 |
|---|---|---|
| 1 | 선택 | 주문 단위 선택 체크박스 |
| 2 | 처리하기 | 현재 상태에서 가능한 행 액션 표시 |
| 3 | 주문일시 | 마켓 주문 발생 일시 표시 |
| 4 | 상품정보 | 썸네일, 상품명, 옵션명, 수량, 마켓 주문번호 표시 |
| 5 | 택배정보 | 국내 택배사, 국내 송장번호, 배송중 처리 표시 |
| 6 | 배송정보 | 수령인명, 수령인 연락처, 우편번호, 배송지 주소, 개인통관부호, 통관부호 일치/불일치 상태, 수정 제공 |
| 7 | 판매처 | 마켓과 연동 계정 표시 |
| 8 | 소싱라이프 | 매칭완료 또는 소싱라이프 주문번호 표시, 주문번호 클릭 시 소싱라이프 주문내역 이동 |

### 5-1. 컬럼 표시 원칙

- 각 컬럼은 하나의 업무 목적 또는 하나의 기능 단위를 담당한다.
- 같은 업무 목적의 값과 상태 표시는 한 컬럼에 함께 표시할 수 있다.
- 주문수집 목록은 반복 처리 속도를 우선하므로 관련 정보는 업무 단위로 병합할 수 있다.
- 상품이미지, 상품명, 옵션명, 마켓 주문번호는 `상품정보` 컬럼에 함께 표시한다.
- 마켓과 연동 계정은 `판매처` 컬럼에 함께 표시한다.
- 주문확인, 매칭하기, 소싱하기, 수동구매 완료, 배송중 처리, 주문취소는 주문 상태별로 `처리하기` 컬럼에 표시한다.
- 수량은 `상품정보` 컬럼에 함께 표시한다.
- 구매자명, 구매자 연락처는 행 확장 자세히 보기의 `구매자` 영역에 표시한다.
- 수령인, 연락처, 주소, 개인통관부호는 `배송정보` 컬럼과 행 확장 자세히 보기의 `배송정보` 영역에 표시한다.
- 개인통관부호가 비어 있거나 형식이 맞지 않으면 모두 `통관부호 불일치`로 표시하고, 형식이 맞으면 `통관부호 일치`로 표시한다.
- 배송정보 컬럼의 `수정` 버튼으로 수령인 배송정보와 개인통관부호를 함께 수정할 수 있다.
- 배송정보 수정 모달에서도 개인통관부호 입력값의 `통관부호 일치/불일치` 상태를 표시한다.
- 국내송장 컬럼명은 `택배정보`이며 택배사, 송장번호를 함께 표시한다.
- 배송중 처리 완료 여부는 별도 컬럼으로 표시하지 않고 주문상태가 배송중으로 바뀌는 것으로 표현한다.
- 화면 전체에는 좌우 스크롤이 생기지 않게 하고, 필요 시 주문 테이블 내부에서만 가로 스크롤을 허용한다.
- 일반 주문수집 메뉴 간 같은 컬럼은 동일한 폭을 유지한다.
- 컬럼 폭은 내용 길이에 따라 메뉴별로 흔들리지 않도록 고정 폭 기준을 사용한다.
- 주문상태 컬럼은 본문 상단 상태 탭과 중복되므로 주문수집 목록에서 제거한다.
- 마켓 주문번호는 `상품정보` 컬럼 안에서 `마켓 주문번호 : 주문번호` 형식의 일반 텍스트로 표시하며 클릭 링크나 주문상세 모달은 제공하지 않는다.

### 5-1-1. 주문수집 목록 숨김 컬럼

주문수집 목록은 아래 컬럼만 노출한다.

| 목록 컬럼 | 포함 정보 |
|---|---|
| 선택 | 주문 선택 체크박스 |
| 처리하기 | 상태별 처리 액션 |
| 주문일시 | 마켓 주문 발생 일시 |
| 상품정보 | 상품이미지, 상품명, 옵션명, 수량, 마켓 주문번호 |
| 택배정보 | 국내송장 |
| 배송정보 | 수령인명, 수령인 연락처, 우편번호, 배송지 주소, 개인통관부호, 통관부호 일치/불일치 상태, 수정 |
| 판매처 | 마켓, 연동 계정 |
| 소싱라이프 | 매칭완료 또는 소싱라이프 주문번호, 주문내역 링크 |

아래 항목은 주문수집 목록에서만 숨긴다. 데이터 모델, 검색/계산/상태 처리에는 유지하며 필요 시 목록 컬럼으로 다시 노출할 수 있다.

| 구분 | 숨김 또는 병합 항목 |
|---|---|
| 목록 숨김 | 마켓 결제완료일시, 상품주문번호, 상품단가, 구매가/결제금액, 구매자명, 구매자 연락처, 구매자 아이디, 정산예정금액, 예상마진, 클레임 사유, 실패 사유, 주문상태 |
| 목록 숨김 | 소싱상태, 소싱상품명, 소싱옵션명, 예상원가, 실제결제금액, 실제마진 |
| 목록 표시 | 소싱라이프 주문정보(소싱라이프 주문번호 표시 및 주문내역 링크) |
| 목록 병합 | 상품이미지, 상품명, 옵션명, 마켓 주문번호는 `상품정보`로 병합 |
| 목록 병합 | 마켓, 연동 계정은 `판매처`로 병합 |
| 목록 병합 | 주문확인, 매칭하기, 소싱하기, 수동구매 완료, 배송중 처리, 주문취소는 `처리하기`로 병합 |

삭제 요청으로 목록에서 제외한 컬럼도 원천 데이터에서는 삭제하지 않는다. 목록 화면의 표시 여부만 조정하며, 운영 또는 개발 판단에 따라 다시 꺼내 쓸 수 있어야 한다.

### 5-2. 목록 스크롤 기준

- 전체 페이지에는 좌우 스크롤이 생기지 않게 한다.
- 주문 테이블 내부는 컬럼 수가 늘어날 경우 가로 스크롤을 허용한다.
- 기본 목록은 압축 컬럼을 사용해 데스크톱 화면에서 핵심 처리 흐름이 한눈에 보이도록 한다.

### 5-3. 상품 이미지/상품명 인터랙션

- 상품이미지 컬럼의 썸네일을 클릭하면 이미지 크게 보기 모달을 연다.
- 이미지 크게 보기 모달에는 이미지 복사 버튼을 제공한다.
- 이미지 복사 버튼은 현재 표시 중인 상품 이미지를 클립보드에 복사한다.
- 상품명 컬럼을 클릭하면 새 창 또는 새 탭으로 오픈마켓 상품 상세 페이지를 연다.
- 상품 상세 링크가 없는 주문은 상품명을 일반 텍스트로 표시한다.

### 5-4. 주문번호 표시 기준

- 마켓 주문번호는 `상품정보` 컬럼 안에서 `마켓 주문번호 : 주문번호` 형식의 일반 텍스트로 표시한다.
- 마켓 주문번호 클릭 링크와 주문상세 모달은 제공하지 않는다.
- 목록에서 숨긴 원천 데이터는 데이터 모델에 유지하며, 필요 시 별도 화면 또는 컬럼으로 다시 노출할 수 있다.

원천 데이터 유지 항목:

| 구분 | 표시 항목 |
|---|---|
| 주문 기본 | 마켓, 연동 계정, 마켓 주문번호, 상품주문번호, 주문일시, 마켓 결제완료일시, 주문상태 |
| 상품 | 상품이미지, 상품명, 옵션명, 수량, 상품단가, 결제금액 |
| 구매자 | 구매자명, 구매자 아이디, 구매자 연락처 |
| 수령인 | 수령인명, 수령인 연락처, 우편번호, 배송지 주소, 배송메시지 |
| 통관 | 개인통관부호, 통관부호 일치/불일치 상태 |
| 소싱 | 소싱상태, 소싱상품명, 소싱옵션명, 예상원가, 실제결제금액, 실제마진, 소싱라이프 주문번호 |
| 송장 | 국내송장 |
| 예외 | 클레임 사유, 실패 사유 |

상태별 행 처리 버튼:

| 주문상태 | 처리하기 버튼 |
|---|---|
| 신규주문 | `주문확인`, `매칭하기`, `주문취소` |
| 상품준비 | `소싱하기`, `수동구매 완료`, `주문취소` |
| 발송대기 | `배송중 처리`, `주문취소` |
| 배송중 | 다음 단계 버튼 없음 또는 조회 전용 |
| 배송완료 | 다음 단계 버튼 없음 또는 조회 전용 |
| 취소/반품/교환 | `취소처리`, `반품처리`, `교환처리` |

### 5-5. 국내송장 입력

- `NEW`, `PREPARING`, `DELIVERED`: 표시값 고정
- `READY_TO_SHIP`: 직접 편집 가능
- `SHIPPING`: 주문수집 목록에서는 국내송장 수정/전송 버튼을 제공하지 않는다.
- `SHIPPING`: 변경된 송장번호가 수신된 경우 택배정보에 변경된 송장번호를 표시해 사용자가 마켓에서 직접 확인할 수 있게 한다.
- 국내송장 컬럼에서 택배사 선택과 송장번호 입력을 함께 제공한다.
- 수동 입력은 운영자가 국내송장 컬럼에서 택배사와 송장번호를 직접 입력하는 기능이다.
- 국내송장은 직접 입력, 소싱라이프 송장 자동 수집, 소싱라이프 송장 수집 중 어떤 방식으로 입력되어도 즉시 자동저장된다.
- 번호 입력은 숫자만 허용
- 미입력 시 placeholder: `국내송장번호`

### 5-6. 처리작업

- NEW: `주문확인`, `매칭하기`, `주문취소`
- PREPARING: `소싱하기`, `수동구매 완료`, `주문취소`
- `수동구매 완료`는 소싱라이프를 통하지 않고 구매한 주문을 처리하는 기능이다.
- `발송대기 처리`를 누르면 송장번호가 없어도 발송대기로 이동하며, 송장번호가 있으면 저장 후 발송대기로 이동한다.
- `배송중 처리`를 누르면 송장번호를 저장하면서 배송중으로 이동한다.
- READY_TO_SHIP: `배송중 처리` 버튼은 항상 표시하고, 국내송장번호가 없으면 비활성화한다.
- 국내송장번호 입력을 시작하면 `배송중 처리` 버튼을 활성화한다.
- 국내송장번호만 입력하고 `배송중 처리`를 누르지 않으면 송장번호만 저장하고 발송대기에 남긴다.
- `배송중 처리`를 누르면 현재 입력된 송장번호를 저장하면서 배송중으로 이동한다.
- SHIPPING: 조회 전용이며 변경된 송장번호가 있으면 표시만 제공한다.
- DELIVERED: 조회 전용
- CLAIM: `취소처리`, `반품처리`, `교환처리`
- `주문취소`는 신규주문, 상품준비, 발송대기에서 행 액션으로 제공한다.
- 신규주문에서는 체크된 주문을 대상으로 상단 전역 `주문취소`도 제공한다.

### 5-7. 주문확인 일괄처리

- 신규주문 메뉴에서 여러 주문을 체크박스로 선택할 수 있다.
- 상단 전역 주문확인 버튼명은 `주문확인`으로 고정한다.
- 체크박스로 선택된 주문이 없으면 `주문확인` 버튼은 비활성화한다.
- 상단 `주문확인`은 체크된 NEW 상태 주문에만 적용한다.
- 일괄 처리 후 성공한 주문은 상품준비로 이동한다.
- 실패한 주문은 신규주문에 남기고 실패 사유를 표시한다.

### 5-8. 주문취소 일괄처리

- 신규주문 메뉴에서 여러 주문을 체크박스로 선택해 `주문취소`를 일괄 실행할 수 있다.
- 체크박스로 선택된 주문이 없으면 `주문취소` 버튼은 비활성화한다.
- 개별 주문취소와 일괄 주문취소 모두 확인 모달을 거친다.
- 처리된 주문은 판매자 주문취소 상태로 이동하며, 취소/반품/교환 클레임 목록에는 노출하지 않는다.

## 6. 메뉴별 전역 액션

| 메뉴 | 전역 액션 |
|---|---|
| 신규주문 | `주문확인`, `주문취소` |
| 상품준비 | `소싱라이프 송장 수신 시 자동 배송중 처리 ON/OFF` |
| 발송대기 | 송장 상태 드롭다운(`전체`, `송장 있음`, `송장 없음`), `소싱라이프 송장 자동 수집 ON/OFF`, `자동 배송중 처리 ON/OFF`, `소싱라이프 송장 수집`, `배송중 처리` |
| 배송중 | 조회 전용 |
| 배송완료 | 조회 전용 |
| 취소/반품/교환 | 주문별 `취소처리`, `반품처리`, `교환처리` |

- 발송대기 송장 상태 드롭다운의 `전체`, `송장 있음`, `송장 없음`은 국내송장 입력 여부로 발송대기 주문을 구분해 보는 필터다.
- 송장 수집은 운영자가 버튼을 눌러 소싱라이프 주문번호 기준으로 발급된 국내송장을 조회하는 기능이다.
- 송장 수집은 소싱라이프 주문번호가 있고 국내송장이 없는 주문만 대상으로 한다.
- 배송중 처리는 국내송장이 있는 주문만 대상으로 한다.
- 체크박스로 조건에 맞지 않는 주문이 함께 선택되어도 송장 수집 또는 배송중 처리 대상에서 제외한다.
- 수동 입력은 운영자가 국내송장 컬럼에서 택배사와 송장번호를 직접 입력하는 기능이다.
- 소싱라이프 송장 자동 수집, 소싱라이프 송장 수집, 수동 입력 모두 국내송장 값이 입력된 것으로 보고 자동저장한다.
- 자동 배송중 처리 ON이면 국내송장 자동저장 직후 배송중 처리를 시도한다.

## 7. 상태별 안내문

- 신규주문: 주문확인하면 상품준비로 이동
- 신규주문: 매칭하기로 소싱라이프 후보와 옵션을 저장한 뒤 주문확인까지 처리
- 상품준비: 소싱하기로 소싱라이프 상품 매칭, 옵션 선택, 결제를 진행
- 발송대기: 송장 없음 주문은 소싱라이프 송장 수집 또는 수동 입력, 송장 있음 주문은 배송중 처리 상태에서 사용
- 배송중: 배송중 처리 완료된 주문
- 배송완료: 마켓 배송완료 또는 구매확정 주문
- 취소/반품/교환: 클레임 확인 및 분기 대상

## 8. 소싱 관련 화면/모달

### 소싱하기 모달(행단위)

- 제목: `소싱하기`
- 모드별 흐름
  - `match-only`(신규주문): 매칭 저장 + 주문확인 동시 처리
  - `payment`(상품준비): 매칭 저장 후 결제 화면 이동
- 표시 항목
  - 현재 주문 정보(상품명, 주문번호, 수령인, 결제금액)
- 추천 소싱 상품 리스트(후보 20개)
- 후보별 썸네일, 한국어 상품명, 중국어 상품명, 판매처, 원화/위안 상품원가
- 옵션 선택 드롭다운은 한국어 옵션명 아래 중국어 옵션명을 함께 표시한다.
- 선택 상품/옵션, 상품 단가, 상품 원가 합계, 결제금액 - 상품원가
- 필수정보 체크
  - 수령인명, 수령인 연락처, 우편번호, 주소, 개인통관부호
- 미매칭 케이스
  - 버튼명: `소싱라이프에서 직접 찾기`
  - 버튼 역할: 운영자가 소싱라이프로 이동해 직접 검색 또는 이미지 검색으로 상품을 찾는다.
  - 버튼 위치: 소싱하기 모달의 `추천 소싱 상품` 제목 오른쪽

### 결제 화면 연동

- 상품준비 단계에서 소싱라이프 결제 화면 이동은 별도 독립 버튼이 아니라 `소싱하기` 흐름 안에서 처리한다.
- `소싱하기`를 누르면 소싱 후보 확인, 옵션 선택, 결제 화면 이동까지 이어진다.
- 결제 화면은 주문팡팡 모달 안에서 소싱라이프 구매대행 신청 페이지와 결제 페이지를 임시 화면으로 표시한다.
- 상품준비 메뉴 상단에는 `소싱라이프 송장 수신 시 자동 배송중 처리` 토글을 제공한다.
- 토글 OFF 상태에서 소싱라이프 결제 완료 시 국내송장이 함께 수신되면 송장번호가 입력된 상태로 발송대기에 남긴다.
- 토글 ON 상태에서 소싱라이프 결제 완료 시 국내송장이 함께 수신되면 배송중 처리를 자동 시도하고 성공 시 배송중으로 이동한다.
- 국내송장이 수신되지 않은 주문은 토글 상태와 관계없이 발송대기로 이동한다.

### 자동 배송중 처리 ON/OFF

- 위치: 발송대기 메뉴 상단 전역 액션 영역
- `소싱라이프 송장 자동 수집 ON/OFF`와 별도 토글로 제공한다.
- 소싱라이프 송장 자동 수집 ON은 발송대기 상태에서 소싱라이프에 발급된 국내송장을 가져오는 기능이다.
- 자동 배송중 처리 ON은 국내송장이 입력되는 즉시 배송중 처리를 자동 시도하고 배송중 전환을 진행한다.
- 자동 배송중 처리 OFF 상태에서는 국내송장이 입력되어도 운영자가 `배송중 처리` 버튼으로 직접 전송한다.
- 자동 배송중 처리는 국내송장이 소싱라이프 송장 자동 수집, 소싱라이프 송장 수집, 수동 입력 중 어떤 방식으로 입력됐는지와 관계없이 동작한다.
- 자동 배송중 처리 실패 건은 발송대기에 남기고 실패 사유를 표시한다.

### 마켓연동 설정

- 위치: 주문관리 > 마켓연동
- 마켓별 인증 정보와 스토어명을 입력/수정한다.
- 플랫폼 수수료율은 주문수집 MVP 화면에서 제공하지 않는다.
- 마켓 추가/수정/삭제는 각각 별도 모달 화면 기준을 가진다.

### 소싱 후보 표시

- 소싱 후보 리스트에서는 구매 1회, AI 매칭률, 별점, 배송일수 정보를 표시하지 않는다.
- 주문 테이블에는 후보 일치율 또는 매칭률 컬럼을 표시하지 않는다.

## 9. 행 확장 상세 기준

- 주문 행을 클릭하면 목록 아래에 자세히 보기 영역을 펼친다.
- 자세히 보기에는 주문상품, 구매자, 배송정보, 택배정보, 소싱상품 순서로 정보를 표시한다.
- 배송정보는 자세히 보기에서도 수정할 수 있다.
- 소싱상품은 썸네일, 상품명, 옵션명, 수량, 소싱금액, 소싱라이프 주문번호만 표시한다.
- 주문일시와 마켓/스토어명은 주문상품 영역에 함께 표시한다.

## 9-1. 와이어프레임 HTML 확인 기준

- 모달/팝오버 HTML은 현재 구현 문구와 레이아웃 기준을 단독 확인할 수 있는 정적 확인 화면이다.

## 10. 실패 사유 기준

### 실패 사유

- 실패 사유는 정상 처리가 되지 않은 주문에만 표시한다.
- 대상 실패는 주문수집 실패, 주문확인 실패, 소싱라이프 연동 실패, 결제 상태 반영 실패, 배송중 처리 실패, 클레임 처리 실패다.
- 정상 주문은 실패 사유 컬럼을 비워둔다.

### 처리이력 제외

- 처리이력은 초기버전 주문관리 화면에서 제공하지 않는다.
- 주문별 상태 변경 로그와 작업 로그는 추후 기능으로 분리한다.
