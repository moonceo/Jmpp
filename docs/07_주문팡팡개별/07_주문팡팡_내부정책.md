# 커머스라이프 주문관리 내부정책

## 1. 기준

현재 내부정책은 프론트 MVP 구현을 기준으로 한다.
백엔드/API가 붙기 전까지 mock data, client state, localStorage 동작을 현재 사양으로 본다.

## 2. 마켓연동 정책

- 대상 마켓은 스마트스토어, 쿠팡, 11번가, G마켓, 옥션이다.
- 사용자는 마켓별 스토어를 여러 개 등록할 수 있다.
- 현재 마켓연동 화면은 마켓, 스토어명, 연동상태, 활성, 관리만 표시한다.
- 플랫폼 수수료율, 마지막 수집, 결과, 별도 계정설정 페이지는 현재 MVP 화면에 제공하지 않는다.
- 주문수집은 활성화된 전체 마켓 계정과 스토어를 대상으로 한다.
- 마켓/스토어 필터는 조회 조건이며 수집 실행 범위 제한 기능이 아니다.
- 마켓/스토어를 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하고, 이때 스토어가 속한 마켓은 자동 포함된 것으로 본다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.

## 3. 주문 식별 정책

| 단위 | 식별 기준 |
|---|---|
| 주문 단위 | 마켓 + 스토어명 + 마켓 주문번호 |
| 주문상품 단위 | 마켓 + 스토어명 + 상품주문번호 |

동일한 마켓 주문번호라도 스토어가 다르면 별도 주문으로 관리한다.

## 4. 주문상태 정책

| 코드 | 라벨 | 정책 |
|---|---|---|
| `NEW` | 신규주문 | 마켓 결제완료 주문 수집 후 주문확인 전 |
| `PREPARING` | 상품준비 | 주문확인 후 소싱라이프 구매 또는 외부 구매 진행 |
| `READY_TO_SHIP` | 발송대기 | 외부 구매 등 호환 흐름에서 국내송장 저장 후 마켓 발송 처리 대기 |
| `SHIPPING` | 배송중 | 소싱라이프 결제완료부터 실제 배송완료 전까지 통합 관리. 마켓 발송 전·후 포함 |
| `DELIVERED` | 배송완료 | 배송완료 또는 구매확정 |
| `ON_HOLD` | 처리보류 | 판매자 취소 요청 접수 후 provider 최종 결과 대기. 모든 일반 처리 액션 차단 |
| `CANCELED` | 판매자취소 | 판매자가 직접 주문취소 처리한 종료 상태. 전체주문과 취소·반품·교환 완료 목록에 함께 표시 |
| `CLAIM` | 취소/반품/교환 | 구매자 요청·마켓 클레임 처리 및 판매자 직접취소 완료 이력 조회 |

전체 주문수집 탭은 `ON_HOLD`를 포함한 일반 주문을 제공하며 `처리보류` 필터를 노출한다.

## 5. 액션 정책

| 상태 | 액션 |
|---|---|
| `NEW` | 목록은 `주문확인`, `매칭하기`, `주문취소`; 상세에서는 같은 실행과 추가 확인 기능 제공. 배송정보 수정은 상세 왼쪽 정보 영역에서 제공 |
| `PREPARING` | 목록은 `소싱하기`, `주문취소`; 상세 처리하기는 진행단계별 결제, `외부구매 배송처리`, 지원 마켓의 `배송중 처리`(직접전달) 추가 |
| `READY_TO_SHIP` | 외부 구매 등 호환 주문에 목록·상세 `배송중 처리`. 미발송이면 스토어 기본 발송 방식 확인, 발송 후이면 백엔드 대사로 재전송 방지 |
| `ON_HOLD` | 액션 없음. `처리보류 / 마켓 취소요청` 표시 |
| `SHIPPING` | 목록 처리하기는 비움; 상세에서 `소싱상품관리`, `배송추적`, 조건부 `배송중 처리`, 제출 전 `운송장 수정` 제공 |
| `DELIVERED` | 목록 처리하기는 비움; 상세에서 `소싱상품관리`, 누적 이력을 여는 `배송추적` 제공 |
| `CLAIM` | `취소처리`, `반품처리`, `교환처리`; 소싱 결제·배송 원장이 있으면 `소싱상품관리`, `배송추적`을 함께 제공하고 환불 조회는 `소싱상품관리` 안에서 제공 |

`주문취소`는 확인 모달 후 처리한다.
신규주문에서는 체크된 주문을 일괄 주문확인 또는 일괄 주문취소할 수 있다.
상품준비와 발송대기에서는 행 단위 주문취소를 제공한다.
판매자가 직접 취소한 주문은 `CANCELED`로 종료하고, 구매자 요청 또는 마켓 수집 클레임인 `CLAIM` 목록과 분리한다.

## 6. 소싱라이프 정책

- 커머스라이프는 소싱라이프와 분리된 독립 주문관리 서비스다.
- 주문관리는 마켓에서 수집된 주문을 기준으로 소싱라이프 결제와 국내송장 결과를 연결한다.
- 결제완료 후 선택한 외부 배송대행지 사이트를 열고 주문서를 자동입력해 접수한다. 연결 대상은 접수 시 국내송장을 즉시 발급하는 배송대행지로 제한하며 `접수대기`와 `접수신청`은 동일 단계다.
- 소싱라이프에서 직접 생성하거나 주문한 내역은 주문관리의 주문수집 목록에 포함하지 않는다.
- 소싱라이프 연동으로 수신한 구매, 검수, 입고, 물류 상태와 결과는 커머스라이프 내부에서 조회한다.
- 신규주문의 매칭 진입 버튼은 `매칭하기`, 상품준비의 구매 진입 버튼은 `소싱하기`로 구분한다.
- 신규주문의 `매칭하기`는 소싱 후보/옵션 저장과 주문확인을 함께 처리한다.
- 상품준비의 `소싱하기`는 현재 매칭을 확인하고 구매대행 신청으로 이어진다.
- 상품준비에서는 버튼명을 `소싱하기`로 사용한다.
- `소싱하기`는 후보 확인, 옵션 선택, 수량 변경, 구매대행 신청/결제 화면을 포함한다.
- 소싱라이프 주문번호는 연동 식별값으로만 보관하며 주문 목록의 단계 배지는 커머스라이프 내부 상태로만 표시한다. 외부 주문내역 링크는 제공하지 않는다.
- 상태 컬럼은 처리 버튼을 넣지 않고 상태/결과만 표시한다.

## 7. 소싱상태 정책

| 코드 | 의미 |
|---|---|
| `NOT_LINKED` | 소싱라이프 연결 전 |
| `MATCHING` | 매칭 진행 중 |
| `MATCH_SAVED` | 소싱완료 |
| `PAYMENT_READY` | 결제 가능 |
| `PAID` | 소싱라이프 결제 완료 |
| `INVOICE_RECEIVED` | 국내송장 수신 |
| `HOLD` | 소싱 처리보류 |

주문 목록의 상태 컬럼은 `소싱필요`, `소싱 검증대기`, `소싱완료`, `결제대기`, `결제완료`, `중국배송중`, `통관 중`, `국내 배송중`, `배송완료`, `구매확정` 상태값을 표시한다. 외부 구매 완료도 `결제완료`로 통합하고 구매경로 `외부구매`는 내부 데이터로 유지한다. 매칭된 소싱상품이 없으므로 자세히 보기에는 소싱상품 영역을 표시하지 않는다. `구매확정`은 배송완료 주문의 마켓 동기화 결과에서 추가되는 목록 상태값이다.

`PAYMENT_READY`는 `결제대기`, `PAID`와 `INVOICE_RECEIVED`, `EXTERNAL_PURCHASE`는 목록에서 `결제완료`로 표시한다. 단, `EXTERNAL_PURCHASE`를 소싱라이프 `PAID`로 변환하지 않고 내부 구매경로와 상세 표시를 유지한다. 국내송장 수신만으로 `중국배송중`을 추정하지 않는다. 판매자 취소·구매자 클레임 상태는 기존 소싱 상태를 보존하며 `HOLD`는 소싱 연동 자체가 보류된 경우에만 사용한다.

목록 파생 상태 정책:

- `status === DELIVERED` 주문은 모두 목록 상태 `배송완료`를 가진다.
- `status === DELIVERED && marketOrderStatus === PURCHASE_DECIDED`이면 목록 상태 `구매확정`을 추가한다.
- `구매확정`은 상태 컬럼과 상태 필터에서 추가 값으로 사용하지만 내부 주문 단계는 `DELIVERED`를 유지한다.
- 배송완료 단계의 상태 드롭다운은 `전체`, `배송완료`, `구매확정`을 제공한다.
- 배송완료 필터는 구매확정 주문까지 포함하고, 구매확정 필터는 구매확정 배지가 있는 주문만 조회한다.

## 8. 국내송장 정책

- 국내송장은 소싱라이프 결제 후 배송대행지 접수 응답 또는 외부 구매 완료 필수 입력으로 저장한다.
- 구매 완료 후 송장이 없으면 상태 전환을 차단한다.
- 정상 발송대기 주문은 송장을 보유한다. 송장이 누락된 비정상 데이터는 모든 배송중 처리 기능을 비활성화하고 오류로 분류한다.
- 마켓 발송 전이면 `배송중 처리` 확인창에 스토어 기본 발송 방식을 표시한다. 송장전송 기본값은 국내송장이 있을 때만 활성화하고 직접전달 기본값은 스마트스토어·11번가에서만 허용한다.
- 마켓 발송이 이미 끝난 주문도 `배송중 처리`를 유지하되 모달 없이 백엔드 대사로 내부 상태만 변경한다.
- 발송대기에서는 별도 `소싱라이프 송장 수집` 버튼이나 소싱라이프 송장 자동 수집 토글을 제공하지 않고 `자동 배송중 처리` 토글만 제공한다.
- 발송대기 전역 액션은 체크된 주문이 있으면 체크된 주문을 우선 대상으로 하고, 체크가 없으면 현재 필터에 보이는 주문을 대상으로 한다.
- 전역 `배송중 처리`는 단일 주문과 같은 선조회 규칙을 사용하며 이미 발송된 주문도 내부 상태 반영 대상으로 포함한다.
- 마켓 발송 완료 주문에는 판매자 `주문취소`를 표시하거나 실행하지 않는다.
- 스마트스토어·11번가 발송 전에는 국내송장을 수정할 수 있지만, 발송 후에는 내부 수정, 판매자센터 이동, 수정내역 불러오기 기능을 제공하지 않는다.
- 변경된 송장번호 항목은 표시하지 않는다.

## 9. 주문 테이블 정책

주문 목록 컬럼 순서:

1. 선택
2. 처리하기
3. 주문일시
4. 상품정보
5. 택배정보
6. 배송정보
7. 판매처
8. 상태

주문상태 컬럼은 본문 상단 탭과 중복되므로 목록에서 제거한다.
주문 행 클릭 시 자세히 보기 영역을 펼친다.
자세히 보기 순서는 주문상품, 구매자, 배송정보, 택배정보, 소싱상품이다.
탭, 검색어, 필터, 데이터 변경 시 체크 선택과 펼쳐진 자세히 보기 상태는 현재 화면 기준으로 초기화한다.

## 10. 개인정보와 통관정보 정책

- 배송정보에는 수취인 이름, 연락처, 주소, 개인통관부호를 표시한다.
- 개인통관부호는 `통관부호 일치` 또는 `통관부호 불일치`로 표시한다.
- 비어 있거나 형식이 맞지 않으면 불일치로 본다.
- 배송정보는 목록과 자세히 보기에서 수정할 수 있다.

## 11. 제외 정책

현재 MVP에서는 다음을 제공하지 않는다.

- 타오바오 직접 결제
- 내부 배대지/창고 관리
- 배송중 송장 변경 API 전송
- 플랫폼 수수료율 설정
- 처리이력 전용 화면
