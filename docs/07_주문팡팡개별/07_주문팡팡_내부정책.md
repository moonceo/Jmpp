# 주문팡팡 내부정책

## 1. 기준

현재 내부정책은 프론트 MVP 구현을 기준으로 한다.
백엔드/API가 붙기 전까지 mock data, client state, localStorage 동작을 현재 사양으로 본다.

## 2. 마켓연동 정책

- 대상 마켓은 스마트스토어, 쿠팡, 11번가, G마켓, 옥션이다.
- 사용자는 마켓별 스토어를 여러 개 등록할 수 있다.
- 현재 마켓연동 화면은 마켓, 스토어명, 연동상태, 활성, 관리만 표시한다.
- 플랫폼 수수료율, 마지막 수집, 결과, 별도 계정설정 페이지는 현재 MVP 화면에 제공하지 않는다.
- 주문수집은 활성화된 전체 연동 계정을 대상으로 한다.
- 마켓/스토어 필터는 조회 조건이며 수집 실행 범위 제한 기능이 아니다.
- 마켓/스토어를 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시하고, 이때 스토어가 속한 마켓은 자동 포함된 것으로 본다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안에서 선택한 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.

## 3. 주문 식별 정책

| 단위 | 식별 기준 |
|---|---|
| 주문 단위 | 마켓 + 스토어명 + 마켓 주문번호 |
| 주문상품 단위 | 마켓 + 스토어명 + 상품주문번호 |

동일한 마켓 주문번호라도 스토어가 다르면 별도 주문으로 관리한다.

## 4. 주문상태 정책

| 코드 | 라벨 | 정책 |
|---|---|---|
| `NEW` | 신규주문 | 마켓 결제완료 주문 수집 후 주문확인 전 |
| `PREPARING` | 상품준비 | 주문확인 후 소싱라이프 소싱/결제 또는 수동구매 진행 |
| `READY_TO_SHIP` | 발송대기 | 국내송장 수집, 입력, 배송중 처리 대기 |
| `SHIPPING` | 배송중 | 배송중 처리 완료 |
| `DELIVERED` | 배송완료 | 배송완료 또는 구매확정 |
| `CANCELED` | 판매자취소 | 판매자가 직접 주문취소 처리한 종료 상태 |
| `CLAIM` | 취소/반품/교환 | 구매자 요청 또는 마켓 클레임 수집 |

별도 전체 주문수집 탭은 현재 제공하지 않는다.

## 5. 액션 정책

| 상태 | 액션 |
|---|---|
| `NEW` | `주문확인`, `매칭하기`, `주문취소` |
| `PREPARING` | `소싱하기`, `수동구매 완료`, `주문취소` |
| `READY_TO_SHIP` | `배송중 처리`, `주문취소` |
| `SHIPPING` | 조회 전용 |
| `DELIVERED` | 조회 전용 |
| `CLAIM` | `취소처리`, `반품처리`, `교환처리` |

`주문취소`는 확인 모달 후 처리한다.
신규주문에서는 체크된 주문을 일괄 주문확인 또는 일괄 주문취소할 수 있다.
상품준비와 발송대기에서는 행 단위 주문취소를 제공한다.
판매자가 직접 취소한 주문은 `CANCELED`로 종료하고, 구매자 요청 또는 마켓 수집 클레임인 `CLAIM` 목록과 분리한다.

## 6. 소싱라이프 정책

- 소싱라이프는 외부 소싱/구매대행/국내송장 확보 서비스다.
- 신규주문에서는 버튼명을 `매칭하기`로 사용한다.
- `매칭하기`는 소싱 후보/옵션 저장과 주문확인을 함께 처리한다.
- 상품준비에서는 버튼명을 `소싱하기`로 사용한다.
- `소싱하기`는 후보 확인, 옵션 선택, 수량 변경, 구매대행 신청/결제 화면을 포함한다.
- 소싱라이프 주문번호가 있으면 주문 목록에서 링크로 표시한다.
- 소싱라이프 컬럼은 처리 버튼을 넣지 않고 상태/결과만 표시한다.

## 7. 소싱상태 정책

| 코드 | 의미 |
|---|---|
| `NOT_LINKED` | 소싱라이프 연결 전 |
| `MATCHING` | 매칭 진행 중 |
| `MATCH_SAVED` | 매칭 저장 완료 |
| `PAYMENT_READY` | 결제 가능 |
| `PAID` | 소싱라이프 결제 완료 |
| `INVOICE_RECEIVED` | 국내송장 수신 |
| `HOLD` | 처리 보류 |

주문 목록의 소싱라이프 컬럼은 `-`, `매칭완료`, 소싱라이프 주문번호 링크 중 하나로 간단히 표시한다.

## 8. 국내송장 정책

- 국내송장은 발송대기에서 입력 또는 수집한다.
- 송장번호 입력값은 자동 저장된다.
- 송장번호가 없으면 `배송중 처리` 버튼은 비활성화한다.
- 송장번호가 있으면 `배송중 처리` 버튼은 활성화한다.
- `소싱라이프 송장 수집`은 소싱라이프 주문번호가 있고 송장번호가 없는 주문만 대상으로 한다.
- `소싱라이프 송장 자동 수집`과 `자동 배송중 처리`는 서로 다른 토글이다.
- 발송대기 전역 액션은 체크된 주문이 있으면 체크된 주문을 우선 대상으로 하고, 체크가 없으면 현재 필터에 보이는 주문을 대상으로 한다.
- 전역 `배송중 처리`는 송장번호가 있는 주문만 실제 처리한다.
- 배송중 상태에서는 송장 수정 API 전송 버튼을 제공하지 않는다.
- 변경된 송장번호가 있으면 사용자 확인용으로 번호만 표시한다.

## 9. 주문 테이블 정책

주문 목록 컬럼 순서:

1. 선택
2. 처리하기
3. 주문일시
4. 상품정보
5. 택배정보
6. 배송정보
7. 판매처
8. 소싱라이프

주문상태 컬럼은 본문 상단 탭과 중복되므로 목록에서 제거한다.
주문 행 클릭 시 자세히 보기 영역을 펼친다.
자세히 보기 순서는 주문상품, 구매자, 배송정보, 택배정보, 소싱상품이다.
탭, 검색어, 필터, 데이터 변경 시 체크 선택과 펼쳐진 자세히 보기 상태는 현재 화면 기준으로 초기화한다.

## 10. 개인정보와 통관정보 정책

- 배송정보에는 수취인 이름, 연락처, 주소, 개인통관부호를 표시한다.
- 개인통관부호는 `통관부호 일치` 또는 `통관부호 불일치`로 표시한다.
- 비어 있거나 형식이 맞지 않으면 불일치로 본다.
- 배송정보는 목록과 자세히 보기에서 수정할 수 있다.

## 11. 제외 정책

현재 MVP에서는 다음을 제공하지 않는다.

- 타오바오 직접 결제
- 내부 배대지/창고 관리
- 배송중 송장 변경 API 전송
- 플랫폼 수수료율 설정
- 처리이력 전용 화면
