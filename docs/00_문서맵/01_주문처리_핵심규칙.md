# 주문처리 핵심규칙

이 문서는 현재 프로토타입의 사용자-facing 주문 상태 전환 기준이다. 화면에서 말하는 `구매 완료`는 구매대행 결제 후 선택한 배송대행지 주문서 접수와 국내송장 즉시 발급까지 끝나 주문관리의 다음 단계로 이동할 수 있는 상태를 뜻한다.

실서비스 서버는 `주문 생성`, `결제 승인(PAID)`, `타오바오 구매 성공(PURCHASED)`, `배송대행지 주문서 접수(FORWARDER_SUBMITTED)`, `국내송장 수신(INVOICE_RECEIVED)`을 별도 사건으로 저장한다. 연결 대상은 접수와 동시에 국내송장을 발급하는 배송대행지로 제한하며, 화면 용어 `접수대기`와 `접수신청`은 같은 접수 단계로 취급한다. 정상 흐름에서 송장은 접수 응답으로 즉시 수신하지만 실패·응답 유실 시 결제 사실을 보존하고 발송 단계 전환만 보류한다.

현재 프로토타입은 외부 배송대행지 사이트 열기, 주문서 자동입력, 접수 요청을 구현하지 않는다. `결제완료` 클릭 시 위 중간 과정을 성공한 것으로 간주해 더미 국내송장을 즉시 생성함으로써 최종 결과만 시연한다.

## 1. 내부 주문 단계

| 내부 상태 | 화면 | 의미 |
|---|---|---|
| `NEW` | 신규주문 | 결제완료 주문을 수집했으며 판매자 주문확인 전 |
| `PREPARING` | 상품준비 | 주문확인 후 구매를 완료해야 하는 상태 |
| `READY_TO_SHIP` | 발송대기 | 구매와 국내송장 확보가 끝났으며 마켓 택배 발송 전 |
| `SHIPPING` | 배송중 | 마켓 발송 처리 또는 직접전달 처리와 구매·송장 확보가 완료됨 |
| `DELIVERED` | 배송완료 | 실제 국내송장 기준 배송완료 |
| `CLAIM` | 취소/반품/교환 | 클레임 처리 대상 |
| `CANCELED` | 취소완료 | 취소 처리 완료 |

## 2. 구매 방식

구매 방식은 두 가지뿐이다.

1. 소싱라이프 구매
2. 외부 구매

`구매 안 함` 상태·버튼·배지는 제공하지 않는다.

소싱라이프 구매 완료 또는 직접구매 `국내송장 등록`에는 실제 국내 택배사와 국내송장번호가 필수다. 소싱라이프 구매는 선택 배송대행지 접수 응답에서 송장을 즉시 가져오며, 송장이 없으면 결제는 보존하되 사용자-facing 구매 완료와 발송 단계 전환을 실행하지 않는다.

## 3. 일반 택배 처리

| 조건 | 자동 배송중 처리 OFF | 자동 배송중 처리 ON |
|---|---|---|
| 구매 완료 + 국내송장 있음 | 내부 `READY_TO_SHIP`, 마켓 결제완료 | 마켓 발송 API 성공 후 마켓 배송중 + 내부 `SHIPPING` |
| 마켓 발송 API 실패 | 해당 없음 | 송장이 있는 `READY_TO_SHIP` 유지, 실패 사유 표시 |

OFF 주문은 발송대기에서 운영자가 `배송중 처리`를 실행해야 마켓과 내부 상태가 배송중으로 변경된다.

## 4. 직접전달 처리

직접전달은 실제 구매·물류 방식이 아니라 마켓에 등록하는 발송 방식이다.

| 처리 순서 | 마켓 상태 | 내부 상태 | 국내송장 |
|---|---|---|---|
| 직접전달만 먼저 처리 | 배송중·직접전달 | `PREPARING` | 없음 |
| 직접전달 후 소싱라이프 구매 완료 | 배송중·직접전달 | `SHIPPING` | 필수 |
| 직접전달 후 외부 구매 완료 | 배송중·직접전달 | `SHIPPING` | 필수 |
| 실제 국내배송 완료 | 마켓 상태 별도 유지 | `DELIVERED` | 필수 |

직접전달 주문은 마켓에 국내송장을 다시 전송하지 않는다. 실제 국내송장은 내부 배송 추적과 배송완료 판정에 사용한다.

## 5. 금지 조합

다음 조합은 정상 상태로 저장하지 않는다.

- 소싱라이프 구매 완료 + 국내송장 없음
- 외부 구매 완료 + 국내송장 없음
- 직접전달 + 소싱라이프 구매 완료 + 국내송장 없음
- 직접전달 + 외부 구매 완료 + 국내송장 없음
- 직접전달 + 구매 미완료 + 국내송장 있음
- 구매 안 함 + 국내송장 있음
- 내부 배송중 + 국내송장 없음
