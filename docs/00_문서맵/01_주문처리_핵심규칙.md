# 주문처리 핵심규칙

이 문서는 현재 프로토타입의 사용자-facing 주문 상태 전환 기준이다. 소싱라이프 결제가 완료되면 주문관리의 내부 단계는 즉시 `배송중`으로 전환하며, 이후 중국 판매자 발송·통관·국내배송을 하나의 배송중 작업함에서 관리한다. 마켓 배송중 처리 여부는 별도 축으로 관리한다.

실서비스 서버는 `주문 생성`, `결제 승인(PAID)`, `타오바오 구매 성공(PURCHASED)`, `배송대행지 주문서 접수(FORWARDER_SUBMITTED)`, `국내송장 수신(INVOICE_RECEIVED)`을 별도 사건으로 저장한다. 연결 대상은 접수와 동시에 국내송장을 발급하는 배송대행지로 제한하며, 화면 용어 `접수대기`와 `접수신청`은 같은 접수 단계로 취급한다. 정상 흐름에서 송장은 접수 응답으로 즉시 수신하지만 실패·응답 유실 시 결제 사실을 보존하고 발송 단계 전환만 보류한다.

현재 프로토타입은 외부 배송대행지 사이트 열기, 주문서 자동입력, 접수 요청을 구현하지 않는다. `결제완료` 클릭 시 위 중간 과정을 성공한 것으로 간주해 더미 국내송장을 즉시 생성함으로써 최종 결과만 시연한다.

## 1. 내부 주문 단계

| 내부 상태 | 화면 | 의미 |
|---|---|---|
| `NEW` | 신규주문 | 결제완료 주문을 수집했으며 판매자 주문확인 전 |
| `PREPARING` | 상품준비 | 주문확인 후 구매를 완료해야 하는 상태 |
| `READY_TO_SHIP` | 발송대기 | 외부 구매 등 호환 흐름에서 국내송장을 확보했고 마켓 발송 처리를 기다리는 상태 |
| `SHIPPING` | 배송중 | 소싱라이프 결제완료부터 실제 배송완료 전까지의 통합 관리 상태. 마켓 발송 전·후를 모두 포함 |
| `DELIVERED` | 배송완료 | 실제 국내송장 기준 배송완료 |
| `CLAIM` | 취소/반품/교환 | 클레임 처리 대상 |
| `CANCELED` | 취소완료 | 취소 처리 완료 |

## 2. 구매 방식

구매 방식은 두 가지뿐이다.

1. 소싱라이프 구매
2. 외부 구매

`구매 안 함` 상태·버튼·배지는 제공하지 않는다.

주문 처리는 리펀디형 `소싱하기`와 샵마인형 `외부구매 배송처리`를 통합 제공한다. 소싱라이프 결제 성공은 국내송장 수신과 별도 사건으로 저장하며 즉시 내부 `SHIPPING`으로 투영한다. 국내송장이 아직 없거나 마켓 발송 전이어도 결제 사실과 배송중 관리는 유지하고, 송장이 확보되면 같은 배송중 주문에서 등록·수정하고 `배송중 처리`로 마켓 반영을 완료한다. `배송중 처리`를 시작한 순간부터 국내송장 등록·수정을 잠근다. 외부구매 배송처리는 배송대행지에서 받은 국내송장이 있어야 `READY_TO_SHIP`으로 이동한다.

## 3. 일반 택배 처리

| 조건 | 자동 배송중 처리 OFF | 자동 배송중 처리 ON |
|---|---|---|
| 소싱라이프 결제완료 | 내부 `SHIPPING`, 마켓 상태 별도 유지 | 내부 `SHIPPING`; 송장 확보 후 마켓 발송 자동 시도 |
| 소싱라이프 마켓 발송 API 실패 | 내부 `SHIPPING` 유지 | 내부 `SHIPPING`과 송장을 유지하고 실패 사유 표시 |
| 외부 구매 완료 + 국내송장 있음 | 내부 `READY_TO_SHIP`, 마켓 결제완료 | 마켓 발송 API 성공 후 마켓 배송중 + 내부 `SHIPPING` |

소싱라이프 주문의 OFF 설정은 내부 상태를 되돌리지 않는다. 운영자는 `배송중 처리` 하나만 실행하며, 백엔드는 마켓 연동 계정에 저장된 발송 기본값으로 마켓 발송을 완료한다.

## 4. 직접전달 처리

직접전달은 실제 구매·물류 방식이 아니라 마켓에 등록하는 발송 방식이다.

| 처리 순서 | 마켓 상태 | 내부 상태 | 국내송장 |
|---|---|---|---|
| 상품준비에서 직접전달만 먼저 처리 | 배송중·직접전달 | `PREPARING` | 없음 |
| 먼저 직접전달한 뒤 소싱라이프 구매 완료 | 배송중·직접전달 | `SHIPPING` | 수신 즉시 저장 |
| 먼저 직접전달한 뒤 외부 구매 완료 | 배송중·직접전달 | `READY_TO_SHIP` | 필수 |
| 발송대기에서 `직접전달로 배송중` 실행 | 배송중·직접전달 | `SHIPPING` | 필수, 마켓에는 보내지 않음 |
| 발송대기에서 `송장으로 배송중` 실행 | 배송중·택배 | `SHIPPING` | 필수, 마켓에 전송 |
| 마켓 발송이 먼저 완료된 발송대기에서 `내부 배송중 처리` 실행 | 기존 배송중 상태 유지 | `SHIPPING` | 필수 |
| 실제 국내배송 완료 | 마켓 상태 별도 유지 | `DELIVERED` | 필수 |

상품준비에서는 결제가 끝나지 않았으므로 선송장 기능을 표시하지 않고 `미리 직접전달`만 제공한다. 사용자가 실행하기 전에는 마켓에 아무 발송정보도 보내지 않는다.

스마트스토어·11번가는 마켓 연동 시 스토어별 기본 발송 방식을 `송장전송` 또는 `직접전달`로 반드시 선택한다. 쿠팡·G마켓·옥션은 `송장전송`으로 고정한다. 발송대기에서는 주문별 방식을 다시 묻지 않고 `배송중 처리` 확인 후 계정 기본값을 적용한다. 이미 마켓에 직접전달 또는 송장 발송이 완료된 주문은 같은 정보를 다시 보내지 않고 내부 단계만 마무리한다. 직접전달 주문의 실제 국내송장은 마켓에 다시 전송하지 않고 내부 배송 추적과 배송완료 판정에 사용한다.

스마트스토어·11번가는 발송 방식 전송 후 API 정정을 허용하지 않는 것으로 취급한다. 전송 전 확인 화면에서 적용 방식을 명확히 표시하고, 전송 후에는 내부 `운송장 수정`, `마켓에서 수정`, `수정내역 불러오기`를 모두 제공하지 않는다. 계정 기본값 변경은 아직 발송하지 않은 주문에만 적용한다.

## 5. 금지 조합

다음 조합은 정상 상태로 저장하지 않는다.

- 소싱라이프 구매 완료 + 국내송장 없음
- 외부 구매 완료 + 국내송장 없음
- 직접전달 + 소싱라이프 구매 완료 + 국내송장 없음
- 직접전달 + 외부 구매 완료 + 국내송장 없음
- 직접전달 + 구매 미완료 + 국내송장 있음
- 구매 안 함 + 국내송장 있음
- 배송완료 + 국내송장 없음

## 7. 소싱상품 환불

소싱상품 환불은 마켓 주문 취소·구매자 환불과 별도인 후속 흐름이다. 두 결과는 하나의 완료 상태로 합치지 않고 각각 저장·표시한다.

- 별도 사이드바 메뉴를 만들지 않는다. 소싱라이프 결제완료 주문의 `소싱상품관리` 안에서 `반품·환불 신청` 또는 현재 환불 상태 버튼을 제공한다. 목록과 상세 `처리하기`에는 별도 환불 버튼을 두지 않는다.
- `/orders?view=claims`는 구매자가 마켓에서 신청한 취소·반품·교환과 판매자가 직접 취소한 완료 이력을 함께 표시한다. 접수 주체로 두 흐름을 구분하고, 상세의 `소싱 구매 후속조치`에서 연결된 소싱환불 필요·진행·완료 상태를 분리 추적한다.
- 신규 요청 가능 대상은 구매가 완료되고 TaoWorld `purchaseOrderId`와 `purchaseOrderLineId`가 저장된 주문상품 중 `결제완료(SOURCED)`부터 `국내 배송중(DOMESTIC_SHIPPING)`까지다. 배송완료 전까지 `소싱상품관리` 안에서 `반품·환불 신청`을 제공하고, 기존 요청은 모든 후속 단계에서 `환불 진행`·`환불 내역`으로 유지한다. `EXTERNAL_PURCHASE`는 대상이 아니며 실제 외부 구매처에서 처리한다.

- 프로토타입도 TaoWorld 공식 계약 순서를 따른다. `/order/refund/render`로 `refundType`, `goodsStatus`, 동적 `reasonId`, 최대 CNY 금액을 구성한 뒤 `/order/refund/submit` 요청 모양으로 demo 원장을 만든다.
- 신청 단위는 구매 주문라인이며 임의 환불 수량 필드를 전송하지 않는다. 원화 금액은 국내 정산 참고값이고 TaoWorld 요청·승인 금액은 CNY로 저장한다.
- 반품 후 환불은 판매자 동의 후 `/order/refund/render/logistics`의 택배사 코드, 반품 송장, 반품자 전화번호를 `/order/refund/submit/logistics` 형태로 등록한다.
- 상태 변경 알림은 `message_type=9`를 가정하되 메시지 순서를 신뢰하지 않고 `refundId`로 `/order/refund/query`한 결과를 화면 상태로 투영한다.
- 화면 상태는 요청 직후부터 `소싱환불 승인대기 → 소싱반품 송장필요/소싱반품 배송중 → 소싱환불 처리중 → 소싱환불 완료`를 정상 흐름으로 사용하고, `소싱환불 거절`, `소싱환불 확인필요`를 예외로 사용한다. 내부 `REQUESTED`와 `PROVIDER_REVIEW`는 모두 `소싱환불 승인대기`로 투영하고 TaoWorld 원본 상태코드와 메시지는 상세 원장에 보존한다.
- `소싱환불 완료`이면서 국내배송이 시작되지 않은 주문은 행 자세히 보기 `처리하기`에 `다시 소싱하기`를 제공한다. 실행하면 완료 환불을 이력에 보존하고 기존 소싱 주문·결제·매칭·배대지·송장을 현재 연결에서 제거한 뒤 `소싱필요`로 돌아가 새 판매처 선택과 결제를 진행한다. 환불 완료 상태에서도 재소싱 전에는 기존 송장 전송·직접전달을 차단한다.
- 환불 요청·확인·반품·정산·대사 중에는 새 `배송중 처리`와 `마켓 직접전달`을 차단한다. 마켓 취소·클레임은 자동 완료하지 않는다.
- 현재 프로토타입은 demo 주문에서만 TaoWorld API 형태의 요청·콜백·조회·반품 송장 상태를 로컬 화면에 반영한다. 실주문 버튼은 TaoWorld 어댑터, 멱등키, message/query 대사가 연결될 때까지 차단한다.

대표 demo 주문은 `ORD-20260610-0021`의 신규 환불 요청, `ORD-20260618-0042`의 환불만 판매자 확인 경로, `ORD-20260618-0043`의 반품 송장 등록 경로, `ORD-20260618-0048`의 미발송 환불 정산 경로, `ORD-20260618-0049`의 판매자 승인 후 중국 반품 배송 경로다.

## 8. 결제상품·판매자 대화·배송추적

- 목록 `처리하기`에는 탭별 필수 실행만 표시한다. 신규주문은 `주문확인`, `매칭하기`, `주문취소`, 상품준비는 `소싱하기`, `주문취소`, 발송대기는 `배송중 처리`만 제공하며 배송중과 배송완료 목록은 빈 셀로 둔다.
- `소싱상품관리`는 소싱 결제완료부터 배송완료까지 행 자세히 보기의 `처리하기`에 항상 표시한다. 같은 관리 화면에서 결제 상품, 결제정보와 중국 판매자 대화를 조회·작성한다.
- `배송추적`은 소싱 결제완료 시점부터 배송완료까지 목록과 상세에 표시한다. 이력은 `결제완료 → 중국배송 → 통관 → 국내배송 → 배송완료` 순으로 누적한다.
- `운송장 수정`은 상세 `처리하기`에서 제공한다. `배송중 처리`를 시작하기 전까지만 배송중 주문의 택배사·운송장번호를 등록하거나 수정할 수 있다. 처리 명령이 접수·실행·재시도·결과확인 중이거나 성공한 뒤에는 버튼과 저장을 모두 차단한다.
- `소싱상품관리`에서 결제상품·결제정보·중국 판매자 대화와 반품·환불을 한 흐름으로 관리한다. `배송추적`은 행 자세히 보기 `처리하기`의 별도 조회 기능으로 유지한다.
