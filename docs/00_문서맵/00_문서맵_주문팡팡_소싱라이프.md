# 소싱라이프 주문관리 문서맵

본 문서는 소싱라이프 내부 주문관리 기능 문서의 전체 구조와 문서별 역할을 정의한다.
기획 및 개발 기준은 아래 1~9번 문서를 기준으로 관리한다.

현재 기준은 소싱라이프 내부 `주문관리` 프론트 MVP 구현 기준으로 관리한다.
백엔드/API가 없는 현재 단계에서는 Next.js 화면, mock data, client state, localStorage 동작을 최신 사양으로 본다.
이 저장소의 활성 MVP 문서는 `docs/00_문서맵`부터 `docs/09_와이어프레임` 체계이며, 별도 `docs/08_주문수집소싱라이프_MVP기획` 폴더는 현재 기준 문서로 사용하지 않는다.

## 문서 목적

- 모든 판매처의 주문을 한 화면에서 모아보고 처리하는 구조를 정의한다.
- 스마트스토어와 쿠팡 API를 1차 기준으로 삼고, 이후 11번가, G마켓, 옥션으로 확장 가능한 구조를 만든다.
- 주문관리는 소싱라이프 내부 기능이며, 마켓 주문 처리 중 소싱라이프 결제와 국내송장 확보 결과를 연결한다.
- 소싱라이프에서 직접 생성/주문한 내역은 주문관리의 마켓 주문수집 대상으로 넣지 않는다.
- 소싱라이프의 기존 구매, 검수, 입고, 물류 상세 처리는 소싱라이프 기존 영역에서 진행한다.
- 상태, 기능, 화면, API, 운영 기준을 일관된 기준으로 정의한다.

## 문서 관리 원칙

1. 기능을 추가할 때는 영향을 받는 1~9번 문서에 빠짐없이 반영한다.
2. 문서와 현재 프론트 구현이 다를 경우 기본 판단은 현재 프론트 구현이 최신이라는 기준으로 문서를 갱신한다.
3. 내부 주문 상태와 소싱라이프 상태는 현재 타입 정의와 상수 매핑을 기준으로 관리한다.
4. 마켓 API 상태는 추후 실제 API 연동 시 내부 주문 상태로 매핑한다.
5. 스마트스토어, 쿠팡, 11번가, G마켓, 옥션은 같은 마켓연동 화면 구조로 관리한다.
6. 주문관리는 소싱라이프 내부 기능으로 정의하며, 소싱라이프 결제 연동만 주문 처리 흐름에 연결한다.
7. 소싱라이프에서 직접 생성/주문한 내역은 마켓 주문수집 목록에 포함하지 않는다.
8. 소싱라이프의 기존 구매, 검수, 입고, 물류 상세 처리는 주문관리 안으로 가져오지 않고 소싱라이프 기존 기능에서 처리한다.
9. 타오바오 직접 결제와 내부 배대지/창고 관리는 현재 MVP 범위에 다시 도입하지 않는다.
10. 유저플로우는 1~7번 기준 문서의 정책, 화면, 기능, API, 운영 기준을 시각화한 보조 기준으로 관리한다.
11. 와이어프레임은 1~8번 기준 문서를 화면 구조, 정보 배치, 대표 상태, 더미데이터로 구체화한 화면 설계 기준으로 관리한다.
12. 공식 API 상세 구현 문서는 원문 전체 복사본이 아니라 공식 URL, 확인일, 문서 버전, 기능별 확인 위치, 내부 매핑 기준을 기록한 개발 참조 문서로 관리한다.
