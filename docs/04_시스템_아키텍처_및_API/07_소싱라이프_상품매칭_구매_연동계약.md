# 소싱라이프 상품매칭·구매 연동 계약

## 1. 책임 경계

### 주문관리 책임

- 마켓 주문과 주문상품 식별
- 타오바오/소싱라이프 후보 검색 요청
- 사용자가 선택한 상품·SKU·수량의 영구 매핑
- 수취정보·통관정보 검증 상태
- 구매대행 신청과 결제 세션 연결
- 소싱라이프 주문·물류·송장·환불 결과 표시
- 마켓 주문 상태와 소싱 상태의 조정

### 소싱라이프 구매대행 책임

- 타오바오/티몰 상품과 SKU 조회
- 가격·재고·옵션·판매자 상태 확인
- 구매대행 비용 계산
- 국내 결제와 타오바오 구매 실행
- 중국 판매자 주문·환불
- 기존 물류/배송대행 연동
- 중국·국제·통관·국내 배송 이벤트와 송장 제공

### 외부 배송대행 책임

- 중국 수취지·입고·검수·합배송·국제운송
- 통관과 국내 인계
- 배송대행 사이트 또는 확장프로그램 연동

주문관리 안에 외부 배송대행지의 창고 운영 기능을 재구축하지 않는다. 필요한 경우 소싱라이프에서 받은 상태와 연결 링크만 제공한다.

## 2. 인증

- 서버 간 OAuth2 client credentials, 서명된 service token 또는 mTLS 중 하나를 사용한다.
- tenant와 사용자 위임 범위를 token 또는 요청 context로 전달한다.
- 모든 쓰기 요청에 idempotency key와 correlation ID를 요구한다.
- 사용자 브라우저에 서비스 비밀키를 전달하지 않는다.
- webhook은 서명, timestamp, nonce, replay window를 검증한다.

## 3. 상품 식별

상품:

- sourcePlatform
- externalProductId
- canonicalUrl
- sellerId
- titleKo, titleZh
- thumbnail
- status
- lastCheckedAt

SKU:

- externalSkuId
- option attributes
- option labelKo, labelZh
- priceCny
- stock status 또는 수량
- status
- lastCheckedAt

URL 조회 결과는 원래 URL이 아니라 canonical product ID와 SKU 목록을 반환해야 한다. 타오바오 단축 URL과 추적 parameter는 정규화한다.

## 4. 후보 검색 API

### 4-1. 이미지 후보

입력:

- 마켓 상품 이미지 URL 또는 업로드 asset ID
- 상품명·옵션명 보조 텍스트
- 최대 후보 수
- tenant와 주문상품 context

출력:

- 후보 상품 ID
- 한국어·중국어 상품명
- 판매처/판매자
- 썸네일
- 대표 원가 CNY/KRW
- 상품 상태
- 검색 방식과 score
- 마지막 확인시각

score는 참고값이며 자동 구매 근거로 단독 사용하지 않는다.

### 4-2. 키워드 후보

입력 키워드와 필터로 최대 20개 후보를 반환한다. 페이지 cursor를 지원한다.

### 4-3. URL 조회

타오바오·티몰·소싱라이프 URL을 입력하면 해당 상품 1개와 SKU를 반환한다. URL이 삭제·권한제한·지역제한이면 구조화된 오류를 반환한다.

## 5. 상품 상세·SKU 재검증

구매 직전 다음을 한 번에 재조회한다.

- 상품 판매 가능 여부
- 선택 SKU 존재·판매 가능·재고
- 현재 단가
- 최소구매수량과 수량 배수
- 중국 내 배송비 또는 미확정 상태
- 제한품목·구매 불가 경고
- 판매자·상품 위험 상태
- 마지막 확인시각

매핑 시점 snapshot과 차이가 나면 변경 목록을 반환한다.

| 변경 | 기본 처리 |
|---|---|
| 가격 상승 | 사용자 재확인 |
| 가격 하락 | 비용 다시 계산 후 사용자 확인 |
| SKU 품절·삭제 | 구매 차단, 대체 후보 |
| 옵션명만 변경 | SKU ID가 같아도 변경내용 표시 |
| 최소수량 변경 | 수량 재계산과 확인 |
| 중국 배송비 미확정 | 비용 미확정 경고 |
| 제한품목 | 구매 차단 또는 운영 검토 |

## 6. 구매 전 견적

구매대행 신청 전에 다음 금액을 분리해 반환한다.

- 상품 원가 CNY
- 적용 환율과 기준시각
- 예상 원화 상품금액
- 구매대행 수수료
- 중국 내 배송비
- 국제배송비: 추정값 또는 후결제 안내
- 예상 관부가세: 추정값 또는 별도 부과 안내
- 기타 비용
- 할인·쿠폰·캐시백이 확정인지 예상인지
- 현재 결제 예정금액 KRW

합계만 표시하지 않는다. 국제배송비와 관부가세를 알 수 없으면 0원으로 오인되지 않게 “별도/미확정”으로 표시한다.

## 7. 통관·수취정보

구매 요청에는 다음 상태를 포함한다.

- 수취인명, 연락처, 주소
- 개인통관고유부호
- 형식 검증 상태
- 본인 일치 검증 상태
- 사용자 동의·수집 목적·검증시각

형식만 맞는 값은 VERIFIED가 아니라 FORMAT_VALID로 전달한다. 본인 일치 확인이 필요한 상품은 검증 완료 전 결제를 차단한다.

개인통관고유부호와 수취정보는 암호화하고 일반 로그에 남기지 않는다.

## 8. 구매대행 신청

입력:

- tenant, user, order item IDs
- 사용한 mapping version
- product ID, SKU ID, 수량
- 주문상품별 원가 snapshot
- 수취·통관정보 참조
- 구매 전 견적 ID와 version
- 사용자 메모
- idempotency key

출력:

- sourcing application ID
- status
- quote snapshot
- payment session 생성 가능 여부
- 실패 item과 사유

복수 item 신청은 item별 성공·실패를 반환한다. 한 item 실패 때문에 성공 item의 결과를 숨기지 않는다.

## 9. 결제 세션

주문관리는 카드번호를 받지 않는다.

결제 세션 생성 응답:

- paymentSessionId
- 단기 만료 redirect URL 또는 client token
- 결제금액과 통화
- 만료시각
- 약관 version
- application ID

사용자 확인:

- 상품·SKU·수량
- 총 결제금액과 비용 구성
- 수취·통관정보
- 품절·가격변경 경고
- 국제배송·관부가세 안내
- 환불·취소 기준

최종 결제는 사용자가 소싱라이프 결제 화면에서 확인한다. 주문관리 화면은 redirect 결과만으로 결제 성공을 확정하지 않고 결제 조회 또는 서명된 webhook으로 대사한다.

| 상태 | 의미 |
|---|---|
| DRAFT | 신청 전 |
| SUBMITTED | 구매대행 신청 접수 |
| PAYMENT_PENDING | 결제대기 |
| PAID | 국내 결제 승인 |
| PURCHASE_PENDING | 타오바오 구매대기 |
| PURCHASED | 타오바오 구매 성공 |
| PARTIAL | 일부 item만 성공 |
| SELLER_SHIPPED | 중국 판매자 발송 |
| CANCELED | 구매 취소 |
| REFUND_PENDING | 환불 진행 |

| HOLD | 운영 검토 |

PAID, PURCHASED, 배송대행지 주문서 접수, 국내송장 발급은 별도 사건으로 저장한다. 다만 연결 배송대행지는 접수 성공 응답에서 국내송장을 즉시 발급해야 한다.

| 이벤트 | 주요 데이터 |
|---|---|
| CHINA_TRACKING_CREATED | 중국 택배사·송장 |
| SELLER_SHIPPED | 중국 출발시각 |
| FORWARDER_RECEIVED | 외부 배송대행지 입고 |
| FORWARDER_EXCEPTION | 오류입고·검수 이슈 |
| INTERNATIONAL_SHIPPED | 국제운송 정보 |
| CUSTOMS_STARTED | 통관 시작 |
| CUSTOMS_HOLD | 통관 보류 사유 |
| CUSTOMS_CLEARED | 통관 완료 |
| FORWARDER_ORDER_SUBMITTED | 선택 배송대행지 주문서 접수. 화면 용어 `접수대기`와 `접수신청`은 동일 단계 |
| DOMESTIC_LABEL_CREATED | 접수 성공 응답으로 즉시 발급된 국내 택배사·송장 |

## 12. 국내송장 계약

확정 정책:

1. 연결 대상은 주문서 접수 성공과 동시에 국내송장을 발급하는 배송대행지로 제한한다.
2. `접수대기`와 `접수신청`은 하나의 접수 단계로 취급한다.
3. 결제완료 후 선택 배송대행지 사이트를 열고 주문서를 자동입력한다.
4. 접수 성공 응답에서 실제 택배사와 국내송장번호를 즉시 수신한다.

추가 계약 확인 항목:

1. 발급된 송장이 실제 택배사 조회가 가능한가.
2. 송장 변경·폐기 이벤트가 있는가.
3. 합배송·분리배송을 어떻게 표현하는가.
4. 한 국내송장에 여러 마켓 주문을 연결할 수 있는가.

연동 규칙:

- 결제 응답 자체에 송장이 없다고 결제 실패로 간주하지 않는다. 송장은 이어지는 배송대행지 접수 응답에서 받는다.
- 배송대행지 접수 실패·응답 유실·송장 누락에도 PAID 상태는 보존하고 접수 재시도 또는 결과 대사를 수행한다.
- FORWARDER_ORDER_SUBMITTED와 DOMESTIC_LABEL_CREATED를 같은 접수 트랜잭션의 연속 사건으로 저장한다.
- DOMESTIC_LABEL_CREATED에서 shipment와 market 발송 후보를 생성한다.
- 송장 변경은 새 revision과 SUPERSEDED 관계로 저장한다.
- 자동 발송은 송장 유효성·클레임·마감조건을 다시 확인한 뒤 명령을 생성한다.

## 13. 취소·환불

입력:

- purchase/application/item
- 취소 수량
- 사유
- 마켓 claim 참조
- 사용자
- idempotency key

결과:

- 요청 접수 여부
- 타오바오 구매 전 즉시 취소 가능 여부
- 중국 판매자 발송 여부
- 반품 배송 필요 여부
- 예상 환불액·비용
- 환불 상태와 완료시각

마켓 취소와 소싱 환불은 한 트랜잭션이 될 수 없으므로 saga 상태를 저장한다.

| 마켓 | 소싱 | 주문관리 표시 |
|---|---|---|
| 성공 | 성공 | 완료 |
| 성공 | 실패/대기 | 소싱 환불 작업 필요 |
| 실패 | 성공 | 마켓 수동 복구 필요 |
| 확인중 | 확인중 | 결과 대사 중 |

한쪽만 성공한 건을 전체 완료로 표시하지 않는다.

## 14. webhook

필수 이벤트:

- application.updated
- payment.updated
- purchase.updated
- purchase.item.updated
- sourcing.product.changed
- shipment.updated
- domestic.invoice.created
- domestic.invoice.updated
- refund.updated

필수 header:

- event ID
- signature
- timestamp
- schema version
- correlation ID

처리 규칙:

- event ID 또는 결정적 hash로 중복 제거
- 원문 append-only 저장
- 서명·시간창 검증 실패 시 거부
- 순서가 바뀐 이벤트는 상태 version/occurredAt으로 정렬
- 알 수 없는 schema version은 현재 상태를 변경하지 않고 dead-letter

webhook 유실을 대비해 updatedSince 기반 polling 또는 단건 조회 API를 제공한다.

## 16. 멱등성과 대사

- 상품 검색은 cache 가능하지만 구매 직전 재조회한다.
- 견적은 version과 만료시각을 가진다.
- 구매 신청 idempotency key는 tenant + order items + mapping versions + request revision으로 만든다.
- 결제 세션 생성과 결제 실행을 구분한다.
- webhook과 polling은 같은 상태 reducer를 사용한다.
- timeout 후 같은 구매를 즉시 재요청하지 않고 application/purchase 조회로 확인한다.
- 주문관리와 소싱라이프는 correlation ID로 상호 추적한다.

15. 한쪽만 성공한 saga 복구
16. webhook 유실 후 polling 대사

실제 유료 결제와 되돌릴 수 없는 구매 제출은 테스트 전용 계정·샌드박스 또는 명시적으로 승인된 소액 테스트 절차에서만 실행한다.

## 19. 1차 생산 수직 슬라이스 구현 범위

2026-07-10 구현은 상품·SKU 매핑과 구매 전 검토초안까지만 제공한다. 소싱라이프 구매대행 신청 제출, 결제 세션 생성, 카드 승인, 타오바오 주문 실행은 포함하지 않는다.

### 19-1. 저장 모델

- `sourcing_source_products`: tenant별 타오바오·티몰·소싱라이프 상품과 제한품목·통관 요구사항, source version, 마지막 확인시각
- `sourcing_source_options`: 정확한 외부 SKU, 옵션 속성, CNY 가격, 재고, 최소수량·수량배수, 중국 내 배송비 상태
- `order_item_sourcing_mappings`: 주문상품별 선택 SKU snapshot과 mapping revision. 이전 매핑은 `SUPERSEDED`로 보존한다.
- `sourcing_purchase_drafts`: 환율·상품원가·수수료·중국배송·국제배송·관부가세·기타비용·할인을 분리한 검토초안
- `sourcing_purchase_draft_events`: 초안 준비·차단·대체 이력

모든 테이블은 tenant 복합 FK와 RLS를 사용한다. 구매초안에는 DB 제약으로 `pre_payment_only=true`, `purchase_submission_status=NOT_SUBMITTED`, `payment_status=NOT_STARTED`만 허용한다.

### 19-2. API

| 메서드·경로 | 역할 |
|---|---|
| `PUT /api/order-items/{id}/sourcing-mapping` | 상품·정확한 SKU snapshot을 저장하거나 revision을 올려 교체 |
| `POST /api/order-items/{id}/sourcing-mapping/validate` | 가격·재고·source version·최소수량·수량배수·중국배송비 freshness 검증 |
| `POST /api/order-items/{id}/purchase-drafts` | 비용과 통관·배대지 준비도를 동결한 결제 전 검토초안 생성 |

쓰기 API는 활성 `OWNER`, `ADMIN`, `OPERATOR` 멤버십과 주문상품 optimistic version을 요구한다. 매핑 변경은 구매 진행 전까지만 허용한다.

### 19-3. 초안 차단 조건

- 상품·SKU snapshot 만료, source version 또는 가격 변경
- 품절·재고부족·최소수량·수량배수 불일치
- 제한·금지품목 또는 운영 검토 필요
- 중국 내 배송비 미확정
- 수취정보 미완료
- 상품 요구수준에 미달하는 PCCC 형식·본인일치·동의 상태
- 외부 배송대행 연동 미준비
- 국제배송비·관부가세가 `UNKNOWN`
- 환율 노후 또는 견적 만료시각이 SKU freshness 범위를 초과

`PAY_LATER`는 0원으로 처리하지 않고 별도 부과 경고와 nullable 금액으로 보존한다. `READY_FOR_REVIEW`도 결제 또는 구매 제출 권한을 의미하지 않는다.

### 19-4. 검증 출처와 영구 매칭 재사용 경계

- 브라우저·운영자 `PUT /sourcing-mapping` 입력은 가격·재고·source version·확인시각을 신뢰하지 않으며 항상 `MANUAL_UNVERIFIED`로 저장한다. 요청 body로 검증 출처를 지정할 수 없다.
- `SERVER_VERIFIED` 승격과 검증된 행 수정은 table owner·superuser가 아닌 전용 BYPASSRLS 커넥터 역할만 가능하다. 앱 역할은 검증된 상품/SKU를 수동 snapshot으로 덮어쓸 수 없다.
- 상품과 정확한 SKU가 모두 서버 검증되지 않으면 freshness 결과와 구매 전 초안에 `SOURCE_SERVER_VERIFICATION_REQUIRED`를 기록하고 `BLOCKED`로 유지한다.
- `sourcing_mapping_rules`는 `tenant + market account + market product ID + market option ID + revision`을 재사용 키로 사용한다. 수동 저장 규칙은 `DRAFT + MANUAL_UNVERIFIED`이며 자동 재사용 대상이 아니다.
- 단일 옵션 상품처럼 마켓 option ID가 없는 경우도 `NULLS NOT DISTINCT` 키와 null-safe 비교로 동일 상품 규칙을 재사용한다.
- `GET /api/order-items/{id}/sourcing-mapping/reuse`는 다른 주문 ID에서 생성되었더라도 같은 마켓 계정·상품·옵션에 해당하는 최신 `APPROVED + SERVER_VERIFIED` 규칙만 반환한다.
- Taobao/Tmall canonical URL은 해당 도메인 또는 실제 하위 도메인의 HTTPS URL만 허용하고, thumbnail URL도 HTTPS만 허용한다.
- 할인은 금액과 함께 `CONFIRMED` 또는 `ESTIMATED` 상태를 남긴다. 국제배송비·관부가세가 `UNKNOWN`이면 0원으로 확정하지 않고 nullable 금액과 차단 사유를 보존한다.
