# 운영자 주문처리 매뉴얼

## 1. 운영 전제

현재 저장소에는 실원장/API와 demo mode가 함께 있다. 운영자는 상단 실데이터/demo 안내를 확인하고 demo 결과를 판매자센터 처리 증거로 사용하지 않는다.
스마트스토어 쓰기는 계정별 UAT capability가 `API/PASSED`인 작업만 실행하며, 나머지는 비활성 또는 수동 대체다.
커머스라이프는 독립 주문관리 서비스이며, 운영 대상 주문은 마켓에서 수집된 주문이다.
소싱라이프에서 직접 생성하거나 주문한 내역은 주문수집 목록에 포함하지 않는다.
소싱라이프 연동으로 받은 구매, 검수, 입고, 물류 상태와 결과는 커머스라이프 주문 화면에서 확인한다. 운영자가 소싱라이프 주문내역으로 이동하는 절차는 사용하지 않는다.

## 2. 기본 처리 순서

1. `주문관리 > 마켓연동`에서 마켓 계정과 활성 상태를 확인한다.
2. `주문관리 > 주문수집`에서 `주문수집` 버튼으로 주문을 수집한다.
3. 신규주문에서 `주문확인` 또는 `매칭하기`를 처리한다.
4. 상품준비에서 `소싱하기` 또는 `외부구매 배송처리`를 진행한다.
5. 필요하면 상품준비 상세의 `배송중 처리`에서 직접전달을 선택한다. 결제 전에는 송장 방식을 사용할 수 없다.
6. 구매와 국내송장이 준비된 발송대기 주문에서 `배송중 처리`를 실행한다. 확인창에서 스토어 기본 발송 방식을 확인하며 이미 발송된 주문은 재전송하지 않고 내부 상태만 반영된다.
7. 배송중, 배송완료, 취소/반품/교환 주문을 조회한다.

상품준비에서 소싱라이프 결제를 진행하기 전 개인통관부호가 `통관부호 일치`인지 확인한다. 불일치 주문은 배송정보에서 통관부호를 수정한 뒤 소싱한다.

## 3. 검색/필터 사용

상단 검색/필터는 현재 화면의 주문 목록을 좁혀 보는 기능이다.
`주문수집` 실행 범위를 제한하는 기능은 아니다.

- 기간 버튼: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 검색어: 상품명, 주문번호, 주문자, 수령인 기준으로 검색한다.
- 마켓/스토어 필터는 하나의 아이콘 버튼에서 선택한다.
- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시한다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안의 선택 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.
- 각 주문 단계에서 `판매처`로 마켓·스토어를, `상태`로 소싱 진행 상태와 구매확정 상태를 필터링할 수 있다.
- 상태 필터는 현재 주문이 없는 상태도 포함해 해당 단계에서 조회 가능한 상태를 모두 표시한다.
- 신규주문은 `소싱필요`, 상품준비는 `소싱필요·소싱완료·결제대기`, 발송대기/배송중은 `결제완료·중국배송중·통관 중·국내 배송중`, 배송완료는 `배송완료·구매확정`을 선택할 수 있다. 수동 검증 전은 `소싱필요`, 외부 구매 완료 주문은 `결제완료`에서 조회한다.
- 구매확정 주문은 `배송완료` 필터에 포함되며, `구매확정` 배지가 있는 주문만 다시 좁혀 볼 때 `구매확정` 필터를 선택한다.
- 배송완료 주문의 진행상태 컬럼에 `구매확정`이 표시되면 네이버에서 구매확정된 주문이다. 판매자가 주문관리에서 구매확정을 실행하지 않으며, 마켓 동기화 결과만 확인한다.
- 상품준비에서는 소싱라이프 또는 외부 구매를 완료한다. 자동 배송중 처리 OFF는 발송대기로 이동하고, ON은 마켓 택배 발송까지 자동 처리한다.
- 상품준비의 `배송중 처리 > 직접전달`은 구매 전에 마켓 발송만 먼저 처리해야 하는 예외 주문에 사용한다.

탭, 검색어, 필터, 데이터가 바뀌면 체크 선택과 펼쳐진 자세히 보기 상태는 현재 화면 기준으로 초기화된다.

## 4. 신규주문 처리

신규주문은 판매자가 주문확인하기 전 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `주문확인` | 주문을 상품준비로 이동 |
| `소싱하기` | 신규주문에서는 소싱 후보/옵션 매칭 저장과 주문확인을 함께 처리 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

상단 `주문확인`과 `주문취소`는 체크된 주문만 처리한다.
선택된 주문이 없으면 일괄 버튼은 비활성화된다.
소싱 후보를 확인하는 중 취소가 필요하면 소싱하기 모달의 `주문확인` 아래 `주문취소`를 누른다. 이어지는 판매자 주문취소 확인 모달에서 사유, 상세 사유, 취소 수량을 입력하면 목록의 개별 주문취소와 동일하게 처리된다.

## 5. 상품준비 처리

상품준비는 주문확인 후 소싱라이프 구매 또는 외부 구매가 필요한 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `소싱하기` | 소싱라이프 후보/옵션/수량과 배대지 수령 프로필을 선택하고 구매대행 신청 후 결제대기로 전환 |
| `결제하기` | 결제대기 주문의 신청 정보·중국 판매자 채팅을 확인한 뒤 별도 결제 화면으로 진행 |
| `소싱상품관리` | 소싱 결제완료부터 배송완료까지 신청상품·결제정보와 중국 판매자 채팅을 확인. 재결제는 불가 |
| `배송추적` | 소싱 결제완료부터 배송완료까지 결제완료·중국배송·통관·국내배송 이력을 누적 조회 |
| `운송장 수정` | 배송중 상세에서 `배송중 처리` 시작 전 택배사·운송장번호를 등록·수정. 처리 시작 후에는 수정 불가 |
| `소싱상품관리 > 반품·환불 신청` | TaoWorld 구매라인이 있는 결제완료~국내 배송중 상품에 반품 또는 환불 요청 |
| `외부구매 배송처리` | 소싱라이프를 사용하지 않고 직접 구매한 주문의 배송대행지 출고정보 등록 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

`결제하기`는 상품준비의 결제대기 주문에만 표시된다. 발송대기·배송중에서 `결제상태 불일치`가 표시되면 결제 버튼으로 복구하지 말고 주문 원장의 결제·구매 완료 여부를 확인한다. 결제완료 또는 외부구매 완료 전에는 배송중 처리를 진행할 수 없다.

실서비스에서는 결제완료 후 같은 모달에서 결제금액, 결제일시, 소싱라이프 주문번호, 배송대행지 주문서 접수 결과, 즉시 발급된 국내송장 반영 결과와 중국 판매자 채팅을 확인한다. 현재 프로토타입의 `배송대행지 자동입력 완료` 표시는 외부 사이트 열기·주문서 자동입력·접수 과정을 생략한 더미 결과다.

`자동 배송중 처리` 토글:

- OFF: 소싱라이프 또는 외부 구매 완료 후 국내송장이 있어도 발송대기로 이동한다.
- ON: 소싱라이프 또는 외부 구매가 완료되고 송장이 있는 일반 택배 주문은 마켓 발송 처리까지 자동 진행한다. 성공하면 마켓과 주문관리 내부 상태가 모두 배송중으로 변경된다.
- 마켓 발송 처리에 실패하면 주문은 송장이 있는 발송대기에 남으므로 실패 사유를 확인한 뒤 다시 처리한다.
- 상품준비와 발송대기의 토글은 같은 설정이다. 어느 화면에서 바꾸더라도 다른 화면에도 동일하게 적용된다.

소싱라이프 결제완료 후 처리:

1. 선택한 배송대행지 사이트를 연다.
2. 주문상품·수취·통관정보를 배송대행지 주문서에 자동입력한다.
3. `접수대기/접수신청` 단일 접수 단계를 실행한다.
4. 접수와 동시에 발급된 국내 택배사·송장번호를 주문에 저장한다.
5. 자동 배송중 처리 OFF면 발송대기로 이동하며 마켓은 아직 배송중이 아니다.
6. ON이면 국내송장을 마켓에 전송하고 성공 확인 후 배송중으로 이동한다.

현재 프로토타입은 1~4를 화면으로 보여주지 않고 결제완료 시 더미 국내송장을 즉시 생성해 5~6의 결과만 시연한다.
- 소싱라이프 구매 완료 결과에 실제 국내송장이 없으면 정상 주문으로 넘기지 않고 연동 오류로 확인한다.

외부구매 배송처리:

- 택배사와 국내송장번호를 반드시 입력해야 등록할 수 있다.
- 국내송장을 등록하면 자동 배송중 처리 OFF에서는 발송대기, ON에서는 마켓 발송 성공 후 배송중으로 이동한다.
- 송장번호가 없으면 완료 버튼이 비활성화되며 주문 상태도 변경되지 않는다.
- 직접전달을 먼저 처리한 주문도 외부 구매 완료 시 택배사와 국내송장번호를 반드시 입력한다. 송장이 없으면 발송대기로 이동하지 않는다.
- 구매 완료 후에는 발송대기에서 주문별 발송방법을 선택하거나, 이미 끝난 마켓 발송의 내부 처리를 마무리한다.

## 6. 발송대기 처리

발송대기는 구매와 국내송장 저장이 완료됐으며 `배송중 처리`가 남은 단계다.

상단 기능:

| 기능 | 기준 |
|---|---|
| `자동 배송중 처리` | 구매 완료와 송장 확보 직후 자동으로 마켓 배송중 처리하는 토글 |
| `배송중 처리` | 마켓 상태를 먼저 확인한 뒤 미발송 주문은 송장/직접전달로 발송하고, 발송 완료 주문은 내부 상태만 배송중으로 반영 |

행 처리:

- 구매 완료 시 저장된 택배사와 송장번호를 확인한다.
- 자동 배송중 처리 OFF 주문은 송장을 보유한 채 발송대기에 남는다.
- `배송중 처리`를 누르면 미발송 주문에만 모달이 열린다. 송장을 고르면 저장 송장을 전송하고, 지원 마켓에서 직접전달을 고르면 국내송장을 보내지 않는다.
- 마켓에 직접전달 또는 송장 발송이 이미 끝난 주문은 모달 없이 처리된다. 백엔드가 실제 발송 방식을 확인하고 내부 단계만 배송중으로 변경한다.
- 송장 누락 주문은 정상 발송대기 상태로 보지 않고 구매 완료 또는 연동 오류로 확인한다.
- `마켓 직접전달`은 실제 국내 물류 방식이 아니라 마켓 발송처리 방식이다. 소싱라이프 국내송장은 계속 수집·표시한다.
- 스마트스토어·11번가 직접전달은 소싱라이프 송장을 마켓에 전송하지 않는다. 쿠팡·G마켓·옥션은 송장전송으로 고정한다.
- 쿠팡 마켓 배송조회가 불가능한 경우에도 실제 국내 배송 진행은 소싱라이프 송장으로 확인한다.
- 소싱라이프 결제 전 직접전달을 먼저 처리해야 하면 상품준비의 `배송중 처리`에서 직접전달을 선택한다. 성공 후 마켓 상태는 배송중이지만 주문은 소싱 업무가 끝날 때까지 상품준비에 남는다.
- 직접전달 후에도 소싱라이프 구매 또는 외부 구매를 반드시 완료해야 한다. `구매 안 함` 처리는 없으며, 구매 완료 전에는 국내송장을 입력하거나 내부 배송중으로 이동하지 않는다.
- 이후 소싱라이프 구매 완료 시 국내송장이 반드시 함께 수신되어야 하며 내부 주문은 발송대기로 이동한다. 송장이 없으면 구매 완료로 처리하지 않고 연동 오류를 확인한다.
- 직접전달 주문의 소싱라이프 국내송장이 배송완료되면 내부 주문은 배송완료로 이동한다. 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않으므로 직접전달 여부는 택배정보의 `직접전달` 배지로 확인한다.
- 직접전달과 구매가 완료되면 필수 국내송장을 함께 저장하고 발송대기에 둔다. `배송중 처리`를 다시 실행하면 별도 마켓 발송 없이 내부 배송중으로 이동한다.

전역 처리 기준:

- 체크된 주문이 있으면 체크된 주문을 우선 대상으로 처리한다.
- 체크된 주문이 없으면 현재 필터에 보이는 주문을 대상으로 처리한다.
- 일괄 `배송중 처리`도 단일 주문과 동일한 모달·백엔드 선조회 규칙을 사용한다.
- 직접전달은 마켓연동에서 해당 기본값을 선택한 스마트스토어·11번가 주문에만 적용한다. 주문 처리 시에는 방식을 다시 선택하지 않는다.
- 마켓 전송이 끝난 주문에는 `마켓에서 수정`과 `수정내역 불러오기`를 제공하지 않는다. 전송 전 확인 화면에서 발송 방식과 송장정보를 확인한다.
- 조건에 맞지 않는 주문은 함께 선택되어도 처리 대상에서 제외된다.

## 7. 배송중/배송완료 조회

배송중과 배송완료는 기본 조회 화면이다.
배송중 화면에서는 송장 수정 버튼을 제공하지 않는다.
변경된 송장번호 항목은 배송중/배송완료 조회 화면에 표시하지 않는다.

## 8. 취소/반품/교환 처리

취소/반품/교환은 `/orders?view=claims`에서 별도 관리한다.

| 클레임 유형 | 버튼 |
|---|---|
| 취소 | `취소처리` |
| 반품 | `반품처리` |
| 교환 | `교환처리` |

현재 화면은 유형 필터만 제공한다.
현재단계 필터는 제공하지 않는다.
판매자가 직접 누른 `주문취소`는 접수 주체를 `판매자 직접취소`로 구분한다. 요청 접수 직후에는 `ON_HOLD / CANCEL_REQUESTED`로 전체주문에 남고, provider 최종 `CANCELED` 확인 후에만 판매자취소로 마감하여 취소·반품·교환의 완료 목록에도 표시한다. 처리보류 중에는 주문확인·소싱·발송·재취소를 실행하지 않는다.

데모 취소 클레임은 처리 모달에서 승인 또는 거부를 시연할 수 있으나, 실클레임의 승인·거부는 현재 조회 전용이다.
반품/교환 클레임은 현재 MVP에서 진행단계와 주문 정보를 확인하는 조회 중심 흐름이다.
회수, 재발송, 반품 승인 같은 상세 클레임 처리는 다음 단계에서 확장한다.

## 9. 마켓연동 관리

위치: `주문관리 > 마켓연동`

- 우측 상단 `마켓 추가`로 계정을 추가한다.
- 목록은 마켓, 스토어명, 연동상태, 활성, 관리 컬럼으로 구성한다.
- 관리 영역의 `설정` 버튼은 마켓 추가와 동일한 계정 수정 모달을 연다.
- 삭제 버튼은 삭제 확인 모달 후 삭제한다.
- 현재 화면에는 플랫폼 수수료율, 마지막 수집, 결과, 별도 계정설정 페이지를 제공하지 않는다.

## 10. 자세히 보기 확인

주문 행을 클릭하면 자세히 보기 영역이 열린다.
운영자는 목록에 없는 상세 정보를 이 영역에서 확인한다.

표시 순서:

1. 주문상품
2. 구매자
3. 배송정보
4. 택배정보
5. 처리하기
6. 소싱상품

배송정보는 자세히 보기에서도 수정할 수 있다.
목록 `처리하기`에는 탭별 필수 실행만 표시한다. 신규주문은 `주문확인`, `매칭하기`, `주문취소`, 상품준비는 `소싱하기`, `주문취소`, 발송대기는 `배송중 처리`만 사용하며 배송중과 배송완료 목록은 비워 둔다. 결제·채팅, 결제상품, 배송추적, 처리이력, 운송장 등록·수정 같은 확인·수정 기능은 행 자세히 보기에서 사용한다. 배송정보 수정은 이전 기준대로 왼쪽 구매자·배송정보 영역에서 제공한다.

## 11. 데이터 초기화

데모 데이터 검수를 위해 좌측 하단 `데이터 초기화` 버튼을 제공한다.
버튼은 소싱 매칭, 소싱 결제, 송장 저장/배송중 처리 localStorage 값을 삭제한다.
PostgreSQL 실주문, 클레임, 명령, 감사로그는 삭제하지 않는다.

## 12. 운영 주의사항

- 화면의 demo 배너가 보이는 주문은 실제 API 호출 대상이 아니다. 실원장 주문도 계정별 UAT 전 쓰기 capability는 차단된다.
- 주문수집 버튼은 현재 특정 마켓/스토어 필터에 따라 수집 범위를 제한하지 않는다.
- 구매대행 신청만으로 결제가 완료되지 않는다. 상태가 `결제대기`인지 확인하고 필요 시 `깎아줘`로 중국 판매자에게 가격 인하를 요청한다. 요청 중에는 `결제하기`가 비활성화된다. 요청을 철회할 때 `깎아줘 취소`를 사용하면 결제가 다시 활성화된다. 두 버튼은 가격이나 결제를 자동 변경하지 않으므로 판매자 답변과 최종 금액을 확인한 후 결제한다.
- 타오바오 직접 결제와 내부 배대지/창고 관리는 현재 MVP 범위가 아니다.
- 배송중 송장 수정 전송 기능은 현재 제공하지 않는다.

## 13. 주문현황으로 이슈 점검

1. 사이드바 `운영 개요 > 주문현황`을 연다.
2. `이슈만 보기`를 켜서 통관부호 누락, 실패, 지연, 진행 중 클레임을 먼저 확인한다.
3. 상태 타일을 선택해 대상 주문을 확인하고 `처리 화면 열기`로 기존 주문·클레임 화면에 이동한다.
4. 실제 조치가 필요 없는 오탐은 `이슈 아님`, 잠시 뒤 재확인할 건은 `2시간 미루기`를 사용한다.
5. 임계값을 바꾸면 현재 화면 판정만 즉시 갱신된다. 프로토타입의 제외·미루기 결과는 서버나 다른 운영자에게 공유되지 않는다.

배대지 그룹은 외부 배송 진행을 이해하기 위한 상태판이다. 커머스라이프에서 입고, 검수, 재포장, 배송비 결제, 출고 작업을 실행하지 않는다.

## 14. 알림·문의·장부 데모 확인

- 알림 설정에서는 고객·셀러 규칙, 고객 발송 시간대, 통관 안내 옵션과 미리보기를 확인한다. `설정 저장`은 실제 알림을 발송하지 않는다.
- 문의 답변에서 `AI 초안 만들기`를 누른 뒤 주문번호·일정·환불 표현을 반드시 검토하고 필요한 내용을 수정한다. 초안 생성만으로 답변이 전송되지 않는다.
- 장부에서 `직접 입력 비용 반영`을 켜면 직접 지출·수입과 실제마진을 확인한다. 현재 값은 데모 데이터이며 회계·세무 증빙으로 사용하지 않는다.

## 15. 소싱상품 환불 처리

1. 주문수집에서 TaoWorld 구매 주문라인 식별자가 저장된 `결제완료`부터 `국내 배송중` 소싱상품을 찾고 `소싱상품관리`를 연다. 배송완료 후에는 기존 환불만 계속 조회·처리한다.
2. 구매대행 신청 상품 영역의 `반품·환불 신청`을 열고 TaoWorld 구매 주문번호·구매 주문라인 ID·상품·CNY 결제금액을 확인한다.
3. 마켓의 취소·반품·교환 처리가 필요한 건이면 `/orders?view=claims`에서 별도로 처리하고, 연결할 클레임 ID를 환불 요청에 기록한다.
4. `/order/refund/render` 데모에서 환불유형과 상품상태에 맞는 동적 사유와 최대 환불 가능 CNY 금액을 확인한다. 발송 전이면 `환불만 요청`, 발송 이후면 `반품 후 환불`을 우선 검토한다.
5. `reasonId`·`refundFee(CNY)`·상세 내용·선택적 증빙 URL을 입력하고 `마켓 주문 취소·구매자 환불은 자동 처리되지 않음`을 확인한다. TaoWorld 제출 계약에 없는 임의 환불 수량은 입력하지 않는다.
6. `/order/refund/submit` 데모 뒤 주문의 진행상태 배지와 자세히 보기의 `refundId`·원본 상태코드를 확인한다. 활성 환불 중에는 배송중 처리와 직접전달을 실행하지 않는다.
7. 콜백 `message_type=9` 수신을 가정한 데모 동작으로 `/order/refund/query` 재조회 상태 전이를 확인한다. `반품 접수 필요`에서는 `/order/refund/render/logistics`의 중국 택배사 코드와 `/order/refund/submit/logistics`의 송장·연락처를 입력한다.
8. `환불 완료` 후에도 마켓 구매자 환불이 완료됐는지 별도로 확인한다. 두 결과 중 하나라도 미완료이면 케이스를 닫지 않는다.
9. 구매자 주문을 유지하고 다른 판매처에서 다시 구매해야 한다면 국내배송이 시작되지 않았는지 확인한 뒤 상세 `처리하기 > 다시 소싱하기`를 누른다. 새 후보 상품·옵션·판매처와 배대지를 선택하고 결제대기에서 상품 결제를 완료한다. 기존 환불 내역은 이력으로 남으며 과거 송장으로 발송하지 않는다.

현재 화면은 TaoWorld 공식 API 계약을 재현한 프로토타입이며 실제 요청을 보내지 않는다. 실주문은 `실전송 비활성`으로 표시하고 demo 성공 메시지를 실제 환불 증빙으로 사용하지 않는다.
