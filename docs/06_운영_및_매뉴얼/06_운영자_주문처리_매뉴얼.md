# 운영자 주문처리 매뉴얼

## 1. 운영 전제

현재 MVP는 실제 백엔드/API 없이 mock data로 주문 처리 흐름을 확인하는 단계다.
운영자는 현재 화면에서 제공되는 버튼과 상태 전환 기준을 기준으로 데모 흐름을 검수한다.

## 2. 기본 처리 순서

1. `주문관리 > 마켓연동`에서 마켓 계정과 활성 상태를 확인한다.
2. `주문관리 > 주문수집`에서 `주문수집` 버튼으로 주문을 수집한다.
3. 신규주문에서 `주문확인` 또는 `매칭하기`를 처리한다.
4. 상품준비에서 `소싱하기` 또는 `수동구매 완료`를 처리한다.
5. 발송대기에서 소싱라이프 송장을 수집하거나 송장번호를 직접 입력한다.
6. 송장번호가 있는 주문을 `배송중 처리`한다.
7. 배송중, 배송완료, 취소/반품/교환 주문을 조회한다.

## 3. 검색/필터 사용

상단 검색/필터는 현재 화면의 주문 목록을 좁혀 보는 기능이다.
`주문수집` 실행 범위를 제한하는 기능은 아니다.

- 기간 버튼: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 검색어: 상품명, 주문번호, 주문자, 수령인 기준으로 검색한다.
- 마켓/스토어 필터는 하나의 아이콘 버튼에서 선택한다.
- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시한다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안의 선택 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.

탭, 검색어, 필터, 데이터가 바뀌면 체크 선택과 펼쳐진 자세히 보기 상태는 현재 화면 기준으로 초기화된다.

## 4. 신규주문 처리

신규주문은 판매자가 주문확인하기 전 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `주문확인` | 주문을 상품준비로 이동 |
| `매칭하기` | 소싱 후보/옵션 매칭 저장과 주문확인을 함께 처리 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

상단 `주문확인`과 `주문취소`는 체크된 주문만 처리한다.
선택된 주문이 없으면 일괄 버튼은 비활성화된다.

## 5. 상품준비 처리

상품준비는 주문확인 후 소싱 또는 수동구매가 필요한 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `소싱하기` | 소싱라이프 후보/옵션/수량을 선택하고 구매대행 신청/결제 화면으로 진행 |
| `수동구매 완료` | 소싱라이프를 통하지 않고 다른 곳에서 구매한 주문 처리 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

`소싱라이프 송장 수신 시 자동 배송중 처리` 토글:

- OFF: 소싱라이프 결제 후 송장이 함께 와도 발송대기로 이동한다.
- ON: 송장이 함께 온 주문은 배송중 처리까지 자동 진행한다.
- 송장이 없으면 ON/OFF와 관계없이 발송대기로 이동한다.

수동구매 완료:

- 송장번호 없이 `발송대기 처리`를 누르면 발송대기로 이동한다.
- 송장번호를 입력하고 `발송대기 처리`를 누르면 송장 저장 후 발송대기로 이동한다.
- 송장번호를 입력하고 `배송중 처리`를 누르면 배송중으로 이동한다.

## 6. 발송대기 처리

발송대기는 국내송장 수집, 입력, 배송중 처리를 기다리는 단계다.

상단 기능:

| 기능 | 기준 |
|---|---|
| 송장 필터 | `전체`, `송장 있음`, `송장 없음` 중 선택 |
| `소싱라이프 송장 수집` | 소싱라이프 주문번호가 있고 송장번호가 없는 주문의 송장 조회 |
| `소싱라이프 송장 자동 수집` | 소싱라이프 송장을 자동으로 가져오는 토글 |
| `자동 배송중 처리` | 송장번호가 입력 또는 수집되면 자동으로 배송중 처리하는 토글 |
| `배송중 처리` | 송장번호가 있는 주문만 배송중으로 이동 |

행 처리:

- 송장번호 입력은 자동 저장된다.
- 송장번호만 입력하면 발송대기에 남는다.
- `배송중 처리`를 누르면 배송중으로 이동한다.
- 송장번호가 없으면 `배송중 처리` 버튼은 비활성화된다.

전역 처리 기준:

- 체크된 주문이 있으면 체크된 주문을 우선 대상으로 처리한다.
- 체크된 주문이 없으면 현재 필터에 보이는 주문을 대상으로 처리한다.
- `소싱라이프 송장 수집`은 소싱라이프 주문번호가 있고 송장번호가 없는 주문만 실제 처리한다.
- `배송중 처리`는 송장번호가 있는 주문만 실제 처리한다.
- 조건에 맞지 않는 주문은 함께 선택되어도 처리 대상에서 제외된다.

## 7. 배송중/배송완료 조회

배송중과 배송완료는 기본 조회 화면이다.
배송중 화면에서는 송장 수정 버튼을 제공하지 않는다.
변경된 송장번호가 있는 경우 번호만 표시해 운영자가 마켓에서 직접 확인할 수 있게 한다.

## 8. 취소/반품/교환 처리

취소/반품/교환은 `/orders?view=claims`에서 별도 관리한다.

| 클레임 유형 | 버튼 |
|---|---|
| 취소 | `취소처리` |
| 반품 | `반품처리` |
| 교환 | `교환처리` |

현재 화면은 유형 필터만 제공한다.
현재단계 필터는 제공하지 않는다.
판매자가 직접 누른 `주문취소`는 `CANCELED` 상태이며 구매자 요청 클레임과 분리한다.

취소 클레임은 처리 모달에서 승인 또는 거부를 선택할 수 있다.
반품/교환 클레임은 현재 MVP에서 진행단계와 주문 정보를 확인하는 조회 중심 흐름이다.
회수, 재발송, 반품 승인 같은 상세 클레임 처리는 다음 단계에서 확장한다.

## 9. 마켓연동 관리

위치: `주문관리 > 마켓연동`

- 우측 상단 `마켓 추가`로 계정을 추가한다.
- 목록은 마켓, 스토어명, 연동상태, 활성, 관리 컬럼으로 구성한다.
- 관리 버튼은 마켓 추가와 동일한 계정 수정 모달을 연다.
- 삭제 버튼은 삭제 확인 모달 후 삭제한다.
- 현재 화면에는 플랫폼 수수료율, 마지막 수집, 결과, 별도 계정설정 페이지를 제공하지 않는다.

## 10. 자세히 보기 확인

주문 행을 클릭하면 자세히 보기 영역이 열린다.
운영자는 목록에 없는 상세 정보를 이 영역에서 확인한다.

표시 순서:

1. 주문상품
2. 구매자
3. 배송정보
4. 택배정보
5. 소싱상품

배송정보는 자세히 보기에서도 수정할 수 있다.

## 11. 데이터 초기화

현재 MVP는 데모 데이터 검수를 위해 좌측 하단 `데이터 초기화` 버튼을 제공한다.
버튼은 소싱 매칭, 소싱 결제, 송장 수집 localStorage 값을 삭제한다.
또한 주문 화면 진입 시 현재 구현은 mock data를 다시 구성한다.

## 12. 운영 주의사항

- 현재 MVP는 실제 API 호출이 아니라 프론트 데모 흐름이다.
- 주문수집 버튼은 현재 특정 마켓/스토어 필터에 따라 수집 범위를 제한하지 않는다.
- 소싱라이프 결제 화면은 모달 안의 임시 구매대행 신청/결제 화면이다.
- 타오바오 직접 결제와 내부 배대지/창고 관리는 현재 MVP 범위가 아니다.
- 배송중 송장 수정 전송 기능은 현재 제공하지 않는다.
