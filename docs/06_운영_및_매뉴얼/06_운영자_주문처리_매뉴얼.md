# 운영자 주문처리 매뉴얼

## 1. 운영 전제

현재 저장소에는 실원장/API와 demo mode가 함께 있다. 운영자는 상단 실데이터/demo 안내를 확인하고 demo 결과를 판매자센터 처리 증거로 사용하지 않는다.
스마트스토어 쓰기는 계정별 UAT capability가 `API/PASSED`인 작업만 실행하며, 나머지는 비활성 또는 수동 대체다.
주문관리는 소싱라이프 내부 메뉴이며, 운영 대상 주문은 마켓에서 수집된 주문이다.
소싱라이프에서 직접 생성하거나 주문한 내역은 주문수집 목록에 포함하지 않는다.
소싱라이프의 구매, 검수, 입고, 물류 상세 처리는 소싱라이프 기존 기능에서 진행한다.

## 2. 기본 처리 순서

1. `주문관리 > 마켓연동`에서 마켓 계정과 활성 상태를 확인한다.
2. `주문관리 > 주문수집`에서 `주문수집` 버튼으로 주문을 수집한다.
3. 신규주문에서 `주문확인` 또는 `소싱하기`를 처리한다.
4. 상품준비에서 `소싱하기` 또는 `국내송장 등록`을 처리한다.
5. 자동 배송중 처리 OFF 또는 자동 발송 실패 주문을 발송대기에서 확인한다.
6. 저장된 송장으로 `배송중 처리`한다.
7. 배송중, 배송완료, 취소/반품/교환 주문을 조회한다.

상품준비에서 소싱라이프 결제를 진행하기 전 개인통관부호가 `통관부호 일치`인지 확인한다. 불일치 주문은 배송정보에서 통관부호를 수정한 뒤 소싱한다.

## 3. 검색/필터 사용

상단 검색/필터는 현재 화면의 주문 목록을 좁혀 보는 기능이다.
`주문수집` 실행 범위를 제한하는 기능은 아니다.

- 기간 버튼: `오늘`, `3일`, `7일`, `30일`, `직접 입력`.
- 검색어: 상품명, 주문번호, 주문자, 수령인 기준으로 검색한다.
- 마켓/스토어 필터는 하나의 아이콘 버튼에서 선택한다.
- 아무것도 선택하지 않으면 전체 주문을 표시한다.
- 마켓만 선택하면 선택한 마켓의 전체 스토어 주문을 표시한다.
- 스토어만 선택하면 해당 스토어 주문을 표시한다.
- 마켓과 스토어를 함께 선택하면 선택한 마켓 안의 선택 스토어 주문만 표시한다.
- 선택한 마켓과 관계없는 스토어는 숨기지 않고 비활성화한다.
- 각 주문 단계에서 `판매처`로 마켓·스토어를, `상태`로 소싱 진행 상태와 구매확정 상태를 필터링할 수 있다.
- 상태 필터는 현재 주문이 없는 상태도 포함해 해당 단계에서 조회 가능한 상태를 모두 표시한다.
- 신규주문은 `소싱필요`, 상품준비는 `소싱필요·소싱 검증대기·소싱완료·결제대기`, 발송대기/배송중은 `결제완료·중국배송중·통관 중·국내 배송중`, 배송완료는 `배송완료·구매확정`을 선택할 수 있다. 외부 구매 완료 주문도 `결제완료`에서 조회하며 자세히 보기의 소싱상품에서 구매경로를 확인한다.
- 구매확정 주문은 `배송완료` 필터에 포함되며, `구매확정` 배지가 있는 주문만 다시 좁혀 볼 때 `구매확정` 필터를 선택한다.
- 배송완료 주문의 진행상태 컬럼에 `구매확정`이 표시되면 네이버에서 구매확정된 주문이다. 판매자가 주문관리에서 구매확정을 실행하지 않으며, 마켓 동기화 결과만 확인한다.
- 상품준비에서는 소싱라이프 또는 외부 구매를 완료한다. 자동 배송중 처리 OFF는 발송대기로 이동하고, ON은 마켓 택배 발송까지 자동 처리한다.
- 상품준비의 `마켓 직접전달`은 소싱 전에 마켓 발송만 먼저 처리해야 하는 예외 주문에만 사용한다.

탭, 검색어, 필터, 데이터가 바뀌면 체크 선택과 펼쳐진 자세히 보기 상태는 현재 화면 기준으로 초기화된다.

## 4. 신규주문 처리

신규주문은 판매자가 주문확인하기 전 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `주문확인` | 주문을 상품준비로 이동 |
| `소싱하기` | 신규주문에서는 소싱 후보/옵션 매칭 저장과 주문확인을 함께 처리 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

상단 `주문확인`과 `주문취소`는 체크된 주문만 처리한다.
선택된 주문이 없으면 일괄 버튼은 비활성화된다.
소싱 후보를 확인하는 중 취소가 필요하면 소싱하기 모달의 `주문확인` 아래 `주문취소`를 누른다. 이어지는 판매자 주문취소 확인 모달에서 사유, 상세 사유, 취소 수량을 입력하면 목록의 개별 주문취소와 동일하게 처리된다.

## 5. 상품준비 처리

상품준비는 주문확인 후 소싱라이프 구매 또는 외부 구매가 필요한 단계다.

| 버튼 | 사용 기준 |
|---|---|
| `소싱하기` | 소싱라이프 후보/옵션/수량과 배대지 수령 프로필을 선택하고 구매대행 신청 후 결제대기로 전환 |
| `결제하기` | 결제대기 주문의 신청 정보·채팅을 확인한 뒤 별도 결제 화면으로 진행 |
| `결제완료 보기` | 결제완료 주문의 신청·결제정보와 채팅을 다시 확인. 재결제는 불가 |
| `국내송장 등록` | 소싱라이프에서 결제하지 않고 직접 구매한 주문의 국내송장 등록 |
| `주문취소` | 확인 모달 후 판매자 직접 취소 처리 |

`결제하기`는 상품준비의 결제대기 주문에만 표시된다. 발송대기·배송중에서 `결제상태 불일치`가 표시되면 결제 버튼으로 복구하지 말고 주문 원장의 결제·구매 완료 여부를 확인한다. 결제완료 또는 외부구매 완료 전에는 배송중 처리를 진행할 수 없다.

실서비스에서는 결제완료 후 같은 모달에서 결제금액, 결제일시, 소싱라이프 주문번호, 배송대행지 주문서 접수 결과, 즉시 발급된 국내송장 반영 결과와 채팅을 확인한다. 현재 프로토타입의 `배송대행지 자동입력 완료` 표시는 외부 사이트 열기·주문서 자동입력·접수 과정을 생략한 더미 결과다.

`자동 배송중 처리` 토글:

- OFF: 소싱라이프 또는 외부 구매 완료 후 국내송장이 있어도 발송대기로 이동한다.
- ON: 소싱라이프 또는 외부 구매가 완료되고 송장이 있는 일반 택배 주문은 마켓 발송 처리까지 자동 진행한다. 성공하면 마켓과 주문관리 내부 상태가 모두 배송중으로 변경된다.
- 마켓 발송 처리에 실패하면 주문은 송장이 있는 발송대기에 남으므로 실패 사유를 확인한 뒤 다시 처리한다.
- 상품준비와 발송대기의 토글은 같은 설정이다. 어느 화면에서 바꾸더라도 다른 화면에도 동일하게 적용된다.

소싱라이프 결제완료 후 처리:

1. 선택한 배송대행지 사이트를 연다.
2. 주문상품·수취·통관정보를 배송대행지 주문서에 자동입력한다.
3. `접수대기/접수신청` 단일 접수 단계를 실행한다.
4. 접수와 동시에 발급된 국내 택배사·송장번호를 주문에 저장한다.
5. 자동 배송중 처리 OFF면 발송대기로 이동하며 마켓은 아직 배송중이 아니다.
6. ON이면 국내송장을 마켓에 전송하고 성공 확인 후 배송중으로 이동한다.

현재 프로토타입은 1~4를 화면으로 보여주지 않고 결제완료 시 더미 국내송장을 즉시 생성해 5~6의 결과만 시연한다.
- 소싱라이프 구매 완료 결과에 실제 국내송장이 없으면 정상 주문으로 넘기지 않고 연동 오류로 확인한다.

직접구매 국내송장 등록:

- 택배사와 국내송장번호를 반드시 입력해야 등록할 수 있다.
- 국내송장을 등록하면 자동 배송중 처리 OFF에서는 발송대기, ON에서는 마켓 발송 성공 후 배송중으로 이동한다.
- 송장번호가 없으면 완료 버튼이 비활성화되며 주문 상태도 변경되지 않는다.
- 직접전달을 먼저 처리한 주문도 외부 구매 완료 시 택배사와 국내송장번호를 반드시 입력한다. 송장이 없으면 내부 배송중으로 이동하지 않는다.
- 마켓 발송은 발송대기의 `배송중 처리`에서 진행한다.

## 6. 발송대기 처리

발송대기는 구매와 국내송장 저장은 완료됐지만 마켓 배송중 처리가 남은 단계다.

상단 기능:

| 기능 | 기준 |
|---|---|
| `자동 배송중 처리` | 구매 완료와 송장 확보 직후 자동으로 마켓 배송중 처리하는 토글 |
| `배송중 처리` | 저장된 국내송장을 즉시 마켓에 전송하고 배송중으로 처리. 선택 모달 없음 |

행 처리:

- 구매 완료 시 저장된 택배사와 송장번호를 확인한다.
- 자동 배송중 처리 OFF 주문은 송장을 보유한 채 발송대기에 남는다.
- `배송중 처리`를 누르면 저장된 국내송장을 즉시 마켓에 전송하고 성공 시 배송중으로 이동한다.
- 송장 누락 주문은 정상 발송대기 상태로 보지 않고 구매 완료 또는 연동 오류로 확인한다.
- `마켓 직접전달`은 실제 국내 물류 방식이 아니라 마켓 발송처리 방식이다. 소싱라이프 국내송장은 계속 수집·표시한다.
- 네이버 직접전달은 소싱라이프 송장을 마켓에 전송하지 않는다. 쿠팡 업체직송은 시스템이 생성한 임의의 숫자 식별값으로 마켓에 처리한다.
- 쿠팡 마켓 배송조회가 불가능한 경우에도 실제 국내 배송 진행은 소싱라이프 송장으로 확인한다.
- 소싱라이프 결제 전 직접전달을 먼저 처리해야 하면 상품준비에서 `마켓 직접전달`을 사용한다. 성공 후 마켓 상태는 배송중이지만, 주문은 소싱 업무가 끝날 때까지 상품준비에 남는다.
- 직접전달 후에도 소싱라이프 구매 또는 외부 구매를 반드시 완료해야 한다. `구매 안 함` 처리는 없으며, 구매 완료 전에는 국내송장을 입력하거나 내부 배송중으로 이동하지 않는다.
- 이후 소싱라이프 구매 완료 시 국내송장이 반드시 함께 수신되어야 하며 내부 주문은 배송중으로 이동한다. 송장이 없으면 구매 완료로 처리하지 않고 연동 오류를 확인한다.
- 직접전달 주문의 소싱라이프 국내송장이 배송완료되면 내부 주문은 배송완료로 이동한다. 진행상태 컬럼에는 `마켓 배송중 · 직접전달` 배지를 표시하지 않으므로 직접전달 여부는 택배정보의 `직접전달` 배지로 확인한다.
- 직접전달과 구매가 완료되면 필수 국내송장을 함께 저장하고 별도 택배 발송 API 호출 없이 내부 배송중으로 이동한다.

전역 처리 기준:

- 체크된 주문이 있으면 체크된 주문을 우선 대상으로 처리한다.
- 체크된 주문이 없으면 현재 필터에 보이는 주문을 대상으로 처리한다.
- 일괄 `배송중 처리`는 송장번호가 있고 직접전달로 이미 처리되지 않은 주문만 실제 처리한다.
- 행의 `마켓 직접전달`은 네이버·쿠팡 주문에만 표시한다.
- 조건에 맞지 않는 주문은 함께 선택되어도 처리 대상에서 제외된다.

## 7. 배송중/배송완료 조회

배송중과 배송완료는 기본 조회 화면이다.
배송중 화면에서는 송장 수정 버튼을 제공하지 않는다.
변경된 송장번호 항목은 배송중/배송완료 조회 화면에 표시하지 않는다.

## 8. 취소/반품/교환 처리

취소/반품/교환은 `/orders?view=claims`에서 별도 관리한다.

| 클레임 유형 | 버튼 |
|---|---|
| 취소 | `취소처리` |
| 반품 | `반품처리` |
| 교환 | `교환처리` |

현재 화면은 유형 필터만 제공한다.
현재단계 필터는 제공하지 않는다.
판매자가 직접 누른 `주문취소`는 구매자 요청 클레임과 분리한다. 실주문 요청 접수 직후에는 `ON_HOLD / CANCEL_REQUESTED`로 전체주문에 남고, provider 최종 `CANCELED` 확인 후에만 판매자취소로 마감한다. 처리보류 중에는 주문확인·소싱·발송·재취소를 실행하지 않는다.

데모 취소 클레임은 처리 모달에서 승인 또는 거부를 시연할 수 있으나, 실클레임의 승인·거부는 현재 조회 전용이다.
반품/교환 클레임은 현재 MVP에서 진행단계와 주문 정보를 확인하는 조회 중심 흐름이다.
회수, 재발송, 반품 승인 같은 상세 클레임 처리는 다음 단계에서 확장한다.

## 9. 마켓연동 관리

위치: `주문관리 > 마켓연동`

- 우측 상단 `마켓 추가`로 계정을 추가한다.
- 목록은 마켓, 스토어명, 연동상태, 활성, 관리 컬럼으로 구성한다.
- 관리 영역의 `설정` 버튼은 마켓 추가와 동일한 계정 수정 모달을 연다.
- 삭제 버튼은 삭제 확인 모달 후 삭제한다.
- 현재 화면에는 플랫폼 수수료율, 마지막 수집, 결과, 별도 계정설정 페이지를 제공하지 않는다.

## 10. 자세히 보기 확인

주문 행을 클릭하면 자세히 보기 영역이 열린다.
운영자는 목록에 없는 상세 정보를 이 영역에서 확인한다.

표시 순서:

1. 주문상품
2. 구매자
3. 배송정보
4. 택배정보
5. 처리하기
6. 소싱상품

배송정보는 자세히 보기에서도 수정할 수 있다.
자세히 보기 하단 왼쪽 `처리하기`에서 현재 단계의 전체 작업을 확인한다. 상품준비의 `국내송장 등록`, `마켓 직접전달`과 발송대기의 `결제완료 보기`, `주문취소` 같은 저빈도 작업은 이 영역에서 실행한다. 직접전달 주문에는 `주문취소`가 표시되지 않는다. 중국배송·통관·국내배송은 별도 보기 화면 없이 진행상태에서 확인한다.

## 11. 데이터 초기화

데모 데이터 검수를 위해 좌측 하단 `데이터 초기화` 버튼을 제공한다.
버튼은 소싱 매칭, 소싱 결제, 송장 저장/배송중 처리 localStorage 값을 삭제한다.
PostgreSQL 실주문, 클레임, 명령, 감사로그는 삭제하지 않는다.

## 12. 운영 주의사항

- 화면의 demo 배너가 보이는 주문은 실제 API 호출 대상이 아니다. 실원장 주문도 계정별 UAT 전 쓰기 capability는 차단된다.
- 주문수집 버튼은 현재 특정 마켓/스토어 필터에 따라 수집 범위를 제한하지 않는다.
- 구매대행 신청만으로 결제가 완료되지 않는다. 상태가 `결제대기`인지 확인하고 필요 시 채팅 문의 후 `결제하기`를 다시 누른다.
- 타오바오 직접 결제와 내부 배대지/창고 관리는 현재 MVP 범위가 아니다.
- 배송중 송장 수정 전송 기능은 현재 제공하지 않는다.
